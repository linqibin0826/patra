# Claude Design 交接简报（Design Brief）

> 每次迭代：把"和 Claude Code 聊定的产品内容"压成本文件的一份副本，作为 Design 画布的出稿依据。
> 设计系统以 [Patra Design System](https://claude.ai/artifact/H6ghni1vGUZen5cZubg1R9) 为准（token 取自 `src/styles/tokens.css`），**每次只交增量**。

## 它在流程里的位置

```
①你 + Claude Code        ②Claude Code 产出        ③Claude Code 出稿          ④Design 画布产出               ⑤回 Claude Code
聊定本次迭代内容   ───►  这份「设计简报」副本  ───►  简报 + 真实数据 + 参考  ───►  流程画板（可交互）      ───►  按 TDD 落地
(brainstorming/spec)                                  (claude.ai Design 画布)       + 视觉画板（静态）
                                                                                    定稿 → 快照入库
```

## 三条铁律（来自业界踩坑）

1. **不在同一对话里既设计又写生产代码** —— 出画布的会话只做设计探索；落地另开会话按 TDD 做。
2. **不写"现代 / 简洁 / clean"这种空词** —— 它会自行选默认值，多半偏离你脑子里的样子。要点名具体。
3. **不漏场景，状态之间怎么切换也要能点出来** —— 空 / 加载 / 错误 / 无结果，不逐屏点名它就不画；只画成一张张静态画板，状态之间怎么切换就没人拍板，留给落地时现场决定。

## 怎么用

1. 复制下面「— 模板 —」整段到 `docs/design-briefs/<版本>/<页面>.md`，填满。
2. 在 Claude Code 里把简报交给它出 Design 画布（claude.ai 的 Design 类型 Artifact）。
3. 附上：相关现有页的 **dev URL**（出稿前先打开看真实页面）+ **真实数据样例**。
4. 迭代用 **画布上的评论**（局部：间距/按钮/组件替换）/ **对话**（结构、布局方向、大的视觉调整）；流程画板点 Play 实际走一遍。
5. 定稿后把画布源文件快照入 `docs/patra/design/snapshots/`，画布链接记到 Design Issue；FE Issue 由 Claude Code 按 TDD 落地。

## 不要写进简报的

- ❌ 设计系统（色 / 字 / 间距 / 阴影 / 圆角）—— 画布直接读 `src/styles/tokens.css`，重复反而让它漂移。
- ❌ 整个代码库 —— 出稿会话能直接读代码，按组件名引用即可。
- ❌ 实现细节（用哪个 hook、状态怎么管、RSC vs client）—— 那是第 ⑤ 步 Claude Code 的活。

# — 填写示例（节选：检索结果页）—

> 仅示范字段 2–4 的填法，帮你建立"够具体"的手感。

## 2. 要设计的屏 / 流程

| 屏 | 路由 | 用途 | 入口 → 出口 |
|----|------|------|------------|
| 检索结果 | `/search?q=` | 展示一次检索的命中文献列表，支持排序/筛选 | 首页搜索框提交 → 点条目进 `/paper/[id]` |

## 3. 每屏内容与数据

**检索结果**
- 信息块与层级：① 顶部检索摘要条（命中数 + 当前 query + 排序/筛选入口）→ ② 结果列表，每条复用 `PaperCard`：标题（最重要）> 作者 > 期刊·年份 > AI 摘要徽标 `AISummaryBadge` > 证据等级标签
- 关键动作：按相关度/时间排序、按年份/期刊/类型筛选、分页
- 真实数据样例：
  ```json
  {
    "total": 1284,
    "items": [
      {
        "id": "PMID-39912345",
        "title": "Tirzepatide for the Treatment of Obstructive Sleep Apnea",
        "authors": ["Malhotra A", "Grunstein RR", "et al."],
        "journal": "N Engl J Med",
        "year": 2024,
        "aiSummary": true,
        "evidenceLevel": "RCT"
      }
    ]
  }
  ```
- 信息密度：高 —— 一屏尽量多放结果，参照现有 explore-feed 的紧凑卡片。

## 4. 流程与场景

| 流程 | 场景（Tweaks 下拉选项） |
|------|------------------------|
| 提交检索 / 改排序 / 改筛选 | 有结果 / 加载中（skeleton 卡片列表） / 无结果（"未找到 'xxx' 的相关文献" + 检索建议） / 检索服务不可用 |
| 翻页 | 有下一页 / 最后一页 |

- 边界：超长标题两行截断省略；缺 `aiSummary` 时不显徽标；`evidenceLevel` 缺失时不占位。
- 视觉画板：结果卡片紧凑 / 宽松两种密度并排比较。
