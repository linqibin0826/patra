# 文献讨论、投稿经验与提醒 — Design Brief

> v0.14 唯一一份设计简报。设计系统与代码库已 onboard，本简报只交增量。
> **产品定义以 release spec 为准**：`docs/patra/release-specs/v0.14-discussion.md` 2.1 节（讨论、投稿经验、PubMed 审稿周期、提醒、账号状态）与第 4 节决策 C、D、E、F、G、H。本简报只定页面、状态与文案；两者不一致时以 spec 为准，简报里发现的缺口列在 §10，不在这里改规则。
> **接口契约以后端工程 spec 为准**：PAP-117（期刊卡片）、PAP-118（identity 提及支撑）、PAP-119（PubMed 审稿周期）、PAP-121（讨论）、PAP-122（投稿经验）、PAP-123（提醒）。写本简报时这几份都还没写，页面对它们的要求列在附录 A。
> 可交互画板：Claude Design 画布「v0.14 讨论」<https://claude.ai/artifact/DcyaGqN7xUMiXNbK3exaBN>（桌面 1440 + 移动 375，4 页 20 块，场景用 Tweaks 切换）；快照 `docs/patra/design/snapshots/2026-10-27-discussion-hifi.zip`（2026-10-27 用户确认后从画布读回）。
> 同版相关：Linear PAP-116（本简报 + 画板）→ PAP-124（讨论区与编辑器）/ PAP-125（投稿经验）/ PAP-126（提醒）。

**目标**：医生和科研人员能在文献页讨论一篇文献，在期刊页查看和写下同行的投稿经验（审稿周期、结果、过程）；讨论和经验都可以追问、回复、@ 同行，被回复或被 @ 时在站内收到提醒。

> **上线门槛（spec 第 3 节 D、D10）**：本版没有审核、举报、实名。合规包完成前，讨论与投稿经验**只在 tailnet 内开放**，不得对公网开放。设计稿里不出现举报、拉黑、审核相关的入口与文案。

## 0. 策略与定位

- **讨论是学术讨论，不是社交。** 页面上没有讨论数、回复数、点赞、热度（spec 第 3 节 A）。能出现的数字只有三类：投稿经验的「条数」与统计（属于期刊信息）、提醒的未读数（只给本人看）、上限提示（字数、@ 人数）。「展开更多回复」「查看对话」都**不带条数**。
- **两层展示，数据仍是树。** 根评论下整楼回复按时间平铺；回复的不是根评论时标「回复 @X」，「查看对话」把这一条的回复链单独拎出来看。永久链接打开「单楼视图」，不做「翻到第 N 页再定位」（决策 F）。
- **一套讨论区，两个地方用。** 文献页的讨论区与经验页的回复区是同一个组件（`Discussion`），差别只有：对象有没有所有者（经验有，显示「作者」）、所有者是否匿名、空状态文案。
- **期刊页的两组审稿周期并排、分开标注、绝不合成一个数**（决策 G）：「同行经验」来自用户填写，含拒稿、样本少；「PubMed 记录：收稿到录用」只统计最终录用的论文、看不到拒稿。
- **匿名是投稿经验独有的。** 讨论不能匿名。匿名经验从数据到界面都遮蔽作者：中性头像、不链主页、作者在自己经验下的回复也是「匿名作者」、提醒里的触发人是「匿名作者」、不进 @ 联想、不出现在别人看到的主页标签里；本人能看见并标注「匿名」（§3.20）。
- **互动区块独立降级**（决策 F，沿用 v0.13 决策 H）：interaction 出问题时，文献页、期刊页主体照常出；讨论区、经验区（「同行经验」那一半与列表）、提醒入口各自显示「暂不可用」。期刊页的 PubMed 那一组来自 catalog，不受影响（§3.21）。
- **渐进式披露**：
  - 默认层：讨论区的根评论与每楼前 3 条回复；经验区两组周期的中位数、经验列表的结构化一行；提醒的未读数。
  - 深数据层：「展开更多回复」「查看对话」「修改历史」；两组周期的 P25–P75、直接拒稿用时、结果分布、录用率与口径说明（卡片内小字，不折叠）；经验页的全部结构化字段与正文；表单的选填项（单独一组，标「选填」）。
- **流程闭环**（画板要能从头点到尾，即 spec 第 1 节的验证场景）：
  1. 陈宇在文献页发起讨论：讨论区为空 → 写下对样本量的质疑 → 发表。
  2. 周敏回复陈宇。
  3. 陈宇在《J Am Heart Assoc》期刊页写投稿经验：3 月 2 日投稿，4 月 13 日首轮大修，6 月 1 日录用 → 发布后条数从 4 变 5，「同行经验」从「只显示条数」变成完整统计。
  4. 林知远在陈宇的经验下追问，输入「@」从参与者里选中陈宇。
  5. 陈宇看到导航栏铃铛上的 2 → 进提醒列表，两条都在「回复我的」。
  6. 陈宇点开林知远那条 → 经验页的单楼视图，目标评论高亮 → 回复。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 读文献的医生 / 研究者 | 读完一篇小样本回顾性研究，在文献页下写下方法学上的疑问，引用后来的 RCT（直接写 PMID 或 DOI） |
| 懂行的同行 | 看到别人的质疑，回复补充；在楼里回复另一位回复者，对方读到「回复 @X」 |
| 选刊的投稿作者 | 在期刊页看同行经验的首轮用时、录用率，和 PubMed 记录的收稿到录用时间对照；读几条具体经历 |
| 刚走完一次投稿的人 | 在期刊页写一条投稿经验，只填日期和结果，用时由系统算；不想被认出来就匿名发布 |
| 想追问的人 | 在经验页追问作者，@ 另一位同行 |
| 被回复、被 @ 的人 | 回到 Patra 时看到铃铛上的未读数，点进提醒，一步落到那条评论 |
| 匿名访客 | 能读讨论与经验；想发表时被引去登录，回来接着写 |

### 2.2 跳转规则

沿用 v0.8 的 `next` 规则与 v0.12、v0.13 的 §2.2，新增：

1. **未登录点「发表」「回复」「写投稿经验」**：按钮文案就是「登录后参与讨论」「登录后写投稿经验」，跳 `/login?next=<当前页路径，含 ?comment=>`。回来后不自动打开编辑器、不恢复草稿（本版不存草稿）。
2. **未登录打开 `/notifications/**`**：跳 `/login?next=<原路径>`。
3. **点一条提醒**：先标为已读，再去它的永久链接（单楼视图，§3.10）。评论已删除时仍去单楼视图，那里显示占位或「已删除」状态；经验已删除时去经验页的「该经验已删除」。
4. **单楼视图里点「查看全部讨论」**：去掉 `?comment=`，回到讨论区正常视图，停在讨论区顶部。
5. **`/posts/<不存在>`**：404（`NotFoundState kind="post"`）。**已删除的经验**不是 404，是「该经验已删除」状态（spec 2.1.2）。
6. **删除自己的经验后**：跳 `/journals/<期刊 id>#experiences`，toast `投稿经验已删除`。
7. **`/u/<旧名>/experiences`**：与主页一样，307 到新名。
8. **发布投稿经验后**：留在期刊页，表单收起，toast `投稿经验已发布` + `查看`（→ `/posts/<新 id>`）。

### 2.3 导航入口

- **顶栏（桌面 > 880px，已登录）**：`文献库` 与头像之间加铃铛（`Bell` 18px，36px 圆形图标按钮，`fg-2`，悬停 `paper-200` 底）。有未读时右上角挂未读数徽标（§3.18）。点击 → `/notifications`。在 `/notifications/**` 时铃铛是当前项（`fg-1` + `paper-200` 底，`aria-current="page"`）。
- **窄屏顶栏（≤ 880px，已登录）**：**定稿为方案 B `[检索] [铃铛] [菜单]`**（2026-10-27 用户定）——铃铛在检索与菜单之间，菜单按钮仍贴右边缘；与桌面「检索 … 铃铛 · 头像」的先后一致（账号相关的都在最右侧）。尺寸沿用现有窄屏图标按钮（36px，间距 6px）。未登录不显示铃铛（顶栏仍是检索 + 菜单）。三个方案的并排对比留在静态板 `NavNarrow` 备查。
- **用户菜单（桌面）**：`个人主页`、`我的文献库`、`提醒`（图标 `Bell`，右端未读数，`fg-3` 等宽）、`设置` | `退出登录`。
- **移动全屏菜单账号块**：头像行下面的三个并排按钮改为 2×2：`主页`、`文献库` / `提醒`（按钮内右上角挂未读数徽标）、`设置`；再下面整行 `退出登录`。
- **其他入口**：讨论区、经验页里的头像与昵称链到主页（主页对你可见时）；经验列表与主页标签的条目链到 `/posts/[id]`；经验页面包屑与侧栏链回期刊页 `#experiences`。

## 3. 每屏内容 ← 最关键

### 3.1 讨论区的位置与结构 `Discussion`

**文献页**：`PublicationDetailView` 主栏最后，`{fullText}`（含「文献档案」）之后，独立的 `<section id="discussion" aria-labelledby="discussion-title">`。侧栏不变。

**经验页**：经验正文之后的「回复」区块（§3.16），同一个组件。

自上而下：

```
▍讨论 · DISCUSSION                                         [ 正序 | 最新 ]
┌ 编辑器（收起态：头像 + 一行占位；点击展开，§3.5） ─────────────────────┐
└──────────────────────────────────────────────────────────────────┘
(32) 陈宇  @chen-yu · 3 天前                                        [···]
     每组只有 47 例，而且是单中心的回顾性前后对照……
     回复
  │ (24) 周敏  @zhou-min · 2 天前
  │      同意。补充一点：……
  │      回复
  │ (24) 王立  @wang-li · 回复 @zhou-min · 1 天前
  │      不过作者自己也写了……
  │      回复 · 查看对话
  │ 展开更多回复
(32) 林知远  @lin-zhiyuan · 1 天前 · 已编辑
     ……
[ 加载更多讨论 ]
```

- 区块标题：`SectionEyebrow as="h2"`，文献页 `讨论 · Discussion`，经验页 `回复 · Replies`。标题上**不带条数**。
- 右端排序：分段控件（v0.13 `CitationFormatTabs` 的胶囊变体，小号）`正序` / `最新`，§3.4。没有评论时、单楼视图里不显示。
- 编辑器在列表**上方**（§3.4 说明新评论插在哪里）。
- 根评论之间 `border-subtle` 分隔线，上下各 20px；楼内回复左缩进 44px（桌面，= 头像 32 + 间距 12），左侧一条 1px `border-default` 竖线连到最后一条回复（结构线，不是强调色）。
- 文字最大宽度 72ch（与正文一致）。

### 3.2 评论条目 `CommentItem`

| 部分 | 根评论 | 楼内回复 |
|---|---|---|
| 头像 | 32px（移动 28px） | 24px（移动 22px） |
| 署名行 | 昵称（`text-sm` 中粗 `fg-1`，链主页）+ `@用户名`（等宽 `text-xs` `fg-3`）+ 可选「作者」标记 + ` · ` + 时间 + 可选 ` · 已编辑` | 同左；回复的不是根评论时，在时间前加 `回复 @用户名`（`fg-3`，`@用户名` 是链接） |
| 正文 | Markdown 子集渲染（§3.7），`text-md`（15px）`leading-relaxed` `fg-1` | 同左 |
| 操作行 | `回复` | `回复` · `查看对话`（只在有「回复 @X」时出现） |
| 菜单 `···` | 所有人：`复制链接`；本人另有：`编辑`、分隔、`删除`（危险色） | 同左 |

- **时间**是链接，指向这条评论的永久链接（§3.10）；悬停 `title` 显示完整时间 `2026-10-24 14:20`。写法见 §3.22。
- **「作者」标记**：对象有所有者（投稿经验）且这条是所有者发的：昵称后一个小胶囊 `作者`（`clay-50` 底、`clay-700` 字、`text-3xs` 等宽、高 18px）。文献没有所有者，文献页永远不出现。
- **「已编辑」**：只在这条评论**有记录的修改版本**时出现（发布 5 分钟内的修改不记版本，也不显示「已编辑」）。`已编辑` 是文字按钮（`fg-3`，悬停下划线），点开修改历史（§3.8）。
- **长评论**：正文超过 12 行时折叠到 8 行，末尾渐隐 + `展开全文`（文字按钮）；展开后末尾 `收起`。
- **本人的评论**：署名行不加「你」（看得见自己的名字）；只有匿名作者本人看自己的匿名回复时写 `匿名作者（你）`（§3.20）。
- **悬停**：整条不变色；操作行的文字按钮悬停 `fg-1`。键盘可达顺序：昵称 → 时间 → 已编辑 → `···` → 正文里的链接 → 回复 → 查看对话。
- **占位与特殊作者**见 §3.9、§3.20。

### 3.3 楼中楼：「回复 @X」与「查看对话」

- **平铺**：一楼里的回复不论回复的是谁，一律按时间正序排在根评论下面。
- **「回复 @X」**：回复的是楼里的另一条回复时出现；X 是被回复那条的作者的**当前用户名**。被回复的那条已删除（占位或整条去掉）时写 `回复已删除的评论`（不链接、不暴露原作者）；被回复的是匿名作者时写 `回复 匿名作者`（不链接）；被回复的作者已注销写 `回复 已注销用户`。
- **每楼默认显示前 3 条回复**；还有更多时，最后一条下面 `展开更多回复`（文字按钮，**不带条数**），点开把这一楼剩下的回复全部接上（一次最多 50 条，还有则继续显示同一个按钮）。
- **「查看对话」**：打开对话框（桌面 `md`，移动底部抽屉），标题 `对话`，按时间列出从根评论到这一条的整条回复链（只有链上的评论，不含楼里其他回复）；当前这条高亮（`clay-50` 底、`radius-md`）。链上有已删除的显示占位。对话框底部 `只看这一楼 →`（去单楼视图）。对话框里只读，不能回复。
- **回复框**：点任何一条的 `回复` → 这一楼先完整展开（如果折叠着），回复框出现在这一楼**最后一条回复下面**（新回复会出现的位置）；框上方一行 `回复 @zhou-min` + `×`（去掉对象，改为回复这一楼）。点根评论的 `回复` 时这一行写 `回复 陈宇 的评论`，没有 `×`。同一时间只开一个回复框；另一个回复框里有内容时先确认 `放弃正在写的回复？`。

### 3.4 排序与分页

- **根评论**：默认 `正序`（最早的在前），可切 `最新`（最新的在前）。排序记在地址 `?sort=latest`（默认不写），刷新保留。楼内永远正序。
- **每次 20 楼**；更多时列表底部 `加载更多讨论`（次按钮，整宽，加载中 `加载中…`）。
- **新评论插在哪里**：
  - `最新`：插在列表最上面。
  - `正序` 且已加载到最后一页：接在列表最后，页面滚到它，高亮 2 秒（`clay-50` 底淡出，`dur-slow`）。
  - `正序` 且后面还有没加载的页：列表不动，编辑器下方出现一行确认 `已发表。按正序排在最后，` + `去看看`（→ 这条的单楼视图）。
- **新回复**：接在这一楼最后，高亮 2 秒；回复框收起。
- 「正序 / 最新」切换时不清空编辑器里的内容。

### 3.5 编辑器 `Composer`

三处用同一个组件：讨论区顶部（发表根评论）、楼内（回复）、原地编辑（§3.8）。投稿经验表单的正文框用同一个编辑器、关掉 @（§3.15）。

**收起态**（讨论区顶部、列表不为空时）：左 32px 当前用户头像 + 一行占位框（`paper-50` 底、`border-default`、`radius-xl`、高 48px），占位文字：文献页 `写下你对这篇文献的看法、疑问或补充证据…`，经验页 `对这条投稿经验有疑问？在这里追问…`。点击或聚焦 → 展开态，焦点进文本框。

**展开态**：

```
┌──────────────────────────────────────────────────────────────┐
│ [编写] [预览]                     B  I  ❝  •  1.  </>  🔗  @    │  ← 标签 + 工具条
│──────────────────────────────────────────────────────────────│
│ 文本框（4 行起，自动增高到 16 行，之后内部滚动）                   │
│                                                              │
│──────────────────────────────────────────────────────────────│
│ 支持 Markdown：粗体、斜体、引用、列表、行内代码、链接    186 / 5,000 │
└──────────────────────────────────────────────────────────────┘
                                             [取消]  [发表]
```

- 外框：`bg-elevated`（纯白，浮起的输入面），`border-strong`，`radius-xl`，聚焦时 `border-focus` + 4px 陶土光晕（同 `.pt-box`）。
- **标签**：`编写` / `预览`（下划线小标签）。`预览` 用与展示完全相同的渲染（§3.7）；内容为空时预览写 `没有可以预览的内容`（`fg-3`）。
- **工具条**（只在「编写」时可用，图标按钮 28px，`fg-3`，悬停 `fg-1`，`aria-label` 写全称）：粗体、斜体、引用、无序列表、有序列表、行内代码、链接、@ 提及。有选区时包住选区，没选区时插入成对标记并把光标放中间；`@` 按钮插入 `@` 并打开联想。窄屏工具条横向滚动，不换行。
- **底栏**：左 `支持 Markdown：粗体、斜体、引用、列表、行内代码、链接`（`text-2xs` `fg-3`；窄屏缩成 `支持 Markdown`）；右字数计数（§3.12）。
- **按钮**：根评论 `取消`（文字按钮）/ `发表`（主按钮，小号）；回复 `取消` / `回复`；编辑 `取消` / `保存`。内容为空（只有空白）时主按钮禁用。`⌘ Enter` / `Ctrl Enter` 提交（按钮 `title` 里写明）。
- **取消**：没内容直接收起；有内容时按钮旁出现确认 `放弃正在写的内容？` + `放弃` / `继续写`（原地，不弹对话框）。
- **提交中**：主按钮 `发表中…`（禁用），文本框只读；成功后清空并收起（根评论编辑器回到收起态），焦点落到新评论的时间链接上。
- **错误**：编辑器下方、按钮上方的提示条（`FormAlert`），内容保留（§4.2）。

### 3.6 @ 联想 `MentionSuggest`

- **触发**：在文本框里输入 `@`（前面是行首、空白或标点）后出现；继续输入的字母、数字、`-`、`_`、汉字是查询词（**用户名或昵称都能搜**，2026-10-27 起 identity 的前缀联想同时按昵称前缀匹配，PAP-118）；输入空格、标点、`Esc`、或光标离开这个词时关闭；没有结果且查询词已超过 6 个字时自动收起（多半是在正常打字，不是在找人）。
- **位置**：桌面锚在光标所在行的下方、左对齐 `@` 的位置（宽 296px，超出右边界时向左收）；窄屏占满编辑框宽度、贴在当前行下方。不遮住正在输入的那一行。
- **内容**（每行 40px，窄屏 44px）：头像 24 + 昵称（`text-sm` `fg-1`，截断）+ `@用户名`（等宽 `text-xs` `fg-3`）。
  - 只输入了 `@`：小标题 `本讨论的参与者`，列出最多 6 位（最近发言的在前；文献页是评论过的人，经验页另加非匿名的作者本人）。还没有参与者时显示 `输入用户名或昵称查找同行`（`fg-3`）。
  - 输入了查询词：先 `本讨论的参与者` 里用户名或昵称以查询词开头的，再 `其他用户`（identity 前缀联想：用户名或昵称以查询词开头，只含主页对你可见的正常账号），合计最多 8 行；两组之间 1px 分隔。每行都同时显示昵称和 `@用户名`，按昵称搜到的人也能一眼看出用户名。
  - 查询中：列表底部一行 12px 转圈 + `正在查找…`（已有的参与者结果先显示）。
  - 没有结果：`没有找到「chen-yuh」。输入完整的用户名也能 @ 到对方。`（`fg-3`；spec：完整输入用户名时，任何正常账号都能 @ 到）。
  - 联想接口失败：`暂时查不到用户，输入完整的用户名也能 @ 到对方。`
- **键盘**：`↑` `↓` 移动（首尾循环），`Enter` / `Tab` 选中，`Esc` 关闭；鼠标点选。选中后把查询词替换为 `@用户名 `（带一个空格；按昵称搜到的也插入用户名，正文里的 @ 始终是用户名）。读屏：文本框 `aria-autocomplete="list"`、`aria-controls`、`aria-activedescendant`；列表 `role="listbox"`。
- **匿名作者**不出现在参与者里（spec 2.1.2）；**自己**不出现（不提醒自己）。
- **@ 人数**：编辑器按文本里的 `@用户名` 个数（去重）粗算，超过 10 时计数旁出现 `一条评论最多 @ 10 人`（`status-danger`），主按钮禁用；以服务端的解析为准（§4.2）。
- 联想只在评论里出现；投稿经验正文不解析 @，那里的编辑器没有 @ 按钮、输入 @ 不弹联想。

### 3.7 Markdown 子集的渲染（评论与经验正文共用）

画板 `Markdown` 是完整对照表。规则：

| 写法 | 显示 |
|---|---|
| `**粗体**` | 粗体（`font-semibold`） |
| `*斜体*`、`_斜体_` | 斜体（中文斜体由字体合成，接受） |
| `> 引用`（行首） | 引用块：左侧 2px `ink-300` 竖线、`fg-2`、左内边距 14px；可连续多行 |
| `- 列表`、`* 列表`、`1. 列表` | 无序 / 有序列表，缩进 22px，项间距 4px；不支持嵌套（缩进的子项按普通行显示） |
| `` `代码` `` | 行内代码：等宽 `text-sm`、`paper-200` 底、`radius-sm`、左右 4px |
| `[文字](https://…)` | 链接（`link` 色，悬停下划线），新窗口打开，`rel="nofollow ugc noopener"` |
| 裸 `https://…` | 自动变成链接，显示时超过 48 个字符中间省略 |
| `PMID 27940189`、`PMID: 27940189`、`PMID:27940189` | 「PMID 27940189」整体变成链接 → PubMed 原文页（新窗口） |
| `10.1001/jama.2019.22176`、`doi:10.…`、`https://doi.org/10.…` | DOI 变成链接 → `https://doi.org/<DOI>`（新窗口） |
| `@用户名`（解析到的） | 提及：`link` 色、中粗，链到 `/u/<当前用户名>`；匿名场景不存在 |
| `@用户名`（已注销） | `@已注销用户`，`fg-3`，不链接 |
| `@不存在的名字` | 原样纯文本 |
| 单个换行 | 保留为换行；空行分段（段距 10px） |
| `# 标题`、`![图](…)`、HTML 标签、表格、代码块 | **不渲染**，按原文显示为普通文字（图片语法不发请求） |
| `\*` 等转义 | 显示字面字符 |

- 链接、PMID、DOI 都不预取、不展开成卡片（spec 第 3 节 G）。
- 渲染结果里的外链一律带外链小图标（`ArrowUpRight` 12px，`aria-hidden`），读屏名称后加 `（新窗口打开）`。

### 3.8 编辑与修改历史

- **编辑**：本人 `···` → `编辑`：正文原地换成编辑器（展开态，内容是原文；@ 标记已换回**当前**用户名），按钮 `取消` / `保存`。保存中 `保存中…`；成功后回到展示态，不出 toast。保存的内容与原文相同 = 直接收起，不发请求。
- **修改历史**：点 `已编辑` → 对话框（桌面 `md`，移动底部抽屉）：
  - 标题 `修改历史`；副标题 `发布 5 分钟后的修改会留下记录，所有人都能看到。`（`fg-3`）。
  - 版本列表，最新的在前：`当前版本 · 10 月 26 日 18:40 修改` / `10 月 26 日 09:12 修改` / `最初版本 · 10 月 25 日 21:03 发表`。
  - 每个版本显示当时的**原文**（Markdown 源文本，`white-space: pre-wrap`，同 GitHub 的修改历史），并**标出与上一版相比的改动**（2026-10-27 用户定）：新增的文字 `moss-50` 底 + 下划线，删掉的文字 `rust-50` 底 + 删除线（颜色之外还有下划线 / 删除线区分）。最初版本不标。列表上方一行图例 `下划线是新增的内容 · 删除线是删掉的内容`。用原文而不是渲染结果，是因为格式改动（加粗、改成列表）在渲染后看不出来。
  - 每个版本超过 8 行折叠，`展开`。
  - 加载中：两块骨架；失败：`修改历史暂时打不开` + `重试`。
- 经验正文的修改历史是同一个对话框（§3.16）。

### 3.9 删除与占位

- **删除**：本人 `···` → `删除` → 确认对话框（`sm`，移动底部抽屉）：
  - 标题 `删除这条评论？`
  - 正文：有回复时 `这条评论下已经有回复。删除后会留下「该评论已删除」，回复照常保留。`；没有回复时 `删除后不能恢复。`
  - 按钮 `取消` / `删除评论`（危险主按钮）；删除中 `删除中…`。
  - 成功：有回复 → 原位置换成占位；没回复 → 整条淡出（`dur-normal`）后移除；toast `评论已删除`。失败：对话框里提示条 `没有删除成功，请稍后再试`。
- **占位**（`comment.deleted`）：保留这一条的位置与缩进，不显示头像、昵称、时间、操作；一行 `该评论已删除`（`fg-3` 斜体，`text-sm`），左侧 32px（回复 24px）的虚线圆占住头像位。楼里的回复照常。
- 作者删除了根评论、楼里还有回复：根评论变占位，这一楼保留。
- 没有回复的评论删除后整条去掉；如果它回复的那条也是占位、也没有其他回复，那条占位一并去掉（由后端判断，界面只按返回显示）。

### 3.14 经验列表 `ExperienceList`

两张卡下面，`border-subtle` 分隔的条目列表（不是卡片网格），每页 10 条，按**投稿日期**倒序（最近的投稿在前；同一天按发布时间倒序）。

**条目**（整条链到 `/posts/<id>`，悬停时标题行下划线绘出）：

```
2026 年 3 月投稿 · 原创研究                                         ← 等宽 2xs fg-3
首轮 42 天 · 大修  →  录用                                          ← 衬线 text-lg fg-1
投稿到录用 91 天 · 审稿 2 轮 · 审稿质量 4/5 · 编辑沟通 3/5 · 付了 APC   ← text-sm fg-2，没填的项不出现

(20) 陈宇 · 发布于 6 月 3 日 · 已编辑                                ← text-xs fg-3
```

- 结果写法：`首轮 <用时> · <首轮结果>  →  <最终结果>`；最终结果 `进行中` 时写 `→ 进行中`；首轮就是最终（如直接拒稿、首轮录用）时写 `首轮 9 天 · 直接拒稿`，不再写箭头。
- **不显示回复数**（spec 2.1.2）。
- 匿名经验：作者行 `(中性头像) 匿名作者`，不链接。作者已注销：`已注销用户`。
- 本人的经验：作者行末尾 `· 你写的`（`fg-3`）；匿名的另加 `匿名` 小胶囊（只有本人看得到）。
- **加载更多**：列表底部 `加载更多投稿经验`（次按钮，整宽）。
- **空列表**（`exp.list.empty`，与 `exp.summary.empty` 同时出现）：列表位置一块空状态：`还没有人分享这本期刊的投稿经验`（衬线 `text-xl`）+ `投过这本期刊？写下投稿、审稿和结果，帮后来的人选刊。` + `写第一条投稿经验`（主按钮，等同区块右上角的按钮）。
- 区块右上角 `写投稿经验`（主按钮小号，图标 `PenLine`）：
  - 匿名访客：`登录后写投稿经验`（次按钮）。
  - 邮箱未验证：按钮禁用，按钮下一行 `amber-700` 小字 `验证邮箱后才能写投稿经验` + `重新发送验证邮件`。
  - 表单展开时按钮隐藏。

### 3.15 填写与编辑投稿经验 `ExperienceForm`

**形态**：期刊页上**原地展开**（2026-10-27 用户定）——点 `写投稿经验`，表单出现在区块标题下面、两张卡上面（卡与列表被推下去），焦点进第一个字段；桌面在主栏宽度内两列排短字段，窄屏单列。理由：spec 说「在期刊页填写」；十几个字段塞进对话框或手机抽屉都别扭，独立页又离开了期刊页。编辑在经验页原地切换（§3.16），同一个表单。

```
写投稿经验                                                            ← 衬线 text-2xl
Journal of the American Heart Association · 一篇稿件写一条；只填日期，用时由系统算出
─────────────────────────────────────────────────────────────────────
投稿与审稿
  投稿日期 *            [2026-03-02 ▾]     首轮决定日期 *      [2026-04-13 ▾]
  首轮结果 *  (直接拒稿)(审后拒稿)(大修)(小修)(录用)
  最终结果 *  (录用)(拒稿)(撤稿)(进行中)
  最终决定日期  选填    [2026-06-01 ▾]     文章类型 *          [原创研究    ▾]
  ── 首轮用时 42 天 · 投稿到最终决定 91 天（由日期算出，随填随更新）
更多细节  选填
  审稿轮数              [ 2 ]（1–10）
  审稿质量              (1)(2)(3)(4)(5)   1 很差 · 5 很好
  编辑沟通              (1)(2)(3)(4)(5)
  是否付了 APC          (付了)(没付)
  是否转投过            (是)(否)
  经历                  [编辑器：编写 / 预览，0 / 2,000，不能 @ 人]
发布方式
  [ ] 匿名发布
      别人看到的作者是「匿名作者」，不会链接到你的主页；这条经验也不会出现在你主页公开的「投稿经验」里（你自己看得到）。
      ⚠ 发布后不能更改匿名设置。                                     ← amber-700
─────────────────────────────────────────────────────────────────────
                                                  [取消]  [发布投稿经验]
```

- **必填**（spec）：投稿日期、首轮决定日期、首轮结果、最终结果、文章类型。标签后红点不用，写 `*`（`fg-3`）并在表单顶部说明 `带 * 的必填`。
- **选填**：最终决定日期、审稿轮数、两个评分、APC、转投、正文。「更多细节」一组标题后写 `选填`。
- **日期**：原生日期输入（`type="date"`，样式同 `.pt-box`），`max` = 今天。
- **单选**：胶囊单选组（`RADIO_INPUT` 的胶囊变体，高 36px，窄屏 44px，选中 `clay-50` 底 + `clay-600` 描边 + `fg-1`）。选填的单选组可以再点一次取消选择（读屏有 `清除选择` 按钮）。
- **评分**：1–5 五个方块单选（36px，选中同上），两端注 `1 很差 · 5 很好`。
- **文章类型**：下拉（`select` 原语），取值以 PAP-122 工程 spec 为准；画板示意：原创研究、综述、病例报告、短篇通讯、其他。
- **审稿轮数**：数字输入（1–10，画板示意；范围以工程 spec 为准）。
- **最终结果选「进行中」**：「最终决定日期」禁用并清空，下面 `fg-3` 小字 `稿件还在进行中，不用填最终决定日期`。
- **算出的用时**：两个日期都有效时，「投稿与审稿」组末尾一行 `fg-3`：`首轮用时 42 天 · 投稿到最终决定 91 天`。
- **正文**：§3.5 的编辑器，关掉 @ 与 @ 按钮；占位 `审稿人关注什么、编辑回复快不快、修回花了多久……`；`0 / 2,000`；底栏说明 `支持 Markdown；这里不能 @ 人`。
- **匿名**：复选框 + 两行说明 + `amber-700` 的不可更改提示。
- **校验**：字段失焦时校验该字段，提交时全部校验，焦点去第一个出错的字段；错误在字段下方（§4.3）。
- **提交**：`发布中…`（禁用整个表单）→ 成功：表单收起、两张卡里的「同行经验」重取并高亮、列表重取，toast `投稿经验已发布` + `查看`。失败：表单底部提示条，内容保留（§4.3）。
- **取消**：没填任何东西直接收起；填了东西时对话框 `放弃这条投稿经验？` + `已经填写的内容不会保存。` + `继续填写` / `放弃`（危险次按钮）。
- **编辑模式**（经验页）：标题 `编辑投稿经验`；字段带原值；「发布方式」换成只读一行：匿名的 `这条经验以匿名发布，不能更改。`，否则 `这条经验以你的名字发布，不能改成匿名。`；按钮 `取消` / `保存修改`；成功回到经验页展示态（有记录版本时出现「已编辑」）。

  - 最终结果 `进行中`：最后一个节点空心、连线虚线，节点名 `进行中`，不写日期。
  - 首轮即最终（直接拒稿 / 审后拒稿且最终拒稿、首轮录用）：只有两个节点。
  - 没填最终决定日期但有最终结果：最后一个节点照画，日期写 `未填日期`，连线上不标用时。
  - 窄屏：时间线改竖排（节点在左、文字在右）。
- **结构化字段**：两列定义表（窄屏单列），只列填了的选填项；没填的不出现。
- **正文**：§3.7 渲染，衬线 `text-lg` `leading-reading`（这是阅读内容，与评论区分开）；没有正文时不渲染这一块。

| 状态 ID | 呈现 |

| `post.mine` | 本人：`编辑`、`···` 含删除 |
| `post.anonymous` | 别人看匿名经验：署名 `(中性头像) 匿名作者`，不链接，没有 `@用户名` |
| `post.anonymous.self` | 本人看自己的匿名经验：署名 `匿名作者（你）` + `匿名发布 · 只有你知道是你写的`（`slate-50` 小提示条，在署名行下） |
| `post.edited` | 署名行 `已编辑` → 修改历史（§3.8 同一个对话框；结构化字段的修改以「字段：旧值 → 新值」列出） |

### 3.18 提醒入口 `NotificationBell`

- **形态**：36px 圆形图标按钮，`Bell` 18px（`strokeWidth 1.75`）。

### 3.22 时间与时长的写法

- **发表时间（相对）**：`刚刚`（< 1 分钟）、`3 分钟前`、`2 小时前`、`昨天 14:20`、`10 月 24 日`（今年）、`2025 年 3 月 2 日`（往年）；`title` 写完整 `2026-10-24 14:20`。提醒列表同。
- **日期**：经验页、表单回显 `2026 年 3 月 2 日`；列表与主页的投稿月份 `2026 年 3 月投稿`。
- **时长**（经验与统计）：一律以「天」为主单位，`42 天`；≥ 28 天时在次要位置补 `约 6 周`（四舍五入到整周）；P25–P75 用「天」：`28–63 天`。两组周期用同一套写法，才能并排读。
- 数字：千分位 `1,286`；百分比取整 `47%`；评分 `4/5`（列表）/ `4 / 5`（经验页）。

## 6. 交互与响应式

- **断点**：讨论区、经验区跟随所在页（文献页、期刊页 980px 两栏变一栏；880px 起移动排版）；提醒列表页、主页 880px；时间线 640px 起竖排。
- **乐观与否**：
  - **乐观**：提醒标为已读（单条与全部）、排序切换、展开回复。
  - **不乐观**（等返回再改界面，期间进行中文案并禁用）：发表、回复、编辑、删除评论；发布、编辑、删除经验。理由：都可能被资格、频率拒绝，乐观插入再撤回比等一下更糟。
- **焦点**：编辑器展开时焦点进文本框；发表成功后焦点到新评论的时间链接；回复框打开时焦点进回复框，关闭回到 `回复` 按钮；对话框打开时焦点在第一个可操作项，关闭回到触发按钮；删除评论后焦点到下一条（没有则到区块标题）；表单提交失败焦点到第一个出错字段或提示条。
- **键盘**：编辑器 `⌘/Ctrl Enter` 提交、`Esc` 先关联想再（有内容时）不做事；联想 `↑↓ Enter Tab Esc`；`···` 菜单 `Shift+F10` 也能打开。不加全局快捷键。
- **读屏**：发表成功播报 `已发表`；新回复出现播报；未读数变化不主动播报（铃铛名称里有）；单楼视图的目标评论 `aria-current="true"`；`展开更多回复` 用 `aria-expanded`。
- **动效**：编辑器展开 / 收起高度过渡 `dur-normal`；新评论高亮 2 秒淡出；删除淡出 `dur-normal`；徽标数字变化回弹；尊重「减少动态效果」（只保留颜色变化）。
- **移动**：对话框都是底部抽屉；输入框 17px、按钮 44px 起；编辑器工具条横向滚动；@ 联想占满编辑框宽度；回复缩进 20px（头像 22px）；经验表单单列、日期用系统选择器；时间线竖排。
- **元素状态**：hover / active / focus / disabled 都要给出，新增的有：铃铛（含徽标）、分段排序、编辑器标签与工具条按钮、联想行、评论的文字按钮、时间链接、胶囊单选、评分方块、经验条目、提醒行、提醒标签。

## 7. 约束

- **视觉**：沿用「叶脉 · 学术编辑风」与设计系统 token（`patra-portal/src/styles/tokens.css` + `@theme`）。**不新增颜色与字族**：危险 `rust`、警示 `amber`、成功 `moss`、信息 `slate`、强调 `clay`。结果分布、录用率不画图表，只用文字与数字。
- **技术**：Next 16 App Router / Tailwind v4 / base-ui(shadcn)。讨论区、经验区首屏服务端取、各自 Suspense + 超时（决策 F）；门户经 interaction 拿讨论、经验、提醒，经 catalog 拿期刊与 PubMed 周期，经 interaction 的联想接口拿 @ 候选（门户不直接调 identity 的内部接口）。
- **可访问性**：沿用 v0.12 §7；另：编辑器联想的 combobox 语义（§3.6）；铃铛名称带未读数；胶囊单选是真正的 `radio`；时间线是有序列表（`<ol>`），用时写进文字而不只在线上。
- **暗色模式**：不做。
- **用词**：界面上只说「投稿经验」「提醒」，**不出现「帖子」「通知」「私信」**（`/posts`、`/notifications` 是地址，不是文案）。

## 附录 A. 页面对后端的要求

> 只写页面需要什么，接口形状由各 Issue 的工程 spec 定。

**PAP-121 讨论**

1. 讨论列表：对象（类型 + key）、排序 `asc | latest`、游标分页，每页 20 楼；每楼带根评论 + **前 3 条回复** + 「还有更多回复」**布尔值**（不要条数——页面不显示回复数，接口也不必给）。
2. 楼内回复：按根评论 id 取剩余回复，正序，每次 ≤ 50，游标。
3. 单楼：按评论 id 取它所在的整楼（根 + 全部回复）与目标 id；目标不存在、不属于该对象时给可区分的结果（页面显示 `disc.single.missing`）。
4. 对话链：按回复 id 取从根到它的祖先链（含占位）。
5. 每条评论：id、根 id、父 id、作者名片（userId、用户名、昵称、头像、头像色号、主页是否对访客可见、状态：正常 / 封禁 / 已注销）、**匿名标记**（作者是匿名所有者时只给 `anonymous: true`，不给 userId）、**「作者」标记**（是对象所有者）、**「这条是我发的」**（会话判断，匿名的也给）、`回复 @X` 的对象（被回复那条的作者名片或「已删除 / 匿名 / 已注销」）、正文 Markdown 原文 + 提及实体（标记 → 当前用户名 / 已注销）、创建时间、**是否有修改记录**（有才显示「已编辑」）、是否占位。
6. 修改历史：按评论 id 取版本列表（时间、正文原文），最新的在前；页面自己算改动标记。
7. @ 联想：查询词（可为空）→ 本讨论参与者在前（不含匿名所有者、不含自己，最近发言的在前，≤ 6）+ identity 前缀联想（≤ 8 合计）；每项 userId、用户名、昵称、头像、色号、来源分组。
8. 写接口的原因码分开：频率（间隔 10 秒）、每日上限、邮箱未验证、账号状态异常、@ 超过 10 人、正文超长（字素 / 字节）、回复目标已删除、对象已删除；成功返回新评论的完整条目（页面直接插入，不重取整个列表）。
9. 编辑时返回的原文把 `<@用户ID>` 换回当前用户名（决策 C）。

**PAP-122 投稿经验**

1. 期刊汇总：参数 `window = 3y | all`；返回条数、首轮用时（中位数、P25、P75、样本数）、直接拒稿用时（中位数、样本数）、结果分布（录用 / 拒稿 / 撤稿 / 进行中各几条）、录用率（与参与计算的已完结条数）；不足 5 条时只返回条数（或带「不足」标记）。另返回「全部」的条数（`window-empty` 状态的「看全部 12 条」要用）。
2. 期刊的经验列表：按投稿日期倒序（同日按发布时间倒序），每页 10 条，游标；每条带结构化字段、正文前 200 字（纯文本摘录）、作者名片或匿名标记、「这条是我发的」、是否有修改记录。
3. 经验详情：全部字段、正文原文、期刊卡片（名称、缩写、ISSN、OA）、作者名片或匿名标记、「这条是我发的」、是否已删除（已删除时只回删除状态与期刊信息）、是否有修改记录；修改历史含结构化字段的逐项变化。
4. 用户的经验列表（主页标签）：按 userId + 访客；别人只看到非匿名的；本人看到全部并带匿名标记；按投稿日期倒序，每页 20 条。「关于」页判断是否出标签只要「有没有」。
5. 写接口的原因码：各项校验（必填、日期先后、晚于今天、进行中不填最终日期、一致性规则）、同一期刊同一投稿日期重复（附已有经验 id，页面给「查看那条经验」）、每日上限、邮箱未验证、账号状态异常。
6. 首轮用时**不含直接拒稿**（2026-10-27 用户定）：首轮用时只算送审的稿件，直接拒稿单独出中位数。

**PAP-119 / PAP-117 catalog**

1. 期刊详情带 PubMed 周期：近 3 年（按录用日期）的中位数、P25、P75（单位天）、样本数；样本 < 5 时只给样本数；0 时可区分。
2. 经验页与提醒的上下文要期刊卡片（名称、缩写、ISSN、OA）——PAP-117 的批量卡片接口。

**PAP-123 提醒**

1. 未读数：总数 + 两个标签各自的未读数（标签上的小数字要用）；支持条件请求（`ETag` / `If-None-Match` → 304）。
2. 列表：按标签（回复我的 / @ 我的）、创建时间倒序、游标分页每页 20；每条：id、类型（回复了你的评论 / 评论了你的投稿经验 / 在评论中 @ 了你）、触发人名片或「匿名作者 / 已注销用户」、对象上下文（文献：id + 标题；经验：id + 期刊缩写 + 投稿月份 + 是否本人的 + 是否已删除）、评论 id 与纯文本摘录（≤ 120 字）与是否已删除、创建时间、是否已读、永久链接所需的 id。
3. 标为已读（单条）、全部标为已读（两个标签一起），返回新的未读数。
4. 「既回复又 @ 同一人只发一条」时，这条提醒**归「回复我的」**（2026-10-27 用户定）。

**PAP-118 identity**（经 interaction 间接用）：前缀联想**按用户名或昵称前缀匹配**（2026-10-27 起），返回头像地址与色号（联想行要画头像）；批量解析含 90 天内旧用户名。

## 10. spec 缺口、冲突与已拍板

**2026-10-27 用户已定**（原为待拍板，用户「都按建议」）：

1. **窄屏顶栏铃铛位置**（Linear AC）：**B `[检索] [铃铛] [菜单]`**。A `[铃铛] [检索] [菜单]`、C 不放顶栏只在菜单按钮挂圆点（不满足 spec「顶栏有提醒图标带未读数」）未采用，对比留在静态板 `NavNarrow`。
2. **投稿经验表单**：**期刊页原地展开**（§3.15），不用对话框，也不另开 `/journals/<id>/experiences/new`。
3. **修改历史**：**逐版标出增删**（§3.8，显示 Markdown 原文，参照 GitHub）。
4. **「首轮用时」不含直接拒稿**：直接拒稿单独有中位数，混进去会把首轮审稿时间拉短；卡片口径写 `首轮用时不含直接拒稿`。spec 2.1.2 没写，PAP-122 按此实现。
5. **既回复又 @ 同一个人时归「回复我的」**：回复关系是结构性的，@ 多半是习惯；「@ 我的」专门收别人楼里提到你的。PAP-123 按此实现。

**同日后端变化**：identity 的 @ 前缀联想同时按昵称前缀匹配（PAP-118），联想的占位与候选项按「用户名或昵称都能搜」写（§3.6）。

**与 spec / Issue 的冲突或缺口**：

1. **简报随哪个 PR**：release spec §2 写「设计简报在后端 PR 合并前完成的，随后端 PR 合入」；v0.13 的做法与 PAP-116 派发时的口径是随前端 PR。本简报以编排会话的决定为准，release spec §2 那句视结果同步。
2. **「结果分布」指哪个结果**：spec 2.1.2 只写「结果分布」。按**最终结果**（录用 / 拒稿 / 撤稿 / 进行中）画，与录用率同一口径。首轮结果分布（直接拒稿占几成）对选刊也有用，本版不加，需要的话在 PAP-122 一起定。
3. **「是否转投过」的含义**：可能指「这篇稿件投这本期刊之前被别的期刊拒过」，也可能指「出版社把稿件转到姊妹刊」。画板标签照写 `是否转投过`，说明文字待 PAP-122 定下含义后补。
4. **经验所有者收哪些「回复我的」**：spec 写「有人评论我的经验」。根评论一定提醒；楼里别人回复别人（不是回复作者）要不要提醒作者，spec 没写。页面文案 `评论了你的投稿经验` 两种都适用，由 PAP-123 定。
5. **讨论区新评论在「正序」下插在哪**：spec 没写，按 §3.4（已加载到底就接在最后，否则给「去看看」）。
6. **单楼视图的地址**：spec 只说「打开对象页的单楼视图」，本简报定为 `?comment=<id>`（服务端首屏要能读到，hash 读不到）。
7. **PMID / DOI 链到哪里**：spec 只说「自动变成链接」。门户里文献页按内部 id，PMID 在渲染时换不到内部 id，所以 PMID 链 PubMed、DOI 链 doi.org（外链、新窗口）。以后有按 PMID 跳转的入口再改。

**简报里由我定的设计点**（看到不对就推翻）：

1. 讨论区标题 `讨论 · Discussion`、经验页回复区 `回复 · Replies`，都不带条数。
2. 编辑器在列表上方，收起成一行；空状态时直接展开当主角。
3. 每楼默认 3 条回复、`展开更多回复` 不带条数；根评论每页 20 楼。
4. 「回复 @X」写在署名行；X 是当前用户名；被回复的已删除 / 匿名 / 已注销各有写法。
5. 「查看对话」用对话框（移动抽屉）只列回复链，底部可去「只看这一楼」。
6. 时间是永久链接；`···` 里有 `复制链接`；别人的评论只有这一项（本版没有举报）。
7. 回复框出现在这一楼最后、先把这一楼展开；一次只开一个回复框。
8. 「已编辑」只在有记录版本时出现。
9. 长评论超过 12 行折叠到 8 行。
10. Markdown 工具条（含 `@` 按钮）；单个换行保留为换行。
11. @ 联想参与者最多 6 位、合计最多 8 行；窄屏占满编辑框宽度。
12. 单楼视图的目标高亮持续显示（不淡出），顶部提示条 + `查看全部讨论`。
13. 空状态写三行「可以讨论什么」（方法 / 证据 / 应用），不画插画。
14. 两组周期用同一套时长写法（天为主、≥ 28 天补约几周）；结果分布用文字计数不画色条；口径写在卡片底部不折叠。
15. 「近 3 年 / 全部」只切「同行经验」卡，不影响列表；列表按投稿日期倒序、每页 10 条。
16. 经验条目第二行是「首轮用时 · 首轮结果 → 最终结果」，不显示回复数，本人的标 `你写的`。
17. 表单原地展开、两组（必填 / 选填）+ 发布方式；评分用 1–5 方块；选填单选可清除；算出的用时随填随显示。
18. 经验页用时间线（三个节点）+ 定义表，正文用衬线阅读字号；右侧栏是期刊小卡。
19. 已删除的经验页保留期刊信息与「看其他投稿经验」，不是 404。
20. 主页标签第三项 `投稿经验`，地址 `/u/<用户名>/experiences`；别人视角只在有非匿名经验时出现。
21. 铃铛徽标 `clay-700` 底、99+ 封顶；不可用时图标变灰仍可点。
22. 用户菜单与移动菜单都加 `提醒`（移动账号块改 2×2）。
23. 提醒列表左对齐、每行三层（谁做了什么 / 摘录 / 在哪）、未读圆点 + 浅底；全部标为已读不确认。
24. 中性头像（灰底 + 人形图标）用于匿名作者与已注销用户，和默认头像区分开。
25. 发表、回复、编辑、删除都不乐观；只有标为已读、排序、展开是乐观的。
