# 有帮助与公开计数 — Design Brief

> v0.15 唯一一份设计简报。设计系统与代码库已 onboard，本简报只交增量，沿用 v0.14 简报（`../v0.14/discussion.md`）的讨论区、经验区与 v0.13 简报（`../v0.13/library.md`）的文献卡片。
> **产品定义以 release spec 为准**：`docs/patra/release-specs/v0.15-helpful.md` 2.1 节（有帮助、排序、公开计数）与第 4 节决策 C、D。本简报只定页面、状态与文案；两者不一致时以 spec 为准，缺口列在 §10。
> **接口契约以后端工程 spec 为准**：PAP-131（有帮助）、PAP-132（讨论串统计与排序）、PAP-133（对象统计与获赞）。页面对它们的要求列在附录 A。
> 可交互画板：Claude Design 画布「v0.15 有帮助与计数」<https://claude.ai/artifact/GzchLSeVWW1dnjnAHVhhDi>（桌面 1440 + 移动 375，5 页 18 块，场景用 Tweaks 切换）。快照 `docs/patra/design/snapshots/2026-10-29-helpful-hifi.zip`（2026-10-29 用户确认后从画布读回）。
> 同版相关：Linear PAP-130（本简报 + 画板）→ PAP-134（有帮助与排序）/ PAP-135（公开计数）。

**目标**：医生和科研人员能给有价值的评论（根评论和楼内回复）和投稿经验点「有帮助」，讨论区和期刊页的经验列表都能按「最有帮助」排序；文献、讨论串和投稿经验上显示公开计数（有帮助数、回复数和最后回复时间、收藏人数、讨论数），用户主页显示「获赞」数。

> **上线门槛（spec 第 3 节 K、D9）**：合规包完成前，门户只在 tailnet 内开放。设计稿里不出现举报、审核相关的入口与文案。

## 0. 策略与定位

- **数字是信号，不是社交。** v0.13、v0.14 刻意不放任何计数；本版放进来的每个数字都回答一个读者问题：这条评论值不值得先读（有帮助数）、这一楼还活不活跃（回复数、最后回复时间）、这篇文献有没有人讨论过（讨论数、收藏人数）、这位同行的贡献被认可过多少（获赞）。不放热度、浏览量、点赞人、排行（spec 第 3 节 A、D、E）。
- **0 不写。** 所有计数为 0 时都不显示数字：有帮助按钮只写「有帮助」，其余计数整段不出现（不写「0 条讨论」「获赞 0」）。小社区里大多数文献是 0，卡片应保持原样。
- **「有帮助」只有一种语义、一个样子。** 一个组件 `HelpfulButton`，两种外形：文字形（评论操作行、经验行，跟「回复」并排）、胶囊形（经验页正文下方，经验是页面主对象）。不做踩、不做表情回应（spec 第 3 节 C）。
- **自己的内容只有数字，没有按钮。** 「有帮助」表达对别人有用，进排序与获赞，所以不能给自己点（spec 2.1.1，Discourse 的做法）。自己的内容显示「N 人觉得有帮助」，不是按钮、Tab 走不到。
- **点了立刻变，失败退回来**（决策 D）：乐观更新，参照收藏按钮。别人点的、新回复带来的变化在重新取数据时更新，不轮询。
- **计数跟着内容走，不另开请求区块。** 评论、楼、经验的计数随列表一起返回；文献卡片的收藏人数、讨论数按屏批量取（决策 C），取不到时只是没有数字，卡片照常。
- **渐进式披露**：
  - 默认层：每条评论与经验的有帮助数、根评论的楼内统计、讨论区标题的条数、文献卡片与文献页的「收藏 · 讨论」、主页的获赞。
  - 深数据层：无新增。「最有帮助」排序是可选视图，默认仍是正序（讨论区）与最新投稿（经验列表）。
- **验证场景**（spec 第 1 节，画板逐条可走）：
  1. A 在期刊页写的经验，B、C 都点「有帮助」→ 期刊页这条显示 `有帮助 2`（作者本人看到 `2 人觉得有帮助`），切到「最有帮助」后排第一（`Journal`）。
  2. A 在文献页发根评论，C 回复；B 给 C 的回复点「有帮助」→ 回复旁 `有帮助 1`；B 再给 A 的根评论点 → 切到「最有帮助」后这一楼排第一；根评论下显示 `1 条回复 · 最后回复 2 小时前`（`Discussion` / `Paper`）。
  3. 检索结果里这篇文献的卡片显示 `N 人收藏 · N 条讨论`（`Cards`）。
  4. A 的主页显示 `获赞 3`（`Profile`）。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 读讨论的医生 / 研究者 | 一篇文献下有十几楼，切到「最有帮助」先读被同行认可的几楼 |
| 懂行的同行 | 读到一条把方法学问题讲清楚的回复，点「有帮助」；点错了再点一下取消 |
| 选刊的投稿作者 | 期刊页经验很多时切到「最有帮助」，先读别人觉得有用的经历；看每条有几条回复，判断有没有后续追问 |
| 写评论 / 经验的人 | 在自己的评论、经验下看到「N 人觉得有帮助」，在主页看到「获赞」 |
| 检索文献的人 | 结果列表里一眼看出哪几篇有人讨论过、有多少人收藏 |
| 匿名访客 | 能看到所有数字；点「有帮助」被引去登录 |

## 3. 每屏内容

### 3.1 有帮助按钮 `HelpfulButton`

**文字形**（评论操作行、经验行底部）：沿用评论文字按钮的样式（`text-xs` `font-medium` `fg-3`，悬停 `fg-1`，窄屏最小高 32px），图标 lucide `ThumbsUp` 14px（`stroke 1.75`），排在「回复」之前。

| 状态 ID | 样子 | 读屏 |
|---|---|---|
| `helpful.idle.zero` | `👍 有帮助`（不写 0） | `有帮助`，`aria-pressed="false"` |
| `helpful.idle` | `👍 有帮助 3`：数字等宽 `text-2xs`、`tabular-nums` | `有帮助，3 人觉得有帮助` |
| `helpful.on` | 图标填充 `clay-500`（描边 `clay-600`）、文字 `clay-700`，图标放大到 1.1 倍；数字含我自己 | `aria-pressed="true"`；再点取消 |
| `helpful.own` | 不是按钮：`👍 3 人觉得有帮助`，图标 `fg-4`、文字 `fg-3` 常规字重 | 纯文本 |
| `helpful.own.zero` | 什么都不显示 | — |
| `helpful.anon` | 样子同 `idle`；点击跳登录 | — |
| `helpful.unverified` | 样子同 `idle`；点击不改数字，按钮右侧行内提示（§3.2） | — |
| `helpful.deleted` | 「该评论已删除」占位不带按钮、不带数字；已删除的经验不在列表里，经验页只剩「该经验已删除」 | — |
| `helpful.rollback` | 数字先变，接口失败后变回原样，右侧行内提示 4 秒（§3.2） | 提示 `role="status"` |

**胶囊形**（经验页正文下方）：高 36px（窄屏 44px）、`radius-pill`、`paper-50` 底、`border-default`，图标 16px，文字 `text-sm`。已点：`clay-50` 底、`clay-200` 边、`clay-700` 字、图标填充。自己的经验：`3 人觉得有帮助`（`text-sm` `fg-3`，不是按钮）。

- **为什么用 `ThumbsUp`**：spec 用词是「有帮助」，图标只是辅助识别；拇指是各平台「认可」的通用符号，与文字一起出现不会误读成「点赞社交」。不用心形（偏情感）、不用向上箭头（暗示投票排名）。
- **数字的写法**：按钮里只写数字（`有帮助 3`）；自己的内容写成一句话（`3 人觉得有帮助`），因为没有按钮可以依附。千分位 `1,204`；本版不缩写成 `1.2k`。
- **动效**：已点 / 取消时图标缩放与颜色过渡 `dur-normal` `ease-out-expo`；「减少动态效果」下只换颜色。
- **不显示谁点了**：没有悬停名单、没有「A 等 3 人」（spec 第 3 节 D）。

### 3.2 点击、乐观更新与失败

1. **未登录**：点了跳 `/login?next=<当前地址>`（同 v0.14 回复按钮），回来后不自动点。
2. **邮箱未验证**（`/auth/me` 的 `emailVerified=false`）：前端直接拦，不发请求、不改数字；按钮右侧 `amber-700` 行内提示 `验证邮箱后才能点有帮助 · 重新发送验证邮件`（复用 `ResendVerificationButton`），4 秒后消失。
3. **其余登录用户**：点下立刻切换已点状态、数字 ±1（乐观），请求期间 `aria-busy="true"`，再点忽略（不排队、不连点）。成功后把这条所在的讨论 / 经验缓存标为过期（决策 D）。
4. **失败**：数字与已点状态退回点击前；按钮右侧 `rust-500` 行内提示 4 秒：

| 状态 ID | 何时 | 提示 |
|---|---|---|
| `helpful.error.network` | 网络 / 5xx | 点的时候 `没有标记成功，请稍后再试`；取消时 `没有取消成功，请稍后再试` |
| `helpful.error.daily` | 当天第 301 次 | `今天已经点了 300 次有帮助，明天再来吧` |
| `helpful.error.ineligible` | 冷静期、封禁、账号状态异常 | `账号状态异常，暂时不能点有帮助` |
| `helpful.error.unverified` | 服务端判定未验证（别处刚改了邮箱） | `验证邮箱后才能点有帮助 · 重新发送验证邮件`（`amber-700`） |
| `helpful.error.gone` | 目标已删除 | `这条评论已被删除` / `这条投稿经验已被删除`；随后讨论 / 经验重新取，变成占位或从列表消失 |
| `helpful.error.self` | 接口拒绝给自己点 | 界面上不会出现（自己的内容没有按钮），只作为接口兜底，按 `network` 处理 |
| 会话失效（401） | — | 跳登录带 `next` |

- **为什么用行内提示而不是 toast**：沿用 v0.14 的约定「toast 只报成功」；有帮助没有表单或对话框可以挂错误，提示贴在按钮旁最不打扰，也最清楚是哪一条失败了。
- 取消不退次数（spec 2.1.1），界面不提示剩余次数。

### 3.3 评论里的位置

- 根评论与楼内回复的操作行：`[有帮助 N] [回复] [查看对话]`，有帮助永远在最前。
- 「查看对话」对话框里的评论只读，不放按钮也不放数字（对话框只用来看回复链）。
- 原地编辑时操作行隐藏（同 v0.14），编辑不影响有帮助数。
- 匿名经验下作者本人的评论：作者看到的是自己的内容（只有数字）；别人看到「匿名作者」的评论照常有按钮（§3.13）。

### 3.4 楼内统计（取代不带数字的「展开更多回复」）

- **位置**：根评论操作行右端（`margin-left: auto`），`text-xs` `fg-3` 常规字重：`4 条回复 · 最后回复 20 小时前`。窄屏换到操作行下一行、左对齐。
- **何时显示**：这一楼有未删除的回复就显示（1 条也显示）；没有回复不显示。时间写法同 v0.14 §3.22（`刚刚`、`3 分钟前`、`昨天 14:20`、`10 月 24 日`…），`title` 写完整时间。
- **根评论已删除、楼里还有回复**：占位行 `该评论已删除` 右侧照样显示统计（占位不显示有帮助数，统计属于这一楼）。
- **「展开更多回复」改为带剩余条数**：每楼默认仍显示前 3 条回复，第 4 条起收起；按钮写 `展开其余 2 条回复 ⌄`（剩余里只数未删除的；剩下的全是占位时写 `展开全部回复`）；加载中 `加载中…`。
- 新回复发表后统计立刻 +1、最后回复变成 `刚刚`（本人发表，前端直接更新，不等重新取）；删除回复同理减 1。
- 楼内回复的有帮助数不计入楼主（spec 2.1.2），统计里不出现有帮助的合计。

### 3.5 讨论区排序：「最有帮助」

- 分段控件三项：`正序`（默认）/ `最新` / `最有帮助`，窄屏 375 仍放得下一行（标题与分段控件之间允许换行兜底）。
- 「最有帮助」：根评论按自己的有帮助数降序，相同时新的在前；楼内回复始终按时间正序（spec 2.1.2）。
- **点了有帮助不重排**：数字变，位置不动；切换排序、翻页、刷新时才按新数字排。否则用户手下的楼会跳走。
- **新发表的根评论**：在「最有帮助」下插在列表最上面并高亮 2 秒（与「最新」相同），刷新后按有帮助数排（新评论是 0，会排到有数的后面）。不用「正序」那种「已发表，去看看」的确认行，因为新评论刚发表时用户最想看到它。
- 翻页期间数字可能变化，前端按 ID 去重（决策 D）。
- 全部为 0 时「最有帮助」等同于「最新」，不加说明。

### 3.6 讨论区标题的条数

- `讨论 · Discussion` 右侧 `7 条`（等宽 `text-2xs` `fg-3`），经验页回复区 `回复 · Replies 5 条`。
- 口径：这个对象下未删除的评论总数，含楼内回复（spec 2.1.3），不是已加载的条数。
- 0 条（空状态）、加载中、暂不可用时不显示；本人发表 / 删除时立刻 ±1。

### 3.7 文献页事实条：收藏、讨论

- 页头事实条（`PaperFacts`）末尾加两格：`收藏` → `23 人`、`讨论` → `7 条`（链接色，点了滚到 `#discussion`）。放在最后，因为这两格来自 interaction，晚到也不挤动前面的格子。
- 为 0 的那格不出现（不写 `0 人`、不写 `—`）；取不到时两格都不出现。
- 本人在页头点「收藏」/ 取消收藏：`收藏` 格同步 ±1（0 → 1 时这一格出现），失败随收藏按钮一起回滚。
- v0.13 删掉的是「我的」收藏格；这里放回的是公开的收藏人数，不是「我收藏了没有」（那由收藏按钮表达）。

### 3.8 期刊页经验列表：排序与条数

- 「同行经验」汇总卡不变。卡片与列表之间加一行工具行：左 `18 条投稿经验`（`text-sm` `fg-2`，总数），右分段控件 `最新投稿` / `最有帮助`。只有 1 条或 0 条时不出分段控件；0 条时整行不出（空状态不变）。
- 「最新投稿」= 现在的按投稿日期倒序（默认）；「最有帮助」= 有帮助数降序，相同时发布时间新的在前。
- 换排序 = 从第一页重新取（已加载的后几页丢掉），`加载更多投稿经验` 照常；点有帮助不重排（同 §3.5）。

### 3.9 经验行改结构：链接与按钮分开

现在的 `ExperienceRow` 整条是一个 `<a>`；按钮不能放进链接里（无效 HTML，键盘与读屏都会出错）。改为：

- 外层 `<article>`（`position: relative`），标题行（期刊页是结果行、主页是期刊名）是链接 `<a href="/posts/<id>">`，用伪元素铺满整行（`::after { inset: 0 }`），整行仍然可点、悬停照样画标题下划线。
- 底部新增一行 `pt-xrow-foot`（`position: relative; z-index: 1`，压在铺满的链接上面）：`[有帮助 N] [💬 3 条回复]`。回复数是纯文本（点了落在行上，进经验页），`MessageCircle` 14px，0 条不显示。
- 焦点环画在铺满的伪元素上（整行一个焦点环），按钮有自己的焦点环。
- 期刊页与主页两种变体都改。

### 3.10 经验页

- 正文（没有正文时是结构化字段）下方、回复区之上：胶囊形有帮助按钮（§3.1）。
- 作者本人（含匿名经验的作者）：`5 人觉得有帮助`，0 时不显示；作者已注销：别人照常能点。
- 该经验已删除：整页只剩「该经验已删除」说明，没有按钮也没有回复区（v0.14 不变）。
- 回复区就是讨论区组件，§3.3–§3.6 的变化全部适用。

### 3.11 主页：获赞与经验行

- **获赞**：头部预留的计数行（`@用户名` 之下、简介之上，v0.12 简报 §3.13 留位 1），本版只放一项：`获赞 7`（标签 `text-sm` `fg-3`，数字 `fg-1` `font-semibold`）。关注、粉丝两格不出现、也不占位（spec 第 3 节 G）。
- 口径：本人未删除、非匿名的评论与经验收到的有帮助总数（spec 2.1.3）。别人视角与本人视角一样。
- 0 或取不到时整行不显示；主页上点了这个人的经验的有帮助，获赞不即时 +1，下次打开主页时更新（获赞单独取，决策 C）。
- 注销用户主页 404，不显示获赞（spec 2.1.1）。
- **「投稿经验」标签的每一行**：同 §3.9，底部 `[有帮助 N] [💬 N 条回复]`；本人看自己的主页全是「自己的内容」（只有数字），本人看到的匿名经验同样只有数字。

### 3.12 四处文献卡片：收藏人数与讨论数

写法统一为 `23 人收藏 · 7 条讨论`（等宽 `text-2xs` `fg-3`，`·` 用 `ink-300`）；只有一项时只写那一项；都为 0 时整行不出现。`N 条讨论` 是链接（悬停 `fg-1` + 下划线）→ 文献页 `#discussion`；收藏人数不是链接（不公开收藏人）。

| 位置 | 组件 | 放哪 |
|---|---|---|
| ① 检索结果 `/papers` | `PaperListItem`（带徽章与摘要） | 卡片末尾单独一行，摘要之后（`CardPlace` 方案 A） |
| ② 我的文献库 `/library` | `PaperListItem`（`summary=false`） | 元信息行之后、归属与备注之前 |
| ③ 公开收藏夹 `/c/…` | `PaperListItem`（日期到月日） | 同 ① |
| ④ 首页文献流 `/` | `PaperCard` | 底部已有的一行里，`阅读详情` 与 `N 引用` 之间（`… 23 人收藏 · 7 条讨论 · 0 引用 [收藏]`）；窄屏放不下，移到底部行上方单独一行 |

- **为什么 ①②③ 单独一行**（`CardPlace` 三案对比）：书目信息与社区信号分开；B「接在元信息行末尾」作者多时整行折行、计数落到下一行行首；C「来源行右端」要挤掉文献类型，窄屏连计数也藏掉了。
- **何时取、取不到**：计数是公开数据，未登录也显示；随页面在服务端批量取（短超时），失败或超时就不渲染这一行，卡片照常。不画骨架、不留空位：大多数文献是 0，留位会让整列表多出空行。文献库页的列表在客户端取时，计数与条目同一批返回，不单独晚到。
- **本人收藏 / 取消收藏**：这张卡的收藏人数同步 ±1（0 → 1 时这一行出现），失败随收藏按钮一起回滚。
- 首页文献流的「N 引用」本版不动（被引数据全 0 的问题与本版无关）。

## 6. 交互与响应式

- **乐观与否**：有帮助、本人收藏带来的收藏人数 ±1、本人发表 / 删除带来的条数与楼内统计变化 → 乐观；其余计数随重新取数据更新，不轮询（决策 D）。
- **焦点**：点有帮助后焦点留在按钮上；失败提示 `role="status"` 播报，不抢焦点。
- **键盘**：按钮是真正的 `<button aria-pressed>`；自己的内容是纯文本，Tab 跳过。经验行整行链接与底部按钮各有焦点。
- **移动**：文字形按钮最小高 32px（与「回复」一致），胶囊形 44px；楼内统计换到操作行下一行；首页卡片的计数移到底部行上方；三项排序在 375 宽一行放得下。
- **元素状态**：hover / active / focus / pressed / busy 都要给出：有帮助两种外形、三项与两项分段控件、事实条讨论格链接、卡片讨论数链接。

## 10. 已拍板与 spec 缺口

**2026-10-29 用户已定**（确认画板，以下十条按画板定稿）：

1. **图标用 `ThumbsUp`**（§3.1），已点为陶土色填充。没有采用：不放图标只写字；`Lightbulb`（「有启发」的意味，但不如拇指好认）。
2. **自己的内容为 0 时什么都不显示**（§3.1）：spec 的「自己的内容照常显示数字」与「0 只显示有帮助」在这里冲突——0 时既没有数字可显示，又不能给自己显示一个点不了的「有帮助」。
3. **经验行改结构**（§3.9）：整行仍可点，按钮与回复数放在压在链接上面的底部行。这是 PAP-134 的组件改动，不只是加一个按钮。
