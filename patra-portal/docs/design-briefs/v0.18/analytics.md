# 行为数据 — Design Brief

> v0.18 唯一一份设计简报。设计系统与代码库已 onboard，本简报只交增量：卡片计数沿用 v0.15 简报（`../v0.15/helpful.md` §3.12）的 `PaperStats` 写法，设置页沿用 v0.12 简报（`../v0.12/user-center.md`）的设置外壳与即时保存，首页文献流沿用现有 `ExploreFeed`。
> **产品定义以 release spec 为准**：`docs/patra/release-specs/v0.18-analytics.md` 2.1 节与第 4 节决策 B、I、J。本简报只定页面、状态与文案；两者不一致时以 spec 为准，缺口列在 §10。
> **接口契约以后端工程 spec 为准**：PAP-170（计数、热读、看过还看了）、PAP-169（阅读历史）、PAP-173（设备与会话 Cookie）。页面对它们的要求列在附录 A。
> 可交互画板：Claude Design 画布「v0.18 行为数据」<https://claude.ai/artifact/CCNaRB5JeLgNCVU544NNFi>（桌面 1440，6 页 9 块，场景用 Tweaks 切换）；简报页 <https://claude.ai/artifact/2MFopuqyppth6pRmtNkcq8> 由本文件生成。快照 `docs/patra/design/snapshots/2026-11-01-analytics-hifi.zip`。
> 同版相关：Linear PAP-166（本简报 + 画板）→ PAP-174（数据展示与阅读历史）；PAP-173（门户埋点）没有界面，只有附录 A 第 12、13 条与隐私政策里的 Cookie 表有关。

**目标**：读者在卡片和文献页上看到每篇文献有多少人看过、多少人读过全文；首页有「热读」，检索结果里在热读榜上的文献带「近期热读」；文献页下方有「看过这篇的人还看了」。登录用户能翻看自己的阅读历史，能关闭记录、逐条删除、一键清空；页脚能找到隐私政策。

## 0. 策略与定位

- **数字是信号，沿用 v0.15 的规矩。** 「看过」「读过全文」跟收藏人数、讨论数是同一类数字，写法、位置、0 不写、取不到就不出现，全部照 v0.15 §0、§3.12。新数字只回答一个问题：这篇有多少同行看过。
- **热读是推荐，不是排序。** 首页多一个标签；检索结果只加标记，不改相关度排序（spec 第 3 节 D）。标记放在来源行（关于这条记录的事实），不放在证据徽章旁边，免得「读的人多」被读成「证据好」。
- **补位要说出来。** 热读榜上的不够时用「最新收录」补齐，每张补位卡片标「最新收录」，标签下的说明句写清有几篇是补位（spec 2.1「不冒充热读」）。「同主题文献」同理：标题换掉，每张卡片写出是哪个主题词。
- **两层数据，界面上说清楚。** 浏览数是汇总后的人数，不显示是谁看过；阅读历史只有自己能看。关闭记录、删除、清空都只动阅读历史，这句话在阅读历史页的清空确认、设置卡片、隐私政策里各出现一次，说法一致。不说「匿名」：统计用的事件带设备标识与账号 ID（spec 决策 A），只能说「不显示是谁」。
- **没有新的社交元素。** 不显示谁看过、不显示「N 人一起读过」的人数（共现门槛只有 3 人，显示人数等于半公开别人的阅读）、不做个性化推荐（spec 第 3 节 C）。
- **渐进式披露**：
  - 默认层：卡片上的「N 人看过」、首页「热读」标签、检索结果的「近期热读」、文献页读者一行、页底「看过这篇的人还看了」。
  - 深数据层：「读过全文」只在文献页（§3.2）；计数口径（同一个人只算一次、去爬虫）放在悬停说明里；热读算法放在热读标签的说明句里；隐私政策是完整说明。
- **验证场景**（spec 第 1 节，画板逐条可走；示例人物沿用 B = 王立、C = 林知远；「现在」是 11 月 1 日 16:00）：
  1. B 打开一篇文献、读了全文 → 1 分钟内文献页读者一行的「看过」「读过全文」各加一（`Paper`；数字更新本身没有界面变化，刷新后看到）。
  2. 首页切到「热读」，排序跟「最近更新」明显不同（`Feed`）；检索结果里榜上的文献带「近期热读」（`Cards` ①）。
  3. 文献页底部「看过这篇的人还看了」列出常被一起读的文献（`Paper` Tweak「rec」）。
  4. C 在设置里关闭「阅读记录」（`Privacy`）→ 阅读历史页顶部出现「阅读记录已关闭」提示，之后打开的文献不出现（`History` Tweak「recording › 已关闭」）；C 清空历史 → 页面变成「阅读历史已清空」（`History` 点「清空历史」）。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 刷首页的医生 | 切到「热读」，看看同行这两周都在读什么；补位的几篇一眼看得出是「最新收录」 |
| 检索文献的研究生 | 一页结果里有两篇带「近期热读」，先点开看；排序没有因此变化 |
| 读完一篇想继续的人 | 文献页底部「看过这篇的人还看了」，接着读同一批人读过的 RCT |
| 想找回上周读过某篇的人 | 头像菜单 › 阅读历史，按天找到那一篇 |
| 在意隐私的人 | 设置 › 隐私关掉「阅读记录」，或者在阅读历史里清空；在页脚找到隐私政策，确认浏览数不显示是谁 |
| 新收录、没人看过的文献 | 卡片和文献页跟现在一样，不出现「0 人看过」 |

## 3. 每屏内容

### 3.1 计数写法与 0（全站统一）

| 项 | 写法 | 说明 |
|---|---|---|
| 看过 | `1,284 人看过` | 看过的人数，按人长期去重：登录用户按账号、访客按设备，同一个人只算 1 次（2026-11-01 定的口径）；千分位、不缩写（`formatCount`） |
| 读过全文 | `312 人读过全文` | 全文区停留满 10 秒或下载 PDF 的人数，同样按人长期去重 |
| 收藏、讨论 | `23 人收藏`、`7 条讨论` | v0.15 不变 |

- **顺序**：看过 → 读过全文 → 收藏 → 讨论。从最宽泛到最投入。
- **0 不写**：哪一项为 0 就不写那一项，四项都为 0（或都取不到）时整行不出现（v0.15 §0）。新收录、没人看过的文献，卡片和文献页跟现在一样。
- **取不到**：看过、读过全文来自行为数据服务；收藏、讨论来自互动服务。两个服务**各自**降级：哪个取不到，就只少它那几项（`Cards` / `Paper` Tweak「analytics」「interaction」「counts」）。
- **悬停说明**（文献页读者一行，`title`）：看过 `看过的人数：同一个人只算一次（登录用户按账号、访客按设备），不含搜索引擎等爬虫；1 分钟内更新`；读过全文 `在全文区停留满 10 秒或下载了 PDF 的人数，同一个人只算一次`。卡片上不加（太密）。
- **本人看了不即时 +1**：计数有 60 秒缓存，刷新后才变（spec 决策 G）。不做收藏那样的乐观 ±1：本人以前看过的话，再看数字不会变（同一个人只算一次）。

### 3.2 卡片上的计数（四处）

- 写进现有 `PaperStats` 那一行，位置都不变（v0.15 §3.12）：检索结果、公开收藏夹在摘要之后单独一行；文献库在元信息之后；首页文献流在底部那一行里，「阅读详情」与「N 引用」之间。
- 例：`1,284 人看过 · 23 人收藏 · 7 条讨论`；只有看过：`37 人看过`。
- **卡片上只写「看过」，不写「读过全文」**（已定，§10 第 1 条；`Cards` Tweak「cardMode」的 B 只作对比）。理由：卡片已经有三项，再加一项在首页右栏（约 460px）会折行；「读过全文」是深一层的信息，留在文献页。
- 计数随页面在服务端批量取（一屏一次，同 v0.15 决策 C），与收藏、讨论两批**并行**取，各自短超时。

### 3.3 文献页：读者一行（定稿方案 B）

- **问题**（`Facts` 画板）：有全文的文献事实条现在有 9 格（证据等级、被引、来源、原文阅读、篇幅、图表、参考文献、收藏、讨论），在 1184px 版心里按 128px 最小宽度正好一行。再加「看过」「读全文」任何一格都会折成两行，第二行只有一两格；没有全文的文献（6 格）不折，两类文献的页头高度还不一样。
- **方案 B（定稿）**：事实条只放书目事实（7 格）；下方单独一行写读者相关的四个数，写法同卡片：`1,284 人看过 · 312 人读过全文 · 23 人收藏 · 7 条讨论`。字号 `text-sm`、`fg-3`，数字 `fg-1` 字重 500；`N 条讨论` 是链接，滚到 `#discussion`，数字用链接色。v0.15 §3.7 的收藏、讨论两格挪进这一行。
- 位置：事实条之后、操作按钮（阅读全文 · 收藏 · 分享）之前，上边距 14px。
- 本人在页头收藏 / 取消：这一行的收藏人数同步 ±1（v0.15 §3.7 的规则搬过来）；讨论数跟讨论区缓存（v0.15 §4.3 不变）。
- 四项都为 0 或都取不到：整行不出现，操作按钮上移。
- 读者一行在 Suspense 里流式到达：两个服务分别到达时**分别插入**，不画骨架（同 v0.15「不留空位」）。
- 方案 A（两格加进事实条）、C（合一格「读者」）都会折行，见 `Facts`；未采用。

### 3.4 检索结果：「近期热读」标记（定稿方案 A）

- **位置**：来源行右端、文献类型（`JOURNAL ARTICLE`）之前，`margin-left: auto` 把它和类型一起推到右边（`HotMark` 方案 A）。窄屏文献类型隐藏时，标记仍在来源行右端。
- **样子**：lucide `TrendingUp` 12px + `近期热读`，等宽 `text-2xs`、字重 500、`clay-700`。不做胶囊、不加底色。
- **悬停说明**（Tooltip，键盘聚焦也能出）：`近 14 天读的人多，在热读榜前 100 名。只是标记，不影响检索排序。`
- **何时出现**：这篇在当前热读榜（每小时重算的快照）前 100 名里。补位的「最新收录」不算上榜，不带标记。行为数据服务取不到时，标记全部不出现，检索照常。
- 只在检索结果出现；文献库、公开收藏夹、首页卡片都不带（spec 2.1 只要求检索结果）。
- 方案 B（证据徽章那一行）、C（标题前）的问题见 `HotMark`；未采用。

### 3.5 首页文献流：第三个标签「热读」

- **标签**：`最近更新` · `高被引` · `热读`（lucide `TrendingUp`），追加在最后，默认仍是「最近更新」。药丸分段控件不变，三格。
- **区块说明句**（h2 下方，三个标签共用）：改为 `最近入库、高被引与近期读的人多的文献。AI 速读即将上线，上线后也只作线索，不能替代阅读原文。`
- **热读标签下的一行说明**（`pt-fnote`：信息图标 + `text-sm` `fg-2`，标签栏与网格之间；只在热读标签出现）：

| 场景 | 说明句 |
|---|---|
| 上榜的够一页（14 篇） | `按近 14 天的阅读排：读了全文的分量更重，越近的阅读分量越重；每小时更新一次。` |
| 上榜的不够 | `近 7 天有 3 位以上读者的文献只有 4 篇；后面 10 篇是最新收录，卡片上标着「最新收录」。`（两个数按实际填） |
| 一篇都没上榜 | `近 7 天还没有文献的读者达到 3 位，下面先列出最新收录。` |

- **排版**：同现有 `FeedLayout`（头条 + 右栏 3 篇 + 两栏列表）。上榜的按名次排在前面，补位的接在后面；补位从哪一格开始都可以（可能落在右栏里），所以不画分隔线，靠每张卡片自己的标记。
- **上榜卡片**：序号就是名次（`01`、`02`…，`accent-strong`），其余与其他标签的卡片相同。
- **补位卡片**：序号的位置换成小胶囊 `最新收录`（`paper-200` 底、`fg-2`、`text-2xs` 字重 500、高 20px）。读屏在标题前读出「最新收录」。补位按收录时间新的在前，去掉已经上榜的。
- **数量**：一页 14 篇，同现在（画板为了版面只画了 12 篇）。
- **加载失败 / 空**：同现有 `ExploreFeedEmpty`。热读几乎不会「空」：补位保证有内容；只有 catalog 一篇文献都没有时才空。
- 画板 `Feed` Tweak「hot」切三种场景，「tab」切初始标签，「load」切加载失败；标签本身可点。

### 3.6 文献页底部：看过这篇的人还看了 / 同主题文献

- **位置**：两栏网格（主栏 + 侧栏）之后、页脚之前，整宽区块（`max-w-page`），上边一条 `border-default`、上边距 96px。不放进侧栏：有全文时侧栏的目录卡一直吸顶到页底，没有位置。
- **标题与说明**（h2 衬线 `text-3xl`，右侧说明 `text-sm` `fg-3`）：
  - 一起读的：`看过这篇的人还看了` / `常和这篇在同一天被同一批读者读过的文献`
  - 补位的：`同主题文献` / `主要主题词与这篇相同；不够时再看同一本期刊`
- **卡片**（三列网格，一行三篇，最多两行 6 篇）：来源行（来源 · 年份 · 类型）→ 衬线标题（三行截断）→ 刊名斜体 · 第一作者「等」。不放收藏按钮、不放计数，保持轻。
- **补位卡片**多一行原因（`fg-3` `text-xs`，标签图标）：`同主题词 Shock, Septic`（主题词用 MeSH 原文，衬线）；同期刊补位时写 `同一期刊 Chest`。
- **组合规则**（spec 2.1：不足 6 条时依次用同主要主题词、同期刊补位）：

| 一起读的篇数 | 呈现 |
|---|---|
| 6 | 只有「看过这篇的人还看了」一组 |
| 1–5 | 两组：先「看过这篇的人还看了」（实际篇数），再「同主题文献」补到合计 6 篇；每组各自一个标题 |
| 0 | 只有「同主题文献」一组（标题直接是它） |
| 0，且同主题、同期刊也没有 | 整个区块不出现 |

- 一起读的那组按相似度从高到低；不显示「N 人一起读过」（§0）。
- **加载中**：区块在 Suspense 里，骨架是标题一条 + 3 张卡片骨架；**取不到**（行为数据服务挂了）：整个区块不出现，页面其余照常。补位数据来自 catalog，按附录 A 第 6 条由同一个接口一起给，不分两次取。
- 已撤稿的文献、自己正在看的这篇不出现在列表里（附录 A 第 5 条）。

### 3.7 阅读历史页 `/history`

页面结构：`TopNav` → 单栏版心（最宽 880px，居中）→ `Footer`。

1. **页头**：h1 `阅读历史`（衬线 48px）；下面一行说明 `你在 Patra 上打开过的文献，只有你自己能看到。同一篇只留最近一次，记录保留 12 个月。`；右侧 `阅读记录设置`（链接，滑块图标，→ `/settings/privacy#reading`）与次按钮 `清空历史`（没有记录时置灰不可点）。
2. **记录已关闭且还有旧记录**：列表上方信息提示条（`status-info-bg`、暂停图标）`阅读记录已关闭：现在打开的文献不会记到这里，下面是关闭之前的记录。` + 文字链接 `去设置里开启`。
3. **按天分组**：组标题 `今天 · 11 月 1 日`、`昨天 · 10 月 31 日`、更早的 `10 月 30 日 周五`；跨年时写上年份 `2025 年 12 月 30 日 周二`。时间按北京时间。组标题样式同提醒页 `pt-day`。
4. **每一行**（三列：时间 56px · 正文 · 删除 32px）：
   - 时间 `15:42`（等宽 `text-xs` `fg-3`），是这篇**最近一次**打开的时间（spec 决策 B：同一篇只留最近一次，再打开就挪到最上面）。
   - 标题（衬线 `text-lg`，两行截断，链到文献页）；下一行 刊名斜体 · 年份；读过全文的再加小胶囊 `读过全文`（书本图标，`paper-200` 底）。
   - 删除按钮：`X` 图标，一直显示（不是悬停才出现，键盘与触屏都能用），`aria-label` 写 `从阅读历史删除：<标题前 40 字>`，`title` 写 `从阅读历史删除`。
   - **文献已不在 Patra 上**（被下架或合并）：标题位置写 `这篇文献已不在 Patra 上`（`fg-3`、无衬线、不是链接），没有刊名行，仍可删除。
5. **单条删除**：点了立即生效，不确认、不做撤销（§10 第 8 条）。行先变淡（`opacity .35`）、按钮不可再点，成功后这一行消失（该组空了组标题也消失）；失败时行恢复，正文下面红字 `没能删除，请重试。`（`role="alert"`）。
6. **翻页**：一次 30 条（画板为了版面只画了 10 条），按时间倒序，游标翻页。底部文字按钮 `加载更早的记录`；到底了写 `没有更早的了。超过 12 个月的记录会自动清理。`
7. **清空**：点 `清空历史` → 确认对话框（`alertdialog`）：
   - 标题 `清空全部阅读历史？`
   - 说明 `已有的阅读记录会全部删除，不能恢复。之后打开的文献会继续记录。文献页上的浏览数是汇总后的人数，不受影响。`（记录已关闭时中间一句换成 `阅读记录现在是关闭的，清空后这里会一直是空的。`）
   - 按钮 `取消` / `清空`（危险色）；点了按钮变 `清空中…`，两个都不可点；成功关闭对话框、页面变成「已清空」空状态；失败对话框留着，里面红色提示条 `暂时没能清空，请稍后再试。`
8. **空状态**（历史图标 48px，衬线标题 + 说明 + 一个次按钮）：

| 状态 | 标题 | 说明 | 按钮 |
|---|---|---|---|
| 开着、没有记录 | `还没有阅读历史` | `你打开过的文献会按时间记在这里，只有你自己能看到。` | `去看看文献` → `/` |
| 刚清空 | `阅读历史已清空` | `之后打开的文献会继续记在这里。` | `去看看文献` |
| 已关闭、没有记录 | `阅读记录已关闭` | `打开之后，你看过的文献会按时间记在这里，只有你自己能看到。` | `去设置里开启` |

9. **加载中**：组标题一条 + 5 行骨架；**取不到**：空状态版式，标题 `阅读历史暂时打不开` / `请稍后再试。文献页照常能看，只是这里暂时列不出来。` + `重试`。
10. 页面标题 `阅读历史 · Patra`。

### 3.8 设置 › 隐私：第四张卡片「阅读记录」

## 6. 交互与响应式

- **只为桌面设计**（spec 2.1）。手机只保证两件事：正文能读、页面不横向溢出。具体：
  - 卡片计数沿用 v0.15 窄屏规则（首页卡片的计数挪到底部行上方单独一行）；「近期热读」留在来源行，文献类型照旧隐藏。
  - 文献页读者一行自然折行；页底区块三列变一列。
  - 首页三个标签放得下（375 宽每个约 100px）；说明句自然折行。
  - 阅读历史：页头按钮换到说明下方；行内时间列缩到 44px。
  - 隐私政策：目录移到正文上方、不吸顶；三列表格每行变成「名称一行、其余一行」的上下排；正文不小于 15px。
  - 不出手机画板；PAP-174 用 Playwright 375 宽截图检查以上几点。
- **焦点**：删除按钮、清空、开关都是原生控件；对话框打开时焦点在 `取消`（危险操作默认不落在确认上），关闭后回到触发按钮；单条删除成功后焦点移到下一行的删除按钮（没有下一行就到上一行，再没有就到「清空历史」）。
- **读屏**：补位卡片在标题前读「最新收录」；「近期热读」有可读文字；删除失败、清空失败的提示 `role="alert"`；保存状态 `aria-live="polite"`。
- **元素状态**：hover / focus / disabled 要给出：三个标签、删除按钮（含删除中）、清空按钮（含没有记录时的置灰）、开关、页底区块卡片、隐私政策目录。
- **减少动态效果**：删除时的变淡不做过渡。

## 7. 约束

- **视觉**：沿用「叶脉 · 学术编辑风」与 token（`patra-portal/src/styles/tokens.css` + `@theme`），不新增颜色与字族。新出现的颜色只有 `clay-700`（热读标记）、`paper-200`（补位与读过全文的小胶囊）、`status-info-bg`（记录已关闭提示），都是现有 token。
- **技术**：Next 16 App Router / Tailwind v4 / base-ui(shadcn) / TanStack Query。热读、共现走服务端渲染；阅读历史的删除与清空走 Server Action 或 Route Handler（前端 spec 定）。
- **可访问性**：沿用 v0.12 §7。
- **暗色模式**：门户不做。
- **用词**：界面说「看过」「读过全文」「热读」「近期热读」「阅读历史」「阅读记录」「清空」；不说「浏览量」「阅读量」「热度」「热门」「足迹」「推荐给你」「猜你喜欢」「匿名」。
- **本版边界**（设计稿里**不要**出现，spec 第 3 节）：按热度排序检索；个性化推荐与「猜你喜欢」；关注；谁看过、「N 人一起读过」；投稿经验与讨论的浏览数；Cookie 同意弹窗；用户分群、A/B；运营面板（Grafana，不在门户里）；阅读历史的导出、按时间筛选、搜索、撤销删除。

## 附录 A. 页面对后端的要求

> 只写页面需要什么，接口形状由各 Issue 的工程 spec 定。

**PAP-170 计数、热读、看过还看了**

1. **批量计数**：按一组文献 ID 一次取「看过」「读过全文」两个数（一屏一批，同 interaction 的 `POST /subjects/stats`）；没有数据的文献返回 0 或不返回，门户都当 0。
2. **热读列表**：一次返回一页（14 篇）有序列表，**每篇带「是不是补位」**；另带上榜篇数（说明句要写「只有 N 篇」）。补位规则在后端做（最新收录、去掉已上榜的），门户不自己拼。列表项字段与 `/portal/publications` 的卡片一致，门户能直接喂给 `PaperCard`。
3. **上榜判断**：检索结果一屏的文献 ID 里，哪些在当前热读榜前 100 名（批量；可以和第 1 条合成一个接口，返回 `hot: true/false`）。
4. **看过还看了**：按当前文献 ID 取最多 6 篇，**每篇带来源**：`CO_READ`（一起读的）/ `SAME_MESH`（带命中的主要主题词原文）/ `SAME_VENUE`（带期刊名）。顺序就是展示顺序（一起读的在前，按相似度）。
5. 列表里不出现当前这篇、已撤稿的文献、已不在 catalog 里的文献。
6. 补位需要 catalog 的主题词与期刊数据：由 analytics 调 catalog 拼好一起返回，或门户并行取两个接口再合并，二选一在工程 spec 定；**页面只要一次拿到完整 6 篇**（不先画一组再插一组）。
7. 对外数字排除爬虫与合成数据（spec 决策 I）；开发环境的 `include-synthetic` 打开时，画板上的数字量级就是用模拟器灌出来的样子。

**PAP-169 阅读历史**

8. 列表：按最近一次打开时间倒序，游标翻页，一页 30 条；每条带文献 ID、最近一次打开时间、是否读过全文；文献的标题、刊名、年份由门户按 ID 批量取（或后端一起给），**文献已不在时也要返回这条**（页面显示「这篇文献已不在 Patra 上」并允许删除）。
9. 单条删除（按记录 ID 或文献 ID）、清空全部；重复删除按成功处理。
10. 记录开关读写：没设过返回默认「开」；读写都要能单独失败（页面上那张卡片单独降级）。
11. 页面需要知道「开关关着」与「有没有记录」两件事来选空状态与提示条，列表接口可以顺带返回开关状态，省一次请求。

**PAP-173 门户埋点**

12. 新增的会话标识 Cookie 定下名称与有效期后，填进隐私政策第 04 节的 Cookie 表（画板里是占位）。
13. 设备 Cookie 改为所有访客首次访问即下发，隐私政策第 04 节已按这个写；如果有效期或名字变了，同步改政策。

## 10. 已拍板与 spec 缺口

**已定**（2026-11-01 用户经编排会话拍板，8 条全部按推荐，原话「按你推荐的」）：

1. **卡片上只写「看过」**，「读过全文」只在文献页（§3.2）。没有采用：卡片也写读过全文。
2. **数字为 0 不写**，四项全为 0 时整行不出现（§3.1，沿用 v0.15）。
3. **文献页读者计数放在事实条下方单独一行**「看过 · 读过全文 · 收藏 · 讨论」，v0.15 的收藏、讨论两格从事实条挪进这一行（§3.3）。没有采用：加格子进事实条、合成一格（都会折行）。Linear To-Do 里的「详情页事实行」以这一行为准。
4. **文献库、公开收藏夹也显示看过数**（共用 `PaperStats`，§3.2）。
5. **「近期热读」放在来源行右端**，陶土色小字（§3.4）。没有采用：证据徽章那一行、标题前。
6. **阅读历史入口是头像菜单 + 独立页面 `/history`**（§3.7、§3.10）。没有采用：放进文献库侧栏。
7. **隐私政策写全站**：账号、登录记录（含 IP，190 天）、Resend、Cloudflare、行为数据（§3.9）。
8. **单条删除立即生效，不做撤销**；清空要先确认（§3.7）。

另定：**计数口径是按人长期去重**（登录用户按账号、访客按设备，同一个人只算 1 次），所以「N 人看过」「N 人读过全文」的写法成立（§3.1）。

**仍待定**：隐私政策的联系邮箱用户还没给，画板里保留占位；生效日期与最近更新默认写上线当天（画板写 `[上线当天]`）；运营者名称、网站域名、服务器所在地也是占位，落地时填。

**由我定的设计点**（随画板一起确认）：

9. 热读补位不画分隔线，靠每张卡片的「最新收录」与标签下的说明句（补位可能从右栏中间开始）。
10. 「看过这篇的人还看了」放在两栏之后的整宽区块，不放侧栏；不显示一起读的人数。
11. 计数不做本人看了即时 +1。
12. 隐私设置的阅读记录卡片单独保存，与上面三项分开。

**与 spec 的出入**：

- spec 2.1 的浏览量写的是「一次会话里看同一篇只算一次」，口径已改为按人长期去重（编排会话 2026-11-01 告知），以新口径为准；spec 是否已同步由编排会话负责。
- spec 2.1 没写的由本简报补：首页一页 14 篇里补位的标法（§3.5）、看过还看了的展示位置与空时不出（§3.6）、阅读历史的分组与入口（§3.7、§3.10）、隐私政策的范围（§3.9）。
