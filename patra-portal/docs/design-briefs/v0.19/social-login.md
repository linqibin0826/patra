**目标**：读者能用 Google、GitHub 或 ORCID 账号登录 Patra，首次登录验证邮箱后账号就建好；已有账号的人能在设置页绑定、解绑；任何一步被拒时，读者都知道发生了什么、下一步做什么。

## 0. 策略与定位

- **第三方只是登录方式，不是身份展示。** 头像、昵称不导入，公开主页不显示绑定了什么（spec 第 3 节 B、D）。账号标识只在本人的设置页和补填页出现。
- **不画对方的页面。** 跳到第三方之后的页面归对方，画板只画「正在前往 GitHub…」和回来之后的结果，不模仿对方的授权页。
- **永不按邮箱合并，界面要说出来。** 撞车时明确告诉读者「没有建新账号，也没有改动原账号」，再给下一步：先用原来的方式登录，再到设置页绑定（决策 D）。
- **再认证只认密码，界面要解释为什么。** 没有密码的人看不到填不了的密码框，看到的是原因、要发生什么、之后怎么继续（决策 E）。
- **三家同等显著。** 同样大小、同样底色、同样字重，顺序 Google、GitHub、ORCID（spec 2.1 的顺序）。
- **入口按配置显示。** 线上公网和本机开发显示，tailnet 不显示；不显示时入口整块不渲染，副文案也退回原样，设置页隐藏绑定、保留解绑。
- **渐进式披露**：
  - 默认层：入口按钮、表单字段；卡片里每家的状态和账号标识。
  - 深数据层：卡片里的绑定日期（一行小字）；撞车、不能解绑、为什么要设密码这些解释只在碰到时才出现。登录页不放 ORCID 介绍；设置页 ORCID 未绑定那一行有一句短说明。

**流程闭环**（画板能从头点到尾）：

1. 小陈：登录页点「用 GitHub 账号登录」→「正在前往 GitHub…」→ 补填页（用户名已预填）→ 发送验证码 → 输入验证码 → 建好账号，回到来源页，`注册成功，已登录`。
2. 撞车：补填页填已注册的邮箱 → 撞车块 → 「去登录」→ 登录页，邮箱已带过去，登录后直接到 `/settings/security`。
3. 老王：设置页点「绑定」→ 再认证 → 去 ORCID → 回到设置页，那一行变成已绑定，`已绑定 ORCID…`。
4. 只有 GitHub 的小陈：想注销或再绑一家 → 「先设置一个密码」弹框 → 发邮件 → 现有重设密码页 → 所有设备下线 → 用新密码登录 → 回来完成操作。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 新读者 | 不想再记一个密码，点一家入口，补两项，填验证码，账号建好 |
| 有账号的读者 | 在设置页绑定一家，以后点一下就进原来的账号 |
| 忘了自己注册过的人 | 第三方登录后填了旧邮箱：被告知已注册，引导回原账号再绑定，不会多出一个账号 |
| 只用第三方的读者 | 做注销、绑定这类敏感操作：先设置密码，知道所有设备会下线 |
| 手滑或反悔的人 | 在对方网站点了取消：回到发起页，一句中性的提示，不算出错 |
| 走内网访问的开发者 | 只看到邮箱密码登录；设置页能解绑，要绑定就去公网地址 |

## 2. 页面清单与跳转

### 2.1 路由

| 屏 | 路由 | 布局 | 需登录 | 归属 |
|---|---|---|---|---|
| 登录页（改） | `/login` | 专注 | 否 | PAP-186 |
| 注册页（改） | `/register` | 专注 | 否 | PAP-186 |
| 补填页 + 验证码页（新） | `/register/complete` | 专注 | 否（要 `patra_oauth_ticket`） | PAP-186 |
| 设置 · 安全（改：新卡片） | `/settings/security` | 设置 | 是 | PAP-187 |
| 再认证对话框（改：加分支） | 任一敏感操作之上 | 对话框 | 是 | PAP-187 |
| 隐私政策（改：§6.3） | `/privacy` | 普通 | 否 | PAP-186 |

补填和验证码是同一个路由的两步：`GET /auth/oauth/registration` 的 `pendingCode` 有值时刷新页面直接回到验证码这一步。发起和回调路由见后端工程设计第 3 节。

### 2.2 跳转规则

1. **发起**：入口按钮带上当前 `next`（沿用 v0.8 规则）。回到页面时不丢 `next`。
2. **老用户成功**：回 `next`，`已登录`。`PENDING_DELETION` 不去 `next`，去 `/account/deletion-pending`，和密码登录一样。
3. **新用户**：到 `/register/complete`；`ticket` 只放 Cookie，不进地址栏。
4. **注册页上点入口**：如果这个第三方账号已有 Patra 账号，直接登录，`已登录`，不提示。
5. **失败**：回到发起的页面（`/login` 或 `/register`），提示条在第三方入口上方。提示读完用 `history.replaceState` 清掉地址栏参数，刷新后不再出现。
6. **撞车「去登录」**：到 `/login?next=/settings/security`，邮箱经 `auth-handoff` 带过去（不进查询参数），焦点在密码框。
7. **绑定回来**：回 `/settings/security`，结果显示在卡片里（成功是 toast），读完清掉地址栏参数。
8. **绑定回调时会话没了（401）**：走现有 `useCommonFailureRedirect`，去登录页。

### 2.3 入口显示条件

门户用一个服务端配置决定是否显示第三方入口，不写死域名判断：线上公网（`patra.linqibin.dev`）和本机开发（`localhost:4000`）显示，tailnet 地址不显示。用户 2026-11-04 拍板，细化决策 G。画板的 Tweak `host` 只分显示和不显示两种。

## 3. 每屏内容

### 3.1 登录页、注册页（显示入口）

自上而下：

1. 标题 `登录` / `注册`（不变）。
2. 副文案：`用第三方账号，或邮箱和密码登录 Patra` / `用第三方账号注册，或用邮箱建一个 Patra 账号`。
3. 提示条位置（从第三方回来时用）。
4. **三家入口**（`ProviderButton`）：`用 Google 账号登录`、`用 GitHub 账号登录`、`用 ORCID 账号登录`；注册页把「登录」换成「注册」。
5. 分隔线：`或用邮箱登录` / `或用邮箱注册`。
6. 邮箱表单（字段、校验、互跳链接全部不变）。

**按钮状态**：

- 默认：白底（`bg-elevated`）、`border-strong` 描边、胶囊圆角、高 46（手机 48）；左边 20px 官方标识，文字居中，`text-base` 中粗。
- 悬停：描边换 `border-hover` + `shadow-xs`，**不换底色**（Google 的 G 只能放在白底上）。禁用时只淡文字，标识不变淡（G 不能改色）。
- 点击后：被点的按钮文字换成 `正在前往 GitHub…`，另外两个 `aria-disabled`，防重复发起。
- 从对方网站后退回来（浏览器后退缓存）：`pageshow` 时恢复默认态。

**放在表单上面**（对比板 `Entries`，决定见 §8 第 1 条）。焦点沿用现状：进入页面时在邮箱框。

### 3.2 登录页、注册页（不显示入口：tailnet）

和今天完全一样：没有入口、没有分隔线，副文案是原来的 `用邮箱和密码登录 Patra` / `用邮箱建一个 Patra 账号`。不解释为什么没有。

### 3.3 补填页

外壳 `AuthShell`，「返回」回登录页（不用确认：记录 30 分钟后自己过期）。

1. 标题 `还差一步`；副文案 `第一次用 GitHub 账号登录 Patra，填好用户名和邮箱就能建好账号。`
2. **已确认的账号**（一小块）：标识 + `已确认你的 GitHub 账号` + 账号标识（等宽）。让读者确认没点错家。
3. **用户名**：沿用 `UsernameField` 的规则和校验，常驻提示同注册页。`suggestedUsername` 有值时预填，并多一行 `已按你的 GitHub 用户名预填，可以改。`
4. **邮箱**：`suggestedEmail` 有值时预填，都可以改。提示随来源变：

| 来源 | 邮箱预填 | 提示 |
|---|---|---|
| GitHub 有公开邮箱 | 有 | `我们会发验证码到这个邮箱。已按你的 GitHub 公开邮箱预填，可以改。` |
| GitHub 没公开邮箱 | 无 | `你的 GitHub 没有公开邮箱，请填一个常用的。我们会发验证码到这个邮箱。` |
| Google | 有 | `我们会发验证码到这个邮箱。已按你的 Google 账号预填，可以改。` |
| ORCID | 无 | `ORCID 不提供邮箱，请填一个常用的。我们会发验证码到这个邮箱。` |

5. 按钮 `发送验证码`，进行中 `发送中…`，字段只读。
6. 底部一句 `已经有 Patra 账号？先登录，再到「设置 › 安全」绑定 GitHub。`（撞车块出现时隐藏，免得说两遍）。

用户名的预填来自后端（`suggestedUsername`）：GitHub 的 `login` 转小写，过不了规则就留空，这时只有输入框，没有「已预填」那行。Google、ORCID 不预填用户名。

**撞车块**（`ALREADY_REGISTERED`，在邮箱字段下方，邮箱框变红）：

> **这个邮箱已经注册过 Patra。**我们没有建新账号，也没有改动原账号。
>
> 如果是你的账号：先用原来的方式登录，再到「设置 › 安全」绑定 GitHub。以后就能用 GitHub 账号登录它了。
>
> [去登录]　换一个邮箱

`amber` 底（`status-warning-bg`），不用红底：这不是读者犯的错。`换一个邮箱` 清空邮箱框并聚焦。改邮箱时撞车块消失。

### 3.4 验证码页

1. 标题 `输入验证码`；副文案 `验证码已发到 chen.yu@example.com，10 分钟内有效。验证通过后账号才会建好。`
2. **一个输入框**（不做六格）：`inputmode="numeric"`、`autocomplete="one-time-code"`、`maxlength=6`，等宽、字距拉开，占位 `000000`。只保留数字，粘贴带空格也能用。
3. 按钮 `完成注册`，进行中 `验证中…`。不自动提交：手机上系统填入验证码后读者自己确认一下。
4. 下方三行小字：`没收到？先看看垃圾邮件。` / 重发 / `改用户名或邮箱（要重新发验证码）`。
5. **重发**：沿用 `resendWaitMessage`，`已发送 · 52 秒后可重发`，到 0 变 `重新发送`。按 `nextResendAt` 倒计时。
6. 「改用户名或邮箱」回补填页，值都保留，已填的验证码清掉。

### 3.5 过期与并发两个结果页

沿用 `StateIcon` + 标题 + 正文 + 主按钮。

- **待补填记录过期**（`ticket` `INVALID`）：`这次注册已过期` / `等得太久了，账号没有建。请重新用 GitHub 账号登录，再填一次。` / `回到登录页`。
- **两个标签页并发**（`PROVIDER_ACCOUNT_TAKEN`）：`这个账号已经建好了` / `你的 GitHub 账号刚刚完成了注册，可能是在另一个标签页。重新用它登录就行。` / `回到登录页`。

### 3.6 设置 · 安全：「登录方式」卡片

放在安全页**最上面**，下面依次是修改密码（有密码时才有）、登录设备。

- 标题 `登录方式`。说明：
  - 有密码：`这些方式都能登录这个账号。绑定和解绑要先验证密码，并会发一封通知邮件。`
  - 没有密码：`这些方式都能登录这个账号。绑定和解绑要先验证密码，你还没有密码，需要先设置一个。`
- **四行**：邮箱和密码、Google、GitHub、ORCID。

| 行 | 状态 | 第二行 | 操作 |
|---|---|---|---|
| 邮箱和密码 | 有密码 | `已设置` | 无（修改在下一张卡片） |
| 邮箱和密码 | 没有密码 | `还没有设置` | `设置密码`（次按钮） |
| 第三方 | 未绑定 | `未绑定`；ORCID 是 `未绑定 · 科研人员身份标识` | `绑定`（次按钮） |
| 第三方 | 已绑定 | 账号标识 + 下一行 `绑定于 2026-10-21` | `解绑`（危险色文字按钮） |

账号标识：Google 显示邮箱，GitHub 显示 `login`（等宽），ORCID 显示 iD（等宽，链接，新标签页打开 `https://orcid.org/<iD>`）。

- **进行中**：`绑定` 变 `正在前往 GitHub…`，其他操作禁用；`解绑` 变 `解绑中…`。
- **不能解绑**（没有密码且只绑了这一家）：`解绑` 置灰（`aria-disabled` + `aria-describedby`），行内多一句 `这是你现在唯一的登录方式，解绑后就登录不了了。先设置密码，之后可以解绑。`，「设置密码」是文字按钮。
- **邮箱未验证**：卡片顶部 `amber` 提示 `绑定前要先验证邮箱。验证邮件已发到 chen.yu@example.com。` + `重新发送`（沿用 `ResendVerificationButton`），`绑定` 全部置灰。
- **tailnet**：`绑定` 不渲染，`解绑` 照常，卡片底部一句 `要绑定新账号，请到 patra.linqibin.dev 操作。`
- **加载中**：三行骨架；**失败**：`登录方式加载失败` + `重试`。

### 3.7 解绑确认

对话框（手机底部抽屉）。标题 `解绑 GitHub 账号？`；正文 `解绑后，不能再用 GitHub 账号 chenyu-med 登录 Patra。通知邮件会发到 chen.yu@example.com。`；`取消` / `解绑`（危险主按钮）。

顺序：确认 → 再认证（需要时）→ 解绑。没有密码的人**不弹确认**，直接到 §3.8，确认了也做不成。

### 3.8 再认证对话框：没有密码的分支

`withReauth` 收到 `REAUTH_REQUIRED` 时看 `hasPassword`：`true` 走现有密码框，不改；`false` 走这里。注销、改邮箱、踢设备、绑定、解绑都走同一个分支。

**询问态**（桌面 460px，手机底部抽屉）：

- 标题 `先设置一个密码`
- 正文 `这项操作要先验证密码，但你的账号还没有密码。用第三方账号登录不算验证：只要对方网站还登录着，别人坐到你的电脑前也能通过。`
- 三步：
  1. `我们发一封邮件到 chen.yu@example.com，点邮件里的链接设置密码。`
  2. `设置后，所有设备都会退出登录，包括这台。`
  3. `用新密码重新登录，再回来完成刚才的操作。`
- 按钮 `取消` / `发送设置邮件`（进行中 `发送中…`）

从卡片里的「设置密码」打开时，标题是 `设置密码`，正文换成 `有了密码，就能用邮箱和密码登录，也能完成绑定、解绑、注销这类要验证身份的操作。`，第 3 步换成 `用新密码或第三方账号重新登录。`

**已发送态**（同一个对话框）：信封图标 + `查看你的邮箱` + `设置密码的邮件已发到 chen.yu@example.com，链接 1 小时内有效。设置好之后所有设备会退出登录，用新密码重新登录就能继续。` + `没收到？先看看垃圾邮件。` + 重发倒计时 + `好的`。

- 关闭对话框时原操作中止，不报错（与密码框的取消一致）。
- 直接调现有 `POST /auth/password/forgot`，用账号邮箱，不跳 `/forgot-password`，少一步。
- 之后的重设密码页（`/reset-password`）和登录页提示 `密码已重设，请用新密码登录` 都不改。

### 4.2 补填页（画板 `Complete`）

| 状态 ID | Tweak | 后端结果 | 位置 | 文案 |
|---|---|---|---|---|

## 5. 三家标识的用法

标识文件来自各家官方，不重画、不改色、不拉伸。**三家的标识是全站唯一不走 token 的颜色。**

| | 文件来源 | 规定 |
|---|---|---|
| Google | [`signin-assets.zip`](https://developers.google.com/static/identity/images/signin-assets.zip)（[规范](https://developers.google.com/identity/branding-guidelines)） | 必须用彩色 G，放在白底上，不能单独用标识不带边框和文字；文字用「Sign in / Sign up / Continue with Google」的本地化；至少和其他入口同等显著 |
| GitHub | [`GitHub_Logos.zip`](https://brand.github.com/GitHub_Logos.zip)（[规范](https://brand.github.com/foundations/logo)）的 `GitHub_Invertocat_Black.svg` | 黑或白，不改比例，不能暗示 GitHub 背书，不比自己的标识显眼 |
| ORCID | [iD 图标](https://orcid.org/assets/vectors/orcid.logo.icon.svg)（[规范](https://info.orcid.org/documentation/integration-guide/orcid-oauth-sign-in-guidelines/)） | 绿色，原样使用，周围留 50% 空白；按钮文字要说清点了会发生什么 |

画布里的 G 是从官方 PNG（`Theme=Light, Show text=No`，@4x）裁出来的，因为画布不支持官方 SVG 里的 `foreignObject`。**前端落地时直接用官方 SVG。**

## 6. 邮件与隐私政策文案

### 6.1 验证码邮件（`registration-code`，版式沿用 v0.12 §3.19 A 类，没有按钮）

- 标题：`你的 Patra 注册验证码`
- 称呼：`{用户名}，你好：`
- 正文：`你正在用 {平台名} 账号注册 Patra。验证码是：`
- 验证码：等宽大字 `483920`
- 下面：`10 分钟内有效。不要把验证码告诉任何人。`
- `如果不是你在注册 Patra，忽略这封邮件，不会有账号被创建。`

### 6.2 绑定、解绑通知（`login-method-linked` / `login-method-unlinked`，B 类）

- 标题：`你绑定了 GitHub 账号` / `你解绑了 GitHub 账号`
- 正文：`你的 Patra 账号绑定了 GitHub 账号 chenyu-med，以后可以用它登录。` / `你的 Patra 账号解绑了 GitHub 账号 chenyu-med，以后不能再用它登录。`
- 安全信息块：时间、设备、IP 与属地（沿用）
- 「不是我」块：`如果不是你本人操作，请立即修改密码，并到安全设置检查登录方式和登录设备。`

### 6.3 隐私政策

「我们收集什么」表格加一行：

| 项目 | 内容 | 用途 |
|---|---|---|
| 第三方账号 | 用 Google、GitHub 或 ORCID 登录时：对方给的账号编号，以及显示用的账号标识（Google 邮箱、GitHub 用户名、ORCID iD）。对方给的邮箱和 GitHub 用户名只用来预填注册表单 | 让你用这个账号登录，并在设置页显示绑定了哪个账号 |

下面加一段：`我们不保存第三方的访问令牌，也不导入头像、昵称。确认身份之后，令牌就丢弃了，Patra 不能替你访问对方的任何内容。解绑后这条记录立即删除；注销到期时一并删除。`

Cookie 表加两行：`patra_oauth_state`（`防止第三方登录被伪造`，10 分钟）、`patra_oauth_ticket`（`第一次用第三方登录时，记住还没填完的注册`，30 分钟）。

| 画板类 | 门户组件 | 说明 |
|---|---|---|
| `.pt-sso-btn` | 新 `ProviderButton`（`src/components/auth/`） | 真 `<a>`：整页跳到 `/api/auth/oauth/{provider}/start` |
| `.pt-sso-or` | 同一组件文件里的分隔线 | |
| `.pt-sso-who`、`.pt-sso-clash`、`.pt-otp` | `RegistrationForm` 内 | 撞车块用 `FormAlert` 的 `warning` 语气 + 操作区 |
| `.pt-lm-*` | 新 `LoginMethodsCard`、`LoginMethodRow`（`src/components/settings/security/`） | 外层用现有 `SettingsCard` |
| `.pt-steps` | `ReauthDialog` 的新分支 | 按 `hasPassword` 选内容，密码流程一行不动 |

要留意的点：

1. **登录入口和「绑定」看着像、走法不同。** 入口是 `<a>` 整页跳转；「绑定」是 `<button>`，经 `withReauth` 调 `POST /me/login-methods/{provider}/link`，拿到 `authorizationUrl` 后 `location.assign`（后端 §2.4），这样 `REAUTH_REQUIRED` 才能回到弹框。
2. **白底只给按钮和标识方块。** `bg-elevated` 就是纯白；不要用 `btnSecondary` 的 `paper-50`，Google 不允许 G 放在其他浅色上。
3. **焦点**：撞车时焦点到撞车块的「去登录」；验证码错时回输入框并全选；对话框沿用 `Dialog` 的焦点管理，询问态初始焦点在「发送设置邮件」。
4. **读屏**：提示条沿用 `FormAlert` 的 `role`；倒计时只在变成可重发时朗读，不要每秒读；禁用的「解绑」用 `aria-describedby` 指向说明。
5. **标识的替代文本**：`alt=""`，平台名已经在按钮文字里。
6. **卡片结果放在卡片内**：读完地址栏参数就清，刷新后不重复提示。
7. **解绑确认的顺序**：见 §3.7；`hasPassword=false` 时直接走 §3.8。
8. **`formatDate` 显示 `linkedAt`**：`2026-10-21`，到日。
9. **本版要改的旧文案**（默认用户有密码的地方）：`DeleteAccountDialog` 两处 `用邮箱和密码登录` 改成 `重新登录`，归 PAP-187；邮件模板归后端，见 §9。

## 8. 设计决定

用户 2026-11-04 全部按以下方案定稿。每条都有画板可以对照。

1. **入口放在表单上面**（`Entries`，A）。注册页有 4 个字段，放下面（B）手机第一屏只露出半个 Google 按钮，这版的主角等于藏起来了。代价：老用户的密码框下移 200px 左右，但手机上仍在第一屏。C（一行三个标识）最省地方，但 Google 不允许标识不带文字，也说不清是登录还是注册，不采用。
2. **按钮用门户 token，标识用官方原样**（`Providers`，方案 1）。Google 自定义按钮规定 `#747775` 描边和 Google Sans，这里用 `border-strong` 和门户字体，是有意的偏离：`#747775` 在纸色页面上比门户其他描边都重，三个按钮连在一起很抢眼（对比板方案 2），Google Sans 又没有中文字形，中文读者看到的还是系统字体。硬规则都守住了：彩色 G、白底、带文字、同等显著。
3. **ORCID 显示裸 iD 并链到记录页**。ORCID 建议显示完整网址，但手机上放不下一行；和 Google 邮箱、GitHub `login` 对齐也更好读。
4. **验证码用一个输入框**。粘贴、系统自动填入、读屏都简单，也是门户现有字段的样子。六格拼接只是好看，边界情况多。
5. **卡片加一行「邮箱和密码」**。规则是「没有密码且只剩这一种时不能解绑」，读者要看到密码这一行才明白为什么。没有别的新数据，只用 `hasPassword`。
6. **「登录方式」放在安全页最上面**。它是这一页里范围最大的概念，修改密码是其中一行的细节。
7. **没有密码时在对话框里直接发邮件**，不跳 `/forgot-password`。少填一次邮箱，也不离开正在做的事。走的还是决策 E 说的找回密码流程。

## 9. 交给后续 Issue 的事

用户 2026-11-04 已定，这里只记去向。

1. **门户（PAP-186）**：入口显示条件按 §2.3 做成服务端配置。
2. **门户（PAP-187）**：`DeleteAccountDialog` 两处 `用邮箱和密码登录` 改成 `重新登录`。
3. **后端（PAP-184）**：`account-deletion-requested`、`account-deletion-reminder` 的 HTML 和文本模板，`用这个邮箱和密码登录` 改成 `重新登录`，否则只用第三方的人会以为取消不了注销。设置密码的邮件怎么写由后端会话一并处理：对从没有过密码的人，「重设密码」有点怪，建议凭据不存在时写「设置密码」。

**规则后果，不用改**：只用第三方的人想再绑一家，也要先设置密码（决策 E），得发邮件、设密码、全部设备下线、重新登录、再绑定。界面已解释清楚。
