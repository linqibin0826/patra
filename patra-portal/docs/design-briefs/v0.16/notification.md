# 通知中心 — Design Brief

> v0.16 唯一一份设计简报。设计系统与代码库已 onboard，本简报只交增量：提醒页沿用 PAP-127 方向 A（`docs/patra/specs/2026-10-28-notification-inbox-redesign-design.md`），设置页沿用 v0.12 简报（`../v0.12/user-center.md`）的设置外壳与即时保存，邮件沿用 identity 的邮件骨架（`patra-api/patra-identity/patra-identity-infra/src/main/resources/mail/html/fragments/layout.html`）。
> **产品定义以 release spec 为准**：`docs/patra/release-specs/v0.16-notification.md` 2.1 节与第 4 节决策 F、H、J。本简报只定页面、邮件、状态与文案；两者不一致时以 spec 为准，缺口列在 §10。
> **接口契约以后端工程 spec 为准**：PAP-142（偏好与退订）、PAP-143（站内提醒）、PAP-144（有帮助提醒）、PAP-146（提醒邮件）。页面与邮件对它们的要求列在附录 A。
> 可交互画板：Claude Design 画布「v0.16 通知中心」<https://claude.ai/artifact/8Ff2pvLjosq8sfdRV4PDBP>（桌面 1440 / 邮件 600 + 移动 375，5 页 11 块，场景用 Tweaks 切换）。快照 `docs/patra/design/snapshots/2026-10-30-notification-hifi.zip`（2026-10-30 用户确认后从画布读回）。
> 同版相关：Linear PAP-140（本简报 + 画板）→ PAP-147（提醒改接通知服务 + 有帮助标签）/ PAP-148（通知设置页 + 退订落地页）/ PAP-149（实时推送）；后端 PAP-146 照 §3.7–§3.11 实现邮件。

**目标**：医生和科研人员不在站上时，也能通过邮件知道有人回复或 @ 了自己，点邮件直接回到那条讨论；每类提醒能选不发、离站时逐条、每日汇总，在邮件里一键退订；自己的评论和投稿经验被点「有帮助」时，站内收到按天合并的一条提醒。

## 0. 策略与定位

- **邮件只负责把人拉回来。** 邮件里放够判断「要不要现在回去」的信息（谁、在哪、说了什么），然后一个按钮回到那一楼。不在邮件里回复、不做邮件里的点赞，也不追踪打开和点击（spec 第 3 节 H）。
- **一封邮件只属于一类。** 「回复我的」「@ 我的」「每日汇总」各是一类：逐条邮件只在同一类里合并，汇总邮件自成一类。这样底部的「退订这类邮件」和邮件头里的一键退订都说得清退的是什么（§3.9、§10 第 1、2 条）。
- **站内照常，邮件是附加的。** 关掉邮件、退订，都不影响站内提醒；设置页、退订页、邮件页脚每处都写这一句。
- **有帮助是安静的信号。** 只在站内、按天合并、不进铃铛红点；作者自己的私人提醒写出最近一位点的人（「周敏 等 2 人」），公开页面仍然只显示数字（v0.15 简报 §3.1「不显示谁点了」不变，两处是有意的区别）。
- **安全邮件不受任何设置影响。** 13 类账号安全邮件不进偏好、不带退订（spec 2.1），设置页与退订页都明说。
- **没有新的实时界面。** 推送只让铃铛和标签上的数字自己变；开着提醒页时新条目出现在最上面，浅陶土底 2 秒淡出（§3.4）。
- **渐进式披露**：
  - 默认层：铃铛数字、提醒页三个标签与列表、设置页两类三档、邮件里的一条摘录和一个按钮。
  - 深数据层：无新增。设置不做按讨论静音、免打扰时段、自选汇总时间（spec 第 3 节 F）。
- **验证场景**（spec 第 1 节，画板逐条可走；A = 陈宇，B = 王立，C = 林知远，D = 周敏）：
  1. 陈宇在文献页发了根评论后离开，王立回复了他 → 10 分钟后陈宇收到邮件（`Mail`「一条回复」），点「查看并回复」落到那一楼。
  2. 陈宇先在站内看了这条提醒 → 不发邮件（界面上没有痕迹；设置页「离站时逐条」的说明写了「在站内看过的不发」）。
  3. 陈宇把「@ 我的」改成每日汇总（`Notify`「回复逐条 · @ 每日汇总」），林知远、周敏各 @ 他一次 → 第二天 8:00 收到一封汇总（`Digest`「只有 @（回复是逐条）」）。
  4. 林知远、周敏先后给陈宇的投稿经验点「有帮助」→ 提醒页「有帮助」标签里一条「周敏 等 2 人觉得你的投稿经验有帮助」（`Inbox` 默认）。
  5. 陈宇点邮件底部「退订这类邮件」→ 退订页（`Unsub`）点「退订这类邮件」，不用登录 → 设置页对应一类显示为「关」（`Notify`「@ 我的已在邮件里退订」）。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 提了问题就离开的医生 | 第二天在邮箱里看到「王立 回复了你」，读完摘录觉得值得回，点按钮回到那一楼 |
| 讨论很多、不想被打扰的人 | 把「回复我的」改成每日汇总，早上 8 点一封看完；或者直接关掉，只看站内 |
| 只想关掉某类邮件的人 | 在邮件底部点「退订这类邮件」，不登录也能退；落地页上顺手「关闭全部提醒邮件」 |
| 写投稿经验的作者 | 站内「有帮助」标签里看到「周敏 等 2 人觉得你的投稿经验有帮助」，知道自己写的东西有人用 |
| 邮箱还没验证的新用户 | 设置页顶部提示：验证之前不会收到提醒邮件 |
| 企业邮箱用户 | 安全网关会预先打开邮件里的链接：退订页打开不生效，点按钮才生效（§3.6） |

## 3. 每屏内容

### 3.1 提醒页：第三个标签「有帮助」

- 标签栏：`回复我的 [3]` `@ 我的 [1]` `有帮助 [1]`，每个标签带自己的未读胶囊（`UnreadBadge`，0 不显示）。窄屏三个标签等分一行。
- 列表、分组（今天 / 昨天 / 更早）、「加载更多提醒」、「提醒保留 5 个月。」都与另外两个标签相同。
- **「全部标为已读」三个标签一起标**（含有帮助）；按钮在三个未读数之和为 0 时置灰。理由：用户点的是「全部」，留下有帮助的未读会让按钮点完还亮着。
- 空状态（`NotificationEmpty` 第三份）：拇指图标 48px，`还没有收到「有帮助」` / `别人觉得你的评论或投稿经验有帮助时，同一条内容每天合成一条，出现在这里。`
- 加载中、取不到（`提醒暂时打不开` + 重试）沿用现有。

### 3.2 有帮助的合并条目

结构同提醒行的三层（头像 · 谁做了什么 · 时间 / 正文 / 在哪），只有内容不同：

| 层 | 写什么 | 例 |
|---|---|---|
| 头像 | 最近一位点的人的头像（与名字是同一个人）；2 人起右下角压一个人数角标 `+1`（等宽 10px，`paper-50` 底、`border-default` 描边） | 周敏的头像 + `+1` |
| 上行 | 名字加粗；`等 N 人` 与动作用常规字重；时间靠右 | **周敏** 等 2 人觉得你的投稿经验有帮助 · 14:05 |
| 正文 | **你自己那条内容**的摘录（点的人没写字，没有这一行就不知道是哪条），两行截断，`fg-2`（不随未读加深） | 第二轮小修后编辑直接接收…… |
| 在哪 | 同回复行：文献标题，或「你的投稿经验 · 期刊 · 投稿月份」 | 你的投稿经验 · J Am Heart Assoc · 2026 年 3 月投稿 |

- **文案**：1 人 `林知远 觉得你的评论有帮助`；2 人起 `周敏 等 N 人觉得你的投稿经验有帮助`。对象只有两种说法：`评论`（根评论与楼内回复都算）、`投稿经验`。名字与头像都是**最近一位点的人**（§10 第 5 条）。
- **投稿经验没有正文时**，正文行写结果行，同经验列表：`大修 → 录用 · 审稿 6 周`。
- **合并与重新未读**（spec 2.1）：按「被点的那条内容 × 北京时间一天」合成一条。当天再有人点：名字与头像换成这个新的人、人数加一、变回未读、时间改成最新一次、挪到「今天」的最上面（这条是因为新的人点了才重新亮起来的，回来看到的应该是这个人）。第二天再有人点：另起一条，昨天那条不动。有人取消：人数不减，已发的提醒不撤回。
- **点开**：去你的那条内容（评论永久链接 `?comment=`，或经验页 `/posts/[id]`），同时标为已读。
- 最近一位点的人后来注销：名字写 `已注销用户`、中性头像，仍计入人数。内容被删除：这条提醒跟着删（同 PAP-127 规则 ③），未读数同步减。
- 画板 `Inbox` 的 Tweak「版式 › helpfulFace」可切另一种头像：`拇指图标`（陶土浅底圆里放 `ThumbsUp`）。推荐头像 + 角标：三个标签的行长得一样，「谁」一眼可见。

### 3.3 铃铛与未读数

- 铃铛红点与账号菜单「提醒」后的数字 = 「回复我的」+「@ 我的」的未读数，**不含有帮助**（spec 2.1）。有帮助只在自己的标签上显示未读数。
- 结果：铃铛可能是 0、有帮助标签却是 2。这是有意的：有帮助不需要用户马上回去。
- 窄屏菜单里的「提醒」按钮同上（`Nav` 不改）。

### 3.4 实时推送（无新界面）

- 推送只带三个未读数（spec 决策 I）。收到后：铃铛、菜单、三个标签的数字立即更新，不弹 toast、不播报。
- **正开着提醒页**：当前标签的列表重新取第一页；新出现的条目在最上面，浅陶土底（`clay-50`）2 秒淡出到透明，「减少动态效果」下不做底色。已加载的后几页不丢。画板 `Inbox` Tweak「场景 › push」可看三种：新回复、当天又有人点有帮助、第二天又有人点。
- 断线退回 60 秒轮询、标签页切到后台断开、401 去登录，都没有界面变化（与现在相同）。

### 3.5 设置 › 通知

页面结构同隐私页：设置外壳（h1「设置」+ @用户名 + 查看我的主页）、左侧分区导航、右侧卡片列。

1. **邮箱未验证时**，顶部警示条（同隐私页）：`你的邮箱还没验证：验证之前，不论下面怎么设置，都不会给你发提醒邮件。` + 文字按钮 `重新发送验证邮件`（复用 `ResendVerificationButton`）。
2. **收件地址一行**：`提醒邮件发到 chen.yu@example.com` + 链接 `更改邮箱`（→ `/settings/account#email`）。邮箱用 `/auth/me` 的，不另取。
3. **「回复我的」卡片**：标题 + 一行说明 `有人回复你的评论、评论你的投稿经验时`；三档单选（`RadioRow`，同隐私页）：

| 档 | 标题 | 说明 |
|---|---|---|
| `OFF` | 关 | 只在站内提醒，不发邮件。 |
| `INSTANT` | 离站时逐条 `默认` | 你不在 Patra 上时，提醒 10 分钟后仍未读就发一封；同一时间到的几条合成一封；在站内看过的不发。 |
| `DIGEST` | 每日汇总 | 每天早上 8:00（北京时间）发一封，列出过去 24 小时里还没读的；都读过了就不发。 |

4. **「@ 我的」卡片**：说明 `有人在评论里 @ 你时`；三档同上。
5. **「有帮助」卡片**：说明 `别人觉得你的评论或投稿经验有帮助时`；没有控件，一枚灰色胶囊「铃铛图标 + `只在站内`」（lucide `Bell`）+ `同一条内容每天合成一条提醒，在提醒页的「有帮助」里看；不计入铃铛上的数字，也不发邮件。`
6. **账号安全邮件说明块**（`paper-100` 底、`border-subtle` 描边、锁图标，不是卡片）：`账号安全邮件总会发送` / `验证邮箱、找回密码、更改邮箱、新设备登录、注销账号等邮件关系到账号安全，不能在这里关闭，也不带退订链接。`

- **保存**：改了立即保存这一类（同隐私页），卡片标题右侧 `保存中…` → `✓ 已保存`（2 秒后淡出）/ `没有保存成功，请重试`（控件退回原值）。不出 toast。两类分别保存，互不影响。
- **从邮件退订后**：对应一类显示为「关」，不加额外标记（spec 验证场景 5）。
- **加载中**：两张卡片的骨架；**取不到**（通知服务不可用）：一张卡片 `通知设置暂时打不开` / `请稍后再试。账号安全邮件不受影响。` + 重试。其余分区照常。
- 「默认」两个字只是标在出厂档位旁的说明，选了别的档也一直显示。

### 3.6 退订落地页（免登录）

版式同现有邮件落地页（`AuthShell`：左表单、右墨色叶脉面板，窄屏只有左栏）。**打开页面不改任何东西**：只读一次链接信息，点按钮才退订。理由：企业邮箱安全网关会预先打开邮件里的链接，打开即生效会被动退订；现有验证邮箱等四个落地页也是这个做法。邮件客户端自带的一键退订（RFC 8058 的 POST）仍是直接生效，不经过这一页。

| 状态 ID | 何时 | 内容 |
|---|---|---|
| `unsub.reading` | 读链接信息 | 标题、说明、地址表、按钮的骨架 |
| `unsub.ready` | 链接有效、这一类还开着 | h1 `退订提醒邮件` / `退订后不再给这个地址发这类邮件，站内提醒照常。`；两行信息表：`地址` `c***@example.com`（脱敏写法同 v0.12 C 类邮件）、`邮件` `「@ 我的」提醒 · 离站时逐条`；主按钮 `退订这类邮件`（汇总邮件是 `退订每日汇总`）；文字按钮 `关闭全部提醒邮件`（其余都已关闭时不出）；页脚 `账号安全邮件（验证邮箱、找回密码等）不受影响，也不能退订。` |
| `unsub.submitting` | 点了按钮 | 按钮 `退订中…`，两个按钮都不能再点 |
| `unsub.done.type` | 退订成功 | 绿色对勾；h1 `已退订「@ 我的」提醒邮件`；说明按类写（见下）；次按钮 `同时关闭其余提醒邮件`（其余都已关闭时不出）；次按钮 `去通知设置`（未登录写 `登录后去通知设置`）；页脚 `点错了？登录后在通知设置里改回来。` |
| `unsub.done.all` | 关闭全部成功 | h1 `已关闭全部提醒邮件` / `回复和 @ 都不再给这个地址发邮件，提醒页里照常能看到。账号安全邮件不受影响。`；`去通知设置`；页脚 `想重新收提醒邮件，登录后到通知设置里打开。` |
| `unsub.already` | 打开时这一类已经是关 | 同 `done.type`，h1 改为 `「@ 我的」提醒邮件已经退订过了` |
| `unsub.invalid` | 令牌不对、缺失、账号已注销 | 红色感叹号；h1 `退订链接无效` / `链接可能不完整（有的邮件客户端会截断长链接），或者对应的账号已经注销。登录后可以在通知设置里关闭提醒邮件。`；`登录后去通知设置` / `去通知设置` |
| `unsub.error` | 提交时网络或服务错误 | 回到 `ready`，信息表下方红色提示条 `暂时没能退订，请稍后再试。` |

- 各类退订成功的说明：回复 `以后有人回复你、评论你的投稿经验，不再给这个地址发邮件；提醒页里照常能看到。`；@ `以后有人在评论里 @ 你，不再给这个地址发邮件；提醒页里照常能看到。`；每日汇总 `「回复我的」「@ 我的」都改为不发邮件，提醒页里照常能看到。`（只有一类在汇总时只写那一类，另一类写「仍是离站时逐条」）。
- **不做免登录的「重新订阅」**：改回来要登录（spec 只要求退订免登录；免登录改回会让拿到链接的人反复开关）。
- 带着登录状态打开：页面照样按令牌工作，不看当前登录的是谁（令牌属于谁就退谁），只影响「去通知设置」的写法。
- 页面 `robots: noindex`，标题 `退订提醒邮件 · Patra`。

### 3.7 提醒邮件共用骨架

照 identity 的 `layout.html`，**不另做一套**：纸色底、600px 卡片、刊头（字标 + 竖线 + `医学文献门户`，右上邮件类别）、栏目小标（陶土竖条 + 等宽小字）、衬线 h1、墨色版权页、卡片外一句「为什么收到」。table 布局、行内样式、系统字体栈；窄屏增强沿用 `@media (max-width: 520px)` 那一组（外边距 16px 8px、内边距 20px、h1 26px、按钮占满一行），深色模式沿用 `p-*` 类。

| 位置 | 提醒邮件写什么 | 安全邮件现在写什么 |
|---|---|---|
| 刊头右上类别 | `讨论提醒` | `账号通知` |
| 栏目小标 | `回复 · REPLY` / `@ 提及 · MENTION` / `每日汇总 · 10 月 31 日` | `邮箱验证 · VERIFY EMAIL` 等 |
| 版权页第二行 | `此邮件由 Patra 系统自动发出，直接回复不会出现在讨论里。` | `此邮件由 Patra 系统自动发出，请勿回复。` |
| 卡片外一句 | `你收到这封邮件，是因为你把「回复我的」设为离站时逐条发送。退订这类邮件 · 通知设置`（两个是链接，`clay-700` 下划线） | 纯文本，无链接 |

- **新增块**：
  - **摘录块**（单条邮件）：`paper-200`（`#f1eadc`）底、8px 圆角、内边距 18px 20px；第一行 `王立 · 10 月 30 日 15:02`（13px，名字 `ink-900` 加粗），第二行摘录 15px `ink-900` 行高 1.75。深色模式补一条 `.p-quote { background: #292524 !important; }`。
  - **列表块**（多条合一、汇总）：上边 1px `ink-900` 实线，条目之间 1px `paper-300` 分隔；每条四行：`名字 动作 ……… 时间`（14px / 时间等宽 12px 靠右）、摘录（15px）、在哪（13px `ink-600`）、`查看并回复 →`（14px `clay-700` 文字链接）。
  - **@ 的名字**在摘录里用 `clay-700`、字重 500。
- **按钮**：主按钮沿用 `button` 片段（陶土药丸），单条写 `查看并回复 →`，多条合一与汇总写 `打开提醒页 →`；不带有效期小字。
- **预览文字**（preheader）：正文最前面一段隐藏文字，收件箱列表里显示：单条是摘录前 60 字，多条与汇总是 `第一条的名字：摘录…`。
- **时间**：一律写绝对时间（北京时间），邮件常常隔很久才打开。单条 `10 月 30 日 15:02`；多条合一只写 `15:02`（同一封里都在这十几分钟内）；汇总 `10 月 30 日 15:02`。
- **名字**：发送那一刻按 user_id 现查（决策 F），写显示名；匿名经验的作者写 `匿名作者`，注销的写 `已注销用户`。摘录里的 `<@ID>` 同样换成当前名字。
- **截断**：单条摘录 ≤ 300 字；多条合一与汇总每条 ≤ 140 字；文献标题单条全写（超过 200 字截断），列表里 ≤ 64 字；截断处加 `…`。邮件客户端不认 `line-clamp`，截断只能在服务端做。

### 3.8 离站时逐条：单条

| 类型 | 主题 | h1 | 「在哪」小标 + 内容 |
|---|---|---|---|
| 回复了你的评论 | `王立 回复了你的评论` | `王立 回复了你` | `文献讨论` + 文献标题（衬线 17px） |
| 评论了你的投稿经验 | `林知远 评论了你的投稿经验` | `林知远 评论了你的投稿经验` | `你的投稿经验` + `J Am Heart Assoc · 2026 年 3 月投稿 · 大修 → 录用` |
| @ 了你 | `林知远 在评论里 @ 了你` | `林知远 在评论里 @ 了你` | `文献讨论` 或 `投稿经验讨论` + 标题 |

- 顺序：栏目小标 → h1 → 在哪 → 摘录块 → `查看并回复 →`（去评论永久链接，同站内提醒的去处）→ 版权页 → 卡片外一句。
- 链接一律是门户的绝对地址，不改写、不加追踪参数。

### 3.9 离站时逐条：到点的几条合成一封

- 同一类里、同一次到点的几条合成一封；**回复与 @ 不混在一封里**（§10 第 1 条）。
- 主题：`3 条新回复：王立、周敏、林知远`；`2 条评论 @ 了你：林知远、周敏`（名字最多写 3 个，多了写 `王立、周敏等 5 人`）。
- h1 `3 条新回复` / `2 条评论 @ 了你`；引导句 `你不在 Patra 上的这段时间，有 3 条回复还没看。`；列表块按时间先后；底部主按钮 `打开提醒页 →`（去对应标签）。
- 合并的上限：一封最多列 10 条，其余写 `还有 N 条没有列出，到提醒页查看。`（同汇总）。

### 3.10 每日汇总

- 北京时间每天 8:00；只列过去 24 小时（前一天 8:00 到当天 8:00）里**发送时仍未读**的回复和 @；一条都没有就不发（spec 2.1）。
- 只包括设为「每日汇总」的类型：两类都是汇总时合成**一封**，分两节；只有一类时只有那一节。
- 主题：`每日汇总：5 条未读的回复和 @（10 月 31 日）`；只有 @ 时 `每日汇总：2 条未读的 @（10 月 31 日）`。
- 栏目小标 `每日汇总 · 10 月 31 日`；h1 `过去 24 小时有 5 条未读`（只有 @ 时 `过去 24 小时有 2 条 @ 没看`）；引导句 `10 月 30 日 08:00 到 10 月 31 日 08:00（北京时间）之间，下面这些提醒你还没看过；在站内看过的不会列在这里。`
- 两节：`回复我的 · 3 条`、`@ 我的 · 2 条`（等宽小标，下面 1px `ink-900` 线）；每节新的在前；列表块同 §3.7。
- 超过 10 条：先列回复再列 @，合计列 10 条，其余 `还有 4 条没有列出（回复 2 条、@ 2 条），到提醒页查看。`
- 底部 `打开提醒页 →`；卡片外一句 `你收到这封邮件，是因为你把「回复我的」「@ 我的」设为每日汇总。退订每日汇总 · 通知设置`。

### 3.11 纯文本部分

每封都带纯文本部分（同 identity 的 `mail/text/*.txt`），结构：

```
王立 回复了你

文献讨论：Hydrocortisone, Vitamin C, and Thiamine for the Treatment of Severe Sepsis…
王立 · 10 月 30 日 15:02
不过作者自己也写了需要更多研究来证实这些初步结果，……

查看并回复：https://[门户地址]/papers/…?comment=…

——
你收到这封邮件，是因为你把「回复我的」设为离站时逐条发送。
退订这类邮件：[退订落地页地址]
通知设置：https://[门户地址]/settings/notifications
此邮件由 Patra 系统自动发出，直接回复不会出现在讨论里。
```

多条与汇总：每条一段（`名字 动作 · 时间` / 摘录 / 在哪 / 链接），段之间空一行。

## 7. 约束

- **视觉**：沿用「叶脉 · 学术编辑风」与 token（`patra-portal/src/styles/tokens.css` + `@theme`），不新增颜色与字族。邮件里的颜色一律写十六进制，取自同一套 token（`paper-50/100/200/300/400`、`ink-900/700/600/300`、`clay-600/700`），与 identity 邮件一致。
- **技术**：Next 16 App Router / Tailwind v4 / base-ui(shadcn) / TanStack Query；邮件由通知服务用 Thymeleaf 渲染（PAP-105 / PAP-146）。
- **邮件客户端**：table 布局、行内样式、系统字体栈；不用网页字体、不用 flex / grid、不用 `line-clamp`；图片只有零张（刊头是文字，不放头像，避免外链图片被拦与追踪疑虑）。
- **可访问性**：沿用 v0.12 §7；邮件里的按钮是真链接、文字对比度 ≥ 4.5:1（`ink-600` 在 `paper-50` 上约 7:1）。
- **暗色模式**：门户不做；邮件沿用 identity 已有的 `prefers-color-scheme: dark` 增强，新块补对应类。
- **用词**：界面说「提醒」「提醒邮件」「每日汇总」「退订」「有帮助」；不说「通知推送」「订阅」「点赞」「赞」。
- **本版边界**（设计稿里**不要**出现，spec 第 3 节）：浏览器系统通知、微信、短信、App 推送；「正在输入」与在线状态；系统公告与群发；关注相关的提醒；按讨论静音、免打扰时段、自选汇总时间；退信与投诉处理；打开与点击追踪（追踪像素、改写链接）；注册时的接收邮件勾选；有帮助的邮件；免登录重新订阅。

## 附录 A. 页面与邮件对后端的要求

> 只写页面和邮件需要什么，接口形状由各 Issue 的工程 spec 定。

**PAP-142 偏好与退订**

1. 偏好读写：「回复我的」「@ 我的」各一个档位（`OFF` / `INSTANT` / `DIGEST`），没设过返回默认 `INSTANT`；按类单独保存（前端一次只改一类）。「有帮助」不进偏好。
2. 退订的类别有四个：`REPLY`、`MENTION`、`DIGEST`（= 关掉此刻设为每日汇总的所有类型）、`ALL`（关闭全部提醒邮件）。逐条邮件带 `REPLY` 或 `MENTION`，汇总邮件带 `DIGEST`。
3. 落地页的数据接口（读，不改任何东西，可被预取）：脱敏邮箱、这封邮件的类别、这一类现在是不是已经关了、其余类型还有没有开着邮件（决定出不出「关闭全部」）。令牌无效、缺失、账号已注销都返回同一种「无效」。
4. 落地页的退订（写）：按类别退订、关闭全部；重复退订按成功处理。
5. RFC 8058 一键退订地址收到 POST 直接生效（不经过落地页），类别同第 2 条。

**PAP-143 站内提醒**

6. 未读数分三个：回复、@、有帮助；铃铛用前两个之和。推送（PAP-145）与轮询返回同样三个数。
7. 「全部标为已读」覆盖三个标签。

## 10. 已拍板与 spec 缺口

**已定**（2026-10-30 用户经编排会话拍板：1～4 按推荐，第 5 条为最近一位）：

1. **逐条合并不跨类型**（§3.9）：回复一封、@ 一封。理由：spec 说每封带的一键退订「只关这一类」，混在一封里就说不清退的是哪类。代价：两类同时到点时会收到两封。
2. **每日汇总自成一个退订类别**（§3.6、附录 A 第 2 条）：退订 = 关掉此刻设为汇总的所有类型。理由同上：一封汇总里可能同时有回复和 @。
3. **退订页先确认再生效**（§3.6）：打开不改任何东西，点按钮才退订；邮件客户端自带的一键退订仍直接生效。验证场景 5「不用登录就生效」不受影响，只是多点一下。
4. **邮箱未验证不发提醒邮件**（§3.5 第 1 条）：决策 F 写了发送时查是否已验证，spec 2.1 没明说；设置页顶部提示。
5. **有帮助条目写最近一位点的人**（§3.2）：名字与头像都是最近点的那位；当天再有人点，名字换成新的人、人数加一、重新未读。理由：这条是因为新的人点了才重新亮起来的，用户回来看到的应该是这个人。没有采用：写第一位点的人。

**由我定的设计点**（2026-10-30 用户确认，按画板定稿）：

6. 有帮助条目的第二行放**你自己那条内容**的摘录（§3.2）；头像用「最近一位的人 + 人数角标」（`Inbox` 可切拇指图标对比）。
7. 「全部标为已读」三个标签一起标（§3.1）。
8. 设置页每类一张卡、三档单选、「默认」标在离站时逐条旁；有帮助卡片只有说明（§3.5）。
9. 邮件不放头像、不放图片；时间一律写绝对时间；版权页第二行改为「直接回复不会出现在讨论里」（§3.7）。
10. 单条邮件摘录 300 字、列表每条 140 字、一封最多列 10 条（§3.7、§3.9、§3.10）；站内摘录仍是 120 字。用户在这组与 PAP-128 的建议（逐条邮件 200 字、汇总每条 80 字）之间选了这组，PAP-128 的默认值随之改。
11. 不做免登录重新订阅（§3.6）。

**与 spec 的出入**：无。spec 2.1、验证场景 4 与 D7 已于 2026-10-30 改为最近一位（「D 等 2 人」，C、D 先后点）。
