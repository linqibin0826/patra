# 账号与登录 — Design Brief

> 交给 Claude Design 的迭代简报（v0.8 唯一一份）。设计系统与代码库已 onboard，本简报只交增量。
> 复制本文正文贴入 Claude Design chat（附录 A 是给后端的，可以不带）；附 dev URL（`http://localhost:4000`：首页、移动端全屏菜单、⌘K 快速检索、任一不存在的地址如 `/papers/0`）让它 web capture 保持风格连续。
> 同版相关：release spec `docs/patra/release-specs/v0.8-accounts.md`；Linear PAP-60（本简报）→ PAP-61（Design）/ PAP-63、PAP-64（BE，消费附录 A）/ PAP-67、PAP-68（FE）。

**目标**：访客能在门户**用邮箱注册账号并登录**。导航栏多一个「登录」入口；登录后它变成用户菜单，可以退出登录。匿名浏览文献和期刊保持不变。
**关联**：Linear v0.8 Accounts 项目。本版是用户系统的地基，不交付任何依赖登录的业务功能。

## 0. 策略与定位

- **登录是可选的。** 首页、`/papers`、`/papers/[id]`、`/journals`、`/journals/[id]` 的匿名浏览与 v0.7 完全一致，任何页面都不出现「请先登录」的拦截。
- **本版登录后没有专属功能。** 登录前后页面上唯一的差别在导航栏右上角：「登录」变成用户菜单。所以两个页面的文案**不许诺登录后的好处**，收藏、订阅、个性化、同步这类说法都不能出现。
- **入口克制。** 登录入口只在导航栏一处。桌面只放「登录」，注册入口在登录页里；移动端全屏菜单空间够，多带一行「还没有账号？注册」。
- **登录页和注册页用专注布局。** 不渲染全站导航栏和页脚，页面只做一件事。
- **渐进式披露**：这两页的默认层就是整张表单，没有深数据层。
- **职责边界**（release spec 边界 B / C / G）：不做邮箱验证、找回密码、修改密码、第三方登录、个人资料（昵称 / 头像）、验证码。此外不放「记住我」和服务条款勾选：登录状态默认保持，30 天不活跃才过期；目前也没有条款文档。设计稿里**不要**出现这些入口。
- 闭环：任一页面的导航栏「登录」→ 登录页 →（成功）回到原页面，导航栏右上角变成用户菜单 →「退出登录」→ 仍在原页面，导航栏回到「登录」。

## 1. 用户与场景

| 用户 | 场景 / 任务 |
|------|-----------|
| 新访客 | 浏览文献或期刊时想建一个账号：点导航栏「登录」→ 在登录页点「注册」→ 填邮箱和密码 → 回到刚才的页面，已是登录态 |
| 已有账号的访客 | 回到门户，点「登录」→ 填邮箱和密码 → 回到刚才的页面 |
| 已登录用户 | 用完公共电脑或想换账号，点用户菜单里的「退出登录」 |

## 2. 要设计的屏 / 流程

| 屏 | 路由 | 用途 | 入口 → 出口 |
|----|------|------|------------|
| 登录页 | `/login` | 用邮箱 + 密码登录 | 导航栏「登录」/ 注册页「已有账号？登录」→ 本页 → 成功后回来源页 / 点「注册」去注册页 / 点「返回」回来源页 |
| 注册页 | `/register` | 用邮箱 + 密码建账号，建完即是登录态 | 登录页「还没有账号？注册」/ 移动端菜单「注册」→ 本页 → 成功后回来源页 / 点「登录」去登录页 / 点「返回」回来源页 |
| 导航栏 · 未登录态 | 全站 | 提供登录入口 | 点「登录」→ 登录页 |
| 导航栏 · 登录态 | 全站 | 显示当前账号，提供退出 | 点圆形标识 → 用户菜单 →「退出登录」→ 未登录态 |

**文字流**：在 `/papers?q=GLP-1` 点导航栏「登录」→ `/login?next=%2Fpapers%3Fq%3DGLP-1` →(点「还没有账号？注册」) `/register?next=…` →(填表提交) 回到 `/papers?q=GLP-1`，右下角提示「注册成功，已登录」，导航栏右上角是圆形标识 →(点开，点「退出登录」) 仍在 `/papers?q=GLP-1`，提示「已退出登录」，导航栏回到「登录」。

**跳转规则**（来源页怎么记、成功后去哪）：

1. **来源页记在链接参数里。** 导航栏的「登录」、移动端菜单里的「登录」和「注册」，链接都带 `next=<当前路径 + 查询参数>`（URL 编码）。地址里 `#` 之后的部分不带。
2. **互跳时 `next` 原样带过去。** 包括登录页与注册页之间的互跳，以及注册页「该邮箱已注册，去登录」里的链接。
3. **登录或注册成功后跳到 `next`。** 没有 `next` 或 `next` 不合法时回首页 `/`。
4. **`next` 只接受站内地址。** 必须是以单个 `/` 开头的相对路径，且第二个字符不是 `/` 或 `\`；否则视为不合法。这是防「开放重定向」：攻击者发一个 `/login?next=https://钓鱼站` 的链接，受害者在真站登录后被带去假站。
5. **`next` 指向 `/login` 或 `/register` 本身时视为不合法。** 避免登录后又回到登录页。
6. **已登录的人打开 `/login` 或 `/register`，直接跳走。** 去 `next`（合法时）或首页，不显示表单。
7. **登出后留在当前页。** 本版所有页面都是公开的，不存在登出后无权查看的情况。
8. **专注布局里的「返回」入口回到 `next` 指向的页面。** 没有或不合法时回首页。

> 共享状态屏（全局 404 / 错误页）已在 v0.5 `detail-pages.md` 设计，本版不重画。

## 3. 每屏内容与数据 ← 最关键

### 3.1 登录页和注册页的共同外壳（专注布局）

- **不渲染 `TopNav` 和 `Footer`。**
- 页面上只有三样东西：
  1. **品牌标识**（左上角）：`BrandMark` + 「Patra」字标，与导航栏左侧那一组相同，点了回首页。
  2. **「返回」入口**：带向左箭头的文字链接「返回」，去向见 §2 跳转规则第 8 条。
  3. **表单**（§3.2 / §3.3）。
- **构图方向**（交 Claude Design 探索，可以出两个方向供选）：桌面左右分栏，一侧是表单，一侧是品牌面板；移动端只留表单，品牌面板收掉或缩成顶部一条。
- **品牌面板的内容**：`Venation` 叶脉图形 + 一句定位语。定位语只描述 Patra 本身，从首页现有文案里取，不写登录后的好处。两句可选素材：
  - 「十个来源，汇入同一根主脉。」
  - 「Patra 汇集 PubMed、Europe PMC、Crossref 等 10 个来源的学术文献，提供统一检索、出处追溯与 AI 辅助速读。」
- **信息密度**：低。这是全站内容最少的两页，桌面端一屏内完成、不出现滚动。
- **浏览器标签标题**：「登录 · Patra」/「注册 · Patra」。

### 3.2 登录页 `/login`

自上而下：

1. **标题**：`登录`（h1，衬线）。副文案一行：`用邮箱和密码登录 Patra`。
2. **表单级提示条的位置**：标题与第一个字段之间。只在出错时出现（§4.2）。
3. **邮箱**：标签「邮箱」，placeholder `name@example.com`。
4. **密码**：标签「密码」，无 placeholder，输入框右侧有显示 / 隐藏切换（默认隐藏）。
5. **提交按钮**：`登录`，主按钮，与表单等宽。
6. **互跳**：`还没有账号？注册`，「注册」是链接。

登录页**不校验密码长度**，只校验非空。密码规则以后可能调整，旧密码不该被前端拦住。

不出现：「忘记密码」「记住我」、第三方登录按钮、验证码。

### 3.3 注册页 `/register`

自上而下：

1. **标题**：`注册`（h1，衬线）。副文案一行：`用邮箱建一个 Patra 账号`。
2. **表单级提示条的位置**：同登录页。
3. **邮箱**：标签「邮箱」，placeholder `name@example.com`。
4. **密码**：标签「密码」，输入框下方**常驻**一句提示 `至少 8 位`，右侧有显示 / 隐藏切换。
5. **确认密码**：标签「确认密码」，右侧有显示 / 隐藏切换。保留这一项的原因：本版没有找回密码，注册时输错密码的代价很高。
6. **一行说明**（提交按钮上方，弱化的辅助文字）：`请牢记密码，目前不支持找回密码。`
7. **提交按钮**：`注册`，主按钮，与表单等宽。
8. **互跳**：`已有账号？登录`，「登录」是链接。

密码规则：8 到 64 位，不限字符种类，过于常见的密码会被拒绝（§4.1）。**不做强度条**，也不逐条列规则清单，常驻提示只有「至少 8 位」这一句。

不出现：昵称、头像、验证码、服务条款勾选、密码强度条、第三方登录按钮。

### 3.4 导航栏 · 未登录态

- **桌面**（宽度 > 880px）：`TopNav` 右侧现在是「快速检索」和「关于」，在最右加一个 `登录`。视觉重量比「关于」这种纯文字链接重一档，比主按钮轻，不抢「快速检索」。
- **移动**（宽度 ≤ 880px）：顶栏不变，仍是检索图标 + 菜单图标。在全屏菜单里、导航项列表之后加一个账号块：一个 `登录` 按钮 + 一行 `还没有账号？注册`。账号块不压过菜单里的检索入口。

### 3.5 导航栏 · 登录态

- **桌面**：「登录」的位置换成一个**圆形标识**，里面是邮箱的首字母。点开是下拉菜单：
  1. 第一行：完整邮箱。不可点；过长时截断，悬停显示完整。
  2. 分隔线。
  3. `退出登录`。
- **移动**：全屏菜单里的账号块换成一行邮箱（过长截断）+ `退出登录` 按钮。顶栏不显示登录状态。
- **圆形标识不是头像功能**：不能上传、不能改，只是把邮箱缩成一个可点的标记。取邮箱第一个字符，字母转大写，数字或符号原样显示。

### 3.6 代表性数据样例

当前用户（导航栏只用到 `email`；字段名和取值以 PAP-64 定稿为准）：

```json
{ "id": "352303128713027974", "email": "chen.yu@example.com", "accountType": "PORTAL_USER" }
```

画稿时请覆盖这三种邮箱：

| 邮箱 | 圆形标识 | 用来看什么 |
|------|---------|-----------|
| `chen.yu@example.com` | C | 常规长度 |
| `postdoctoral.researcher.zhang@cardiovascular-research.university-hospital.example.org` | P | 用户菜单和移动端账号块里的截断；输入框里的横向滚动 |
| `2024cohort@example.org` | 2 | 首字符不是字母 |

## 4. 必做状态（逐屏点名，一个不漏）

**错误出现在两个位置**：

- **字段级**：写在该字段下方，字段描边变色。用于这个字段自己的问题。
- **表单级**：标题下方的一条提示条。用于不属于某一个字段的问题。
- **不用右下角的 toast 报错。** toast 会自动消失，容易错过。toast 只用于成功提示（§4.3）。

### 4.1 注册页

- [ ] **默认**（空表单，焦点在邮箱框）
- [ ] **提交中**
- [ ] **字段校验错误**（下表每一条）
- [ ] **邮箱已注册**
- [ ] **密码太常见**
- [ ] **网络或服务错误**

| 状态 | 位置 | 文案 |
|------|------|------|
| 提交中 | 按钮 | `注册中…`（按钮禁用，字段只读） |
| 邮箱为空 | 邮箱下方 | `请输入邮箱` |
| 邮箱格式不对 | 邮箱下方 | `邮箱格式不正确` |
| 邮箱已注册 | 邮箱下方 | `该邮箱已注册，去登录`（「去登录」是链接，带上 `next`） |
| 密码为空 | 密码下方 | `请输入密码` |
| 密码不足 8 位 | 密码下方 | `密码至少 8 位` |
| 密码超过 64 位 | 密码下方 | `密码最长 64 位` |
| 密码太常见 | 密码下方 | `这个密码太常见，容易被猜到，请换一个` |
| 确认密码为空 | 确认密码下方 | `请再输入一次密码` |
| 两次密码不一致 | 确认密码下方 | `两次输入的密码不一致` |
| 网络或服务错误 | 提示条 | `注册没有成功，请稍后再试` |

密码字段出错时，错误文案**替换**常驻提示「至少 8 位」，不同时显示两行。「邮箱已注册」和「密码太常见」由后端在提交后返回，其余在前端校验。

### 4.2 登录页

- [ ] **默认**（空表单，焦点在邮箱框）
- [ ] **提交中**
- [ ] **字段校验错误**（下表前三条）
- [ ] **邮箱或密码错误**
- [ ] **被暂时限制**
- [ ] **账号已被封禁**
- [ ] **网络或服务错误**

| 状态 | 位置 | 文案 |
|------|------|------|
| 提交中 | 按钮 | `登录中…`（按钮禁用，字段只读） |
| 邮箱为空 | 邮箱下方 | `请输入邮箱` |
| 邮箱格式不对 | 邮箱下方 | `邮箱格式不正确` |
| 密码为空 | 密码下方 | `请输入密码` |
| 邮箱或密码错误 | 提示条 | `邮箱或密码错误` |
| 被暂时限制 | 提示条 | `尝试次数过多，请 15 分钟后再试` |
| 账号已被封禁 | 提示条 | `该账号已被封禁，无法登录` |
| 网络或服务错误 | 提示条 | `登录没有成功，请稍后再试` |

「被暂时限制」里的分钟数是示例。实际值由后端返回的剩余秒数向上取整到分钟，不足 1 分钟显示「1 分钟」；后端没有给出剩余时间时显示 `尝试次数过多，请稍后再试`。不做倒计时，也不禁用提交按钮。

### 4.3 导航栏和全局提示

- [ ] **未登录态**：桌面「登录」；移动端菜单里的账号块
- [ ] **登录态 · 菜单收起**：圆形标识
- [ ] **登录态 · 菜单展开**：邮箱 + 「退出登录」
- [ ] **登录态 · 移动端菜单里的账号块**
- [ ] **登录态未定（占位）**
- [ ] **退出进行中**
- [ ] **三条成功提示**

| 状态 | 位置 | 呈现 |
|------|------|------|
| 登录态未定 | 导航栏右上角 | 与圆形标识同尺寸的中性占位。不先显示「登录」再跳成圆形标识。移动端菜单里的账号块同理，用同高的中性占位 |
| 退出进行中 | 用户菜单 | 「退出登录」一项禁用，直到完成 |
| 注册成功 | 右下角提示 | `注册成功，已登录` |
| 登录成功 | 右下角提示 | `已登录` |
| 已退出 | 右下角提示 | `已退出登录` |

**会话失效时没有专门的状态。** 失效有三种来源：30 天不活跃过期、被撤销、被封禁。处理方式相同：下一次打开或刷新页面时静默回到未登录态，不弹提示、不打断浏览。被封禁的人再去登录时，在登录页看到封禁提示。

**登出在用户看来总是成功。** 即使后端暂时不可用，门户也会清掉本机的登录状态，所以登出没有失败态。

### 4.4 文案背后的规则

1. **「邮箱或密码错误」不区分是哪一个错。** 否则别人能用登录页探测某个邮箱有没有注册。
2. **封禁提示只在邮箱和密码都对的时候出现。** 密码不对时一律是「邮箱或密码错误」。否则任何人都能查出某个邮箱是否被封禁。
3. **被限制时告诉用户还要等多久，但不提前提示还能再试几次。** 限制期内密码正确也被拒绝；对没注册过的邮箱表现相同。
4. **注册页的「邮箱已注册」会暴露邮箱是否注册过，本版接受。** 要避免它得靠邮箱验证，而邮箱验证不在本版范围。

### 4.5 边界

- **邮箱很长**：输入框里可以横向滚动；用户菜单和移动端账号块里截断。
- **重复提交**：提交中按钮已禁用，不会发出第二次请求。
- **失败后的表单**：注册页保留全部已填内容；登录页保留邮箱、清空密码、焦点回到密码框。
- **再次提交**：先清掉上一次的提示条，再显示新的结果。
- **浏览器自动填充**：邮箱和密码字段要能被浏览器和密码管理器识别、填充和保存；不禁止粘贴。自动填充后的输入框底色不能破坏纸色表面。

## 5. 复用 vs 新增组件

**复用**（按名引用，别重造）：

- `BrandMark` · `Venation`（品牌面板的叶脉图形）
- `TopNav`（右侧区域加账号区）· `Sheet`（移动端全屏菜单，加账号块）
- 原语 `button` `input` `sonner`（成功提示沿用现有右下角的 toast）
- `portal-ui` 里的 `btnPrimary` / `btnSecondary` / `btnBlock`（暖纸按钮）
- `QuickSearch` 的浮层观感（用户菜单的浮起表面、阴影、入场缓动与它一致）
- `StatusScreen` 的叶脉水印与大留白（品牌面板的气质参照）

**新增**（描述用途，视觉交 Claude Design）：

- `AuthShell` —— 专注布局外壳：品牌标识 + 「返回」+ 品牌面板 + 表单区。

## 6. 交互与响应式

- **进入页面**：焦点落在邮箱框。
- **回车**：在任一输入框里回车即提交。
- **校验时机**：离开一个字段时校验它；点提交时校验全部，并把焦点移到第一个出错的字段；出错后随输入重新校验，改对即消。
- **提交中**：按钮禁用并换成进行中文案，字段只读；互跳链接和「返回」仍可点。
- **密码显示 / 隐藏**：默认隐藏；切换后光标位置不变。注册页的两个密码框各有一个切换，互不联动。
- **用户菜单**：点圆形标识开合；点菜单外、按 Esc、选中菜单项都会关闭；方向键在菜单项之间移动；关闭后焦点回到圆形标识。
- **退出**：点「退出登录」立即执行，不二次确认。完成后菜单关闭，留在当前页，导航栏回到「登录」，右下角提示「已退出登录」。
- **元素状态**：hover / active / focus / disabled 都要给出。涉及输入框（含错误态下的 focus）、主按钮、文字链接、显示 / 隐藏切换、导航栏「登录」、圆形标识、菜单项。
- **微交互 / 动效**：提示条出现、字段错误文案出现、用户菜单弹出。时长和缓动沿用现有约定，尊重「减少动态效果」的系统设置。
- **响应式**：
  - 登录页 / 注册页：桌面分栏，移动单列只留表单。分栏的断点和列宽交 Claude Design。
  - 导航栏：沿用现有 880px 断点。以上是桌面形态，以下把账号区收进全屏菜单。
  - 移动端输入框和按钮的高度要适合手指点按。

## 7. 约束

- **视觉**：沿用「叶脉 · 学术编辑风」。这两页与首页、404 页的气质连续，用户从任何页面点「登录」过来，不该有换了个站的感觉。
- **技术**：映射到 **Next 16 App Router / Tailwind v4 / base-ui(shadcn)**。表单提交在服务端处理；登录状态存在页面脚本读不到的 Cookie 里，设计上不需要考虑在页面里展示或存储令牌。
- **可访问性**：
  - 表单用 `<form>`，每个输入框有可见的 `<label>`。
  - 字段错误用 `aria-invalid` 标记，并用 `aria-describedby` 关联到错误文案；常驻提示同样关联。
  - 表单级提示条出现时读屏要朗读（`role="alert"`）。
  - 错误不只靠颜色表达：有文字，字段级错误另有图标或描边变化。
  - 显示 / 隐藏切换是按钮，读屏名称为「显示密码」/「隐藏密码」。
  - 圆形标识是按钮，读屏名称为「账号菜单」；下拉菜单用菜单语义，全程可键盘操作。
  - 焦点可见，焦点顺序与视觉顺序一致。
- **暗色模式**：不做。全站目前没有暗色模式。
- **本版边界**：没有邮箱验证、找回密码、修改密码、第三方登录、个人资料、验证码、「记住我」、服务条款勾选、收藏。设计稿里**不要**出现这些入口，也不要出现暗示这些功能的文案。

## 附录 A. 前端字段与后端接口的对应 + 错误语义（给 BE）

> 本附录只写产品语义：每个接口收什么、成功给什么、每种失败怎么区分、前端显示什么。
> 接口路径、错误码的具体字符串、登录失败限制的阈值与计数方式、密码哈希算法，由 PAP-63 / PAP-64 的工程设计决定。

### A.1 四个接口

| 接口 | 入参 | 成功时 | 前端用在哪 |
|------|------|--------|-----------|
| 注册 | 邮箱、密码 | 建账号并直接建会话，返回会话令牌（注册即登录） | 注册页提交 |
| 登录 | 邮箱、密码 | 建会话，返回会话令牌 | 登录页提交 |
| 登出 | 当前会话 | 撤销会话 | 用户菜单「退出登录」 |
| 当前用户 | 无 | 用户 ID、邮箱、账号类型 | 导航栏判断登录态并显示邮箱 |

没有续期接口。会话的有效期由网关在每次请求时延长，门户不需要做任何事。

### A.2 字段规则

| 字段 | 规则 |
|------|------|
| 邮箱 | 去掉首尾空格；不区分大小写，`A@x.com` 和 `a@x.com` 是同一个账号；最长 254 个字符；格式合法 |
| 密码 | 8 到 64 位，长度按 Unicode 码点计（一个汉字算 1 位）；不限字符种类；首尾空格不去掉；不在常见密码名单里 |
| 确认密码 | 只在前端校验，不传给后端 |

- **后端要把同样的规则再校验一遍。** 前端校验只是为了反馈快，不能当作防线。
- **前后端用同一种方式算密码长度。** 都按码点计，否则同一个密码前端放行、后端拒绝。
- **登录接口不校验密码长度**，只要求非空。
- 常见密码名单的来源与规模由 PAP-63 定。

### A.3 失败语义与文案

| 接口 | 失败 | HTTP 状态 | 语义特征 | 要带的额外信息 | 前端呈现 |
|------|------|----------|---------|---------------|---------|
| 注册 | 字段不合法 | 422 | `RULE_VIOLATION` | 出错的字段；「密码太常见」要能和「长度不对」区分开 | 对应字段下方，文案见 §4.1 |
| 注册 | 邮箱已注册 | 409 | `CONFLICT` | 无 | 邮箱下方：`该邮箱已注册，去登录` |
| 登录 | 字段不合法（空 / 邮箱格式） | 422 | `RULE_VIOLATION` | 出错的字段 | 对应字段下方，文案见 §4.2 |
| 登录 | 邮箱或密码错误 | 401 | `UNAUTHORIZED` | 无 | 提示条：`邮箱或密码错误` |
| 登录 | 被暂时限制 | 429 | `QUOTA_EXCEEDED` | 还要等多少秒 | 提示条：`尝试次数过多，请 N 分钟后再试` |
| 登录 | 账号被封禁 | 403 | `FORBIDDEN` | 无 | 提示条：`该账号已被封禁，无法登录` |
| 当前用户 | 未登录或令牌失效 | 401 | `UNAUTHORIZED` | 无 | 导航栏显示未登录态 |
| 任一接口 | 超时、网络错误、5xx | — | — | 无 | 注册：提示条 `注册没有成功，请稍后再试`；登录：提示条 `登录没有成功，请稍后再试`；登出：照常清掉本机登录状态；当前用户：本次显示未登录态 |

- 响应体沿用现有的统一错误格式：RFC 7807 ProblemDetail，加 `code` / `traits` / `errors[]` 等扩展字段（见 `ErrorKeys`）。字段级错误放在 `errors[]` 里，每项带 `field`。
- 「语义特征」一列是现有错误体系里的 `StandardErrorTrait`。它们本来就映射到表中的状态码，不需要新增特征。
- 字段不合法的状态码按现有约定写为 422；如果统一格式对参数校验失败的实际映射不同，以实际为准，只要它和同一接口的其他失败不重复。

### A.4 交给后端工程设计时要注意的几点

1. **同一个接口里，每种失败的 HTTP 状态都不同。** 前端靠状态就能区分，不需要解析文案。
2. **邮箱不存在与密码错误返回完全相同的失败。** PAP-63 的验收标准里已经有。
3. **封禁只在凭据正确时暴露。** 邮箱和密码都对、账号处于封禁状态，才返回 403；密码不对时返回 401。
4. **限制期内密码正确也返回 429；对没注册过的邮箱表现相同。** 否则「被限制」这个结果本身会暴露邮箱是否注册过。429 要带剩余等待秒数，前端据此显示分钟数。
5. **登出总是成功。** 登出按会话令牌删除会话；重复登出、对已失效的会话登出，都按成功处理。
6. **密码哈希如果选 bcrypt，它只处理前 72 个字节。** 64 个字符的密码如果含中文或表情，会超过 72 字节。PAP-63 选算法时要处理这一点，Argon2 没有这个限制。
7. **密码接受 Unicode 时，哈希前先做规范化（NFKC）。** 否则同一个密码在全角 / 半角或不同输入法下的字节不同，用户会登不上。
