# 用户中心 — Design Brief

> v0.12 唯一一份设计简报。设计系统与代码库已 onboard，本简报只交增量。
> **产品定义以 release spec 为准**：`docs/patra/release-specs/v0.12-user-center.md` 2.1 节（字段、长度、流程、状态）。本简报只定页面、状态与文案；两者不一致时以 spec 为准，简报里发现的缺口列在 §10，不在这里改规则。
> **接口契约以后端工程 spec 为准**：`docs/patra/specs/2026-10-20-identity-account-rebuild-design.md`（PAP-93）、`2026-10-21-identity-email-verification-design.md`（PAP-96）、`2026-10-22-identity-account-security-design.md`（PAP-98）、`2026-10-22-identity-profile-design.md`（PAP-95）、`2026-10-21-catalog-org-mesh-suggest-design.md`（PAP-94）。PAP-97（头像）、PAP-99（登录设备）、PAP-100（注销）的工程 spec 还没写，本简报对它们只提页面需要什么（§9 附录 A）。
> 可交互画板：Claude Design 画布「v0.12 用户中心」<https://claude.ai/artifact/W8hmKqm6JcFdZu5FPy6MQ8>（桌面 1440×900 + 移动 375×812，场景用 Tweaks 切换）；快照 `docs/patra/design/snapshots/2026-10-22-user-center-hifi.zip`。
> 同版相关：Linear PAP-92（本简报 + 画板）→ PAP-101（注册、导航、资料、隐私、主页）/ PAP-102（账号、安全、再认证、落地页、取消注销）。

**目标**：用户在 Patra 有一个别人看得见的身份（用户名、昵称、头像、简介、专业背景、关注领域、公开主页），也能自己管好账号（验证邮箱、改密码、改邮箱、找回密码、看和踢登录设备、注销）。

## 0. 策略与定位

- **浏览仍然不需要登录。** 首页、文献、期刊的匿名浏览与 v0.11 完全一致。新增的公开主页 `/u/<用户名>` 也能匿名打开（按隐私设置）。
- **用户中心是「设置」，不是「个人后台」。** 没有仪表盘、没有统计、没有欢迎页。导航栏菜单直达「个人主页」和「设置」两处，设置页四个分区平铺，每个分区一页。
- **本版仍然没有依赖登录的业务功能。** 文案**不许诺**收藏、关注、讨论、通知这些以后的东西；主页给它们留的位置**本版不渲染、不占空白**（§3.13 讲怎么留）。
- **登录、注册、找回密码、邮件落地页、取消注销页都用 v0.8 的专注布局（`AuthShell`）。** 这些页只做一件事，不渲染导航栏和页脚。设置页和公开主页是普通页面，带导航栏。
- **自述不带认证外观。** 身份大类、职称、机构、科室在主页上按原样展示，不加对勾、徽章、「已认证」字样，也不用会被读成认证的强调色（spec 2.1.2）。
- **邮箱永不对别人出现。** 主页、主页的任何状态、给别人的任何文案里都没有邮箱。本人自己的设置页、横幅里可以出现自己的邮箱。
- **渐进式披露**：
  - 默认层：主页头部（头像、昵称、`@用户名`、简介）；设置页每个分区的表单本身。
  - 深数据层：主页的专业背景、关注领域在头部之下；设置页里规则说明（改名的保留与冷却、注销的后果）用常驻的一两行提示，不藏进「了解更多」。
- **流程闭环**（画板要能从头点到尾）：
  1. 注册（邮箱、用户名、密码）→ 回到来源页，已登录，顶部出现「验证邮箱」横幅 → 邮件里点链接 → 落地页点「验证邮箱」→ 横幅消失。
  2. 导航栏头像 → 设置 → 个人资料：换头像（裁剪）、填昵称、简介、链接、身份、职称、机构（搜索选中或手填）、科室、关注领域 → 保存 → 「查看我的主页」。
  3. 匿名窗口打开 `/u/chen-yu` → 看到头部、专业背景、关注领域，看不到邮箱。
  4. 设置 → 安全 → 踢掉另一台设备（先弹再认证）→ 列表只剩本机。
  5. 设置 → 账号 → 注销 → 再认证 + 输用户名 → 全部下线 → 冷静期内再登录 → 取消注销页 → 恢复。

## 1. 用户与场景

| 用户 | 场景 |
|---|---|
| 新访客 | 想建账号：注册页多填一个用户名 → 登录态 + 验证横幅 → 去邮箱点验证 |
| 新注册的医生 / 科研人员 | 补资料：头像、昵称、医院与科室、关注领域，把主页链接发给同事 |
| 同事 / 匿名访客 | 打开别人发来的 `/u/<用户名>`：看身份与专业背景；主页不公开时看到的和「不存在」一样 |
| 已登录用户 | 改密码、改邮箱、看哪些设备登录着、踢掉公共电脑上的登录 |
| 忘了密码的人 | 登录页「忘记密码？」→ 邮件 → 重设页 → 用新密码登录 |
| 收到可疑邮件的人 | 「你的邮箱已更改」通知里点「不是我」→ 撤销页 → 账号锁住、收重设邮件 |
| 想离开的人 | 注销 → 15 天冷静期 → 期内反悔就登录取消 |

### 2.2 跳转规则

沿用 v0.8 §2 的 `next` 规则（站内相对路径、不指向登录 / 注册页本身），新增：

1. **未登录打开 `/settings/**`**：跳 `/login?next=<原路径>`。
2. **登录或注册成功时 `user.status` 是 `PENDING_DELETION`**：不去 `next`，去 `/account/deletion-pending?next=<原 next>`。
3. **`PENDING_DELETION` 状态下打开任何页面**（含公开页面）：跳 `/account/deletion-pending?next=<当前路径>`。写接口回 409 且 `traits` 含 `PENDING_DELETION` 时同样跳（并发：别的标签页刚申请了注销）。取消注销成功后回 `next`。
4. **公开主页的旧用户名**：`/u/旧名` 临时跳到 `/u/新名`（307，不缓存）。画面上没有专门的状态，地址栏变成新名。
5. **落地页读完 `#token=…` 立即用 `history.replaceState` 把片段从地址里去掉**，令牌不留在历史记录和截图里；刷新后视为「链接不完整」。
6. **重设密码成功**：跳 `/login`，预填邮箱（经页面内状态带过去，不放进查询参数），表单上方是成功提示（§4.2）。

### 2.3 导航入口

- 导航栏用户菜单：`个人主页`（→ `/u/<用户名>`）、`设置`（→ `/settings/profile`）、`退出登录`。
- 未验证横幅：`重新发送`、`更改邮箱`（→ `/settings/account#email`）。
- 设置页标题旁：`查看我的主页 ↗`。
- 公开主页（本人视角）：`编辑资料`（→ `/settings/profile`）。
- 登录页：`忘记密码？`（→ `/forgot-password`）。
- 安全页改密码区：`忘记当前密码？`（→ `/forgot-password`）。
- 再认证对话框：`忘记密码？`（→ `/forgot-password`，新标签页打开，不丢当前页的输入）。

## 3. 每屏内容 ← 最关键

### 3.1 注册页 `/register`（改）

在 v0.8 注册页上改，外壳、互跳、按钮、错误位置都不变。

自上而下：

1. 标题 `注册`，副文案 `用邮箱建一个 Patra 账号`（不变）。
2. 提示条位置（不变）。
3. **邮箱**（不变）。
4. **用户名**（新，在邮箱下面）：
   - 标签 `用户名`。输入框不带域名前缀（门户域名还没定，现在是 mini 的主机名），改为下方常驻一行提示：`3–30 位，小写字母、数字、_ 或 -，用作主页地址 /u/<输入的值>`；输入为空时提示末尾显示 `/u/你的用户名`。
   - 输入时自动转小写（大写字母键入即显示为小写，不报错）。
   - `autocomplete="username"`、`spellcheck=false`、`autocapitalize="none"`。
5. **密码**：常驻提示 `至少 8 位`（不变）。
6. **确认密码：保留**（v0.8 的字段、校验与文案不变，只在前端比对；2026-10-22 定，见 §10 第 1 条）。
7. **删除** v0.8 的 `请牢记密码，目前不支持找回密码。`
8. 提交按钮 `注册`、互跳 `已有账号？登录`（不变）。

成功：回 `next`，右下角 `注册成功，已登录`（不变）；导航栏是默认头像；顶部出现未验证横幅。

### 3.2 登录页 `/login`（改）

1. 密码标签行右端加文字链接 `忘记密码？`（`AuthLink` 样式，和标签同一行、右对齐）。
2. 从重设密码页跳来时：邮箱已预填，焦点在密码框，表单上方是**成功语气**的提示条 `密码已重设，请用新密码登录`（`FormAlert` 新增 `tone="success"`，用 `status-success-bg` + `moss-700`，不新增颜色）。
3. 登录成功且 `status` 是 `PENDING_DELETION`：不弹 `已登录` toast，直接去取消注销页（§2.2 第 2 条）。
4. 其余状态与文案不变（v0.8 §4.2）。

### 3.3 导航栏账号区（改）

**桌面**：

- 圆形标识换成**头像**（36px 圆）：有头像用 128 档图；没有用默认头像（§3.20）。占位态不变（同尺寸中性圆）。
- 点开的菜单：
  1. 头部（不可点）：40px 头像 + 两行：昵称（`text-sm` 中粗，过长截断）/ `@用户名`（等宽小字 `fg-3`）。邮箱**不再**出现在菜单里（它不是身份，是登录凭据；本人在设置 · 账号里看）。
  2. 分隔线。
  3. `个人主页`（图标 `UserRound`）。
  4. `设置`（图标 `Settings`）。
  5. 分隔线。
  6. `退出登录`（不变，含进行中的禁用态）。
- 菜单宽度 240px；昵称、用户名都截断，悬停 `title` 显示全文。
- **顶栏只放头像，不放昵称文字。** 顶栏右侧已有「快速检索」「关于」，昵称最长 30 字素，放进去要截断且挤压检索入口；昵称在菜单头部。见 §10 第 9 条（spec 2.1.4 写「导航栏显示头像和昵称」）。

**移动**（全屏菜单底部的账号块，80px 高的约束放宽为两种高度）：

- 已登录：一行 `头像 40px + 昵称 / @用户名`；下面两个并排的次按钮 `个人主页`、`设置`；再下面整行 `退出登录`。
- 未登录、占位：不变。

### 3.4 未验证邮箱横幅（新）

- **出现条件**：已登录、`emailVerified=false`、`status=ACTIVE`。所有带导航栏的页面都有，位置在导航栏正下方、页面内容之上，随页面滚走（不吸顶，不和导航栏的毛玻璃叠）。专注布局的页面没有。
- **不可关闭**（spec「常驻」）。
- 外观：整宽一条，`status-warning-bg` 底、上下发丝线 `amber-500/30`，内容对齐 `page-max`；左侧 `MailWarning` 图标（`amber-700`）。
- 文案（桌面一行）：`验证邮箱后，别人才能看到你的主页。验证邮件已发到 chen.yu@example.com。` 右侧两个文字按钮：`重新发送` · `更改邮箱`。
- 移动：两行，第一行 `请验证邮箱：别人现在看不到你的主页`，第二行左邮箱（截断）右 `重新发送`；`更改邮箱` 收进设置页，不在横幅上。
- 「重新发送」的状态：

| 状态 | 呈现 |
|---|---|
| 可发送 | `重新发送` |
| 发送中 | `发送中…`（禁用） |
| 刚发出（202） | 按钮位置换成 `已发送 · 52 秒后可重发`，按 `nextResendAt` 倒计时，到 0 变回 `重新发送`；右下角 toast `验证邮件已发送` |
| 注册后 60 秒内（首封计入冷却） | 横幅首次出现时就是倒计时态（读 `/auth/me` 拿不到 `nextResendAt`：前端按注册时间起算 60 秒；不准时点了会得到 429，按下一行处理） |
| 429 | 按钮位置换成 `发送太频繁，请 N 分钟后再试`（`retryAfterSeconds` 向上取整到分钟，< 60 秒显示「N 秒」并倒计时） |
| 409 `EMAIL_ALREADY_VERIFIED` | 刷新 `/auth/me`，横幅消失，toast `邮箱已验证` |
| 网络或服务错误 | toast（错误语气，不自动消失前不挡操作）`没有发出去，请稍后再试`；按钮恢复 |

### 3.5 设置页外壳

- **桌面**：导航栏 → 页面容器（`page-max` + `gutter`）。
  - 顶部：h1 `设置`（衬线 `display-3`），同一行右端 `查看我的主页 ↗`（文字链接）。h1 下一行 `@chen-yu` 等宽小字。
  - 下面两栏：左侧分区导航 200px（吸顶，`top` = 导航栏高 + 24px），右侧内容列最大 640px。分区导航四项竖排：`个人资料`、`账号`、`安全`、`隐私`，当前项左侧 2px `clay-500` 竖线 + `fg-1`，其余 `fg-2`。
  - 「通知」「已连接账号」不渲染（spec 2.1.11）。
- **移动**：h1 `设置` + `查看我的主页 ↗` 一行；下面是四个等宽的分段标签（`资料` `账号` `安全` `隐私`，用现有 `tabs` 原语的下划线样式），吸顶在导航栏下；内容整宽。
- 每个分区内部用**分组卡片**：卡片标题（`text-lg` 衬线）+ 一行说明（`fg-3`）+ 内容。卡片之间 32px。危险区卡片描边 `rust-500/40`，标题 `status-danger`。
- 浏览器标签标题：`个人资料 · 设置 · Patra` 等。

### 3.6 设置 · 个人资料 `/settings/profile`

一张表单（`PUT /me/profile` 整份替换），头像是例外：头像上传 / 删除即时生效，不跟表单一起保存。

**卡片 1 · 头像**（即时生效）

- 左 96px 头像（移动 72px，保持与按钮同一行）；右侧：`上传新头像`（次按钮）、`移除`（文字按钮，仅有自定义头像时出现）；下方说明 `JPG、PNG 或 WebP，不超过 5 MB，短边至少 128 像素`。
- 点上传 → 系统选文件 → 先在本地校验（§4.6），通过后打开裁剪对话框（§3.7）。
- 移除：立即执行，不二次确认；toast `已恢复默认头像`。

**卡片 2 · 公开资料**

| 字段 | 控件 | 常驻提示 / 占位 |
|---|---|---|
| 昵称 | 单行 | 占位符显示当前用户名（`chen-yu`）；提示 `2–30 个字。不填就显示用户名。昵称可以和别人重复，主页上会同时显示 @用户名` |
| 简介 | 多行（3 行高，自动增高到 3 行为止） | 右下角计数 `86 / 200`；提示 `最多 3 行` |
| 链接 | 0–5 行，每行「标题（可选）」+「网址」两个输入框 + 行尾 `删除` 图标按钮；下方 `+ 添加链接`（满 5 条时隐藏，换成 `最多 5 条链接`） | 网址占位 `https://`；标题占位 `标题（可选，不填显示域名）`。邮箱未验证时卡片内一行 `amber` 提示：`验证邮箱后，链接才会展示在主页上` |

**卡片 3 · 专业背景**

- 卡片说明：`按你填写的原样展示，不代表经过认证。` 下一行显示当前可见性：`当前：所有人可见` / `当前：仅自己可见`，后跟 `更改`（→ `/settings/privacy`）。

| 字段 | 控件 | 说明 |
|---|---|---|
| 身份 | 单选下拉：`医师`、`护士`、`药师`、`医技`、`科研人员`、`学生`、`行业从业者`、`其他`，外加一项 `不填写` | 枚举值见 spec 2.1.2 |

### 3.19 安全邮件的版式（三类）

邮件客户端不加载网页字体、不跑脚本、常屏蔽图片，所以：字族用 tokens 里同一套字体名 + 系统回退（不新增字族），品牌用**文字字标**「Patra」（衬线），不用图片；颜色只用 tokens 里的值；单栏 560px，移动端 100%。

3. 正文：一两句话说发生了什么。
4. （按类别）按钮 / 安全信息块 / 「不是我」块。
5. 页脚（`fg-3` 小字）：`这是一封系统邮件，请勿直接回复。Patra 不会在邮件里索要你的密码。` + 门户地址。

### 3.20 默认头像

- 昵称里第一个「字」：跳过开头的标点和空白（如「·小林」取「小」），汉字取首字、拉丁字母取大写、数字原样、emoji 原样；整个昵称都没有可取的字时退回用户名的首字母（2026-10-22 定，细化 spec 2.1.3 的「首字素」）。

- 12 色板**全部取自现有 token，不新增颜色**，按色号 0–11 依次是：`clay-700`、`slate-500`、`moss-500`、`ink-700`、`rust-500`、`amber-700`、`clay-900`、`moss-700`、`ink-500`、`clay-800`、`ink-900`、`ink-600`。纸色字（`paper-50`）在每一种上都 ≥ 4.5:1（最低是 `ink-500` 4.53、`moss-500` 4.54），所以 36px 头像里 15px 的小字也合格；`clay-500`（3.45）、`clay-600`（4.47）、`amber-500`（3.05）不够，不进色板。相邻色号隔开色相，避免一屏里几个默认头像都是同一个色系。

## 6. 交互与响应式

- **断点**：沿用 880px（导航栏、专注布局、设置页两栏 ↔ 分段标签、主页两栏 ↔ 单列）。
- **焦点**：页面进入时焦点落在第一个输入框（注册、忘记密码、重设密码）；落地页就绪态焦点在主按钮；对话框打开时焦点在第一个输入框，关闭后回到触发按钮；保存失败焦点到第一个出错字段。
- **校验时机**：沿用 v0.8（离开填了内容的字段时校验，提交时校验全部，出错后随输入重验）。
- **提交中**：按钮禁用 + 进行中文案，字段只读；对话框提交中 `Esc` 与点遮罩不关闭。
- **倒计时**：每秒更新，读屏只在开始和结束时播报（`aria-live="polite"` 只挂结束态的文案）。
- **组合框**（机构、主题词）：`role="combobox"`、`aria-expanded`、`aria-activedescendant`，候选是 `listbox`；结果数变化用 `aria-live` 播报 `找到 N 个机构`。
- **拖动排序**一定有键盘替代（§3.9）。
- **动效**：对话框、下拉、提示条、保存条入场沿用现有时长与缓动；设备行移除淡出 `dur-normal`；尊重「减少动态效果」。
- **移动**：输入框 17px、按钮 48px 高；对话框改底部抽屉；吸底保存条避开底部安全区。
- **元素状态**：hover / active / focus / disabled 都要给出，新增的有：头像按钮、分区导航项、分段标签、候选项、胶囊的移除按钮、设备行的退出按钮、危险按钮、开关、单选。

## 7. 约束

- **视觉**：沿用「叶脉 · 学术编辑风」与设计系统 token（`patra-portal/src/styles/tokens.css` + `@theme`）。**不新增颜色与字族**：危险用 `rust`，警示用 `amber`，成功用 `moss`，信息用 `slate`，强调用 `clay`；默认头像 12 色板也只取现有 token（§3.20）。
- **技术**：Next 16 App Router / Tailwind v4 / base-ui(shadcn)。登录状态在页面脚本读不到的 Cookie 里；再认证、改密码成功后换 Cookie 由服务端完成，画面上无感。
- **可访问性**：沿用 v0.8 §7；另：头像 `alt` 为空（旁边就有昵称），默认头像的字 `aria-hidden`；危险操作的按钮名称写清后果（`注销账号`、`撤销更改并锁定账号`）；主页链接图标 `aria-hidden`、链接文字可读。
- **暗色模式**：不做。
- **本版边界**（设计稿里**不要**出现）：关注 / 粉丝 / 获赞计数、动态、讨论、收藏夹、私信、通知设置、已连接账号、第三方登录按钮、两步验证、手机号、实名、职业认证标识或「已认证」外观、IP 属地公开展示、数据导出、服务条款勾选、中文 MeSH 标签。

## 10. spec 缺口、冲突与待拍板

**与 spec / Issue 的冲突或缺口**（2026-10-22 用户已拍板，结论写在每条末尾；涉及 release spec 与 Issue 的改动由规划会话同步，本简报不改 spec）：

1. **注册页有没有「确认密码」**：release spec 2.1.11 写「注册页改为邮箱、用户名、密码三项」；PAP-93 工程 spec 8.1 写「确认密码仍只在前端校验」（暗示保留）。**定：保留确认密码**，注册页、安全页改密码、重设密码落地页都有「确认（新）密码」，只在前端比对。release spec 2.1.11 的「三项」要同步改成「邮箱、用户名、密码（+ 确认密码）」。
2. **落地页数量与路径**：spec 2.1.11 列三个落地页（验证、重设、撤销改邮箱），漏了「确认新邮箱」；PAP-102 的 To-Do 写 `/revert-email`，后端配置默认值是 `/revert-email-change`。**定：按后端配置做四个**：`/verify-email`、`/reset-password`、`/confirm-email-change`、`/revert-email-change`。release spec 2.1.11 与 PAP-102 To-Do 要同步。
3. **改邮箱放哪个分区**：spec 2.1.11 放在「账号」；PAP-98 工程 spec §18 与 PAP-102 评论写「安全设置页」。**定：放账号页**（邮箱和验证状态在一处）。PAP-98 §18 的「安全设置页」措辞要同步。
4. **默认头像按用户 ID 取色，但公开主页拿不到用户 ID**：`GET /users/{username}` 有意不返回用户 ID（PAP-93 / 95），门户在主页上无法按 ID 取色；只能按用户名取色（改名会变色，违反「改昵称不变色」的精神也违反 spec 字面）。建议给 `/users/{username}` 和 `/auth/me` 加一个 `avatarPalette`（0–11 的色号，服务端按 ID 哈希算），或由头像接口直接出默认头像。需要 PAP-95 / PAP-97 补字段。另：12 色板 spec 没给，用 §3.20 的 12 个现有 token。**定：加 `avatarPalette` 字段**（服务端按用户 ID 哈希出 0–11），色板按 §3.20。
5. **用户名占用只能提交后知道**：没有「查用户名是否可用」的接口，注册页和账号页只能提交后才看到 `ALREADY_TAKEN`。本版接受，不加接口（加了就是又一个枚举探针）。（我定的，未单独提问。）
6. **注销发起的响应**（附录 A PAP-100）：结果屏要写到期日，但发起成功时本机会话已撤销，需要发起接口直接回 `deletionDueAt`。**定：PAP-100 的发起接口回 `deletionDueAt`。**
7. **撤销改邮箱时旧地址已被抢注**：PAP-98 写「用户只能找管理员」，但产品里没有任何联系渠道。**定：本版不放联系方式**，失败态只写「无法改回原邮箱 / 原邮箱已被另一个账号注册。」
8. **重发验证邮件的初始冷却**：`/auth/me` 不带 `nextResendAt`，注册后横幅无法准确显示「N 秒后可重发」。**定：前端从注册时刻起算 60 秒**，点早了按 429 处理，`/auth/me` 不加字段。
9. **导航栏「显示头像和昵称」**：spec 2.1.4 原话。按顶栏只放头像、昵称在菜单头部画（§3.3），理由是顶栏空间与 30 字昵称的截断；用户审简报时未提异议，画板上可以对比。

**简报里由我定的设计点**（看到不对就推翻）：

1. 设置页桌面左侧分区导航、移动顶部分段标签；`/settings` 跳 `/settings/profile`。
2. 个人资料整页一个保存（吸底保存条），头像即时生效；隐私页改了立即保存。
3. 改用户名、改邮箱都在账号页卡片内展开，不开新页、不开对话框；注销用对话框（两步：后果 → 输用户名）。
4. 踢设备、移除头像不二次确认。
5. 公开主页的留位：计数行、标签栏、右上操作区三处，本版不渲染也不占空白；本版正文就是以后的「关于」标签。
6. 主页 404 对任何原因同一句 `没有找到这个用户 / 地址可能有误，或者这个主页没有对你公开。`
7. 落地页打开时不发请求、读完令牌立即从地址里抹掉；验证落地页对「已登录且已验证」直接显示已验证。
8. 机构候选的类型小标、MeSH 的 16 个大类中文名（§3.8 / §3.9）。
9. 安全邮件用文字字标、不放图片；撤销按钮用危险色。
10. 再认证对话框成功后不额外 toast，取消不报错。
11. 首字素是标点时：**定（2026-10-22）：跳过开头的标点取第一个字**（「·小林」→「小」）。release spec 2.1.3 的「昵称首字素」要同步成「昵称里第一个非标点字素」。

**落地时的调整**（PAP-101 实施，2026-10-23）：

1. §4.5「409 并发修改」：后端没有乐观锁，资料保存的 409 只是「沿用的机构名称快照被另一次并发保存删掉」，原样再交一次就会成功。门户改为自动重试一次、保留全部输入，仍失败时提示条写 `资料没有保存成功，请再保存一次`，不提供「刷新」（刷新会丢掉未保存的修改）。见工程 spec `docs/patra/specs/2026-10-23-portal-user-center-profile-design.md` §9.3。
2. §3.7 头像裁剪对话框桌面宽度按画板 `Profile` 取 620px（本节文字写的 520px 放不下两个预览）。
