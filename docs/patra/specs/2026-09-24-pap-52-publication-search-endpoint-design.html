PAP-52 文献检索端点：GET /portal/publications/search + /search/facets

📅 2026-09-24 🌿 feat/pap-52-publication-search 👤 linqibin 🎫 PAP-52 / Issue #188 🎯 spec draft
关键决策摘要

在 patra-catalog 新建一条文献检索读端口 PublicationSearchReadPort，同时服务新端点 /search、/search/facets 与现有首页 feed 端点——feed 是"无筛选、按更新时间排"的检索特例，旧的 PortalFeed* 读端整套删除。列表 DTO 只有一份：PortalPaperResponse 追加 venueId / evidenceLevel / abstractSnippet，feed 与 search 同形。关键词对剥除内联标记后的标题做 ILIKE 子串匹配，作者匹配 cat_publication_author.display_name 快照，证据等级在 SQL 里按 EvidenceLevel 同一映射表先算每篇最强档再等值过滤。DAO 用一个共享 WHERE 常量拼出列表、count 与五个 facet 查询，drill-down 靠把本维度参数置 null 实现。无 Flyway、无索引、无前端改动。

1. 背景与现状

v0.7 Papers Search 要把门户导航"文献"入口从 SOON 占位变成可用的浏览 / 检索页（/papers），并接通首页搜索框、主题云、期刊详情"该刊文献"等出口。release-spec（docs/patra/release-specs/v0.7-papers-search.md）决策 B 要求新建检索端点、feed 端点契约不动；决策 A 不做全文检索、不加索引；决策 D 证据等级走类型映射不加物化列。设计简报附录 A 已核对：本页所需数据全部在库，无需新采集，也无需 schema 变更。

catalog 现状：期刊侧已有完整的 browse / facets 三件套（VenueBrowseFilter + VenueBrowseReadPort + VenueBrowseReadAdapter + VenueDao 八条 facet SQL + PortalVenueBrowseQueryService + PortalVenueController），文献侧只有 feed（PortalFeedReadPort / PortalFeedReadAdapter / PortalFeedDao，tab 为 recent / cited）和详情两条读端。feed 的 SQL 已经做了作者 string_agg 与类型子查询，是检索列表 SQL 的直接前身。

文档 PR #191 评审（Codex + CodeRabbit）已把三条实现约束写进简报：作者匹配走快照列（author_id 仅 ORCID 命中才有值）、证据等级先分级再过滤、标题剥标记后匹配且 LIKE 通配转义。

2. 范围边界

In Scope
  • GET /portal/publications/search：分页列表，13 个查询参数，两种排序。
  • GET /portal/publications/search/facets：年份 / 类型 / 证据等级 / 语言 / OA 计数 + total + lastSyncedAt，drill-down 语义。
  • PortalPaperResponse 追加三个字段，feed 端点一并返回。
  • feed 端点内部迁移到新读端口，删除 PortalFeed* 读端六个类与其 IT。
  • FacetCount 抽成顶层共用类型、EvidenceLevelView 抽成顶层响应视图，期刊侧与详情响应改引用。
  • domain / app / adapter 单测 + infra / adapter 集成测试，TDD。
Out of Scope
  • 全文检索、分词、相关度、被引排序、自动补全（release-spec 边界 A / B / C）。
  • 任何 Flyway 迁移、索引、物化列。
  • venue facet 候选列表（前端用 /portal/venues?q= 选、/portal/venues/{id} 取名）。
  • 详情端点 PublicationDetailReadAdapter 不动。
  • 前端页面（PAP-53）与出口接通（PAP-54）。
  • OA 数据补齐、被引数据补齐（当前全 false / 全 0，端点支持参数即可）。

3. 请求契约

两个端点共用一个请求 record PortalPublicationSearchRequest（adapter 层，Spring MVC 自动绑定 query params）。facets 端点忽略 sort / page / pageSize。多值参数一律用重复参数（type=Review&type=Clinical%20Trial%2C%20Phase%20III），不按逗号拆分：真实类型值含逗号（库里 Clinical Trial, Phase I/II/III/IV/Veterinary 共 19 行），Spring 默认的 String→List 逗号拆分会把它切成两个值而漏掉目标文献。实现：PortalPublicationController 加 @InitBinder，为 List 类型注册一个不拆分的 PropertyEditor，只影响本控制器。编辑器必须同时覆写两个入口：setAsText(String)（单个参数值 → 单元素 List，不拆逗号）与 setValue(Object)（String[] → 逐元素 List）——Spring 的 TypeConverterDelegate 在走 setAsText 之前会先把 String[] 用逗号 join 成一个 String，只实现 setAsText 会让重复参数合并成 "A,B" 一个元素。元素级转换（venue 的 Long）仍由 ConversionService 完成。adapter 单测覆盖单值含逗号与重复参数两种形态，adapter IT 以单个含逗号的 type 值作 Red 起点。期刊端点的逗号约定不动。参数名 camelCase，与 /portal/venues 现有约定（pageSize / casTop）一致，前端 query 名同名零映射。

4.3 领域层（domain/model/read/portal/）

  • PublicationSearchFilter（@Builder record）：keyword / author / pmid / doi / yearFrom / yearTo / venueIds（List<Long>）/ types / evidenceLevels（List<EvidenceLevel>）/ isOpenAccess / languages / sort。紧凑构造器：null 列表换空不可变列表、sort 为 null 换 LATEST。
  • PublicationSearchSort enum：LATEST / YEAR / CITED + fromCode(String)（null / 未知→LATEST）。CITED 只给 feed 的 cited tab 用，search 请求校验不放行。
  • FacetCount(String value, long count)：顶层 record + of()，替换 VenueBrowseFacets.FacetCount 内嵌版本。
  • PublicationSearchFacets（@Builder record）：years / types / evidence / languages（List<FacetCount>）+ openAccess / total（long）+ lastSyncedAt（Instant，可空）。
  • PortalPaperReadModel 追加 venueId（Long）/ evidenceLevel（EvidenceLevel，非空，无类型时 UNKNOWN）/ abstractSnippet。字段数 14，从工厂构造改为 @Builder。
  • PublicationSearchReadPort：search(filter, paging) + facets(filter)，签名与 VenueBrowseReadPort 同构。
  • InlineMarkup（domain/model/vo/publication/，纯 Java）：TAG_PATTERN 常量——与前端 rich-inline-text.ts 同一份标签白名单（i b u sub sup + math mrow mi mo mn msub msup msubsup mtext mspace mstyle mover munder munderover mfrac msqrt semantics annotation）的正则 </?(i|b|u|sub|sup|math|…|annotation)(\s[^<>]*)?\s*/?\s*>，PostgreSQL ARE 与 java.util.regex 语法兼容；toPlainText(String)：删闭合 annotation 子树 → 剥白名单标签 → 解码实体；truncate(String, int) 按码点截断。标题检索的 SQL 与摘要片段的 Java 共用这一个白名单。
  • EvidenceLevel 新增 typeValuesOf(EvidenceLevel)：返回该档在映射表里的小写 type_value 集合（UNKNOWN 返回空集）；映射表仍只在这个枚举里。
  • 删除 PortalFeedFilter / PortalFeedTab / PortalFeedReadPort。recent / cited 解析挪到 PortalFeedQueryService。

5. SQL 策略

5.1 一份 WHERE，七处复用

全部条件都是 (:x IS NULL OR …) 形式，列表、count 与五个 facet 查询共用同一段 WHERE 文本。在 PublicationSearchDao 接口里定义 String WHERE = """…""" 文本块常量（接口字段隐含 static final，文本块是编译期常量），@Query(value = SELECT_LIST + WHERE + ORDER_BY) 拼接。drill-down 由传参实现：算年份 facet 时把 yearFrom / yearTo 传 null，其他维度同理——与期刊侧语义一致，但不用复制八遍 WHERE。

参数条件（p = cat_publication）
固定p.deleted_at IS NULL
:keywordregexp_replace(p.title, :tagPattern, '', 'gi') ILIKE CONCAT('%', :keyword, '%') ESCAPE '!'，Java 侧先 escapeLike（! / % / _）。:tagPattern 绑定 InlineMarkup.TAG_PATTERN，只剥白名单标签：age < 5、x<y and z>0 这类字面尖括号原样保留（前端 RichInlineText 同样按字面显示），库里 7 篇标题含字面尖括号。实体：匹配对象是落库原文，库里 0 篇标题含 &amp; 类实体，不解码
:authorEXISTS (SELECT 1 FROM cat_publication_author pa WHERE pa.publication_id = p.id AND pa.display_name ILIKE CONCAT('%', :author, '%') ESCAPE '!')
:pmidp.pmid = :pmid
:doilower(p.doi) = :doi，Java 侧去前缀并小写
:yearFrom / :yearTop.publication_year >= :yearFrom / <= :yearTo
:venueIdsp.venue_id = ANY((:venueIds)::bigint[])
:typesEXISTS (SELECT 1 FROM cat_publication_type pt WHERE pt.publication_id = p.id AND lower(pt.type_value) = ANY((:types)::text[]))，Java 侧小写
:isOpenAccessp.is_oa = :isOpenAccess
:languagesp.language_base = ANY((:languages)::text[])
:evidenceRanks<rank 表达式> = ANY((:evidenceRanks)::int[])

5.2 证据等级 rank 表达式

COALESCE((SELECT max(CASE
    WHEN lower(pt.type_value) = ANY((:lvl5)::text[]) THEN 5
    WHEN lower(pt.type_value) = ANY((:lvl4)::text[]) THEN 4
    WHEN lower(pt.type_value) = ANY((:lvl3)::text[]) THEN 3
    WHEN lower(pt.type_value) = ANY((:lvl2)::text[]) THEN 2
    WHEN lower(pt.type_value) = ANY((:lvl1)::text[]) THEN 1
    ELSE 0 END)
  FROM cat_publication_type pt WHERE pt.publication_id = p.id), 0)

lvl5..lvl1 五个数组由 EvidenceLevel.typeValuesOf() 提供，读适配器每次查询都传（每个 DAO 方法固定带这 5 个参数）。SQL 里没有任何类型字符串，与 classify() 永远同源。SQL 里的数字 5..1 对应枚举 rank()，域层测试锁死这组值。UNKNOWN 的 rank 为 0，"未分级"筛选就是 0 = ANY(:evidenceRanks)。

5.3 列表查询

feed 那条 SQL 的升级版，单次查询、无 N+1：

  • studyType 子查询换成 string_agg(pt.type_value, E'\x1f' ORDER BY pt.type_order ASC NULLS LAST, pt.id ASC) 聚合一列 publicationTypesAgg。Java 拆开后第一个当 kind、整个列表喂 classify() 得 evidenceLevel，一列两用。
  • 新增 p.venue_id AS "venueId"、left(a.plain_text, 2000) AS "abstractRaw"（原文有界取回，片段派生在 Java，见 §4.1；2000 字原文足以在剥标签后凑满 300 可见字）（LEFT JOIN cat_publication_abstract a ON a.publication_id = p.id；uk_pub_abstract 保证 1:1，不会放大行数）。
  • 作者 string_agg(pa.display_name, E'\x1f' ORDER BY pa.author_order) 沿用。
  • 排序内嵌 SQL，:sortMode 传枚举名：
    • LATEST：p.last_synced_at DESC NULLS LAST, p.id DESC
    • YEAR：p.publication_year DESC NULLS LAST, p.last_synced_at DESC NULLS LAST, p.id DESC
    • CITED：COALESCE(p.citation_count, -1) DESC, p.id DESC（feed 现状）
  • count 查询：SELECT count(*) FROM cat_publication p + WHERE，独立方法 countMatching(...)，同时充当 facets 的 total。

5.4 facet 查询（各自把本维度参数置 null）

facetSQL 要点置 null 的参数
yearsSELECT p.publication_year::text AS "value", count(*) … AND p.publication_year IS NOT NULL GROUP BY p.publication_year ORDER BY p.publication_year DESCyearFrom / yearTo

7. 错误处理与测试

7.1 错误处理

  • 参数校验全部在 adapter 层 request record 收敛为 400，走现有全局校验异常映射，不新增异常类型。
  • evidence 非法值由 @Pattern 拦截，控制器 valueOf(upper) 不会再抛。
  • 读端口无业务异常。0 命中返回空页；pmid / doi 未命中同样是空页，不是 404。
  • feed 的 tab 非法值：request @Pattern 拦在 400，服务层 IllegalArgumentException 兜底，行为不变。

8. 关键决策与备选

决策 1：一条读端口服务 feed 与 search，删除 PortalFeed* 读端

feed 就是"无筛选、按更新时间排"的检索。新建 PublicationSearchReadPort，feed 的 PortalFeedQueryService 把 tab 映射为排序后调用同一端口；作者聚合、类型聚合、摘要截断、venue join 只写一次，feed 将来要筛选就是传 filter。

备选 A：独立三件套，feed DAO 只补三列 — 否决：两条几乎一样的 SQL，之后 feed 要检索时还得再合并一次。
备选 B：单 SQL、双端口双适配器 — 否决：只省 SQL 重复，多出的端口没有各自职责，形式隔离。

决策 2：单一列表 DTO，PortalPaperResponse 加三字段

全站只有一种"文献卡片"契约，前端 Paper 类型不分叉，首页文献流顺便也能显示证据徽章。release-spec "feed 端点不动"指排序 / 分页 / tab 语义，加字段是纯增量。

备选：新建 PortalPublicationSearchResponse — 否决：14 个字段重复一份，前端维护两个近似类型。

决策 3：参数名 camelCase，sort 非法值 400，venue facet 不返回候选

yearFrom / pageSize 与 /portal/venues 现有约定一致；sort 非法值按 Issue AC "非法参数 400" 处理，与 feed 的 tab 一致；2,924 本期刊的计数列表没有意义，前端用期刊检索端点选。

备选：snake_case（release-spec 草稿写法）— 否决：与期刊端点和前端现有 query 名不一致。
备选：sort 静默回落默认（期刊端点做法）— 否决：Issue AC 明确 400。

决策 4：证据等级在 SQL 里先算最强档，映射表以数组参数传入

每篇文献 max(CASE …) 得 rank 后再等值过滤 / 分组，多类型文献只落一档，与 classify() 徽章一致。五个 text[] 由 EvidenceLevel.typeValuesOf() 提供，SQL 不含类型字符串。

备选 A：选中等级的类型集合成员匹配 — 否决：同时标 Meta-Analysis 与 RCT 的文献同时落 5 级与 4 级，与徽章不一致（Codex / CodeRabbit 各指出一次）。
备选 B：SQL 里硬编码映射表 — 否决：两份映射表必然漂移。
备选 C：物化列 — 否决：release-spec 决策 D 排除。

决策 5：DAO 共享 WHERE 常量，drill-down 靠置 null 参数

接口文本块常量 + 注解拼接，列表 / count / facet 七处只维护一段条件。facet 计算某维度时把该维度参数传 null，语义与期刊侧一致。

备选 A：期刊侧写法，每条 @Query 复制 WHERE — 否决：八份副本，改一个条件要改八处。
备选 B：JdbcClient 动态拼 SQL — 否决：放弃 Spring Data 分页与投影，多一套 SQL 拼装代码。

决策 6：关键词对剥白名单标签后的标题匹配，摘要片段在 Java 派生，作者匹配快照列

regexp_replace(title, :tagPattern, '', 'gi') 以 InlineMarkup.TAG_PATTERN 白名单剥标签，让 CO2 能搜到 CO<sub>2</sub>，且不吞 x<y and z>0 这类字面尖括号；白名单与前端 rich-inline-text.ts 同一份。本版本就无索引，剥标记不改变成本模型。作者匹配 cat_publication_author.display_name，因为 author_id 仅 ORCID 命中才有值。

备选 A：经 cat_author 关联匹配 — 否决：漏掉绝大多数作者行。
备选 B：剥标签用泛型正则 <[^>]+> 或 </?[a-z][^<>]*> — 否决：吞掉 age < 5、x<y and z>0 这类可见文字，与前端渲染不一致（Codex 两轮各指出一次）。
备选 C：摘要片段在 SQL 里 left(regexp_replace(...), 300) — 否决：SQL 解不了实体、去不掉 annotation 子树，会产出 xx 和 &a；PG 里没有实体解码函数，硬做只能堆嵌套 replace。

9. 风险与缓解

风险等级缓解
facets 7 条全扫 SQL 在库增长后变慢 low 决策 A 明知代价，18,807 篇量级可接受；搜索引擎专题整段替换。IT 里不做性能断言。
SQL 里 rank 数字 5..1 与枚举 rank() 漂移 low 域层测试锁定 rank 值；adapter IT 对多类型样本比对 classify()。
接口文本块常量拼接超出注解常量表达式的编译器支持 low Java 15+ 文本块是常量表达式，接口字段隐含 static final；第一个 DAO 测试编译即验证。
标签白名单在 BE InlineMarkup 与 FE rich-inline-text.ts 两份，日后一边加标签另一边忘了 low 两边注释互相指向；白名单来源是 PubMed DTD 固定集合，实际变动概率极低。
feed 迁移改变现有排序 / 作者顺序行为 mid feed IT 的断言先迁入新 IT 再删旧类；PortalPublicationControllerIT feed 用例保留。
FacetCount / EvidenceLevelView 抽顶层波及期刊侧与详情响应 low 纯类型移动，JSON 形状不变；现有期刊 / 详情 IT 覆盖。
record 构造绑定不消费 @InitBinder 注册的 List 编辑器，含逗号的单个 type 值仍被拆分 mid adapter IT 以 ?type=Clinical Trial, Phase III 单值作第一个 Red；若编辑器不生效，退回在控制器方法上以 @RequestParam MultiValueMap 读取列表参数再组装 record，契约不变。
前端 PAP-53 沿用期刊页的逗号拼接习惯，把 type 拼成一个值 low 本 spec §3 与 Linear PAP-53 明确「重复参数」约定；BE 对单个含逗号值按完整类型匹配，拼错会命中 0 条而不是错误结果。
