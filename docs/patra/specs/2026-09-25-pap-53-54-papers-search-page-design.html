文献检索页 /papers 与全站文献出口 设计

📅 2026-09-25 🌿 feat/v0.7-papers-search-fe 👤 linqibin 🎫 PAP-53, PAP-54（GitHub #189, #190） 🎯 spec draft
关键决策摘要

新建 /papers 文献检索页，并把导航、首页搜索框、主题云、首页文献流、期刊详情五处文献入口全部接到这个页面（两个 Issue 合为一份 spec，进同一个前端 PR）。页面沿用 /journals 的做法，地址栏即状态、服务端取数。在此基础上补一个公用的地址栏导航钩子，解决现有写法"点了没反应（约 0.5 s）"和"快速连点丢操作"两个缺陷，期刊页一并受益。两页共有的筛选组、chip 行、排序、分页、骨架、空态外壳从期刊页抽到 components/portal/browse/ 共用，期刊页外观与行为不变。交互上：年份单选（逐年项与"近 N 年"互斥）；关键词和作者可叠加，PMID / DOI 提交时清空其他条件、命中 1 篇由服务端直跳详情；信息行本版不显示"来源"。

1. 背景与现状

v0.7 Papers Search 已完成前三个 Issue：设计简报 PAP-50、hi-fi 稿 PAP-51（快照 docs/patra/design/snapshots/2026-09-24-papers-list-hifi.zip）、后端端点 PAP-52（GET /portal/publications/search 与 /search/facets，已部署 Mac mini，真实数据冒烟通过）。本 spec 覆盖最后两个前端 Issue：

  • PAP-53：/papers 页面本身，包括浏览态、检索态、facet、chip、分页和各种状态。
  • PAP-54：接通全站指向文献的入口。目前导航"文献"是 SOON 占位，首页搜索框提交只弹"功能即将上线"，主题云词条是 disabled 状态。

前端现状与约束：

  • /journals 已跑通"RSC 服务端取数 + URL query 同步"：page.tsx 用两个 Suspense 分别渲染筛选栏（无 key）和结果区（key = 序列化后的 query）。但它的组件写死了 /journals 路径和 VenueBrowseQuery 类型，多值参数用逗号拼接，文献页无法原样复用。
  • /journals 的筛选组件用 props 里的 query 计算下一状态，勾选框的 checked 直接读 query。实测 Mac mini 上一次筛选变更，search 与 facets 两个请求并行，较慢的一个约 0.3–0.5 s。这导致两个缺陷：勾选后要等这段时间才打勾；连点时第二次点击基于旧 query 计算，第一次点击会丢失。
  • 前端 Paper 类型还没有 PAP-52 新增的 venueId / evidenceLevel / abstractSnippet。
  • 后端对本端点不按逗号拆分多值参数（真实类型值含逗号，如 Clinical Trial, Phase III），非法参数统一返回 422；在 RSC 中 422 会抛错，落到全局错误页。
  • gateway 地址（PATRA_GATEWAY_BASE_URL）只在服务端可见，浏览器无法直连后端。

2. 范围边界

In Scope
  • /papers 浏览态与检索态：四 tab 检索条、信息行、chip 行、六组 facet（年份 / 类型 / 证据等级 / 期刊 / 语言 / 开放获取）、紧凑列表、页码分页
  • PMID / DOI 命中 1 篇时服务端直跳 /papers/[id]
  • 加载、切换中、四种空态、页码越界、错误等状态；1440 桌面与 375 手机两种布局
  • 从期刊页抽出公用浏览部件，期刊页改为调用它们（外观与行为不变）
  • 公用地址栏导航钩子：即时反馈、连点叠加、pending 标记（期刊页一并接入）
  • 标题关键词高亮（支持跨内联标签）
  • 期刊候选中转 /api/venues/suggest
  • PAP-54：导航"文献"、首页搜索框四 tab、主题云、首页文献流"查看更多"、期刊详情"查看该刊文献"
  • Vitest 单测与 Playwright 冒烟（连 Mac mini 真实数据）
Out of Scope
  • 高级检索语法、自动补全、相关度 / 被引排序（release spec 边界 A / B / C）
  • 收藏、保存检索式、导出引用（边界 D）；PaperCard 上的占位按钮保持不动
  • 主题云热词真实计算，以及"浏览全部主题"按钮（边界 E，按钮保持占位）
  • 信息行的"来源"段：后端没有该数据，本版不显示，也不写死
  • 任何后端改动：search / facets 契约以 PAP-52 为准
  • 暗色模式、i18n（边界 G）
  • 期刊页视觉改版：只做部件抽取与缺陷修复，外观不变

4. URL 契约与数据流

4.1 地址栏参数

FE query 名与 BE 参数名一一对应（release spec 决策 C），camelCase。示例：

/papers?q=GLP-1&author=Smith&yearFrom=2024&type=Review&type=Clinical+Trial%2C+Phase+III&evidence=RANDOMIZED_CONTROLLED_TRIAL&venue=123&lang=en&sort=year&page=2
参数类型规则
q / authorstring可以同时存在
pmid / doistring精确定位模式：URL 中只要出现其一，就只保留它（pmid 优先于 doi），其余条件、sort、page 一律丢弃（§4.2）
yearFrom / yearToint单选某一年写成 yearFrom=Y&yearTo=Y；"近 N 年"写成 yearFrom=当年−N+1（绝对年份，链接不随时间漂移）
type / evidence / venue / lang重复参数不按逗号拆分，也不用逗号拼接
oabool只在 true 时写 oa=true
sortlatest | year默认 latest，不写入 URL
page1 … MAX_PAGE1 不写入 URL；每页固定 20 条，pageSize 不进 URL。MAX_PAGE = ⌊2147483647 / 20⌋ = 107374182：后端 offset 是 Integer，实测 page=107374184 起即 422

4.2 解析规则：脏参数在前端丢弃

parsePaperSearchQuery(searchParams) 对照后端校验规则，逐项过滤。原因是后端 422 会把整页打到全局错误页，一个拼错的参数不应该让整页失败。

  • 字符串：trim，空白视为未传；q / author / doi 超过 200 字时丢弃。
  • pmid：不匹配 ^\d{1,15}$ 时丢弃。
  • 年份：非整数，或不在 1000–9999 范围内时丢弃；yearFrom > yearTo 时自动对调。
  • venue：保持字符串，须匹配 ^[1-9]\d{0,18}$ 且用 BigInt 比较不超过 Long 上限 9223372036854775807，不经 Number 转换以免损失精度（实测超上限即 422）；evidence：不在 6 个枚举名内的丢弃（大小写归一为大写）。
  • 多值：去空白、去重，保持首次出现的顺序。
  • sort：只接受 latest / year，否则用默认值；page：非正整数或大于 MAX_PAGE 时取 1。
  • 精确定位归一：过滤后若 pmid 存在，query 只保留 pmid；否则若 doi 存在，只保留 doi。sort 回默认、page 回 1。于是精确定位永远查第 1 页，也不会与其他条件组合出"看不见原因的空结果"。

往返一致：parse(serialize(q)) 等于 q，并且序列化结果的参数顺序稳定。结果区的 Suspense key 用的就是序列化结果。

4.3 服务端渲染流程（app/papers/page.tsx）

searchParams → parsePaperSearchQuery → query
  │
  ├─ query.pmid 或 query.doi 存在？
  │     在 page 顶层 await fetchPublicationSearch(query)（query 已归一为第 1 页）
  │       ├─ items.length === 1 → redirect(`/papers/${items[0].id}`)
  │       └─ 否则继续渲染，已取到的结果传给 PaperResults，不再重复请求
  │
  └─ <PapersQueryProvider query currentYear>
       BrowseHead                                  立即渲染
       PaperSearchBar                              立即渲染（client）
       Suspense → PapersInfoRow                    fetchPublicationFacets（cache 去重）
       Suspense → PaperActiveChipsServer           已选期刊并行 fetchVenueDetail 取刊名，client 从乐观 query 推导 chip
       ┌ Suspense（无 key）  → PaperFiltersServer  fetchPublicationFacets（与信息行共用一次请求）
       └ PendingRegion → Suspense key=serialize(query) → PaperResults   fetchPublicationSearch
  • 后端请求：search 带全部筛选、sort、page 和 pageSize=20；facets 只带筛选条件。非 2xx 时 throw，落到全局错误页。
  • 浏览态与检索态：没有任何筛选或检索条件时是浏览态。sort 和 page 不算条件。
  • currentYear 由服务端算出，作为 prop 下发，保证服务端与客户端对"近 N 年"的推算一致。
  • 期刊刊名查不到（404）时，chip 显示"期刊 #id"，仍然可以移除。

4.4 交互 → URL：公用导航钩子

BrowseQueryProvider（client）持有服务端下发的 query，对外提供三样东西：

  • query：乐观值。由 useOptimistic 维护；transition 期间是用户最新操作后的状态，transition 结束后回落为服务端下发的真实 query。
  • navigate(next | (cur) => next)：在 startTransition 内先设置乐观值，再 router.push(basePath + serialize(next))。函数式写法基于当前乐观值计算下一状态，所以连点会叠加，不会互相覆盖。
  • isPending：给 PendingRegion 用，让结果区变淡。
  • 所有交互都经 navigate：检索提交、勾选、chip 移除、排序、清除全部。改动筛选或排序时 page 归 1。分页用普通 <Link>，天然会滚回页面顶部。
  • pending 期间分页不可点：旧页码属于旧结果集，且链接由旧的服务端 query 生成，此时点击会撤销刚做的筛选。所以 isPending 为真时 BrowsePagination 整体 aria-disabled 并禁止指针事件，新结果到达后恢复。
  • 切换时结果区的实际观感：点击后先等服务端返回新页面骨架（通常很短），这段时间旧列表变淡；骨架到达后结果区因 key 变化换成列表骨架，再换成新结果。
  • 每次操作都 push，产生一条浏览历史，"后退"即撤销上一步。与期刊页一致。
  • 期刊页的 JournalFilters、JournalActiveChips、JournalSearchSortControls 改用同一个钩子。期刊检索框原有的 300 ms 防抖与 replace 行为保持不变。

4.5 期刊候选

VenueFacetSearch 输入后防抖 250 ms，经 TanStack Query 请求 /api/venues/suggest?q=（key 为 queryKeys.venueSuggest(q)）。Route Handler 转发到后端 /portal/venues?q=&pageSize=8，返回 {id, name, abbr}[]：

  • trim 后为空时直接返回 []，不打后端。
  • 后端失败时返回 502 与 []，下拉显示"候选加载失败"，不影响整页。
  • 选中候选即 navigate，给 venue 追加该 id；已选的期刊不再出现在候选里。

5. 页面结构与部件规则

视觉以 hi-fi 快照为准（桌面浏览态 / 检索态 / 无结果态；移动检索态 / 筛选抽屉 / PMID 未命中）。本节只记录交互规则，以及设计稿没有说清的地方。

5.1 页面结构（从上到下）

  1. 页头：面包屑"Patra / 文献浏览"，eyebrow"按文献浏览"，h1"浏览全部文献"，副文案。
  2. 检索条：tab 行（关键词·默认 / PMID / DOI / 作者），然后是输入框（带 × 清除）与"检索"按钮。桌面端排序段控件（最近更新 ↓ / 年份）放在检索按钮右侧；移动端下移一行，与"筛选"按钮并列，筛选按钮角标为已选条件数。
  3. 信息行：浏览态显示"共 18,807 篇 · 最近同步 2026-08-30"（lastSyncedAt 按本地时区格式化为 yyyy-MM-dd，空库时省略）；检索态显示"共 1,284 篇"。
  4. chip 行：只在检索态出现。分组依次为关键词、作者、年份、类型、证据等级、期刊、语言、开放获取；末尾是"清除全部"。移动端横向滚动。
  5. 两栏：左侧 facet 栏（移动端进抽屉），右侧列表 + 分页。

5.2 检索条

  • 初始 tab：有 pmid 选 PMID；有 doi 选 DOI；只有 author 选作者；其余情况选关键词。
  • 切 tab：只切换输入框内容，显示该 tab 对应参数的当前值，没有则为空，不触发导航。PMID 与 DOI 用等宽字体。
  • 关键词 / 作者提交：只替换各自的参数，同时清除 pmid / doi，保留普通筛选以及关键词与作者之间的叠加，page 归 1。提交空值等于移除该参数。
  • PMID / DOI 提交：生成只含 pmid 或 doi 的全新 query，命中 1 篇由服务端直跳详情。PMID 输入非纯数字时，框下提示"PMID 应为纯数字"，不提交。
  • chip 移除关键词或作者后，输入框同步清空（跟随乐观 query）。

5.3 facet 栏

组规则
发表年份快捷项"近 1 年 / 近 3 年 / 近 5 年"，下面是 facets.years 的年份倒序单选列表（radio 语义），带计数。快捷项与逐年项互斥，再点一次已选项即取消。chip 文案：from == to 时显示"2025 年"；只有 from 且等于 currentYear−N+1（N ∈ 1/3/5）时显示"近 N 年"；其他只有 from 的情况显示"2024 年起"；只有 to 时显示"2025 年及以前"
文献类型默认显示计数前 6 项，其余收进"更多类型 ↓"；已选项即使不在前 6 也始终显示。标签为"综述 · Review"，字典查不到时只显示原值
证据等级固定 6 档，按后端顺序（强 → 弱，UNKNOWN 末尾），标签与 EvidenceBadge 一致。"未分级"一行用弱化色
期刊VenueFacetSearch：输入框占位"搜刊名添加…"，候选下拉有三态（加载中 / 有候选 / "未找到匹配期刊"），支持 ↑↓ / Enter / Esc，ARIA combobox + listbox。已选期刊列在输入框下，是没有计数的勾选行，取消勾选即移除
语言标签为"英文 · en"，带计数；超过 6 项时折叠
开放获取FacetToggleRow"仅开放获取"，计数为 facets.openAccess
  • 空组不渲染：某组没有可选项、也没有已选项时整组不渲染。本库 OA 全为 0，所以开放获取组本版不可见。
  • 计数用千分位（Intl.NumberFormat("en-US")）；计数为 0 的未选项变淡，但仍可点。
  • 桌面侧栏底部有"清除全部筛选"。
  • 移动抽屉：从底部弹出，标题"筛选 · 已选 N 项"，页脚是"清除全部"与"查看 N 篇结果"（N 取 facets.total）。勾选时抽屉不关，结果在后台刷新。

5.4 列表项 PaperListItem

  1. 来源行：来源色点 + source + DOI（等宽、弱色）。
  2. 标题：衬线字体，最多两行，超出用 line-clamp 截断；链接到 /papers/{id}。有 q 时高亮命中片段，用 <mark>。
  3. 元信息行：期刊名（斜体；有 venueId 时链接 /journals/{venueId}，单行截断）· 年份 · 前 2 位作者，后接"等 N 位作者"。作者为空时省略该段。
  4. 徽章行：kind 类型徽章，加上 EvidenceBadge（仅 derived 为 true 时显示）。两者都没有时该行不占位。
  5. 摘要：abstractSnippet 最多两行，为 null 时不占位。
  6. 不显示：收藏、评论、引用按钮，以及被引数。

高亮实现：highlightInlineNodes(nodes, q) 在 parseInlineMarkup 的节点树上工作。先把全部文本节点拼成纯文本，大小写不敏感地找出所有命中区间（按字面匹配），再遍历节点树，把落在区间内的文本片段包成 mark 节点。命中跨越标签时（如搜 CO2 命中 CO<sub>2</sub>），会拆成多段 mark。不改动原有标签结构，也不拼 HTML 字符串。

关键决策与备选

决策 1：保留"地址栏即状态 + 服务端取数"，补公用导航钩子

地址栏仍是唯一的状态来源。BrowseQueryProvider 用 useOptimistic + useTransition 提供即时反馈、连点叠加和 pending 标记，期刊页一并接入。

备选 A：浏览器取数（TanStack Query + 客户端状态，再同步到 URL）— 否决：首屏先白屏再转圈；每个后端接口都要加中转；出现内存状态与 URL 两份真相，需要同步。
备选 B：原样照抄期刊页 — 否决：会把"点了没反应约 0.5 s"和"连点丢操作"两个缺陷带进文献页。

决策 2：抽浏览页公用部件到 components/portal/browse/

把 facet 组 / 行、筛选容器、chip 行、排序、分页、骨架、空态外壳抽成与具体页面无关的部件；期刊页改为调用，外观与行为不变。

备选 A：为文献页另写一套 — 否决：约 400 行近似重复，两页样式会逐渐漂移，也违背设计稿"骨架与 /journals 同构"的要求。
备选 B：让期刊组件整体泛型化（query 类型参数 + 注入序列化） — 否决：两页 facet 组成差异大，泛型化会产生大量配置分支，属过度抽象。

决策 3：年份单选，"近 N 年"与逐年项互斥

逐年项写成 yearFrom = yearTo = Y；"近 N 年"写成 yearFrom = 当年 − N + 1。语义上是 radio，视觉沿用设计稿的行样式。

备选 A：多选后取连续区间 — 否决：勾 2024 与 2026 会隐式包含 2025，但界面上 2025 没被勾，容易误导。
备选 B：改成起止年输入框 — 否决：偏离设计稿，也失去逐年计数。

决策 4：关键词 / 作者叠加，PMID / DOI 清空

关键词和作者 tab 只替换自己的参数，并清除 pmid / doi；PMID 和 DOI 是精确定位，提交时生成全新 query，命中 1 篇直跳详情。解析层同样保证精确定位与其他条件互斥（§4.2），手拼的 URL 也遵守。

备选 A：任何 tab 都叠加 — 否决：残留的筛选条件会让 PMID 查不到，落到空态。
备选 B：任何 tab 提交都重置 — 否决：在已筛选的结果里换个词，就得重新勾选全部筛选。

决策 5：信息行本版不显示"来源"

只显示"共 N 篇 · 最近同步 …"。PAP-53 验收标准中的"来源"同步删除。

备选 A：前端写死"PubMed" — 否决：接入第二个数据源后会静默过期，属于页面上的假数据。
备选 B：后端 facets 增加 sources — 否决：需要在前端 PR 里改后端，或另开后端 PR，与本版"后端契约冻结"冲突。

决策 6：前端解析时丢弃脏参数

按后端校验规则在 parsePaperSearchQuery 中过滤非法值，保证发往后端的请求一定合法。

备选：透传给后端，由 422 兜底 — 否决：RSC 中 422 抛错会让整页落到全局错误页，一个拼错的参数就能打挂整页。

决策 7：PMID / DOI 直跳放在 page 顶层 redirect，接受定位时的加载骨架

只在精确定位模式下，page 顶层 await 一次 search（第 1 页）。items.length === 1 时 redirect 到详情；未命中时复用这次结果渲染空态。由于 app/papers/loading.tsx 会在 page 外自动建立 Suspense，直接打开这类链接时响应是 HTTP 200：先输出整页骨架，再由 Next 注入跳转（经 Codex 用 Next 15.5.26 最小复现确认），而不是 307。本版接受这一点：用户看到的是约 0.3 s 的加载骨架，不会看到列表。站内从检索条或首页提交时走客户端导航，本来就不涉及 HTTP 状态码。

备选 A：去掉 loading.tsx，换取直开链接时的真 307 — 否决：从导航进入 /papers 时会失去即时骨架反馈，为少见的"直开 PMID 链接"场景牺牲高频路径。
备选 B：独立定位入口（如 /papers/lookup Route Handler 返回 307） — 否决：多一条路由和一套链接规则，而 /papers?pmid= 仍须处理；收益只是 HTTP 状态码。
备选 C：客户端 useEffect 跳转 — 否决：要先渲染完列表页再跳，用户会看到一闪而过的页面。

决策 8：期刊候选走 Route Handler + TanStack Query

/api/venues/suggest 在服务端转发，客户端用 TanStack Query 带防抖请求，按 q 缓存。

备选 A：浏览器直连后端 — 否决：gateway 地址只在服务端可见。
备选 B：Server Action — 否决：Server Action 是 POST，逐个串行执行，也不进 TanStack 缓存，不适合"边打字边查"的高频只读请求。

决策 9：标题高亮在节点树上做，前端负责

highlightInlineNodes 在 parseInlineMarkup 的结果上切分文本节点并插入 mark，RichInlineText 增加可选 highlight prop。

备选 A：在原始标题字符串里插 <mark> — 否决：可能切断标签或实体，还要额外做转义，有注入风险。
备选 B：后端返回高亮片段 — 否决：后端已合并，设计简报 A.1 也已定为前端完成。
