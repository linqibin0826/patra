## 1. 页面清单

全部在 `next build` 时预渲染（决策 B），运行时不读 `content/`。读者进度相关的部分是客户端组件，服务端 HTML 就是「新读者 / 清空本地记录后」的样子，水合后读到进度再切换。

| URL | 页面 | 画板 |
|---|---|---|
| `/` | 首页：今天读这一条 + 进度卡（老读者）/ 从这里开始 + 难度说明（新读者）、学习路线、正在长的主题、标签、最近写的 | Main |
| `/entries/<slug>` | 条目页：被取代横幅、个人环境说明、位置、类型 · 难度 · 掌握度 · 标签、标题、出处与时长、先读这几篇、正文、掌握度、上一篇 / 下一篇；侧栏：所在路线前后两篇、同一主题、读完可以接着读、出处与代码钉住的提交 | Concept / Debug / Decision / Pitfall |

## 3. 读者进度

- **存储**：`localStorage` 一个键 `patra-learn.progress`，值是 JSON：`{ "<slug>": { "level": 1|2|3, "markedAt": 毫秒, "readAt": 毫秒 } }`，三个字段都可缺。解析容错：不是对象、字段类型不对、未知 slug 一律忽略那一项，不抛错。
- **读写都 try/catch**：读不到（隐私模式、禁用存储、配额满）时按空进度处理；写失败时退到内存，本次打开的页面里标记照样生效，刷新后丢失。页面不因存储失败报错。
- **何时写**：打开条目页记 `readAt`；在条目页文末或首页回顾卡里标掌握度记 `level` 与 `markedAt`，取消标记删 `level`、保留 `readAt`；首页「清空这个浏览器里的记录」删掉整个键。
- **「读过」= 标过掌握度**（**编排期自定**）：画板的「读过 n 篇」与掌握度分段条相加相等，只打开过没标的不算读过，只用来算「最近阅读时间」。
- **钩子**：`useSyncExternalStore`，服务端快照为空进度（`ready: false`），`storage` 事件同步其他标签页。`Mastery` 组件在挂载时记下初始值，所以条目页等进度就绪后才挂载它，「上次你标的是」才显示得出来。

## 4. 今天读这一条

- **候选**（**编排期自定**）：有阅读或标记记录、不是个人环境、没有被取代、正文有诊断题的条目。从没打开过的条目不进候选，它们属于「接着读」。
- **排序**（**编排期自定**）：先按档位，再按「最近一次看到」（`readAt` 与 `markedAt` 取晚的）从旧到新，同时间按 slug。
  1. 标过「刚接触 / 理解中」且至少 1 天没看；
  2. 打开过没标的且至少 1 天没看，或标过「吃透了」且至少 30 天没看；
  3. 其余（今天刚看过的、30 天内标过「吃透了」的）。
  候选为空时第一屏显示「从这里开始」。「换一条」沿这个顺序往下走，卡上写「还有 N 条候选」。
- **理由文字**：标过的写「你标过「理解中」· 17 天没看了」，没标的写「上次看是 17 天前」，不满 1 天写「今天看过」。
- **问题与答案**（**编排期自定**）：复用每篇开头的诊断题（内容模型没有单独的回顾字段）。问题是题干；答案是正确选项文字加 `ifWrong` 的讲解，讲解开头的「答案是 B。」去掉，因为正确选项已经单独写出。构建时从正文语法树里取 `Diagnose` 的字面量参数（`mdx-rules.ts` 新导出 `readComponentProps`，与内容校验同一个解析器）。
- **新读者**：第一屏「从这里开始」用第 1 条路线（`order` 最小）的前三篇，「从第一篇读起」链到它的第一篇。

## 5. 其他由数据算出的展示（编排期自定）

| 展示 | 算法 |
|---|---|
| 阅读时长 | 正文（含组件里的题目与说明）的汉字数 / 400 + 西文词数 / 200，向上取整，至少 1 分钟 |
| 正在长的主题 | 非 `personalOnly` 的主题按其条目里最新的出处版本降序，首页取前 3 个；`/topics` 列全部 |
| 最近写的 | 非个人环境条目按最新出处版本降序（没出处的排最后），取前 3 篇 |
| 路线难度跨度 | 路线里条目的最低与最高难度，如「入门 → 实战」 |
| 条目页位置 | `order` 最小的、含本篇的路线「第 n 篇，共 m 篇」；不在路线里时用第一个主题；个人环境条目写「标签 · 个人环境」 |
| 上一篇 / 下一篇 | 同上那条路线里的前后篇 |
| 侧栏「读完可以接着读」 | 把本篇列为前置的条目。画板的「这些条目提到了它」要由正文里的条目链接生成，现有 142 篇正文没有条目间链接，做出来永远是空的，所以换成反向前置 |
| 路线页「读完这条，可以接着走」 | `order` 排在后面的两条路线（到末尾从头接） |
| 主题时间轴节点 | 按条目最早出处版本分组，节点写版本号与该组的 Issue；内容模型没有「那时发生了什么」的字段，不写这句 |
| 被取代 | 条目页页首琥珀色横幅：取代它的条目标题与其最早出处版本；主题页划掉标题，取代它的那篇写「↺ 取代了「…」」 |
| 缺失的条目 | 路线 / 前置里引用了还没写的条目时，页面跳过它（不渲染链接、不计篇数），由内容校验报 `route-entry-missing` / `prerequisite-missing` |

## 6. 个人环境（决策 E）

- 不进路线（校验已保证）、首页（推荐、最近写的、标签计数）、搜索结果、主题列表里的 `personalOnly` 主题。
- 普通标签页不列个人环境条目、计数也不算（**编排期自定**：简报 4.3「只在个人环境标签下能找到」）；`/tags/personal-env` 列全部个人环境条目，有这类条目时左侧标签表底部才出现「个人环境」。
- 搜索命中个人环境条目时只提示「另有 N 篇『个人环境』条目也提到了它」，链到 `/tags/personal-env`。
- 主题页照常列出其中的个人环境条目并带「个人环境」标记；全由个人环境条目组成的主题页存在，只从条目侧栏与个人环境标签页可达。

## 7. 搜索

浏览器里查构建时生成的索引：`/search` 的服务端组件把非个人环境条目的标题、摘要、类型、难度、标签名、所在路线名，以及个人环境条目的同样字段（只用于计数）作为 props 交给客户端组件，不建服务、不发请求。按空白分词，每个词都要在「标题 + 摘要 + 标签名 + 路线名」里出现（不区分大小写）；标题命中的排在前面，其次按难度。标题与摘要里第一个命中的词高亮。查询只存在页面状态里（**编排期自定**：不写进 URL，免得 `useSearchParams` 要求 Suspense 边界）。常搜词是代码里一份固定清单，构建时只保留有结果的。
