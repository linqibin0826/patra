# v0.15 Helpful 上线 runbook

> 一次性操作手册：把 v0.15 的后端（只改 interaction）上到 mini。
> 设计依据：release spec `docs/patra/release-specs/v0.15-helpful.md` 第 5 节 D3、D10；各 Issue 的工程 spec：
> [reaction 有帮助（PAP-131）](../specs/2026-10-29-reaction-helpful-design.md)、
> [讨论串统计（PAP-132）](../specs/2026-10-29-discussion-stats-design.md)、
> [对象统计与获赞（PAP-133）](../specs/2026-10-29-object-stats-design.md) 第 5、7 节。
>
> - 在 MacBook 的仓库根目录执行；mini 上的命令经 `ssh mini` 执行。
> - 每步给出命令、预期结果和失败时的动作。**改动 mini 的步骤，先确认上一步的预期全部满足，并征得用户同意再执行。**
> - 不打印任何密钥：命令只输出状态码、计数和名字。
> - 实测结果写回 release spec 第 5 节对应 D 项的「实际：」行。
>
> 本手册由 PAP-133 起草，覆盖 PAP-131 ~ PAP-133 的全部后端步骤。

## 1. 合并前：记录资源基线（D10）

```bash
ssh mini 'docker stats --no-stream --format "{{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}" | sort; df -h / | tail -1'
```

预期：磁盘剩余不少于 20 GB，interaction 容器内存在 1 GB 上限内。把输出写进 D10 的「实际：」行，标「上线前」。

剩余不足 20 GB：停下，先清理（旧镜像、构建缓存），不要上线。

## 2. 后端 PR 合进 main、CD 结束后：核对部署

```bash
SHA="$(git rev-parse origin/main)"   # 先 git fetch origin main，确保是这次合并的提交
until RUN_ID="$(gh run list --workflow cd.yml --commit "$SHA" -L 1 --json databaseId -q '.[0].databaseId')" && [ -n "$RUN_ID" ]; do sleep 10; done
gh run watch "$RUN_ID" --exit-status > /dev/null; echo "CD exit=$?"
gh run view "$RUN_ID" --log | grep -E '===== deploy|全部部署成功|自动回滚|✗'
```

预期：`CD exit=0`；有 `===== deploy interaction`，最后是 `✓ 全部部署成功`。

## 3. 迁移与回填（D3）

v0.15 的迁移都随 interaction 新镜像启动时由 Flyway 执行，建表与回填在同一个迁移文件里；部署时旧容器先停、新容器才迁移，回填期间没有写入。

### 3.1 迁移都成功

```bash
ssh mini 'export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH";
  docker exec patra-postgres psql -U postgres -d patra_interaction -At -c "
    SELECT version, success FROM public.flyway_schema_history
     WHERE version >= '"'"'20261029200000'"'"' ORDER BY installed_rank;"'
```

预期：每行 `success` 都是 `t`，至少有：

| 版本 | 内容 | Issue |
|---|---|---|
| `20261029200000`、`20261029200100` | 建 `reaction` schema 与三张表 | PAP-131 |
| `20261029200200` | 发表守卫允许 `HELPFUL` 种类 | PAP-131 |
| `20261029230000` | 建 `collection.subject_stats` 并回填收藏人数 | PAP-133 |
| `20261029210000` | 建 `discussion.thread_stats`、`discussion.subject_stats` 并回填 | PAP-132 |

interaction 日志报 `Migration checksum mismatch` / `Validate failed`：已在 mini 上执行过的脚本被改了，处理办法同 v0.13 runbook 第 5 步的退路表。

### 3.2 收藏人数回填与明细一致（只读）

```bash
ssh mini 'export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH";
  docker exec -e PGOPTIONS="-c default_transaction_read_only=on" patra-postgres \
  psql -U postgres -d patra_interaction -At -c "
    SELECT count(*) FROM (SELECT subject_id, count(*) n FROM collection.library_item GROUP BY subject_id) d
      FULL JOIN collection.subject_stats s ON s.subject_id = d.subject_id
     WHERE COALESCE(d.n, 0) <> COALESCE(s.collector_count, 0);"'
```

预期：`0`。

### 3.3 讨论统计回填与明细一致（只读，PAP-132）

```bash
ssh mini 'export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH";
  docker exec -e PGOPTIONS="-c default_transaction_read_only=on" patra-postgres \
  psql -U postgres -d patra_interaction -At -c "
    SELECT count(*) FROM (SELECT root_id, count(*) FILTER (WHERE state = '"'"'ACTIVE'"'"') n,
                                 max(created_at) FILTER (WHERE state = '"'"'ACTIVE'"'"') last_at
                            FROM discussion.comment WHERE parent_id IS NOT NULL GROUP BY root_id) d
      FULL JOIN discussion.thread_stats s ON s.root_id = d.root_id
     WHERE COALESCE(d.n, 0) <> COALESCE(s.reply_count, 0) OR d.last_at IS DISTINCT FROM s.last_reply_at;
    SELECT count(*) FROM (SELECT subject_id, count(*) FILTER (WHERE state = '"'"'ACTIVE'"'"') n
                            FROM discussion.comment GROUP BY subject_id) d
      FULL JOIN discussion.subject_stats s ON s.subject_id = d.subject_id
     WHERE COALESCE(d.n, 0) <> COALESCE(s.comment_count, 0);"'
```

预期：两行都是 `0`。

## 4. 登记并执行一次按明细重算（D3）

### 4.1 登记任务

在 xxl-job-admin「任务管理」新增：执行器 `patra-interaction`，JobHandler `statsRecountJob`，**调度类型「无」（只手动触发）**，运行模式 BEAN，路由策略「第一个」，阻塞处理「单机串行」，超时 600 秒，失败重试 0 次，描述「按明细重算公开计数（手动）」。

也可以用接口登记（先在页面上核对一次参数名与调度中心版本一致）：

```bash
BASE=http://linqibins-mac-mini:7070/xxl-job-admin; CK="$(mktemp)"
read -rs -p 'xxl-job admin 密码: ' PW; echo
curl -s --noproxy '*' -c "$CK" "$BASE/auth/doLogin" --data-urlencode userName=admin --data-urlencode "password=$PW" -o /dev/null -w '%{http_code}\n'
# 找 patra-interaction 执行器的 jobGroup
curl -s --noproxy '*' -b "$CK" "$BASE/jobgroup/pageList" -d 'appname=patra-interaction&start=0&length=10' | jq '.data[] | {id, appname}'
GROUP=<上一步的 id>
curl -s --noproxy '*' -b "$CK" "$BASE/jobinfo/add" \
  --data-urlencode jobGroup="$GROUP" --data-urlencode jobDesc='按明细重算公开计数（手动）' \
  --data-urlencode author=linqibin --data-urlencode scheduleType=NONE --data-urlencode glueType=BEAN \
  --data-urlencode executorHandler=statsRecountJob --data-urlencode executorRouteStrategy=FIRST \
  --data-urlencode misfireStrategy=DO_NOTHING --data-urlencode executorBlockStrategy=SERIAL_EXECUTION \
  --data-urlencode executorTimeout=600 --data-urlencode executorFailRetryCount=0
# 期望：{"code":200,"content":"<jobId>"}
```

### 4.2 手动执行一次

```bash
JOB=<上一步的 jobId>
curl -s --noproxy '*' -b "$CK" "$BASE/jobinfo/trigger" --data-urlencode id="$JOB" --data-urlencode executorParam= --data-urlencode addressList=
sleep 10
curl -s --noproxy '*' -b "$CK" "$BASE/joblog/pageList" -d "jobGroup=$GROUP&jobId=$JOB&logStatus=-1&start=0&length=1&filterTime=" \
  | jq '.data[0] | {triggerCode, handleCode, handleMsg}'
ssh mini 'docker logs patra-interaction --since 5m 2>&1 | grep -E "统计重算(完成|修正)"'
```

预期：`handleCode` 为 200，`handleMsg` 形如 `差异 0 行：{collection.collector_count=0, discussion.comment_count=0, discussion.thread_stats=0, reaction.helpful_count=0, reaction.helpful_received=0}`；日志只有一行 `统计重算完成: corrected=0, …`，没有 `统计重算修正` 行。把 `handleMsg` 写进 D3 的「实际：」行。

差异不为 0：日志里每个 `统计重算修正: counter=…, key=…, before=…, after=…` 是一行被改过的统计。重算已经把它们改对了；先把这些行交给用户，查是回填口径与写方口径不一致，还是上线前就有坏数据，再决定要不要修代码。再跑一次应为 0。

任务执行失败（`执行失败：…`）：看 interaction 日志里的堆栈；重算每个键一个事务，失败前改对的行已经提交，修好后重跑即可。

## 6. 回滚

v0.15 的迁移只建新表、加约束种类与回填，旧镜像不读这些表，照常工作，不需要撤销。回滚到旧镜像期间，收藏、评论的写入都不维护新的统计表（`collection.subject_stats`、`discussion.thread_stats`、`discussion.subject_stats`），各项统计都可能漂移；比明细少的统计行会让之后的移出、删回复撞上计数非负约束报 500。所以**再升级后立即手动执行一次 `statsRecountJob`**（第 4.2 节），执行结果里的差异就是回滚期间漂移的行。
