# v0.11 全文阅读 运维手册

> 版本：[v0.11 Full Text Reader](../release-specs/v0.11-fulltext-reader.md) · 工程 spec：[全文阅读后端](../specs/2026-10-19-fulltext-reader-backend-design.md)

本手册记录 v0.11 新增的三个 XXL-Job 怎么建、怎么跑、出问题怎么查。XXL-Job 的任务都在控制台手工建，没有种子 SQL。

## 1. PubMed 文件导入（`pubmedImportJob`）

> v0.13（PAP-110）起 baseline 与 updatefiles 合成一条可重放的导入流水线，本节随之改写；原 `pubmedUpdateSyncJob` / `pubmedBaselineImportJob` 已删除。设计见 [文献引用数据、可重放导入与导出](../specs/2026-10-24-catalog-citation-data-export-design.md) 第 5 节，上线回填步骤见第 9 节。

参数留空时是每日增量：从进度表 `cat_pubmed_file` 里最小的未完成 UPDATE 文件开始（没有则最后一个成功 UPDATE 文件的下一个），按文件号依次处理 NLM updatefiles 到最新，跳过其间已成功的文件；遇到失败的文件就停下，下次运行从它重试，并续跑它上次的作业实例（进度表 `job_generation` 列）。每个文件先按 `.md5` 旁文件校验；比库里旧的记录跳过（`skipped_stale`），所以任何文件都可以重放而不会回退。

### 1.1 建任务

| 项 | 值 |
|---|---|
| 执行器 | patra-catalog |
| JobHandler | `pubmedImportJob` |
| 调度类型 | CRON `0 0 5 * * ?`（Asia/Shanghai；NLM 美东 14:00 前后发布，即北京时间次日 02:00 ~ 03:00） |
| 子任务 ID | 全文抓取任务（2.1 节第一条）的 ID，建好后回填 |
| 运行模式 | BEAN |
| 阻塞处理策略 | 单机串行 |
| 任务参数 | 留空（见 1.2） |

另建一条手动任务 `pubmedReparseJob`（不配 CRON、无参数）：不联网，从来源表 `cat_publication_source` 读每篇的原文重新解析覆盖，解析器升级后回填用。它与导入共用一把锁。

### 1.2 参数

都可以省略，用逗号分隔：

| 参数 | 含义 |
|---|---|
| `kind=BASELINE\|UPDATE` | 文件目录，缺省 `UPDATE`。`BASELINE` 必须给 `from` |
| `from=N` | 起始文件号。UPDATE 缺省按进度表续跑 |
| `to=M` | 结束文件号（含）。BASELINE 缺省等于 `from`，UPDATE 缺省为最新 |
| `maxFiles=K` | 本次最多处理 K 个文件，首次追赶时分批用 |
| `scope=EXISTING_ONLY\|ALL` | 覆盖配置 `patra.catalog.pubmed.scope`。`EXISTING_ONLY` 只更新库里已有的文献 |
| `reprocess=true` | 已成功的文件也重跑，换新的作业实例重放（用于换 `scope` 或回填新字段）；未完成的文件续跑它上次的实例 |

配置（默认值在 `PubmedDataSourceProperties`，环境差异在 Nacos `patra-catalog.yaml`）：

| 键 | 默认 | 开发环境（mini） |
|---|---|---|
| `patra.catalog.pubmed.baseline-url` | `https://ftp.ncbi.nlm.nih.gov/pubmed/baseline/` | 同默认 |
| `patra.catalog.pubmed.update-url` | `https://ftp.ncbi.nlm.nih.gov/pubmed/updatefiles/` | 同默认 |
| `patra.catalog.pubmed.file-prefix` | `pubmed26n` | 同默认 |
| `patra.catalog.pubmed.scope` | `EXISTING_ONLY` | `EXISTING_ONLY`（绝不改成 `ALL`） |
| `patra.catalog.pubmed.update-start-seq` | `1335`（2026 年第一个 updatefile） | 同默认 |

### 1.3 查进度

```sql
SELECT kind, file_seq, status, scope, updated_count, created_count, deleted_count,
       skipped_absent_count, skipped_stale_count, skipped_invalid_count, doi_conflict_count,
       skip_error_count, started_at, finished_at, last_error
FROM cat_pubmed_file
ORDER BY file_seq DESC
LIMIT 20;
```

- `FAILED`：看 `last_error`，修好后直接再触发一次，会从这个文件续传。md5 连续 3 次不符也记 `FAILED`。
- `skipped_invalid_count` 不为 0：单篇解析或校验失败被跳过（年份不在 1800 ~ 2100、缺标题等），在任务日志里搜 `跳过无效 PubMed 记录`（带 PMID 与文件名）。
- `skip_error_count` 不为 0：写入时撞了唯一约束被跳过，按 PMID 在任务日志里搜 `PubMed 导入写入出错被跳过`。
- 另一个导入或重算实例正在运行时，本次任务记成功，消息是"另一个 PubMed 导入或重算实例正在运行，本次跳过"。

## 2. PMC 全文抓取（`pmcFullTextFetchJob`）

按批取到期候选（有 PMCID 且没有全文记录、抓取失败到期、PMCID 变了、暂不可用到期），并发从 PMC Cloud Service 下载 XML、PDF、正文图片写入 MinIO 桶 `patra-catalog-fulltext`，直到取不到候选为止。

### 2.1 建任务

同一个 handler 建两条：

| 项 | 子任务那条 | 兜底那条 |
|---|---|---|
| JobHandler | `pmcFullTextFetchJob` | `pmcFullTextFetchJob` |
| 调度类型 | 无（只作为增量同步的子任务被触发） | CRON `0 30 * * * ?`（每小时第 30 分） |
| 子任务 ID | 解析任务（3.1 节子任务那条）的 ID，建好后回填 | 不配 |
| 阻塞处理策略 | 单机串行 | 单机串行 |

两条撞上时，后启动的那条拿不到任务锁，直接返回成功、统计为 0。

建完这两条后，回到 1.1 节把子任务那条的 ID 填进增量同步的"子任务 ID"。

### 2.2 参数

| 参数 | 含义 |
|---|---|
| 留空 | 处理全部到期候选 |
| `publicationIds=1,2,3` | 手动重抓这几篇，忽略当前状态 |

配置（默认值在 record 里）：`patra.catalog.fulltext.fetch.batch-size`（200）、`concurrency`（4）、`max-attempts`（8）、`patra.catalog.fulltext.bucket`（`patra-catalog-fulltext`）、`patra.catalog.fulltext.pmc.base-url`。

### 2.3 查状态

```sql
SELECT status, unavailable_reason, count(*)
FROM cat_publication_fulltext
GROUP BY status, unavailable_reason
ORDER BY 1, 2;

-- 超过重试上限、等人工处理的
SELECT publication_id, pmcid, attempt_count, last_error
FROM cat_publication_fulltext
WHERE status = 'FETCH_FAILED' AND attempt_count >= 8
ORDER BY next_attempt_at DESC
LIMIT 50;
```

修好原因后用 `publicationIds=…` 手动重抓。

## 3. JATS 全文解析（`jatsFullTextParseJob`）

从 MinIO 读已抓取的 XML，解析成正文 JSON 写入 `cat_publication_fulltext_body`，记录变为 `PARSED`（或 `UNAVAILABLE / NO_BODY`、`PARSE_FAILED`），并更新 `cat_publication_metadata.has_full_text`。全程不访问 PMC。

### 3.1 建任务

| 项 | 子任务那条 | 兜底那条 |
|---|---|---|
| JobHandler | `jatsFullTextParseJob` | `jatsFullTextParseJob` |
| 调度类型 | 无（只作为全文抓取的子任务被触发） | CRON `0 45 * * * ?`（每小时第 45 分） |
| 子任务 ID | 不配 | 不配 |
| 阻塞处理策略 | 单机串行 | 单机串行 |
| 任务参数 | 留空 | 留空 |

建完后回到 2.1 节，把子任务那条的 ID 填进全文抓取的"子任务 ID"。

### 3.2 全量重新解析

改了解析规则时：

1. 把 `JatsBodyParserPort.PARSER_VERSION` 加 1，随代码合并部署；
2. 手动触发一次解析任务（或等兜底任务）。`PARSED`、`PARSE_FAILED`、`NO_BODY` 中版本较低的都会重新解析；读的是 MinIO 里已有的 XML，不重新下载。

### 3.3 查状态

```sql
SELECT status, unavailable_reason, parser_version, count(*)
FROM cat_publication_fulltext
WHERE status IN ('FETCHED', 'PARSED', 'PARSE_FAILED') OR unavailable_reason = 'NO_BODY'
GROUP BY 1, 2, 3
ORDER BY 1, 2, 3;

-- 解析失败的原因
SELECT publication_id, pmcid, last_error
FROM cat_publication_fulltext
WHERE status = 'PARSE_FAILED'
ORDER BY parsed_at DESC
LIMIT 50;
```

## 4. mini 验收（release spec 第 5 节）

> 本节是 v0.11 验收的历史记录，已执行完毕。其中的 `pubmedUpdateSyncJob`、`pubmedBaselineImportJob` 与参数 `fileIndex`、`fromFile` 已被 v0.13（PAP-110）的 `pubmedImportJob` 取代（对应写法：`maxFiles=20`；`kind=BASELINE,from=1200`；`kind=UPDATE,from=1335,reprocess=true`），参数见第 1.2 节。

后端 PR 合入、CD 部署到 mini 后按顺序执行，结果回写 release spec 第 5 节的"实际："行。

### 4.1 首次追赶增量同步（D2）

先记一次补全前的 PMCID 占比（下面 4.4 的第一条 SQL），然后分批追赶：n1335 到最新约 350 个文件，每个约 1 万条记录。

1. 手动触发 `pubmedUpdateSyncJob`，参数 `maxFiles=20`，看 1.3 节的进度表确认计数正常；
2. 正常后参数留空再触发，一次追到最新（之后每天 05:00 自动跑）；
3. 追完再记一次 PMCID 占比，目标 ≥ 40%。

### 4.2 抓取与解析（D3）

增量同步成功后会依次触发抓取与解析（子任务）。首次候选量大，抓取可能跑几个小时，期间每小时的兜底任务会因拿不到锁直接返回。跑完后按 2.3、3.3 节查状态，并检查：

- 每篇候选都有全文记录（4.4 的第二条 SQL 结果为 0）；
- `FETCH_FAILED` 与 `PARSE_FAILED` 合计 < 2%，每条有 `last_error`；
- 图片都读出了宽高。webp 靠 TwelveMonkeys 插件读取，打包后的 jar 里插件没注册时，宽高会是空值，下面的 SQL 应返回 0：

```sql
SELECT count(*)
  FROM cat_publication_fulltext f, jsonb_array_elements(f.media) m
 WHERE f.status IN ('FETCHED', 'PARSED')
   AND m->>'name' ILIKE '%.webp'
   AND (m->'width' IS NULL OR m->'width' = 'null'::jsonb);
```

较早文献的验证：导入一个较早的 baseline 文件（`pubmedBaselineImportJob` 参数 `fileIndex=1200`），再用 `fromFile=1335` 重放增量同步，确认其中的文献也走完"同步 → 抓取 → 解析"。

抓取候选分三路查询，几百万行时要看执行计划：

```sql
-- 新文献（预期 NOT EXISTS 走 uk_publication_fulltext_publication 的反连接）
EXPLAIN (ANALYZE, BUFFERS)
SELECT DISTINCT ON (i.publication_id) i.publication_id, i.identifier_value
  FROM cat_publication_identifier i
  JOIN cat_publication p ON p.id = i.publication_id AND p.deleted_at IS NULL
 WHERE i.type = 'pmc' AND i.publication_id > 0
   AND NOT EXISTS (SELECT 1 FROM cat_publication_fulltext f WHERE f.publication_id = i.publication_id)
 ORDER BY i.publication_id, i.id
 LIMIT 200;

-- 到期重试与再查（预期走 idx_fulltext_status_next）
EXPLAIN (ANALYZE, BUFFERS)
SELECT f.publication_id
  FROM cat_publication_fulltext f
 WHERE f.status IN ('FETCH_FAILED', 'UNAVAILABLE') AND f.next_attempt_at <= now()
   AND ((f.status = 'FETCH_FAILED' AND f.attempt_count < 8)
        OR (f.status = 'UNAVAILABLE' AND f.unavailable_reason IN ('NOT_IN_BUCKET', 'NOT_OPEN_ACCESS')))
 ORDER BY f.next_attempt_at, f.publication_id
 LIMIT 200;
```

### 4.3 最大 PDF 完整下载（D6）

```sql
SELECT publication_id, pmcid, pdf_size, pdf_md5
FROM cat_publication_fulltext
WHERE pdf_object_key IS NOT NULL
ORDER BY pdf_size DESC
LIMIT 1;
```

经门户的同源转发地址下载（门户 Route Handler 由 PAP-88 提供），算 md5 与 `pdf_md5` 比对：

```bash
curl -sS -o /tmp/largest.pdf "http://100.103.73.27:4000/api/papers/<publication_id>/pdf" && md5 /tmp/largest.pdf
```

### 4.4 查数 SQL

```sql
-- 带 PMCID 的文献占比（D2）
SELECT round(100.0 * count(DISTINCT i.publication_id) / (SELECT count(*) FROM cat_publication WHERE deleted_at IS NULL), 1) AS pmcid_pct
FROM cat_publication_identifier i
JOIN cat_publication p ON p.id = i.publication_id AND p.deleted_at IS NULL
WHERE i.type = 'pmc';

-- 有 PMCID 却还没有全文记录的篇数（D3，跑完后应为 0）
SELECT count(DISTINCT i.publication_id)
FROM cat_publication_identifier i
JOIN cat_publication p ON p.id = i.publication_id AND p.deleted_at IS NULL
LEFT JOIN cat_publication_fulltext f ON f.publication_id = i.publication_id
WHERE i.type = 'pmc' AND f.id IS NULL;

-- 可读全文、有 PDF、is_oa 篇数（D3）
SELECT
  (SELECT count(*) FROM cat_publication_fulltext f JOIN cat_publication p ON p.id = f.publication_id AND p.deleted_at IS NULL
    WHERE f.status = 'PARSED') AS readable,
  (SELECT count(*) FROM cat_publication_fulltext f JOIN cat_publication p ON p.id = f.publication_id AND p.deleted_at IS NULL
    WHERE f.pdf_object_key IS NOT NULL) AS with_pdf,
  (SELECT count(*) FROM cat_publication WHERE deleted_at IS NULL AND is_oa) AS is_oa;
```
