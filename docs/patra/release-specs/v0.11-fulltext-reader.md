## 1. 版本目标 / 价值

打开一篇在 PMC 开放获取子集里的文献，能在 Patra 详情页直接读完整正文（章节目录、图表、参考文献），也能下载期刊原版 PDF（PMC 提供了才有）。原文由后台任务批量抓取入库，详情页打开即读。没有全文的文献，页面说清原因并给出去原文的出口。

**规划时的数据现状**（mini，2026-10-18）：

- 库内 18,807 篇文献全部来自 2026 baseline 最后一个文件 `pubmed26n1333`，带 PMCID 的只有 1,337 篇（7%）。原因是记录停在 baseline 生成时，PMCID 后来才由 PubMed 修订补上，而 catalog 不导入 updatefiles。抽查 40 篇缺 PMCID 的文献，当前 PubMed 记录全部已带 PMCID。
- 抽样 400 篇查 Europe PMC：48% 有 PMCID，46% 在 PMC 开放获取子集。补齐 PMCID 后，可读全文的文献预计约占全库 46%。
- 根因已核实，改用 PubMed updatefiles 增量同步让记录跟上 PubMed（决策 H），不再用 Europe PMC 回查。2026 年的 updatefiles 从 `pubmed26n1335` 开始，规划时已有 353 个文件，每个约 1 万条记录。
- 库内没有原文；`is_oa`、`oa_status`、`cat_publication_oa_location`、`has_full_text` 均无写入路径。
- PMC OA Web Service（oa.fcgi）与 FTP 批量文件已于 2026-08 下线，原文改从 PMC Cloud Service（公开 S3 桶 `pmc-oa-opendata`）获取；mini 直连该桶可用。

**验证场景**：

1. 从首页或检索点开一篇有 PMC 全文的文献，在详情页读到某一节、点引用跳到参考文献，再点"下载 PDF"拿到原版文件。
2. 点开一篇没有全文的文献，页面显示"无开放全文"，保留"去全文 · DOI"出口。

## 3. 范围边界（不做的事）

| # | 不做的事 | 理由 |
|---|---------|------|
| A | 已抓到的全文不做定期复查 | 只抓一次，页面标抓取日期并链接 PMC 最新版（满足 PMC 条款"保持最新或明示可能不是最新"的后一种）；撤稿由增量同步带来的 PubMed 撤稿标记在展示时下线 |
| B | 不抓 PMC 以外的开放获取原文 | 出版商官网的 OA HTML / PDF（Unpaywall、Crossref 链接等）格式各异，没有统一 XML；这类文献保留"去全文 · DOI"出口 |
| C | 不展示"在 PMC 免费可读但没有开放许可"的文章 | 没有转载许可，PMC Cloud Service 也没有文件；只给去 PMC 的链接 |
| D | 不自己生成 PDF | PMC 没提供原版 PDF 的文献不显示下载按钮 |
| E | 不展示补充材料和多媒体 | 只做正文、图、表、参考文献；补充材料文件、视频、数据集不下载也不展示 |
| F | 正文不进检索 | 文献检索仍只搜标题、摘要等元数据 |
| G | 不做阅读辅助功能 | 划词翻译、高亮批注、参考文献跳 Patra 内部详情页、用全文生成 AI 速读都不做；AI 速读卡片保持"即将上线" |

## 4. 关键决策

> 依据：2026-10-18 规划时对 catalog 架构、对象存储、网关与门户链路、历史文档与 ingest、PMC / Europe PMC 外部数据的五路调研；2026-10-19 写后端工程 spec（`docs/patra/specs/2026-10-19-fulltext-reader-backend-design.md`）时改用增量同步（决策 H），并据此改写 A / B / D / E。

### A. 全部放在 catalog，作为 publication 的补充数据

- **影响 Issue**：PAP-84 / 85 / 86 / 87
- **决策**：增量同步、抓取、解析、读端点都在 `patra-catalog`，按 `PublicationOaLocation` 的"聚合边界外补充数据"建模，新建独立的全文 Repository，不往现有 `PublicationRepository` 里加。增量同步与 baseline 导入共用解析与写入代码。抓取与解析任务沿用 LetPub / Scopus 补全任务的写法（XXL-Job → Runner / Worker / Persister）。文件由 catalog 用 `patra-tool-object-storage` 直写专用桶，与期刊封面一致，不经 `patra-object-storage` 服务登记。

### B. 原始文件存 MinIO，结构化正文与处理状态存 PG

- **影响 Issue**：PAP-85 / 86 / 87
- **决策**：JATS XML、正文图片、PDF 放 MinIO。解析后的正文在 PG 里一篇一行，整篇存为一个 JSONB 文档，不拆章节表 / 段落表（正文总是整篇读出，又不做全文检索）。同一行记处理状态（待抓取 / 已抓取 / 已解析 / 无原文 / 出错）与失败次数，区分"确实没有原文"和"中途出错"：出错的按退避重试，暂不可用的（禁发期内、PMC 尚未上架）按放开日期或退避再查。

### C. 前后端交换 Patra 自己的正文结构；全文单独一个接口

- **影响 Issue**：PAP-86 / 87 / 88
- **决策**：后端把 JATS 解析成章节、块、行内节点三层结构，前端按结构渲染。不选后端输出 HTML（注入风险、样式难控），也不选前端解析 XML。行内节点沿用门户摘要 `RichInlineText` 的白名单渲染做法，补上引用跳转和图片节点；公式用 MathML 由浏览器原生渲染（PMC 桶内没有 XML 引用的公式图片），不引入新的前端依赖。新增 `GET /portal/publications/{id}/fulltext`，详情接口只加有无全文、有无 PDF、阅读时长三个字段，整篇正文不塞进详情接口。只做格式转换、不改写内容（ND 许可只允许格式转换）。

### D. 展示门槛：PMC 标记开放获取且未撤稿；页面必须署名

- **影响 Issue**：PAP-85 / 87 / 88
- **决策**：以 PMC 元数据为准：`is_pmc_openaccess = true` 且 `is_retracted = false` 才抓取。撤稿判定分两处：抓取时看 PMC 的 `is_retracted`；展示时看 PubMed 文献类型是否含 `Retracted Publication`（由增量同步带来），已抓到的全文在文献被撤稿后自动停止展示。页面必须显示许可类型（元数据许可为空时显示"许可见原文"）、作者与出处（期刊、DOI、PMC 链接）和"数据来源：美国国家医学图书馆 NLM"；不使用 PMC 标志。

### E. 抓取与解析分开；已抓到的不复查

- **影响 Issue**：PAP-85 / 86 / 88
- **决策**：解析任务读 MinIO 里的原始 XML，解析器改进后可全量重新解析，不重新下载。每篇按元数据挑开放获取的版本，不取最大版本号（版本号不代表新旧，同一 PMCID 可能并存手稿版与正式版）。已抓到的全文不复查：页面显示抓取日期并链接 PMC 最新版，满足 PMC 条款"保持最新或明示可能不是最新"的后一种。暂不可用的文章（不在桶里、未开放获取）按 PubMed 记录里的 PMC 放开日期或退避再查。

### F. PDF 与图片经门户同源接口转发

- **影响 Issue**：PAP-87 / 88
- **决策**：浏览器 → 门户 Route Handler（如 `/api/papers/[id]/pdf`）→ `gatewayFetch` → 网关 → catalog 从 MinIO 流式读出。门户是 BFF，浏览器访问不到网关；已有 `/api/venues/suggest` 转发先例。不用 MinIO 预签名链接，不开公开桶。缓存头、类型、下载文件名由 catalog 设置（网关不补缓存头）。网关读超时是 60 秒空闲超时（下游持续发数据就不断，2026-10-19 由总时长改来），由 Done 判定 D6 实测最大 PDF 兜底。

### G. PMC 开放获取写进 OA 位置表和 `is_oa`

- **影响 Issue**：PAP-85 / 87 + 现有文献检索的"开放获取"筛选
- **决策**：确认 PMC 开放获取后同时写入：`cat_publication_oa_location` 一条 PMC 记录（带许可，改写后的 `PublicationOaLocation.ofPmc`）、`cat_publication.is_oa = true`、`has_full_text` 表示站内可读。`oa_status` 保持空（PMC 不提供金色 / 绿色之分）。"开放获取"筛选第一次有数据，含义为"确认开放获取"，未确认的仍为 false。

### H. 用 PubMed updatefiles 增量同步取代 Europe PMC 回查

- **影响 Issue**：PAP-84 / 85 + 现有文献检索与详情
- **决策**：PMCID 缺失的根因是 catalog 的记录停在 baseline 生成那一刻；增量同步让整条记录跟上 PubMed，PMCID、撤稿、勘误、删除都随之同步，少接一个外部数据源。覆盖规则：内部 ID 不变；PubMed 管的部分（主表来源列、metadata 的七个 PubMed 列、`source = 'PubMed'` 的标识符、各子表）全部替换；别的流程写的字段（`is_oa`、`citation_count`、`has_full_text`、OA 位置、全文记录等）保留；`last_synced_at` 更新为同步时间。导入范围可配：只更新已有 / 新文献也导入；mini 只更新已有。细节见工程 spec 第 4 节。

> **不进本字段**：正文放详情页内还是单开阅读页（PAP-83 决定）；正文结构字段定义、表结构、MinIO 对象命名规则（各 Issue 工程 spec 决定）。
