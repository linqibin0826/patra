# v0.11 Full Text Reader：开放获取全文阅读

> **目标**：PMC 开放获取子集里的文献，在 Patra 详情页直接读完整正文、下载期刊原版 PDF；原文由后台任务批量抓取入库。
> **Linear Project**：[v0.11 Full Text Reader](https://linear.app/papertrace/project/v011-full-text-reader-e38a9ec4eb5c)（P-PAP-8）
> **Issue 池**：PAP-83 ~ PAP-88（Design 1 + BE 4 + FE 1）
> **创建日期**：2026-10-18
> **状态**：进行中
> **上一版**：[v0.10-tool-reorg](v0.10-tool-reorg.md)（工具层重组）

## 1. 版本目标 / 价值

打开一篇在 PMC 开放获取子集里的文献，能在 Patra 详情页直接读完整正文（章节目录、图表、参考文献），也能下载期刊原版 PDF（PMC 提供了才有）。原文由后台任务批量抓取入库，详情页打开即读。没有全文的文献，页面说清原因并给出去原文的出口。

**规划时的数据现状**（mini，2026-10-18）：

- 库内 18,807 篇文献全部来自 2026 baseline 最后一个文件 `pubmed26n1333`，带 PMCID 的只有 1,337 篇（7%）。原因是记录停在 baseline 生成时，PMCID 后来才由 PubMed 修订补上，而 catalog 不导入 updatefiles。抽查 40 篇缺 PMCID 的文献，当前 PubMed 记录全部已带 PMCID。
- 抽样 400 篇查 Europe PMC：48% 有 PMCID，46% 在 PMC 开放获取子集。补齐 PMCID 后，可读全文的文献预计约占全库 46%。
- 库内没有原文；`is_oa`、`oa_status`、`cat_publication_oa_location`、`has_full_text` 均无写入路径。
- PMC OA Web Service（oa.fcgi）与 FTP 批量文件已于 2026-08 下线，原文改从 PMC Cloud Service（公开 S3 桶 `pmc-oa-opendata`）获取；mini 直连该桶与 Europe PMC 均可用。

**验证场景**：

1. 从首页或检索点开一篇有 PMC 全文的文献，在详情页读到某一节、点引用跳到参考文献，再点"下载 PDF"拿到原版文件。
2. 点开一篇没有全文的文献，页面显示"无开放全文"，保留"去全文 · DOI"出口。

## 3. 范围边界（不做的事）

| # | 不做的事 | 理由 |
|---|---------|------|
| A | 不导入 PubMed updatefiles | 本版只补 PMCID 这一个字段；记录的其他修订、撤稿、删除不同步，那是让 catalog 跟上 PubMed 的另一件事 |
| B | 不抓 PMC 以外的开放获取原文 | 出版商官网的 OA HTML / PDF（Unpaywall、Crossref 链接等）格式各异，没有统一 XML；这类文献保留"去全文 · DOI"出口 |
| C | 不展示"在 PMC 免费可读但没有开放许可"的文章 | 没有转载许可，PMC Cloud Service 也没有文件；只给去 PMC 的链接 |
| D | 不自己生成 PDF | PMC 没提供原版 PDF 的文献不显示下载按钮 |
| E | 不展示补充材料和多媒体 | 只做正文、图、表、参考文献；补充材料文件、视频、数据集不下载也不展示 |
| F | 正文不进检索 | 文献检索仍只搜标题、摘要等元数据 |
| G | 不做阅读辅助功能 | 划词翻译、高亮批注、参考文献跳 Patra 内部详情页、用全文生成 AI 速读都不做；AI 速读卡片保持"即将上线" |

## 4. 关键决策

> 依据：2026-10-18 规划时对 catalog 架构、对象存储、网关与门户链路、历史文档与 ingest、PMC / Europe PMC 外部数据的五路调研。

### A. 全部放在 catalog，作为 publication 的补充数据

- **影响 Issue**：PAP-84 / 85 / 86 / 87
- **决策**：补 PMCID、抓取、解析、读端点都在 `patra-catalog`，按 `PublicationOaLocation` 的"聚合边界外补充数据"建模，新建独立的全文 Repository，不往现有 `PublicationRepository` 里加。Europe PMC 客户端在 catalog 内按 OpenAlex 客户端的写法新建，不复用 ingest 的 `EpmcClientAdapter`（只有检索一个接口，ingest 去留未定）。补 PMCID 任务沿用 LetPub / Scopus 补全任务的写法（XXL-Job → Runner / Worker / Persister）；追加 PMCID 不能用 `replaceIdentifiersBatch`（整表删后重插）。文件由 catalog 用 `patra-tool-object-storage` 直写专用桶，与期刊封面一致，不经 `patra-object-storage` 服务登记。

### B. 原始文件存 MinIO，结构化正文与处理状态存 PG

- **影响 Issue**：PAP-85 / 86 / 87
- **决策**：JATS XML、正文图片、PDF 放 MinIO。解析后的正文在 PG 里一篇一行，整篇存为一个 JSONB 文档，不拆章节表 / 段落表（正文总是整篇读出，又不做全文检索）。同一行记处理状态（待抓取 / 已抓取 / 已解析 / 无原文 / 出错）与失败次数，区分"确实没有原文"和"中途出错"：出错的下次重试，无原文的不再反复查。

### C. 前后端交换 Patra 自己的正文结构；全文单独一个接口

- **影响 Issue**：PAP-86 / 87 / 88
- **决策**：后端把 JATS 解析成章节、块、行内节点三层结构，前端按结构渲染。不选后端输出 HTML（注入风险、样式难控），也不选前端解析 XML。行内节点沿用门户摘要 `RichInlineText` 的白名单渲染做法，补上引用跳转和图片节点；公式用 MathML 由浏览器原生渲染（PMC 桶内没有 XML 引用的公式图片），不引入新的前端依赖。新增 `GET /portal/publications/{id}/fulltext`，详情接口只加有无全文、有无 PDF、阅读时长三个字段，整篇正文不塞进详情接口。只做格式转换、不改写内容（ND 许可只允许格式转换）。

### D. 展示门槛：PMC 标记开放获取且未撤稿；页面必须署名

- **影响 Issue**：PAP-84 / 85 / 88
- **决策**：以 PMC 元数据为准：`is_pmc_openaccess = true` 且 `is_retracted = false` 才抓取展示。Europe PMC 只用来找候选（它的 `isOpenAccess` 与 PMC 一致；`hasPDF` 对作者手稿也是 Y，不能用来判断有无 PDF）。页面必须显示许可类型（元数据许可为空时显示"许可见原文"）、作者与出处（期刊、DOI、PMC 链接）和"数据来源：美国国家医学图书馆 NLM"；不使用 PMC 标志。

### E. 抓取与解析分开；靠定期复查保持最新

- **影响 Issue**：PAP-85 / 86 / 88
- **决策**：解析任务读 MinIO 里的原始 XML，解析器改进后可全量重新解析，不重新下载。每篇按元数据挑开放获取的版本，不取最大版本号（版本号不代表新旧，同一 PMCID 可能并存手稿版与正式版）。定期复查已入库文章的元数据：md5 变了重新抓取，元数据消失（被 PMC 撤下）停止展示。PMC 条款要求再分发"保持最新或明示可能不是最新"，页面显示抓取日期。不用 PMC 每日清单文件做全量对账，逐篇复查即可。

### F. PDF 与图片经门户同源接口转发

- **影响 Issue**：PAP-87 / 88
- **决策**：浏览器 → 门户 Route Handler（如 `/api/papers/[id]/pdf`）→ `gatewayFetch` → 网关 → catalog 从 MinIO 流式读出。门户是 BFF，浏览器访问不到网关；已有 `/api/venues/suggest` 转发先例。不用 MinIO 预签名链接，不开公开桶。缓存头、类型、下载文件名由 catalog 设置（网关不补缓存头）。网关读超时为 60 秒总时长（含流式），由 Done 判定 D6 实测最大 PDF 兜底。

### G. PMC 开放获取写进 OA 位置表和 `is_oa`

- **影响 Issue**：PAP-85 / 87 + 现有文献检索的"开放获取"筛选
- **决策**：确认 PMC 开放获取后同时写入：`cat_publication_oa_location` 一条 PMC 记录（带许可，用 `PublicationOaLocation.ofPmc`）、`cat_publication.is_oa = true`、`has_full_text` 表示站内可读。`oa_status` 保持空（PMC 不提供金色 / 绿色之分）。"开放获取"筛选第一次有数据，含义为"确认开放获取"，未确认的仍为 false。

> **不进本字段**：正文放详情页内还是单开阅读页（PAP-83 决定）；正文结构字段定义、表结构、MinIO 对象命名规则（各 Issue 工程 spec 决定）。

## 5. Done 判定

> 数字均在 mini 实测，结果写进本节"实际："行。

- [ ] **D1：6 个 Issue 全部 Done**

- [ ] **D2：补 PMCID 生效**——Europe PMC 回查对全库跑完后，带 PMCID 的文献占比 ≥ 40%（规划时 7%，抽样估计约 48%），记录补全前后数字

- [ ] **D3：抓取与解析跑完**
  - 每篇候选文献都处于终态（已解析 / 无原文 / 出错），出错 < 2% 且每条有原因
  - 记录可读全文篇数、有 PDF 篇数、`is_oa = true` 篇数
  - 另导入一个较早的 baseline 文件（如 `fileIndex=1200`），其文献也能走完"补 PMCID → 抓取 → 解析"

- [ ] **D4：mini 端到端走通**（1440×900 与 375×812 两种尺寸）
  - 有全文：正文可读，章节目录跳转、图片、表格、MathML 公式、引用跳参考文献正常
  - 有 PDF：下载后文件能正常打开；有全文无 PDF：不显示下载按钮
  - 无全文：显示"无开放全文"并保留"去全文 · DOI"；已撤稿：不展示全文
  - 速览栏"原文阅读"显示真实阅读时长

- [ ] **D5：许可与出处齐全**——每篇全文显示许可类型、作者与出处（期刊、DOI、PMC 链接）、NLM 数据来源与抓取日期

- [ ] **D6：最大 PDF 经门户完整下载**——库内最大的 PDF 下载后 md5 与 PMC 元数据一致，未被网关 60 秒总时长切断

- [ ] **D7：定期复查有效**——集成测试覆盖：元数据 md5 变化触发重新抓取；元数据消失停止展示

- [ ] **D8：检查与测试全绿**
  - 后端 `./gradlew check` 全绿
  - 门户 `pnpm lint && pnpm typecheck`、Vitest 全绿；Playwright smoke 覆盖"有全文""无全文"两条路径
  - 文献检索按"开放获取"筛选，返回条数等于 `is_oa = true` 篇数且大于 0
  - 设计简报与画板快照已入库
