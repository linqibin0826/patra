## 1. 版本目标 / 价值

没写过后端的人打开 Patra 学习站，可以沿着学习路线，从「HTTP 请求是什么」一直读到「发件箱怎么保证消息不丢」。每篇都标着难度，写明先读哪几篇，讲的是 Patra 里真实的代码和真实踩过的坑。看过的人再回来，首页会挑一条最久没看的让他回顾两分钟。从这一版起，Patra 每做完一版、每查清一个棘手问题，Agent 都会把学到的东西写成新条目，学习站跟着项目一起长。

现在学到的东西散在每一版的总结 Artifact、学习笔记 Artifact 和 Claude 的记忆里，没有一个能「走进去学」的地方。上一个学习站做完后一次都没有打开过：它是一次性建好的 CI/CD 课程，不会随版本长出内容，也没有任何时刻把人拉回去。Patra 以后要开源，学习站也要写给第一次接触这个项目的人看，不只是作者自己的笔记本。

**规划时的现状**（2026-10-31 核对，main `cc2956951`）：

- **patra-learn**：「地铁线路图」式的 CI/CD 课程，3 条线 13 站，另有术语表、事故档案、操作卡。内容是 `src/content/` 下的 TS/TSX，Next.js 16 静态站，端口 4001，只在 tailnet 内访问，由 `learn-cd.yml` 部署到 mini。
- **公网入口**：门户 `patra.linqibin.dev` 自 10/28 起经 Cloudflare Tunnel 对公网开放，学习站没有公网入口。
- **学习材料**：v0.11～v0.16 各有版本总结 Artifact，v0.16 另有一份带动手区的学习笔记 Artifact；排查记录在 Claude 的记忆里（代理、Nacos、网关、测试抖动等），措辞是写给 Agent 避坑用的。
- **Linear**：Backlog 里没有学习站相关的 Issue。

**验证场景**：

1. 一个没碰过消息队列的人，从「消息与事件」路线第一篇「消息队列是什么」开始，按顺序读到「发件箱」，每一篇都不需要先懂后面的内容。
2. 读者在「发件箱」页标了「理解中」。几天后再打开首页，「今天读这一条」推给他的是一篇他标过或很久没看的条目，并先抛出一个问题让他想。
3. 版本收尾时，Agent 按维护技能把这一版学到的东西写成条目，放进对应的主题和路线；这一版用了新技术时，Agent 检查入门层缺不缺对应的篇目，缺就补上。
4. 在公网不登录也能打开学习站，看不到凭据、内网地址或只跟作者本机环境有关的推荐内容。

### 2.1 产品定义

| 项 | 规则 |
|---|---|
| 读者 | 想借 Patra 这个真实项目学后端的人，最低起点是没写过后端；作者自己也是读者 |
| 难度 | 四档：**入门**（没写过后端）、**基础**（会写简单接口）、**进阶**（做过项目、开始碰到真实问题）、**实战**（Patra 里真实发生过的事）。每篇必标 |
| 条目类型 | 四种：**概念**、**排查**（现象 → 怎么查 → 根因 → 修法）、**决策**（背景、选项、选择、代价）、**坑**（一坑一页） |
| 前置 | 每篇写明「先读这几篇」；读者答不上开头的诊断问题时，页面引导他先去读前置篇 |
| 路线 | 一条路线是按难度从低到高排好的一串篇目，像一门小课；一篇可以在多条路线里 |
| 主题 | 同一件事在不同版本里又碰到时，条目挂到同一个主题下，主题页按时间展示它怎么演进 |
| 标签 | 平铺的标签（后端、网络、数据库、部署、测试、前端、DDD 等），带计数 |
| 教学写法 | 照 learn 技能的做法：开头一个诊断问题；有结构的概念才配图，一张图只讲一个关系；逐步动画每一步前先问「你猜会怎样」，不一口气播完；结尾一道复述题或迁移题 |
| 交互 | 图示、逐步动画（GSAP）、参数滑块与开关、对比切换、考考自己，全部来自教学组件库；该有动效就有动效，不跟随系统「减少动态效果」设置 |
| 读者进度 | 掌握度（刚接触 / 理解中 / 吃透了）与最近阅读时间存在读者浏览器里，不登录 |
| 今天读这一条 | 首页第一屏，从读者标过「刚接触 / 理解中」或最久没看的条目里挑一篇，先给问题再给答案；新读者看到「从这里开始」的入门路线 |
| 屏幕 | 只为桌面设计与验收；手机上保证正文能读、页面不横向溢出（覆盖产品工作区「前端要检查移动端布局」的通用要求，本版明确） |

**初定 8 条路线**（篇目清单由 Issue 1 定稿）：

| 路线 | 入门 | 基础 | 进阶 / 实战举例 |
|---|---|---|---|
| Web 与 HTTP | 打开一个网页时发生了什么 | 请求与响应、状态码、Cookie 与会话、REST 接口 | 网关与反向代理、SSE、网关把事件流攒住 |
| 数据库与事务 | 数据库和表 | SQL 查询、索引、事务 | 隔离级别与锁、Flyway 迁移、孤儿连接堆积 |
| Java 与 Spring | Java 程序怎么跑起来 | 依赖注入、Spring Boot 自动配置 | JPA、Nacos 配置与刷新、推回原文不刷新 |
| 消息与事件 | 为什么要异步 | 消息队列是什么、交换机 / 队列 / 绑定 / 路由键、ack | 发件箱、至少一次 + 去重、死信、乱序 |
| DDD 与六边形 | 为什么代码要分层 | 实体、值对象、聚合 | 限界上下文、子域、端口与适配器、领域事件与集成事件 |
| 测试 | 为什么要写测试 | 单元测试、Mock、TDD | 集成测试与 Testcontainers、端到端测试、偶发失败 |
| 部署与 CI/CD | 代码怎么变成线上服务 | Git 分支与 PR、Docker 镜像 | CI 流水线、CD 部署、Cloudflare Tunnel（旧 CI/CD 课程改写进来） |
| 前端 | 网页由什么组成 | React 组件与状态、Next.js 页面 | 服务端组件、Route Handler 透传 |

## 3. 范围边界（不做的事）

> 下面这些都和学习站高度相关、很容易被顺手加进来，列在这里是明确「本版不做」。

| # | 不做的事 | 理由 |
|---|---------|------|
| A | **账号与跨设备同步进度** | 进度只存在读者浏览器里，换浏览器或清缓存就没了；学习站不连 identity、没有后端 |
| B | **站内评论、提问、读者投稿** | 开源后纠错与补充走 GitHub Issue / PR |
| C | **英文版与多语言** | 只写中文 |
| D | **邮件或推送提醒回访** | 本版只做首页「今天读这一条」；每天发学习邮件要接通知服务，本版不做 |
| E | **视频与录屏讲解** | 代码一改就得重录，维护不起；图示、动画、交互都做 |
| F | **自动写条目的流水线** | 条目由会话里的 Agent 按维护技能写，不在 CI 里挂机器人从 PR 或提交记录生成 |
| G | **站内 AI 对话辅导** | 静态站，不接 Claude API；诊断、先猜后看、迁移题写进页面结构 |
| H | **手机端专门适配** | 设计与验收只针对桌面，手机上只保证正文能读、不横向溢出 |

## 4. 关键决策

> 进本节的门槛：影响 2 个以上 Issue、同时影响内容与页面、或事后很难改回来。

### A. 公网入口：Cloudflare Tunnel + `learn.linqibin.dev`

- **影响 Issue**：9、2（发布步骤）
- **选择**：走门户已在用的 Cloudflare Tunnel，独立域名 `learn.linqibin.dev`；原来 tailnet 的 4001 入口去掉。
- **为什么不用 `learn.patra.linqibin.dev`**：Cloudflare 免费证书只覆盖一级子域。
- **代价**：学习站从内网工具变成公开站点，此后每次发布都对公网生效。

### B. 纯静态站

- **影响 Issue**：3、9、10
- **选择**：Next.js 16 构建时生成全部页面，不连任何 Patra 后端服务；部署沿用 `learn-cd.yml` 到 mini。
- **代价**：读者相关的一切（进度、今天读这一条）只能在浏览器里算。

### C. 内容存放：MDX 平铺 + 路线与主题 YAML

- **影响 Issue**：1、2、3、4～7、9
- **选择**：每篇条目一个 MDX 文件，平铺在 `patra-learn/content/entries/<slug>.mdx`；元数据写类型、难度、标签、前置、出处、主题、是否个人环境。每条路线一个 YAML（`content/routes/<slug>.yaml`，列篇目顺序），每个主题一个 YAML（`content/topics/<slug>.yaml`，只写标题与简介，成员由条目的 `topics` 决定，主题页按出处版本排序）；标签是一份固定清单 `content/tags.yaml`。索引在构建时生成。细节见 PAP-155 工程 spec（10/31 用户确认）。
- **为什么平铺**：一篇可以挂在多条路线、多个主题下，不按目录绑死归属；写内容的会话按路线分工也不会改到同一个文件。
- **代价**：文件多了以后靠元数据和搜索找，不靠目录。

### D. 交互只从教学组件库来，动画用 GSAP

- **影响 Issue**：2、3、4～7、8、10
- **选择**：条目里的图示、动画、滑块、小测全部用组件库的组件拼；某篇需要新交互时，先做成通用组件加进组件库再用，不在条目里写一次性的小程序。动画用 GSAP；不跟随系统「减少动态效果」设置。
- **代价**：组件库是所有内容的依赖，组件接口改动要同步改用到它的条目（校验兜底）。

### E. 公开边界：写的时候就守住

- **影响 Issue**：2、3、7、9
- **问题**：仓库公开，条目文件在 GitHub 上谁都能读，「个人环境」标签只管站内展示，藏不住内容。
- **选择**：所有条目都必须可公开：不写凭据，不写 tailnet IP 与主机名，用 `<mini 的地址>` 这类占位；个人环境条目不进路线、不进首页推荐，只在它的标签页可见；内容校验拦内网地址，gitleaks 照旧拦密钥。
- **代价**：从记忆转写排查记录时要逐条去掉本机细节，PAP-161 工作量因此变大。

### F. 代码引用钉在提交上

- **影响 Issue**：2、3、4～7
- **选择**：条目引用代码写成 `路径@提交SHA`，页面链到 GitHub 上那次提交的永久地址；校验文件是否还在、钉住的提交之后是否改过，改过的列进体检报告，由维护技能处理。
- **代价**：每次重构后体检报告会变长，要有人（Agent）去更新对应条目。

### G. 视觉：花园方向，学习站自有 token，不加中文网页字体

- **影响 Issue**：8、9、10
- **选择**：沿用样稿 B「花园」，学习站有自己的 token，不用 Patra 门户设计系统。中文用系统字体（正文黑体、标题系统宋体），西文与数字自托管 Source Serif 4 与 JetBrains Mono。
- **为什么不加中文网页字体**：每页首次访问多下载约 1 MB，与现在 learn 的约束一致。
- **代价**：标题宋体在不同系统上字形不完全一样。

### H. 旧学习站整体替换

- **影响 Issue**：3、6、9
- **选择**：删除地铁图首页、线路页、TS/TSX 内容与相关测试，不保留旧版本；CI/CD 课程内容改写进「部署与 CI/CD」路线。
