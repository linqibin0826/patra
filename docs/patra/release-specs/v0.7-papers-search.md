## 1. 版本目标 / 价值

访客能在 Patra 门户**检索并浏览全部文献**。首页搜索框、主题云、导航"文献"、期刊详情"查看该刊文献"四个出口都落到同一个文献页 `/papers`，按年份 / 期刊 / 文献类型 / 证据等级 / 开放获取 / 语言筛选、排序、翻页，点任一篇进入已有的文献详情页。

文献页与首页的关系，同"首页期刊模块 vs `/journals`"：首页是门面给入口，文献页是工作台出结果。首页文献流继续做精选展示，不被替代。

**两种状态，同一个页面**：

- **浏览态**（不带参数，点导航"文献"进入）：全部文献按最近更新排列，顶部信息行给库总况（总篇数 / 来源 / 最近同步），筛选栏每项带计数。
- **检索态**（带参数，从任一出口跳入）：关键词 / 作者 / 筛选条件生效，生效条件以 chip 挂在检索条下可单个移除，URL 可直接分享。

**验证场景**：首页搜 "GLP-1" → `/papers?q=GLP-1` 出结果 → 筛"近 3 年 + RCT" → 点一篇进详情 → 点期刊名进期刊详情 → 点"查看该刊文献"回到 `/papers?venue=xxx`。

## 3. 范围边界（不做的事）

| # | 不做的事 | 理由 |
|---|---------|------|
| A | **高级检索**：布尔运算、字段限定（`ti:` `au:`）、MeSH 主题词 facet | 本版是简单检索 + facet，先把页面搭出来走通；高级检索是独立大专题，届时连同搜索引擎一起做 |
| B | **搜索建议 / 自动补全 / 拼写纠错** | 搜索框提交即跳转，不做输入过程中的联想；属高级检索专题 |
| C | **"被引最多"排序 / 相关度排序** | 被引数据几乎全 0；本版关键词为标题子串匹配无相关度分。排序只放最近更新 / 年份 |
| D | **收藏、保存检索式、导出引用、AI 速读筛选** | 全部依赖用户系统或 LLM，无登录体系，本版不做 |
| E | **主题云热词真实计算** | 词条仍为静态配置，本版只接跳转；热度统计是独立数据任务 |
| F | **全量 baseline 导入、解析器补齐（GrantList / CoiStatement 等）** | 数据面工作，与文献页无依赖，不混进本版 |
| G | **i18n、暗色模式** | 沿用 v0.5 边界，单一中文 light theme |

## 4. 关键决策

### A. 本版不做全文检索，关键词为标题子串匹配；搜索引擎留给高级检索专题

- **影响 Issue**：PAP-52 / PAP-53 / PAP-54
- **决策**：关键词 tab 提交后对标题做 `ILIKE` 子串匹配，不分词、不排相关度，不加任何索引或 schema 变更。高级检索专题确定会引入 Elasticsearch / OpenSearch（布尔 / 字段限定 / MeSH 树 / 高亮 / 联想是其本行），届时本段匹配逻辑整段替换。
- **否决**：PostgreSQL tsvector + GIN——搜索引擎上线即整体作废，白干一遍；关键词 tab 本版不接——"搜索框能用"对走通出口的价值远大于实现成本。

### B. 新建检索端点，首页 feed 端点不动

- **影响 Issue**：PAP-52 / PAP-53 / PAP-54
- **决策**：新建 `GET /portal/publications/search` + `GET /portal/publications/search/facets`，复用期刊侧 `filter / paging / facets` 三件套的模式。PMID / DOI 精确查找走 search 端点的 `pmid=` / `doi=` 参数，命中一条时前端 redirect 到详情。现有 `GET /portal/publications`（feed，tab 参数）保持不变。
- **理由**：feed 是精选流语义，检索是工作台语义；合并会把 feed 的"高被引"tab 拖进检索端点，与边界 C 冲突。

### C. URL 即状态，服务端取数

- **影响 Issue**：PAP-52 / PAP-53 / PAP-54
- **决策**：检索词、筛选、排序、页码全部放 query string，页面 RSC 服务端取数，无客户端状态库；BE 请求参数名与 FE query 名一一对应。这是 `/journals` 已在走的路，五个出口本质上都是拼一个 URL 跳过去。

### D. 证据等级 facet 走类型映射，不加物化列

- **影响 Issue**：PAP-52 与前端徽章一致性
- **决策**：BE 用 `EvidenceLevel.classify()` 的类型映射表把等级翻译成对应的 PublicationType 集合去过滤和计数；映射表与详情页徽章共用同一份，两处永远一致。

> **已排除出本字段**（属项目规约或 Issue 层）：分页大小 / facet 计数 SQL 写法 / 作者名匹配方式（PAP-52 Tech Design）；渐进式披露、RSC 服务端优先（portal CLAUDE.md 已定）；Claude Design handoff 机制（沿用 v0.4）。
