## 1. 版本目标 / 价值

医生和科研人员能把文献收进自己的文献库，按收藏夹整理、写备注，导出 RIS / BibTeX 或复制规范引用，并把收藏夹公开给同事。

社区互动分几个连续版本交付，这是第一个：先做「一个人用也有价值」的文献库，同时搭好互动服务和对象登记表。讨论、关注动态、通知、审核、计数与热度不在本版（见第 3 节）。

**规划时的现状**（2026-10-24 核对）：

- 没有任何互动功能的后端。门户的收藏按钮是 Zustand 内存里的假数据，刷新即清空；后端的收藏数写死为 0，只在文献详情页的事实条显示。
- 门户没有分享、复制链接和引用导出；文献页、期刊页没有页面元数据。
- catalog 的文献、期刊内部 ID 在每日增量下稳定，但换库重建时会整表重发（v0.6 发生过）；机构与 MeSH 每次重导都换 ID；没有 ORCID 的作者（约 75%）重跑导入会拿到新 ID。catalog 不发任何事件，也没有按 ID 批量查询的接口。
- catalog 缺引用要用的数据：页码解析了但没落库，文章号（ELocationID）没解析，出版日期缺月日时补成 1 月 1 日，期刊只有 NLM 缩写。
- identity 没有批量用户摘要接口；头像地址按当前用户名拼，改名即失效；公开主页视图不带用户 ID。
- 网关传给下游的身份断言只有用户 ID、会话 ID、账号类型、客户端类型。封禁时 identity 已删光该用户的会话，网关每个请求都查会话且不缓存，所以封禁立即生效。
- 全仓只有 ingest 有 Outbox，且它在 mini 上从未运行。

**验证场景**：

1. A 在检索结果和文献详情页一共收藏 3 篇文献，建一个「组会」收藏夹并写上备注，其中一篇同时放进另一个收藏夹。
2. A 把「组会」设为公开；B 在 A 的主页「收藏夹」栏打开它，并复制成自己的收藏夹。
3. A 把「组会」导出为 RIS，导入 Zotero 后作者、期刊、卷期页、年份齐全；复制一条 GB/T 7714 引用，格式正确。

### 2.1 文献库的定义

本节是产品定义，按最终形态定好。来源见文末「调研依据」。

#### 2.1.1 收藏（文献库条目）

| 项 | 规则 |
|---|---|
| 可收藏的对象 | 本版只有文献 |
| 唯一性 | 同一用户对同一篇文献只有一个条目 |
| 入口 | 文献详情页页头、首页文献卡片、检索结果列表项 |
| 资格 | 登录即可，包括邮箱未验证的账号（与 v0.12 一致） |
| 备注 | 可选，纯文本，≤ 500 字（按字素计） |
| 取消收藏 | 从文献库删除条目，同时移出所有收藏夹，备注一并删除 |
| 上限 | 每人 20,000 条 |
| 文献失效 | 文献在 catalog 被删除（软删）时，条目保留，显示「已失效」和收藏时记下的标题；文献恢复后正常显示 |
| 公开计数 | 本版不显示任何收藏数，文献详情页事实条的「收藏」格删掉 |

#### 2.1.2 收藏夹

| 项 | 规则 |
|---|---|
| 结构 | 扁平，不嵌套，没有标签，不支持协作 |
| 名称与简介 | 名称 1 ~ 100 字，同一用户下不重名；简介可选，纯文本，≤ 500 字 |
| 归属 | 一个条目可以放进多个收藏夹；删除收藏夹不删条目；不在任何收藏夹里的条目归入「未分类」 |
| 可见性 | 默认私有，可以设为公开。设为公开要求邮箱已验证、账号状态正常 |
| 谁能看公开收藏夹 | 当且仅当 identity 判定「所有者的主页对这位访客可见」。所有者封禁、注销、冷静期中、邮箱未验证，或主页设为仅自己 / 仅登录用户可见时，都按 identity 的规则判定 |
| 地址 | `/collections/{id}`，不随所有者改用户名而变 |
| 主页展示 | 公开收藏夹出现在所有者主页的「收藏夹」栏 |
| 搜索引擎 | 跟随所有者主页的「允许搜索引擎收录」开关 |
| 复制 | 登录用户可以把别人的公开收藏夹复制成自己的私有收藏夹：同名（重名自动加序号），其中的文献加进自己的文献库（已收藏的不重复添加），备注不复制 |
| 夹内排序 | 按加入时间倒序，可切换为按出版日期、按期刊 |
| 上限 | 每人 200 个收藏夹，每个收藏夹 5,000 条 |
| 审核 | 本版没有审核：门户只在 tailnet 内可访问 |

#### 2.1.3 导出与复制引用

| 项 | 规则 |
|---|---|
| 导出范围 | 单篇、选中的多篇、一个收藏夹、整个文献库 |
| 导出格式 | RIS、BibTeX、CSV、CSL-JSON |
| 复制引用格式 | GB/T 7714-2015（顺序编码制）、Vancouver（NLM）、APA 第 7 版、AMA 第 11 版 |
| 字段 | 作者（全名，保持顺序）、标题、期刊全称与 ISO 缩写、卷、期、页码或文章号、出版日期（按实际精度）、DOI、PMID、PMCID |
| 规模 | 导出单次最多 5,000 条，同步流式下载；复制引用一次最多 100 条 |
| 生成方 | catalog 用 citeproc-java 加官方 CSL 样式文件生成引用文本；门户只负责发起和展示 |

#### 2.1.4 分享与页面信息

| 项 | 规则 |
|---|---|
| 页面信息 | 文献页、期刊页、公开收藏夹页输出标题、描述、规范地址（canonical） |
| 复制链接 | 复制规范地址 |
| 复制引用 | 复制所选格式的引用文本 |
| HTTP 降级 | mini 只有 HTTP，浏览器的剪贴板接口不可用时，退回选中文本复制 |
| 不做 | 二维码海报、系统分享、短链、分享图（第 3 节 H） |

#### 2.1.5 账号状态与数据

| 项 | 规则 |
|---|---|
| 注销 | 冷静期内照常可用；注销执行后，每日清理任务物理删除其收藏与收藏夹（含公开的）。别人从他那里复制的收藏夹属于别人，不受影响 |
| 封禁 | 数据保留；封禁期间他的公开收藏夹对别人不可见（identity 判定主页不可见） |
| 已注销用户的展示 | 出现在收藏夹所有者等位置时显示「已注销用户」占位，不显示用户名 |
| 用户相关字段 | 互动服务的任何表只存用户 ID，不存用户名、昵称、头像（仓库规则「用户名只存 identity」） |

## 3. 范围边界（不做的事）

> 下面这些都和社区互动高度相关，列在这里是明确「本版不做」。

| # | 不做的事 | 理由 |
|---|---------|------|
| A | **关注、关注动态、周摘要** | 要先定 mini 的同步范围、全文抓取上限和新文献、新标引的信号。直接把同步切到 ALL，会把大量老文献的修订当成新文献建进来，加上积压的约 330 个文件和自动抓全文，几天就会写满磁盘 |
| B | **讨论、期刊投稿经验点评、「有帮助」** | 靠多人往来才有价值，没有回复提醒和审核时很弱；本版先交付一个人用就有价值的文献库 |
| C | **通知、审核与举报、手机号实名、网关限流与熔断** | 属于公开上线前的合规包：《互联网跟帖评论服务管理规定》要求发表类互动后台实名，并有审核、举报、申诉；门户现在只在 tailnet 内，没有公开用户 |
| D | **公开计数与热度** | 本版页面不显示任何计数；计数要异步管线和对账，与热度排序一起做 |
| E | **行为数据：埋点、ClickHouse、浏览记录、个性化开关** | 与关注动态一起做，那里才有曝光、点击这类推荐要用的数据；事件格式与采集点到那时一次定死 |
| F | **公共事件模块（Outbox）与 ingest 的去留** | 本版跨服务只有「注销后清理」一个需求，每日对账已够（决策 G）；只有一个消费方时就建，还会造成与 ingest 的 Outbox 两套并存，违反「禁止多版本并存」 |
| G | **收藏期刊、作者、机构、MeSH 主题** | 本版只收藏文献。期刊、作者这类对象是「持续出新内容的来源」，以后用关注表达；作者身份不稳（约 75% 没有 ORCID），机构、MeSH 没有实体页 |
| H | **二维码海报、系统分享、短链、分享图** | mini 只有 HTTP 和 tailscale 地址，浏览器的剪贴板与系统分享接口不可用；分享图需要公网域名和非 woff2 的中文字体 |
| I | **期刊标识唯一约束、期刊卡片接口** | 只有关注期刊用得上 |
| J | **Redis 拆成缓存与状态两个实例** | 本版没有缓存用途；现有实例本来就是状态型配置 |

## 4. 关键决策

> 依据：2026-10-24 的 9 路设计调研与 7 路代码核对（见文末）。Issue 编号见 2.2。

### A. 新建 patra-interaction，按子域组织，本版只建用到的子域

- **影响 Issue**：PAP-111 / PAP-112 / PAP-113 / PAP-114
- **决策**：社区互动（本版的收藏，以及以后的讨论、关注、通知、行为数据）都放进一个新服务 `patra-interaction`，六层模块不变；每层下按子域分包（`dev.patra.interaction.{domain|app|infra|adapter}.{子域}`）。本版只建 `subject`（对象底座）和 `collection`（收藏）两个子域。子域之间只经对方的读端口与底座交互，不直接用对方的实体或仓储，由 ArchUnit 规则守住。拆分条件写进服务 README：某个子域的负载、发布节奏或存储引擎明显和核心分化时，剥成独立服务。网关前缀 `/patra-interaction/**`，错误码前缀 `INTERACTION`。
- **为什么**：单人在一台 mini 上维护，每多一个服务就多一套 Gradle 模块、JVM、库、Nacos 配置和 CD；各种互动共享「用户对某个对象做动作」这一抽象和同一条读聚合。
- **否决**：每种互动一个服务；放进 catalog（PubMed 镜像，以批量导入为主）或 identity（安全核心）；本版就建齐全部子域的空包和空 schema（违反「不写预防性代码」）。

### B. 存储：一个库，子域各占一个 schema，共用一份 Flyway 历史

- **影响 Issue**：PAP-111 / PAP-112 / PAP-113
- **决策**：库 `patra_interaction`（现有 PG 实例）。每个子域一个 schema，在迁移脚本里 `CREATE SCHEMA`；整个服务一份 Flyway 历史，版本号用时间戳，避免子域之间撞号。子域表不对 `subject` 底座建跨 schema 外键，只建索引，引用完整性由写入路径和对账保证。状态类窄表（文献库条目、收藏夹条目）从第一天起按 `user_id` 哈希分 16 区，不建 JPA 实体，用原生 upsert（catalog 正文表有先例）。新迁移照常过 R6 用户名列检查。
- **为什么**：分区键、主键形状、schema 划分建成后再改要重写数据，属于难逆决定；按 `user_id` 分区服务最热的两个查询（我的文献库、一页 20 条的我的状态），也是以后分片的分布列。
- **否决**：每个子域一个库（单机多库、多套连接池）；全部放 public schema（以后拆服务要逐表挑）；子域表对底座建外键（子域与底座在库层耦合，拆分要先拆外键）。

### C. 对象登记表：互动数据只引用本地 subject_id，对象身份锚定在外部标识

- **影响 Issue**：PAP-109 / PAP-112 / PAP-113
- **决策**：`subject` 子域维护登记表，每个被互动过的对象一行：本地 `subject_id`；`natural_key` 是外部身份锚（本版只有文献：`pmid:…`）；`source_id` 是 catalog 内部 ID 的缓存；`state` 为 ACTIVE / UNAVAILABLE（catalog 软删，可复活）；`snapshot` 存标题、期刊、年份，只用于兜底和「已失效」展示。对象第一次被互动时同步调 catalog 批量解析接口入表，之后只查本地；catalog 不可用时，首次收藏该文献的请求直接失败并提示重试，不先收下再补校验；解析结果为「不存在」时同样拒绝，不建登记行。对外接口用 `(type, key)`，文献的 key 就是门户 URL 里的 catalog 内部 ID。对象能被做哪些互动写在代码枚举 `SubjectType` 里（稳定编码 + 能力集），本版只开「收藏文献」。
- **为什么**：catalog 内部 ID 在换库重建时会整表重发（v0.6 发生过），dev 上也常清库重导。互动表只认本地 ID，catalog 怎么重导都只需对账刷新登记表，互动行不动。B 站评论区的 subject、Disqus 的 thread 都是这个做法。
- **否决**：互动表直接存 catalog 内部 ID（重导后要改写全部互动行）；互动表直接存 PMID 等字符串键（索引膨胀，键本身也会变）；一张通用互动表；用配置表驱动能力矩阵（省不掉代码，还把不变量挪出编译期）。

### D. 收藏模型：「文献库 + 收藏夹」两层

- **影响 Issue**：PAP-107 / PAP-113 / PAP-114
- **决策**：收藏 = 文献库条目（用户 × 文献唯一，可带备注）；收藏夹 = 扁平文件夹，默认私有，可设为公开。一个条目可以进多个收藏夹，删收藏夹不删条目，删条目同时移出所有收藏夹；不在任何收藏夹里的条目就是「未分类」。复制别人的公开收藏夹 = 新建自己的收藏夹并把条目加进自己的文献库。不做嵌套、标签、协作收藏夹。
- **为什么**：与 Semantic Scholar、Zotero 的语义一致；以后的收藏数按「多少人收了」计，不会因一人多夹重复计数。
- **否决**：标签（多夹归属已覆盖）；嵌套文件夹；协作收藏夹；每个收藏夹各存一份条目（同一篇在多个夹里备注不一致）。

### E. 用户信息由 interaction 拼装；修订 v0.12 的两处约定

- **影响 Issue**：PAP-108 / PAP-113 / PAP-114
- **决策**：identity 提供内部接口 `POST /_internal/users/summaries`（一次最多 100 个）。请求可带访客的用户 ID（匿名为空）；返回用户 ID、用户名（只用来拼主页链接）、昵称、头像地址、账号状态、邮箱是否已验证，以及 identity 按自己的隐私规则为这位访客算好的「主页是否可见」；已注销的返回占位，不带用户名。interaction 调它，把收藏夹所有者的信息嵌进自己的响应，门户不直接按 ID 查人。修订 v0.12 两处：①头像地址从 `/users/{username}/avatar` 改为按用户 ID 拼，identity 路由与门户转发路由一起改；②公开主页响应带上用户 ID（PAP-95 工程 spec 原写明不含），门户靠它取该用户的公开收藏夹。
- **为什么**：`/_internal` 在网关一律 403，门户调不到；用户数据只归 identity，不开放「拿 ID 就能查到昵称头像」的公开接口；按 ID 的头像地址改名后不失效。Snowflake 用户 ID 能推出注册时间，X、Discord 也公开用户 ID，接受。
- **否决**：门户经网关调公开的批量用户接口（可被枚举）；interaction 冗余昵称、头像快照（违反「用户名只存 identity、展示时按 ID 取」）。

### F. 门槛与可见性：本版不改身份断言，公开动作写入时回查 identity

- **影响 Issue**：PAP-108 / PAP-113 / PAP-114
- **决策**：私人收藏任何登录用户可用（含邮箱未验证，与 v0.12 一致）。把收藏夹设为公开要求邮箱已验证、账号状态正常，写入时经决策 E 的内部接口回查。公开收藏夹对某个访客可见，当且仅当 identity 返回的「主页是否可见」为真；interaction 只透传访客 ID，不自己实现隐私规则。网关断言保持 v0.12 决策 H 的形状，本版不加字段。
- **为什么**：设为公开频率很低，回查一次 identity 的代价可以忽略；给断言加字段要改约 51 个文件、6 个服务全量重建；封禁本来就立即生效。
- **否决**：断言加「实名等级」（本版没有数据来源）；Redis 封禁撤销集（前提不成立）；公开收藏夹不看所有者状态（会绕过 identity 的主页隐私）。

### G. 注销清理与对象对账用每日任务，本版不建事件模块

- **影响 Issue**：PAP-112 / PAP-113（以及 PAP-108 的内部接口）
- **决策**：interaction 注册 XXL-Job 执行器，跑两个每日任务：①对象对账：按 `natural_key` 批量回查 catalog，刷新 `source_id`、`state`、`snapshot`；②注销清理：分批回查有互动数据的用户状态，DELETED 的物理删除其收藏与收藏夹。执行器与两个任务的登记写进 PAP-111 的接入核对单和上线 runbook。公共事件模块（Outbox）本版不做。
- **为什么**：本版跨服务只有「注销后清理」一个通知需求，注销本身有 15 天冷静期，最多晚一天清理可以接受；只有一个消费方时就建事件模块，还会逼出 ingest 两套 Outbox 并存的问题。
- **否决**：identity 注销时直接调 interaction（identity 要知道所有持有用户数据的服务）；本版就建公共 Outbox。

### H. 读路径：门户只在需要时带会话，互动区块独立降级

- **影响 Issue**：PAP-113 / PAP-114 / PAP-115
- **决策**：公共数据（文献卡片）不带会话；可见性取决于所有者设置的内容（公开收藏夹页、主页的收藏夹栏），访客已登录时带会话，匿名不带；「我是否收藏过、在哪些收藏夹里」走 interaction 的批量接口（一次最多 100 个对象，按主键查），带会话。门户新增调用 interaction 的公共层；每个互动区块单独 Suspense，设超时，失败只显示「暂不可用」，文献页主体照常出；收藏等交互用局部状态更新，不用 `router.refresh()`（会把全文重新取一遍）。
- **为什么**：网关对每个带令牌的请求都要调 identity 查一次会话，只在必要的调用上带会话；一屏 20 条只发一次批量请求，没有 N+1；互动服务出问题不能拖垮文献页。
- **否决**：网关聚合（网关要懂领域）；interaction 代取 catalog 数据（同步依赖链变长）；每条单独查。

### I. 引用数据与导出归 catalog，用 CSL 标准

- **影响 Issue**：PAP-110 / PAP-113 / PAP-114 / PAP-115
- **决策**：catalog 补齐引用要用的数据：页码、文章号（ELocationID）、期刊 ISO 缩写；出版日期按实际精度存（年 / 年月 / 年月日），不再把缺失的月日补成 1 月 1 日。catalog 提供按 ID 批量导出的接口（RIS、BibTeX、CSV、CSL-JSON），以及四种格式的引用文本（GB/T 7714-2015、Vancouver、APA、AMA），用 citeproc-java 加官方 CSL 样式文件生成。收藏夹导出时，门户从 interaction 拿到文献 ID，再调 catalog。现有文献按重跑导入回填（登记表锚在 PMID 上，互动数据不受影响）；日期精度的变化连带 catalog 的检索排序和门户现有的日期展示，写进 PAP-110、PAP-114 的验收。
- **为什么**：引用数据在 catalog；CSL 是文献管理软件的通用标准；按现在的数据导出会印出编造的日期、缺页码。
- **否决**：门户用 citation-js（CPAL / AGPL 许可，仓库没有 LICENSE）；手写四种格式模板（自研基础组件）；运行时调 NCBI 的导出接口（每秒 3 次限制，也没有 GB/T 7714）。

## 调研依据

2026-10-24 两轮并行调研，报告在当天会话里，这里只记结论和用到的来源。

**设计调研（9 路）**

1. **多态对象与互动数据模型**：对象登记表（本地 `subject_id`）以外部标识为锚；状态类互动每种一张窄表；能力矩阵写在代码里。来源：[GitLab 多态关联指南](https://docs.gitlab.com/development/database/polymorphic_associations/)、[Disqus URL Mapper](https://help.disqus.com/en/articles/1717129-url-mapper)、[B 站评论 API（type + oid 定位评论区）](https://github.com/moushicheng/bilibili-API-collect/blob/master/docs/comment/readme.md)。
2. **多层嵌套评论**（供讨论功能使用）：父指针 + `root_id` + `depth` + `path bigint[]`；不用 ltree，Snowflake ID 位数变化后文本序会乱（本机 PG17 实测）。
3. **高并发计数**（供计数功能使用）：精确计数由事件驱动重算并每晚对账；同一事务里给计数 +1，热点评论区吞吐降到 1/13 ~ 1/32（本机 PG17 实测）。
4. **行为数据底座**（供分析与推荐使用）：事件信封、曝光日志、ClickHouse 单节点。
5. **收藏、关注、分享、通知**：收藏只收文献；「库 + 多夹」语义；收藏必须配引用导出。来源：[Zotero collections and tags](https://www.zotero.org/support/collections_and_tags)、[Semantic Scholar FAQ](https://www.semanticscholar.org/faq)。
6. **境内合规与内容安全**：评论、回复、点赞等发表类互动要后台实名；审核、举报、申诉是硬义务；个人主体备案的网站不能开论坛类功能。来源：[互联网跟帖评论服务管理规定](https://www.cac.gov.cn/2022-11/16/c_1670253725725039.htm)。
7. **服务边界与读写路径**：一个服务内按子域划分、写明拆分条件；门户 RSC 当 BFF；只在需要时带会话；互动区块独立降级。
8. **学术社区产品**：以讨论起家的学术产品大多冷清，工具先行。来源：[PubMed Commons 关停公告](https://ncbiinsights.ncbi.nlm.nih.gov/2018/02/01/pubmed-commons-to-be-discontinued/)、[Mendeley 读者数与医学文章引用](https://research.universityofgalway.ie/en/publications/mendeley-readership-altmetrics-for-medical-articles-an-analysis-o/)。
9. **代码事实**：catalog 各对象 ID 的稳定性、事件基础设施、身份断言、门户现状，见第 1 节「规划时的现状」。

**代码核对（7 路）**

- **事件与消息**：ingest 的 Outbox 在 mini 上从未运行，公共模块要从头写；与 ingest 两套并存违反「禁止多版本并存」。
- **identity 与网关**：批量用户摘要只能走内部接口；封禁已立即生效；断言加字段波及约 51 个文件。
- **catalog**：缺页码、文章号、真实月日、ISO 缩写；update-scope ALL 不等于导入新文献；门户只能经 `/portal/**` 访问 catalog。来源：[citeproc-java](https://central.sonatype.com/artifact/de.undercouch/citeproc-java)、[CSL 样式库](https://github.com/citation-style-language/styles)。
- **服务平台**：新服务接入约 27 项，`dumpModuleGraph` 的 `unitOf` 漏改会让 CI 照绿、CD 永不部署；多 schema、分区表、子域 ArchUnit 规则在仓库里都是第一次。
- **门户**：收藏按钮在三处复用同一个假数据；mini 是 HTTP，剪贴板与系统分享不可用；不要用 `router.refresh()` 刷新互动状态。
- **基础设施**：网关路由在网关 jar 的 `application.yml` 里，接入新服务网关要重部署；runner 看门狗要求磁盘 ≥ 20 GB（2026-10-24 清理后剩 36 GB）。
- **进度与流程**：没有在途工作；Linear 里的 PAP-104（邮件改走 Outbox）、PAP-105（通知中心归属）与公共事件模块、通知相关，本版不动。
