# 教学写法

学习站是静态页面，没有人在旁边辅导。对话里的辅导做法（先摸清读者在哪、一次只推一步、让读者先猜、讲完让他复述）要写进页面结构：读者翻到哪里、先看到什么、要点哪一下才看到答案，都由条目决定。

目标是读者读完能自己答出这个问题，下一次碰到类似的也能答，不是读过一段好的讲解。

## 每篇的骨架

1. **开头诊断题**（`Diagnose`，正文第一块）：一道凭直觉就能作答的判断或预测题，答案能看出读者缺不缺前置。页面按 `prerequisites` 自动在题下列出「答不上来？先读：」，正文不用再写。
   - 好：「同一台机器上 curl 通、Java 程序拿到空 503。问题更可能出在目标服务，还是请求走的路？」
   - 坏：「你了解 HTTP 代理吗？」（读者只能答是或否，看不出缺什么）
2. **一节一步**：每节只推进一个想法，节标题写成那一步的结论或问题。段落短，一段一个意思。
3. **先猜后看**：在读者最可能猜错的地方放「你猜会怎样」，答案折起来或下一步才出现。每篇 1～3 处；答案不能紧挨在题目下面直接可见。
4. **配图**：内容有结构时才配图——几个部件之间的关系、一条流程、状态怎么变、两种做法并排比。一张图只讲一个关系；道理写在文字里，图只承载结构。纯步骤、命令、名词解释不配图。
5. **逐步动画**：一步一个变化，读者点「下一步」才往前走；在会猜错的那一步之前插「你猜」。不做从头播到尾的整段动画——那等于把答案直接递过去。查问题的文字经过不做成动画，写成有序的节。
6. **滑块与开关**：用在「参数变了结果怎么变」，先问读者预测，再让他拖。
7. **结尾**（正文最后一块）：一道迁移题 `Transfer`（换个场景还成立吗、换个参数会怎样），或一道复述题 `Recap`（用自己的话说出 X 为什么会 Y）；能出迁移题就出迁移题。下一篇由路线页给出，正文不写。

## 按难度调

- **入门**：不假设任何后端经验。先用日常例子，术语第一次出现当场解释；每节只引入一个新词。
- **基础**：可以假设读者写过简单接口，术语链到概念篇，不重复解释。
- **进阶 / 实战**：可以直接给代码、日志、配置；把篇幅花在「为什么会这样」和「怎么查到的」上。

## 语气

平实、直接。难的地方直说「这里大多数人会卡住」，不说「很简单」。不用 emoji，不喊口号，不夸读者。读者是有能力的成年人。

## 常见错误

| 错误 | 改成 |
|---|---|
| 诊断题问「你知道 X 吗」 | 问一个要用到 X 才能答对的判断题 |
| 一开头就是三段讲解 | 先诊断题，再一节一步 |
| 「你猜」的答案就在下一行 | 答案折起来，或放到「下一步」之后 |
| 每节都配一张图 | 只给有结构的内容配图 |
| 一张图同时讲调用链、数据流和状态 | 拆成几张，一张一个关系 |
| 整个机制做成一段自动播放的动画 | 拆成几步，读者点着走，中间插「你猜」 |
| 结尾是要点总结 | 换成迁移题或复述题 |
