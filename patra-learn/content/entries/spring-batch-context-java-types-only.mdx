## 坑

Spring Batch 6 的 `ExecutionContext` 默认用 `DefaultExecutionContextSerializer` 存进数据库：

- **写入**要求值是 `Serializable`；
- **读回**只放行 `java.*` 与 `org.springframework.batch.**` 包下的类型。

往里放一个领域 record：没实现 `Serializable`，当场写不进；实现了，写得进去，读回来时被拒绝。

## 为什么

`ExecutionContext` 的用途是**保存进度**：每个 chunk 提交时把它序列化进元数据表，任务失败后重新启动，从表里读回来，从断点继续。

读回时要把字节流还原成对象。反序列化任意类型是 Java 里出名的安全隐患（构造恶意的字节流就能执行代码），所以新版的默认序列化器只信任 JDK 自带的类型和 Spring Batch 自己的类型。你的领域 record 不在白名单里。

v0.11 全文阅读那一版做 PubMed 增量同步时碰到了这个限制：每个更新文件处理完要汇报新建、更新、删除、跳过各多少条。写完实现计划后，先把计划里的代码落到副本里实跑了一遍，查出计数 record 放进上下文这条路走不通。

## 怎么避开

只放 `java.*` 类型：字符串、整数、`ArrayList<String>`。每个计数按 key 单独存一个 `Integer`，key 集中定义在一个类里，并写明为什么：
