## 「现在」是最容易被忽视的外部依赖

Patra 有一个规则：用户改名之后，30 天内不能再改。要测这个规则，你需要验证两件事：第 29 天不行，第 30 天可以。

如果代码里是这样取时间的：

```java
Instant now = Instant.now();   // 直接问系统「现在几点」
```

测试就卡住了。`Instant.now()` 答的是真实的系统时间，测试无法让它说「现在是 30 天后」。你只能真等 30 天，或者去改电脑的系统时间——两样都荒唐，而且一旦改了系统时间，机器上别的程序也跟着乱。

<Callout kind="analogy">

出一张考卷，题目写「请回答今天是星期几」。它每天的标准答案都不一样，永远没法给它打一个固定的分数。要考卷可以打分，得改成「如果今天是 2026 年 10 月 20 日，请问……」——把「今天」变成题目给出的条件。

</Callout>

## 办法：把时钟当成依赖传进来

Java 标准库里有一个 `java.time.Clock`：它代表「一个能回答现在几点的东西」。代码不再自己问系统，而是**从外面接收一个 `Clock`**，向它要时间：

```java
Instant now = Instant.now(clock);   // 问传进来的这个时钟
```

生产环境传进来的是系统时钟；测试里传一个假的，假的想说几点就几点。Patra 的测试约定里明确写了这一条：

<CodeRef at=".claude/rules/testing/conventions.md@cfec9c9f30270dcf03f5cd7b6e54a0cd3b59296b" lines="1-30" />

注入 `java.time.Clock`，不要直接调用 `LocalDateTime.now()` 或 `Instant.now()`。

## 在 Patra 里，时钟从哪儿来

不是每个业务类都要自己造一个 `Clock`。Patra 的启动模块统一提供了一个系统 UTC 时钟：

<CodeRef at="patra-tool/patra-tool-launch/src/main/java/dev/patra/tool/launch/autoconfigure/LaunchAutoConfiguration.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="56-60" />

```java
@Bean
@ConditionalOnMissingBean
Clock clock() {
  return Clock.systemUTC();
}
```

关键是 `@ConditionalOnMissingBean`：意思是「如果容器里已经有别人提供的 `Clock`，我就不提供了」。这是故意留的让位口：测试只要自己声明一个 `Clock`，启动器的系统时钟就会退场。

业务代码就直接注入它。比如门户的引用导出接口，用它取当天日期给导出文件命名：

## 真实的例子：拨时钟验证改名规则

回到开头的问题。Patra 的一个集成测试，把「改名冷却 30 天、旧名保留 90 天」这些规则从头到尾走了一遍，中间就是靠拨时钟：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/integrationTest/java/dev/patra/identity/UsernameChangeFlowIT.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="70-100" />

```java
clock.set(IdentityClockITSpringConfig.START);   // 回到起点
// ……第一次改名成功，马上再改一次：409 ……
clock.advance(Duration.ofDays(30));              // 拨快 30 天
RawResponse back = changeUsername(alice, "alice");
assertThat(back.status()).as(back.body()).isEqualTo(200);
```

自己试一下：从第一次改名起，拨多少天之后才能再改？

测试没有真的等 30 天，从第一次改名到验证成功，只用了一行 `advance`。

<Callout kind="warn">

时钟只能管住「应用自己算的时间」。Redis 的过期时间由 Redis 服务器按真实时间计，换了应用里的 `Clock` 管不到它。所以那个测试特意声明：它不依赖会话过期。

</Callout>

<Callout kind="warn" label="还有一个小细节">

`MutableClock` 固定为 UTC，`withZone(…)` 只会返回它自己。如果业务代码靠 `clock.withZone(某个时区)` 取当地日期，换成它之后拿到的是 UTC 的日期。测试断言日期时要留意。

</Callout>
