## 先能看，后能点

第一次打开一页时：服务器先把页面画成 HTML 发过来，浏览器马上显示；同时下载客户端组件的 JavaScript。代码到了以后，React 在浏览器里把这些组件再渲染一遍，拿结果和页面上已有的 HTML 逐处对照，对上了就直接沿用这些 DOM 节点，把点击、键盘这些事件挂上去。这一步叫**水合**（hydration）。

水合不重新造页面，只是给已有的页面「接上线」。所以它有一个硬要求：**浏览器里的第一次渲染，必须和服务器画出的 HTML 一模一样。**

<Callout kind="analogy">

像先送来一台装好外壳、还没通电的样机，线路板随后到。装线路板时，每个接口都得对准外壳上的孔；对不上，只能把外壳拆了重装。

</Callout>

## 一个按钮上的快捷键

导航栏的快速检索按钮上写着快捷键：苹果设备是 ⌘K，其他系统是 Ctrl K。是哪种，只有浏览器知道。门户是这样写的：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="62-71" />

```tsx
  // 快捷键提示：服务端与首帧写 ⌘K，挂载后在非 Apple 平台改写 Ctrl K（避免水合不一致）
  const [shortcut, setShortcut] = useState("⌘K");
  const pathname = usePathname();
  useUnreadCountsPolling();

  useEffect(() => {
    if (!/Mac|iPhone|iPad|iPod/.test(navigator.platform || navigator.userAgent)) {
      setShortcut("Ctrl K");
    }
  }, []);
```

## 对不上会怎样

React 发现某处对不上时，会当作一个水合错误：开发模式下页面上弹出报错；它不再沿用那一片的服务器 HTML，而是从最近的出错边界或 `Suspense` 边界开始，在浏览器里整片重新渲染。服务器那部分活白干了，用户还可能看到页面闪一下。

<Callout kind="warn">

React 有个 `suppressHydrationWarning` 属性，能让它对某一个元素的文字差异不报错、保留页面上已有的内容。它只管那一个元素，只适合「本来就注定不同」的个别文字，不是修不一致的办法。

</Callout>

## 不一致从哪来

凡是「服务器和浏览器算出来不一样」的东西，放进第一次渲染都会出事。常见的几类：

| 来源 | 例子 | 改法 |
|---|---|---|
| 随机与计数 | `Math.random()`、库里用全局计数器自动生成的 id | 用 `useId`，两边给出同一个 id |
| 时间 | `Date.now()`、按本机时区和语言格式化日期 | 服务器上定好格式，或等水合后再换成本地格式 |
| 浏览器才有的信息 | window、navigator、localStorage、屏幕宽度 | 第一次渲染用固定的默认值，挂载后再读 |
| 别人改了页面 | 浏览器扩展往 HTML 上加了属性 | 不是代码的问题，学会认出它 |

## Patra 里的两种稳妥写法

第一种就是上面的 TopNav：第一次渲染用默认值，`useEffect` 里再换成真实值。

第二种用 React 的 `useSyncExternalStore`。它可以额外给一份「服务端快照」：服务器渲染和水合那一次用这份快照，水合之后才换成浏览器里的真实值。门户判断屏幕宽度的 Hook 是这样写的，服务端快照一律是「不命中」：

<CodeRef at="patra-portal/src/lib/use-media-query.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="7-19" />

```ts
export function useMediaQuery(query: string): boolean {
  return useSyncExternalStore(
    (onChange) => {
      if (!supported()) {
        return () => {};
      }
      const list = window.matchMedia(query);
      list.addEventListener("change", onChange);
      return () => list.removeEventListener("change", onChange);
    },
    () => supported() && window.matchMedia(query).matches,
    () => false,
  );
}
```

同样的办法还做出了一个「是否已经过了水合」的开关：

<CodeRef at="patra-portal/src/lib/use-hydrated.ts@6ead12db647bcd3e56f651af791d56e418cb79ff" lines="5-13" />

```ts
/// 是否已经过了水合：服务端渲染与水合那一次是 false（与服务端输出一致），之后是 true。
/// 客户端里直接挂载（不是水合）的组件第一次渲染就是 true
export function useHydrated(): boolean {
  return useSyncExternalStore(
    subscribe,
    () => true,
    () => false,
  );
}
```

导航栏读当前登录用户时就用它：水合那一次一律显示「登录状态未定」的占位，和服务器画的一致，之后才显示头像或「登录」。

设置页的关注领域选择器（拖拽排序）两种来源都碰上了，开头这几行都是为了让两边第一次渲染一致：
