## HTTP 没有记性

上一篇你看到，一问一答之后服务器就把你忘了。可是登录之后，你期望「我是谁」被一直记住。这中间缺的这一块，靠两个东西补上：

- **会话**（session）：服务器那边存的一条记录，写着「某个人，几点登录，设备是什么」。
- **Cookie**：浏览器那边存的一小段文字，写着这条会话的**号码**。浏览器之后每次请求都自动带上它。

<Callout kind="analogy">

游乐场的手环。入口处登记（登录）后，工作人员给你戴一个手环（Cookie），手环上只有一个编号。你去任何项目，对方扫编号，查登记簿（会话）就知道你买过票。手环丢了可以挂失，登记簿是他们自己的，随时能作废。

</Callout>

## 会话存在哪、存多久

在 Patra 里，会话由 identity 独占，存在 Redis 里。创建时有三件事：

- 写一条以令牌哈希为键的记录（用户、设备、创建时间、不活跃超时、绝对过期时间）。
- 记录的存活时间取「不活跃超时」和「距离绝对过期」两者中较短的那个。
- 每个用户的会话数有上限，超过时按创建时间挤掉最老的。

这就是服务端会话的好处：想踢掉哪台设备、封禁一个账号，直接删记录，下一次请求就会失败。

## Cookie 的三个安全属性

门户写会话 Cookie 时固定设了这些属性：

<CodeRef at="patra-portal/src/lib/auth/session-cookie.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="21-33" />

| 属性 | 作用 |
|---|---|
| `HttpOnly` | 页面里的脚本读不到这个 Cookie。就算页面被注入恶意脚本，也偷不走令牌。 |
| `Secure` | 只在 https 连接上发送，不在明文 http 上泄露。 |
| `SameSite=Lax` | 从别的网站发起的跨站请求，一般不带这个 Cookie，挡住一类伪造请求。 |

自己动手关掉它们，看会发生什么。先猜一猜。

<Callout kind="insight">

`Secure` 开着时，Cookie 名字前还有 `__Host-` 前缀：浏览器只接受本站经 https 写入、不带 Domain 的那一份。同一个域名下别的子网站没法种入或覆盖它。

</Callout>
