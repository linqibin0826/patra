## 浏览器只跟门户说话

门户的后端是一组服务（identity、interaction、notification……），统一从网关进。按说浏览器可以直接请求网关，但有两个麻烦：

1. 网关和门户不同源，浏览器默认不让门户的脚本读网关的响应。
2. 网关要 `Authorization: Bearer <令牌>`，而门户把令牌存在 HttpOnly Cookie 里，浏览器里的脚本读不到它，也就没法自己写这个头。

门户的做法是在中间加一层：浏览器只请求门户自己的 `/api/...`，同源、自动带 Cookie；门户在服务端读出令牌，换成请求头去请求网关。

<Callout kind="analogy">

像去银行办事，你只跟柜台说话。柜员拿着你的回执（Cookie）去后台调档案，把需要给你看的那几页复印给你。你不进后台，也不用知道后台的门牌号。

</Callout>

## Route Handler：一个文件就是一个接口

在 `app/` 目录下放一个 `route.ts`，导出名叫 `GET`、`PUT` 这类 HTTP 方法的函数，这个路径就成了一个接口。它收标准的 `Request`、回标准的 `Response`，跑在门户的服务器上。门户取提醒列表的接口整个文件只有这么多：

<CodeRef at="patra-portal/src/app/api/me/notifications/route.ts@4a13287485468f2c489027f1aac0bb6174643e8d" lines="6-16" />

```ts
export const dynamic = "force-dynamic";

/// 一个标签下的一页提醒（`tab`：`replies` / `mentions` / `helpful`；`cursor` 是下一页）。标签不认识时 404，不打网关
export async function GET(request: Request): Promise<NextResponse> {
  const query = new URL(request.url).searchParams;
  const tab = notificationTabSchema.safeParse(query.get("tab"));
  if (!tab.success) {
    return readReply({ kind: "not-found" });
  }
  return readReply(await fetchNotifications(tab.data, query.get("cursor") ?? undefined));
}
```

`force-dynamic` 让它每次请求都现跑，不被缓存：每个人的提醒都不一样。

真正发请求的是 `gatewayFetch`。整个门户只有这个文件知道网关在哪：

<CodeRef at="patra-portal/src/lib/gateway.ts@4a13287485468f2c489027f1aac0bb6174643e8d" lines="30-44" />

```ts
/// 统一网关客户端（server-only）：全仓库只有这里读 `PATRA_GATEWAY_BASE_URL`、向网关发请求。
/// 只负责把请求发出去：原样返回网关的响应，不解读状态码；网络错误和超时照常抛出。
/// 没传令牌就不带 `Authorization`，所以正文请求不会带上用户的令牌。
export async function gatewayFetch(path: string, init: GatewayRequestInit = {}): Promise<Response> {
  const baseUrl = process.env.PATRA_GATEWAY_BASE_URL;
  if (!baseUrl) {
    throw new Error("PATRA_GATEWAY_BASE_URL 未配置");
  }
  if (init.json !== undefined && init.body !== undefined) {
    throw new Error("json 和 body 只能给一个");
  }
  const headers: Record<string, string> = { ...forwardingHeaders(init.client) };
  if (init.token) {
    headers.Authorization = `Bearer ${init.token}`;
  }
```

这个文件第一行是 `import "server-only"`：要是有哪个客户端组件不小心 import 了它，构建直接报错。网关地址从环境变量来，只在服务器上读，浏览器永远不知道它。

## 门户不只是转发

中间这层顺手做了几件网关不该管、浏览器做不了的事：

| 做了什么 | 为什么 |
|---|---|
| 参数不合法就自己回，不请求网关 | 错的请求不往后端送 |
| 把结果收成 200 / 401 / 404 / 502 | 页面只按这四种分支，不用懂网关和各服务的错误格式 |
| 响应带 `Cache-Control: private, no-store` | 每个人的数据不同，不能被任何一层缓存给别人 |
| 写操作先查 `Origin` | Route Handler 不像 Server Action 那样自带跨站检查，要自己补 |

最后一条是写操作的门槛。「全部标为已读」的接口一开头就查：

<CodeRef at="patra-portal/src/app/api/me/notifications/read/route.ts@4a13287485468f2c489027f1aac0bb6174643e8d" lines="8-14" />

```ts
/// 全部已读（两个标签一起），返回新的未读数。写操作校验 `Origin`
export async function PUT(request: Request): Promise<NextResponse> {
  if (!isSameOrigin(request)) {
    return forbidden();
  }
  return readReply(await markAllNotificationsRead());
}
```
