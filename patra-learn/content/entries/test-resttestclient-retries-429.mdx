## 坑

用 `RestTestClient` 打真实端口（`webEnvironment = RANDOM_PORT`）的流程测试，底层是 Apache HttpClient 5。它遇到 429 会按响应里的 `Retry-After` 自动重发。被测接口的限流窗口一长（这次是到明天零点），测试就卡到 30 秒的集成测试超时，永远断言不到 429。

## 为什么

Apache HttpClient 5 自带一个默认的重试策略：对 429、503 这类「服务器说稍后再来」的响应，读 `Retry-After`，等到时间再发一次。这对真实客户端是好事，对测试却是障碍：测试想看的恰恰是第一次拿到的 429。

`RestTestClient` 在 RANDOM_PORT 下用的就是这个客户端，测试代码里看不出来。

<Callout kind="warn">

MOCK 环境（不起真实端口）的 `RestTestClient` 走 MockMvc，不经过这个 HTTP 客户端，表现不一样。换了测试环境，同一段断言的行为可能跟着变。

</Callout>

## 怎么避开

断言 429 的那一次请求，不经 `RestTestClient`，改用 JDK 自带的 `HttpClient` 直接发。它不会自动重试，拿到的就是服务器的第一个响应：

```java
private HttpResponse<String> postWithoutRetry(long user, Map<String, Object> body)
    throws Exception {
  HttpRequest.Builder request =
      HttpRequest.newBuilder(URI.create("http://localhost:" + port + POSTS))
          .header("Content-Type", "application/json")
          .POST(HttpRequest.BodyPublishers.ofString(JSON.writeValueAsString(body)));
  TestIdentity.headers(user)
      .forEach((name, values) -> values.forEach(v -> request.header(name, v)));
  try (HttpClient client = HttpClient.newHttpClient()) {
    return client.send(request.build(), HttpResponse.BodyHandlers.ofString());
  }
}
```
