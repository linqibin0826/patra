<Callout kind="lead">

**异常**是方法说「我做不下去了」的方式。`throw` 一出，当前方法立刻中断，异常沿着调用链往外走，直到遇到一个 `catch` 把它接住；一路都没人接，就由框架把它变成一个错误响应。好的异常要说清**错在哪一类**，接住它的人才知道该怎么办。

</Callout>

## 异常往外走，直到有人接住

方法 A 调用 B，B 调用 C。C 抛出异常而自己没接，C 就结束了，异常交回给 B；B 也没接，就交回给 A……这条「谁调用了谁」的链叫**调用栈**。接住的写法是 `try { … } catch (某种异常 e) { … }`：`try` 里的代码抛了这种异常，就跳进 `catch` 处理。

## 受检异常与非受检异常

Java 的异常分两大类，区别在于编译器管不管：

- **受检异常**：编译器强制你处理。调用一个声明了会抛它的方法，要么 `catch` 住，要么在自己的方法上也声明 `throws`，否则编译不过。
- **非受检异常**：继承自 `RuntimeException` 的那些，编译器不管，想不处理就不处理。

Patra 里有一个很典型的受检异常。登录限次要算邮箱的 SHA-256，Java 的 `MessageDigest.getInstance` 声明了会抛受检的 `NoSuchAlgorithmException`（「没有这种算法」）：

<CodeRef at="patra-api/patra-identity/patra-identity-infra/src/main/java/dev/patra/identity/infra/account/throttle/LoginThrottleAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="158-165" />

```java
  private static String sha256Hex(String value) {
    try {
      MessageDigest digest = MessageDigest.getInstance("SHA-256");
      return HexFormat.of().formatHex(digest.digest(value.getBytes(StandardCharsets.UTF_8)));
    } catch (NoSuchAlgorithmException e) {
      throw new IllegalStateException("JDK 缺少 SHA-256", e);
    }
  }
```

SHA-256 是每个 Java 运行环境都必须带的算法，这个异常实际上不会发生；真发生了，说明运行环境本身坏了，调用方也救不回来。所以这里接住它，换成非受检的 `IllegalStateException` 再抛，并把原来的异常 `e` 作为**原因**（cause）一起带上，排查时还能看到最初是哪里出的错。

Patra 自己定义的异常全是非受检的。业务出错（重名、没权限、找不到）大多数调用方都处理不了，只能交给最外层统一回错误；用受检异常，每一层都得写一遍 `throws`，却没人真去处理。

## 带上「错在哪一类」

光说「出错了」不够：最外层要决定回 404 还是 409，日志要能看出是用户填错了还是下游挂了。Patra 的领域异常有一个共同的基类：

<CodeRef at="patra-tool/patra-tool-core/src/main/java/dev/patra/tool/core/error/DomainException.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="64-85" />

```java
public abstract class DomainException extends RuntimeException implements HasErrorTraits {

  /// 与此异常关联的语义特征集合（不可变）。
  private final Set<ErrorTrait> traits;

  /// 使用提供的消息和语义特征创建领域异常。
  ///
  /// **核心构造函数** - 所有领域异常必须提供至少一个语义特征。
  ///
  /// @param message 异常消息（应包含足够的上下文信息用于调试）
  /// @param traits 语义特征（至少提供一个，推荐使用 {@link StandardErrorTrait}）
  /// @throws IllegalArgumentException 如果未提供任何 trait
  protected DomainException(String message, ErrorTrait... traits) {
    super(message);
    if (traits == null || traits.length == 0) {
      throw new IllegalArgumentException(
          "DomainException 必须提供至少一个 ErrorTrait。"
              + "这确保了异常的业务语义完整性。"
              + "请使用 StandardErrorTrait 或自定义 trait。");
    }
    this.traits = Set.of(traits);
  }
```

它继承 `RuntimeException`（非受检），并且构造时**必须**给至少一个**语义特征**（trait），比如 `NOT_FOUND`（找不到）、`CONFLICT`（冲突）、`DEP_UNAVAILABLE`（依赖的服务不可用）。不给就造不出来。重名异常给的是「冲突」：

## 别的服务出错了：翻译成自己的话

Patra 的服务之间会互相调用。被调的服务回了错误，调用方拿到的是一个统一的 `RemoteCallException`，里面带着对方的状态码、错误码和追踪号。它只该在最靠近网络的那一层出现，要翻译成本服务自己的领域异常再往外抛。

<Callout kind="warn">

接住异常却什么都不做（`catch (Exception e) {}`），是最难查的写法：出了错，日志里一个字没有，代码还当没事继续跑。要么处理，要么换成更有意义的异常再抛，并带上原因。

</Callout>
