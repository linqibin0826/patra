<Callout kind="lead">

Spring Batch 是专门跑「大量数据从一处搬到另一处」的框架。它把一次导入叫一个 **Job**，Job 由若干 **Step** 组成；最常见的 Step 是「分块」的：**Reader** 一条一条读，读满一块交给 **Writer** 一起写，然后提交一次事务、记下读到了哪。

</Callout>

## 为什么要分块

上面那道题说明了一个大事务的问题：断一次，前功尽弃。另一个极端是每条记录一个事务，2100 万次提交，光提交本身就要花很多时间。

分块（chunk）取中间：每 N 条一个事务。断了只丢当前这一块，提交次数也只有总数除以 N。

## 作者导入长什么样

```java
  @Bean

  /// 配置 PubMed Computed Authors 导入 Step。
  ///
  /// @return Step 实例
  @Bean
  public Step authorImportStep() {
    int chunkSize = getChunkSize();
    log.info("配置 authorImportStep，chunk size: {}", chunkSize);

    var stepBuilder =
        new StepBuilder("authorImportStep", jobRepository)
            .<AuthorAggregate, AuthorAggregate>chunk(chunkSize)
            .transactionManager(transactionManager)
            .reader(authorItemReader(null))
            .writer(authorItemWriter);
```

后面几行是按需挂上进度指标监听器，这里没贴。

这里没有 Processor：从 Reader 出来的已经是领域对象 `AuthorAggregate`，不需要中间再加工，所以 `chunk` 的两个类型参数都是 `AuthorAggregate`。

Reader 标了 `@StepScope`，意思是「每次 Step 执行时才创建」。这样它才能在创建时拿到这次运行的参数：下载地址是从 Job 参数 `downloadUrl` 注入的。

MeSH 主题词导入（`MeshDescriptorJobConfig`）是同一个结构：一个分块 Step，一个下载并解析 XML 的 Reader，一个 Writer，Job 参数多了一个 `meshVersion`。

数据和进度在同一个事务里提交，所以两者永远对得上：不会出现「数据写了、进度没记」导致重复，也不会出现「进度记了、数据没写」导致漏掉。

## 断点续跑要两个条件

**第一，重跑时要被认成「同一次导入」。** Spring Batch 用「Job 名 + 标识性参数」认一个 Job 实例。同一个实例上次失败了，再启动就是接着跑；参数不同就是一个全新的实例，从头来。Patra 启动作者导入时特意不加时间戳参数：

<CodeRef at="patra-api/patra-catalog/patra-catalog-infra/src/main/java/dev/patra/catalog/infra/author/batch/AuthorBatchAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="50-59" />

```java
    // 不添加时间戳，相同参数的 Job 只执行一次（支持断点续传）
    return jobOperatorHelper.launch(authorImportJob, jobParams, false);
```

**第二，Reader 要会存进度、会跳回去。** 框架只负责把 ExecutionContext 存好、下次交还，「读到哪了」「怎么跳到那」要 Reader 自己写。`AuthorItemReader` 在 `update()` 里存 `currentIndex`，在 `open()` 里读回来，重新下载文件后跳过这么多条：

## 谁来启动它

catalog 的 `application.yml` 里写了 `spring.batch.job.enabled: false`：服务启动时不自动跑任何 Job。

导入由调度中心 XXL-Job 触发：任务入口 `AuthorImportScheduleJob` 把下载地址放进命令交给应用层，应用层经端口 `AuthorBatchPort` 调到上面的 `AuthorBatchAdapter` 启动 Job。应用层不知道 Spring Batch 的存在，只知道「启动一次作者导入」。调度中心本身另有一篇讲定时任务。
