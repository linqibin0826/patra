## 背景

v0.17 重做学习站时定了两件事：站点对公网开放，读者是以后接触这个开源项目的人；条目由 Agent 从版本总结、排查记录里改写出来。排查记录原本是写给 Agent 自己避坑用的，里面有真实的机器名、内网地址、本机代理端口。

最初的想法是给这类条目打一个「个人环境」标签，站内不推荐它们，问题就解决了。规划时发现这条路走不通：条目是公开仓库里的文件，标签只能决定页面上展不展示，挡不住任何人去 GitHub 上读原文件。

## 选择

<Callout kind="lead" label="选了什么">

所有条目都必须能公开：不写凭据，不写 tailnet 地址、内网主机地址和机器主机名，需要时写 `<mini 的地址>` 这类占位，或者用文档专用的 `192.0.2.x`。「个人环境」标签只负责让这类条目不进路线、不上首页推荐。最后再由内容校验扫一遍全文，漏写的直接让测试失败。

</Callout>

校验认的是「具体地址」，不认网段写法：`100.64.0.0/10`、`10.0.0.0/8` 这种带前缀的写法可以照常出现在讲解里，`100.x.x.x` 这样的具体主机地址才拦。

## 代价

<Callout kind="cost">

改写排查记录时要逐条去掉本机细节，v0.17 转写旧材料的工作量因此变大。校验也只是兜底：它认得出地址和常见的令牌格式，认不出「这段描述其实暴露了作者的家庭网络」。所以维护技能里写明，守边界首先是写作者的事。如果以后条目改成不进公开仓库，这个决策就该重新考虑。

</Callout>
