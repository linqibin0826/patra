<Callout kind="lead">

**注解**是以 `@` 开头、贴在类、方法、字段上的标签。它自己不执行任何代码。**有人读它，它才有用**：编译器读、编译时的注解处理器读、运行时的框架读、测试工具读。同一个注解，没人读，就跟没写一样。

</Callout>

## 长什么样

前面几篇已经见过不少：

- `@Override`：贴在方法上，说「这个方法是在兑现接口或父类里的某一条」；
- `@Builder`：贴在 `UserCard` 上，让它多出一个 `builder()`；
- `@SpringBootApplication`：贴在每个服务的启动类上。

注解还可以带参数，比如 `@Transactional(propagation = MANDATORY)`，括号里是给读它的人看的设置。

<Callout kind="analogy">

注解像贴在快递箱上的「易碎」「此面朝上」。贴纸本身不会让箱子变结实；是快递员看到贴纸，才轻拿轻放。换一个不识字的快递员，贴纸就没用了。

</Callout>

下面按「谁在读、什么时候读」看四种。

## 读者一：编译器

`@Override` 是给编译器看的。登录限次的实现类里，每个兑现接口的方法都贴着它：

<CodeRef at="patra-api/patra-identity/patra-identity-infra/src/main/java/dev/patra/identity/infra/account/throttle/LoginThrottleAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="89-92" />

```java
  @Override
  public void recordSuccess(LoginAttempt attempt) {
    settle(attempt, "SUCCESS");
  }
```

编译器看到它，会去核对：接口或父类里真有一个 `recordSuccess(LoginAttempt)` 吗？没有就编译报错。

这能防住两类手滑。一类是重写父类已有的方法时写错了：比如想重写所有对象都有的 `toString()`，却拼成了 `toStirng()`，不贴标签，编译器以为你新写了一个方法，照常通过，运行时用的还是旧的 `toString()`；贴了标签，编译直接报错。另一类是接口改了：哪天 `LoginThrottlePort` 删掉了 `recordSuccess`，实现类里那个旧方法贴着 `@Override`，编译就会报错，提醒你它已经不对应任何约定了。

`@Override` 不改变代码做什么，只让编译器多帮你查一件事。

## 读者二：注解处理器，在编译时替你写代码

**注解处理器**是挂在编译器上的小程序，编译时扫描源码里的注解，按注解生成新的代码。Lombok 就是一个注解处理器。

catalog 里的字典解析适配器贴了 `@RequiredArgsConstructor`：

<CodeRef at="patra-api/patra-catalog/patra-catalog-infra/src/main/java/dev/patra/catalog/infra/kernel/registry/DictionaryResolverAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="30-37" />

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class DictionaryResolverAdapter implements DictionaryResolverPort {

  private static final String STATUS_RESOLVED = "RESOLVED";

  private final DictionaryEndpoint dictionaryEndpoint;
```

源码里没有构造器。Lombok 编译时看到 `@RequiredArgsConstructor`，就替它生成一个「把每个 `final` 字段都作为参数」的构造器，等于你手写了：

```java
public DictionaryResolverAdapter(DictionaryEndpoint dictionaryEndpoint) {
  this.dictionaryEndpoint = dictionaryEndpoint;
}
```

`@Slf4j` 同理，生成一个叫 `log` 的日志对象；`@Builder` 生成 `builder()` 和一整套按名字填值的方法。这些代码只出现在编译出的 `.class` 里，源码里看不到。

Lombok 要被挂到编译器上才会工作，这一步写在 Patra 的构建约定插件里：

<CodeRef at="build-logic/src/main/kotlin/patra.java-base.gradle.kts@b6e01875bb5692356021c8a19562f557f319fc54" lines="180-191" />

```kotlin
// ==================== Annotation Processors ====================
// extendsFrom 不传递 annotationProcessor configuration，需要为每个 suite 显式声明
dependencies {
    // Lombok
    compileOnly(libs.findLibrary("lombok").get())
    annotationProcessor(libs.findLibrary("lombok").get())
    testCompileOnly(libs.findLibrary("lombok").get())
    testAnnotationProcessor(libs.findLibrary("lombok").get())
    "integrationTestCompileOnly"(libs.findLibrary("lombok").get())
    "integrationTestAnnotationProcessor"(libs.findLibrary("lombok").get())
    "e2eTestCompileOnly"(libs.findLibrary("lombok").get())
    "e2eTestAnnotationProcessor"(libs.findLibrary("lombok").get())
```

两种写法各管一件事：`compileOnly` 让编译器认得 `@Builder` 这个名字；`annotationProcessor` 才是把 Lombok 挂上去、让它真的去生成代码。开头那道题删的就是后者：标签还认得，但没人照着标签干活，`builder()` 就不存在。

## 读者三：Spring，在服务启动时

`DictionaryResolverAdapter` 上还有一个 `@Component`，它是给 Spring 看的。

服务启动时，Spring 从启动类所在的包开始，往下扫描所有的类，看见贴着 `@Component` 的，就替你 `new` 一个对象，交给需要它的地方（这件事叫依赖注入，下一篇讲）。catalog 的启动类在 `dev.patra.catalog` 包里：

<CodeRef at="patra-api/patra-catalog/patra-catalog-boot/src/main/java/dev/patra/catalog/PatraCatalogApplication.java@cfec9c9f30270dcf03f5cd7b6e54a0cd3b59296b" lines="31-40" />

`@SpringBootApplication` 里就包含了「从这个包开始扫描」。`DictionaryResolverAdapter` 在 `dev.patra.catalog.infra.kernel.registry`，是它下面的包，所以会被扫到、被创建。整个过程里，`@Component` 自己一行代码都没执行，干活的是 Spring。

## 读者四：测试工具

注解也可以被测试读，用来守规矩。Patra 不许把 `@Transactional`（开启数据库事务的注解）贴在整个类上，这条规矩由一个架构测试检查：

<CodeRef at="patra-tool/patra-tool-test/src/main/java/dev/patra/tool/test/archunit/HexagonalArchitectureRules.java@cfec9c9f30270dcf03f5cd7b6e54a0cd3b59296b" lines="438-447" />

```java
  /// 禁止类级 `@Transactional`：注解只加在 public 方法上，事务范围一眼可见。
  ///
  /// @return ArchRule 规则实例
  public ArchRule noClassLevelTransactions() {
    return noClasses()
        .should()
        .beAnnotatedWith(Transactional.class)
        .as("禁止类级 @Transactional")
        .because("类级注解会把每个方法都包进事务，见 .claude/rules/tech/transaction.md 第 4 节");
  }
```

测试工具 ArchUnit 读取编译好的所有类，看哪个类上贴了 `@Transactional`，有就让测试失败。同一个 `@Transactional`，服务运行时 Spring 读它去开事务，跑测试时 ArchUnit 读它去查规矩，两个读者各取所需。
