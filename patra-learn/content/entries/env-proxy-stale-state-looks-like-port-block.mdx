<Callout kind="lead" label="结论先说">

代理软件里加了两条规则（VPN 网段跳过代理、部署机主机名总是解析成真实地址）之后，配置其实已经对了。但之前建立的连接、缓存的假地址还要几个小时才过期，期间表现为「一部分端口好了、一部分还挂着」。过了一夜，所有端口、主机名、裸 IP 都秒开。

- **值得记住**：改完代理或 DNS 配置后的「部分生效」，先怀疑旧状态没过期，用一个从没访问过的新端口做对照

</Callout>

背景：作者的笔记本开着代理软件，经 Tailscale 访问家里的部署机。这个组合之外的人碰不到同样的现象，但「三个视角对照」和「换一个新端口做对照」的查法到处适用。

## 现象

2026-08，笔记本浏览器访问部署机的几个控制台端口：有三个超时，一个慢但能通，其余正常。同一台笔记本上 curl 访问这些端口，全部正常。

## 根因

代理软件处理一个请求，前后要用到几份会缓存的状态：

1. **名字解析**：fake-ip 模式下，名字到假地址的映射会缓存一段时间；
2. **已经建立的连接**：浏览器和代理之间的长连接会复用，不会因为规则变了就重建。

改了规则，新的解析、新的连接按新规则走；旧的那些按旧规则走，直到过期。浏览器对不同端口的连接建立时间不同，于是有的端口碰到旧状态、有的碰到新状态。

## 修法

规则本身两条就够了（作者在代理软件里自己操作）：VPN 网段跳过代理；部署机的主机名总是解析成真实地址。改完之后要做的是**等**，或者主动清掉旧状态（重启浏览器、重启代理软件），而不是继续改规则。
