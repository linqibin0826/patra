## 痛点：要确认「你是谁」，又不能碰你的密码

v0.19 之前，读者只能用邮箱和密码注册 Patra。这一版的目标是：小陈点「用 GitHub 登录」，几步之后账号就建好了；老王已有账号，在设置页绑定 ORCID，下次直接用 ORCID 进原来的账号。

这里有一个绕不开的矛盾。Patra 要确认「这个人确实是 GitHub 上的这个账号」，能证明这件事的只有 GitHub；而 GitHub 只有在用户输入自己的密码后才知道他是谁。这个密码又绝不能经过 Patra。

## 以前怎么做，哪里不够

| 做法 | 能做到 | 不够的地方 |
|---|---|---|
| 只用邮箱和密码 | 账号完全自己管 | 读者要再记一个密码，注册多一道门槛 |
| 让读者把第三方密码交给网站 | 网站确实能登录第三方 | 密码出了手，范围限制不了，收回只能改密码 |
| 认第三方给的邮箱，邮箱一样就当同一个人 | 不用用户多操作 | 第三方不一定给邮箱，给了也不一定验证过；后面几篇会讲它怎样变成账号被接管 |

## OAuth2 和 OIDC 是什么

<Callout kind="lead">

OAuth2 是一个授权协议：用户在平台自己的页面上同意，平台发一个有范围的令牌给应用，应用全程碰不到密码。OIDC（OpenID Connect）是建在 OAuth2 上的一层约定，多发一张平台签名的 `id_token`，写明「这是谁」。

它们不是账号系统。平台只回答「这个人控制着我这里的这个账号」，Patra 的账号、会话和权限仍然是 Patra 自己的。

</Callout>

## 核心思路：回来时只带一张取件号

用户在平台上同意之后，要有东西从平台传回应用。这条路要经过浏览器，而浏览器地址栏、历史记录、日志都可能留下痕迹，所以回来时只带一个一次性的**授权码**。真正的令牌由应用的后端，凭只有它知道的密钥，直接向平台换。

<Callout kind="analogy">

像到办事大厅开证明。你不会把家门钥匙交给窗口，而是自己去派出所说明情况，拿回一张取件号。窗口凭取件号和自己的工作证到派出所领证明。取件号被人看到也没用，因为领证明还要那张工作证。

</Callout>

| 概念 | 一句话 | 在 Patra 里 |
|---|---|---|
| 客户端 | 在平台注册过的应用 | 密钥只放后端，不进仓库 |

| 授权码 | 一次性的取件号 | 回调地址上的 `?code=…&state=…` |
| `access_token` | 调平台接口的令牌 | 只在一次请求里活着，不进数据库和 Redis |

## 三家不一样在哪

Patra v0.19 接了三家，正好覆盖两种流程。Google 和 ORCID 走 OIDC，GitHub 只是纯 OAuth2。

| | Google | GitHub | ORCID |
|---|---|---|---|
| 权限范围 | `openid email` | `read:user` | `openid` |
| 流程 | OIDC | 纯 OAuth2 | OIDC |
| 怎么知道是谁 | `id_token` 的 `sub` | 调 `/user` 取 `id` | `id_token` 的 `sub`，规范化成裸 iD |
| 设置页显示 | 邮箱 | `login` | iD |
| 邮箱 | `id_token` 里有 | 只有公开邮箱，常为空 | 发现文档声明的字段里没有 |
| PKCE | 开 | 开 | 关（对方没有声明支持） |

ORCID 是给科研人员发永久编号的组织，这个编号叫 iD。它的公共 API 只允许非商业使用，Patra 目前是学习项目，符合条件；以后要收费就得换会员 API。

## 常见误解

- **以为 `access_token` 能证明身份。** OAuth2 讲的是授权，令牌回答「能做什么」。「这是谁」要么另调接口，要么靠 OIDC 的 `id_token`。
- **以为邮箱一样就是同一个人。** Patra 只按 `(provider, subject)` 认第三方账号，永不按邮箱合并。邮箱是用户自己填的，要证明能收信才算数。
- **以为接了第三方，Patra 就能替用户调平台接口。** 这次只做登录。确认身份后令牌就丢弃，头像和昵称也不导入，用户名只作预填建议。
- **以为第三方登录过，就算刚验证过身份。** 平台的登录状态可能早就在了，所以 Patra 的再认证只认密码。

## 什么时候用，代价是什么

<Callout kind="cost">

想降低注册门槛、不想再让用户多记一个密码时值得接。它不能替代账号系统，也不是没有成本：

- 登录多依赖了外部平台和出站网络，这条路连不上时只能用邮箱密码。
- 回调地址要在平台后台提前注册，Google 和 ORCID 正式环境都要求 HTTPS（Google 只对 `localhost` 例外）。Patra 为此每个环境一套应用，经内网地址访问门户时不显示第三方入口。
- 自动化测试只能用模拟平台，真实三家的行为要在部署后手工验收。

</Callout>

## 学习路线

| 档 | 学什么 | 对应篇目 |
|---|---|---|
| 协议 | 三个一次性值分别防什么 | `state`、`nonce`、PKCE 分别防什么 |
| 框架 | Spring Security 替你做了什么、哪里要换 | `oauth2Login`：两个过滤器与一组扩展点 |
| 决策 | 架构放在哪、账号何时建、再认证、撞车 | 门户收回调；验证邮箱后才建账号；再认证只认密码；邮箱撞车就地绑定 |
| 实战 | 真实碰到的坑和排查 | 加一条过滤器链，默认链没了；第三方登录时好时坏；JDK 和 Spring 的两个超时 |

Patra 只当客户端。自己当授权服务器、开放给别的应用接入，以及多站单点登录都没有做，要学这部分请看 OAuth2 和 OIDC 的官方规范。
