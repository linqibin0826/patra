<Callout kind="lead">

`@ConfigurationProperties` 把一组前缀相同的配置键，绑定到一个普通 Java 对象的字段上。代码里只读这个对象，不关心值是从 jar 里的 yml、Nacos 还是环境变量来的。

</Callout>

## 为什么不写死在代码里

「输错 5 次锁 15 分钟」是一条规则，可这两个数字以后很可能要调：被人撞库了想收紧，误伤太多想放宽。写死在代码里，每调一次都要改代码、重新构建、重新发布。写成配置，改一行配置就行，代码不动。

<Callout kind="analogy">

代码像一台空调，配置像遥控器上的温度。出厂时设了 26 度（默认值），住进来的人按遥控器改成 24 度，用不着拆开空调改电路。

</Callout>

## 一个配置类长什么样

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/config/LoginThrottleProperties.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="18-41" />

```java
@Data
@Validated
@ConfigurationProperties(prefix = "patra.identity.login-throttle")
public class LoginThrottleProperties {

  /// 计数窗口内允许的失败次数，到达即上锁。
  @Min(1)
  private volatile int maxFailures = 5;

  /// 计数窗口。
  @NotNull
  @DurationMin(nanos = 1)
  private volatile Duration window = Duration.ofMinutes(15);

  /// 锁定时长。
  @NotNull
  @DurationMin(nanos = 1)
  private volatile Duration lockDuration = Duration.ofMinutes(15);

  /// 在途登记的过期时间。
  @NotNull
  @DurationMin(nanos = 1)
  private volatile Duration inFlightTtl = Duration.ofSeconds(30);
}
```

一行一行看：

- `prefix = "patra.identity.login-throttle"`：这个类管哪一段配置。配置里 `patra.identity.login-throttle.max-failures` 绑到字段 `maxFailures`。
- 名字的写法可以不一样：yml 里习惯写 `max-failures`（短横线），Java 字段写 `maxFailures`（驼峰），Spring 认得它们是同一个。环境变量里写成全大写下划线 `PATRA_IDENTITY_LOGIN_THROTTLE_MAX_FAILURES`，也能对上。
- 类型自动转换：配置里写 `15m`，绑到 `Duration` 字段就是 15 分钟；写 `30s` 就是 30 秒。
- `@Validated` 加上 `@Min(1)`、`@NotNull`：值不合法（比如写了 `0`），启动直接失败，不会带着一个荒唐的规则跑起来。
- 字段上的 `= 5`、`= Duration.ofMinutes(15)`：谁都没写这个键时的默认值。Patra 现在的 Nacos 文件里就没写这几个键，线上用的就是这些默认值。

这个类自己不会进容器，要有人用 `@EnableConfigurationProperties` 登记它。identity 的装配类登记了它，再用它造出领域层要的规则对象：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/config/IdentityConfiguration.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="62-70" />

```java
  @Bean
  public Supplier<LoginThrottlePolicy> loginThrottlePolicy(LoginThrottleProperties properties) {
    return () ->
        LoginThrottlePolicy.of(
            properties.getMaxFailures(),
            properties.getWindow(),
            properties.getLockDuration(),
            properties.getInFlightTtl());
  }
```

领域层的 `LoginThrottlePolicy` 不知道有配置这回事，它只拿到几个数。配置类留在启动模块里，这也是六边形架构里「领域层不依赖框架」的一个体现。

## record 写法：启动后就不变的配置

identity 的其他配置用的是另一种写法，record 加 `@DefaultValue`（下面只截了开头几个字段）：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/config/IdentityProperties.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="20-24" />

```java
@ConfigurationProperties(prefix = "patra.identity")
public record IdentityProperties(
    @DefaultValue PasswordHashing passwordHashing,
    @DefaultValue Session session,
    @DefaultValue Username username,
```

两种写法的区别只在一件事：**运行中能不能改**。record 造好就不能改，适合数据源、端口、会话策略这类启动后不变的；`LoginThrottleProperties` 写成可变的类、字段加 `volatile`，是为了配置中心推来新值时能原地改掉（v0.9 决策 D，Nacos 那篇细讲）。不需要在线改的，Patra 一律用 record。

## 同一个键写在好几处，听谁的

最后那个「Nacos 盖过 jar」不是天生的，是启动器 `PatraApplication` 放进去的：

<CodeRef at="patra-tool/patra-tool-launch/src/main/java/dev/patra/tool/launch/PatraApplication.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="55-64" />

```java
    Map<String, Object> properties = new LinkedHashMap<>();
    properties.put("spring.application.name", applicationName);
    // 后导入的覆盖先导入的：本服务的配置覆盖公共配置
    properties.put(
        "spring.config.import", "nacos:" + COMMON_DATA_ID + ",nacos:" + applicationName + ".yaml");
    properties.put("spring.cloud.nacos.config.namespace", NAMESPACE);
    // Nacos 的值覆盖 jar 里的默认值（SCA 默认是本地优先）
    properties.put("spring.cloud.nacos.config.preference", "remote");
    properties.put(ConfigSourceCheckPostProcessor.REQUIRED_PROPERTY, "true");
    return properties;
```

这几行本身放在 Spring 的 default properties 里，那是比 jar 里的 yml 还低的一层，所以服务想改也改得了。

决策 C 当时否掉的另一种做法是「本地优先，并要求同一个键不在两处出现」：只能靠人记，迟早出错。现在的做法是 Nacos 赢，再加一个测试（`JarConfigOverlapCheckerTest`）检查 jar 和 Nacos 有没有写重同一个键。

## 环境变量覆盖：一个真实例子

identity 的 jar 里写着 IP 属地数据文件的目录，默认在用户主目录下。容器里没有那个目录，于是 compose 给容器设了一个环境变量，把它改成挂载进来的目录：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/resources/application.yml@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="101-104" />

```yaml
    # IP 属地（PAP-99）：ip2region 两个 xdb 所在目录，由 patra-infra/scripts/fetch-ip2region.sh 下载；
    # 容器里由 compose 设 PATRA_IDENTITY_IP_GEOLOCATION_DIRECTORY=/data/ip2region（只读挂载）。缺文件启动失败
    ip-geolocation:
      directory: ${user.home}/.patra/data/ip2region
```

同一份 jar，本机跑和容器里跑用的是不同的目录，代码和 yml 都不用改。

<Callout kind="warn">

真正的密钥（Redis 密码、外部 API key）不要写进任何一层配置文件。Patra 的配置文件里只写 `${变量}` 引用，值放在机器本地，由环境变量递进来（v0.9 决策 E）。

</Callout>
