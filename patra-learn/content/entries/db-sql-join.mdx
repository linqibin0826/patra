## 为什么要连表

上一篇的查询都只涉及一张表。可数据常常分在好几张表里：评论的正文在评论表，评论被点了几次有帮助在另一张统计表。页面要一次展示「正文 + 有帮助数」，就得把两张表按某一列对上，拼成一行。这就是**连表查询（JOIN）**。

对上的依据，就是前面讲过的外键关系：统计表的 `target_id` 对应评论表的 `comment_id`。

## 内连接：两边都对得上才留下

```sql
SELECT c.comment_id, c.body, hs.helpful_count
FROM discussion.comment c
JOIN reaction.target_stats hs
  ON hs.target_type = 'COMMENT' AND hs.target_id = c.comment_id;
```

（示意，表名取自 Patra，写法已简化。）`ON` 后面写「怎么对上」。表名后的 `c`、`hs` 是别名，省得每次写长名字。

写 `JOIN`（也叫 `INNER JOIN`，内连接）时，只有 `ON` 条件成立的行对才会出现在结果里。评论 B 在统计表里没有行，它就被"连丢"了。

## 左连接：左边的行一个都不丢

要让所有评论都出现，把 `JOIN` 换成 `LEFT JOIN`。它的规则是：**左边表（FROM 后面的那张）的每一行都保留；右边找不到对应行时，右边那几列填 NULL**。

Patra 读评论时用的就是它：

<CodeRef at="patra-api/patra-interaction/patra-interaction-infra/src/main/java/dev/patra/interaction/infra/discussion/persistence/CommentRows.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="44-58" />

```java
  static final String RECORD_SELECT =
      """
      SELECT c.comment_id, c.subject_id, c.root_id, c.parent_id, c.author_id, c.state, c.body,
             c.created_at, c.revised_at, p.author_id AS parent_author_id, p.state AS parent_state,
             EXISTS (SELECT 1 FROM discussion.comment r WHERE r.parent_id = c.comment_id)
                 AS has_replies,
             COALESCE(hs.helpful_count, 0) AS helpful_count
        FROM discussion.comment c
        LEFT JOIN discussion.comment p ON p.comment_id = c.parent_id
        LEFT JOIN reaction.target_stats hs
               ON hs.target_type = 'COMMENT' AND hs.target_id = c.comment_id
      """;
```

这段里有三个值得读的点：

- 评论表**连了自己**（`p` 是父评论）。顶层评论没有父评论，`LEFT JOIN` 让它仍然留在结果里，只是 `p` 的几列是 NULL。
- 统计表按设计「有过一次有帮助才有行」，表注释写着 `a missing row means 0`，没有行就是 0 个。所以用 `LEFT JOIN`，再用 `COALESCE(hs.helpful_count, 0)` 把 NULL 换成 0。
- 同一个 `FROM` 后面可以连多张表，每个 `LEFT JOIN` 各管各的。

## 一对多连表之后，行数会变多

连表还有一个让新手意外的地方：左边一行如果对上了右边的好几行，结果里它就出现好几次。

比如一篇文献有 3 位作者，作者在中间表 `cat_publication_author` 里是 3 行。把文献表连上作者中间表，这篇文献的标题会在结果里出现 3 次，每次配一位作者。

<Callout kind="warn">

连了一对多的表之后，`count(*)` 数的是**配对数**，不是左边实体的个数。想数有几篇文献，写 `count(DISTINCT p.id)`。

</Callout>
