<Callout kind="lead" label="结论先说">

部署机的 JVM 自动继承了系统代理。代理对 `CONNECT` 先回 200 再去拨上游，拨不通就关隧道，JVM 把这报成 `Remote host terminated the handshake`。Gradle 只对连接类异常重试，不重试握手异常，于是一次就失败。

- **怎么修**：在部署机的 Gradle 配置里让镜像站真正直连，错误就变回真实的超时，Gradle 会重试
- **值得记住**：报错写着 TLS，不代表问题在 TLS；先弄清连接经过了谁

</Callout>

## 现象

v0.13 后端的 CD 在部署机上连续失败两次，都卡在 Gradle 下载依赖：

```text
Could not download citeproc-java-3.5.2.jar
  > Remote host terminated the handshake
```

依赖来自国内的 Maven 镜像站 `maven.aliyun.com`。错误信息指向 TLS 握手，很容易让人去查证书、TLS 版本、JDK 的加密套件。

为什么一次就挂：Gradle 下载依赖时会判断异常值不值得重试，只认 `SocketException`、`SocketTimeoutException` 这类连接问题，`SSLHandshakeException` 不在里面。一次网络抖动，就成了整条 CD 失败。

那十几分钟里（01:09～01:25），直连拨号和代理节点同时大面积超时，问题出在部署机之外（路由器、上行或运营商），具体是哪一环没有查到。

## 修法

在部署机的 `~/.gradle/gradle.properties` 里，让镜像站绕过代理、真正直连（三条都要写，下面的值是示意，关键是都含镜像站）：

```properties
systemProp.http.nonProxyHosts=localhost|127.*|maven.aliyun.com
systemProp.https.nonProxyHosts=localhost|127.*|maven.aliyun.com
systemProp.socksNonProxyHosts=localhost|127.*|maven.aliyun.com
```

这样再遇到网络抖动，JVM 自己拨号超时，报的是 `SocketTimeoutException`，Gradle 会重试。注意 SOCKS 那一项的名字是 `socksNonProxyHosts`，写成 `socks.nonProxyHosts` 不生效；HTTP 那两项也要写，只写一个照样会进代理。

这个配置目前只在部署机上手工加了，还没写进 runner 的安装脚本。临时绕过的办法不变：在 runner 检出里先跑 `./gradlew` 预热缓存，再只重跑失败的任务。

<Callout kind="insight" label="怎么认出它">

JVM 报「握手被断」，先去代理日志里找同一时刻有没有 `dial … i/o timeout`，别先去调 TLS 参数。

</Callout>
