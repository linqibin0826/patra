<Callout kind="lead">

Java 程序跑起来要经过三步：**编译**（`.java` 源码变成 `.class` 字节码）、**打包**（一堆 `.class` 装进一个 jar）、**运行**（JVM 读 jar，从 `main` 方法开始一行行执行）。

</Callout>

## 电脑看不懂你写的代码

我们写的 Java 代码是给人看的文字，比如 `PatraIdentityApplication.java`。电脑的处理器只认一种很底层的指令，叫**机器码**；而且不同的处理器（Mac 的芯片、服务器的芯片）认的机器码还不一样。

所以中间需要翻译。很多语言是直接翻译成某一种处理器的机器码，翻好的东西只能在那一种机器上跑。Java 选了另一条路。

<Callout kind="analogy">

把源码想成一份中文菜谱。Java 不把它直接翻成某个厨师的方言，而是先翻成一种「通用速记」。每个厨房里都请一位看得懂速记的厨师，照着做菜。速记就是**字节码**，厨师就是 **JVM**。菜谱翻一次，哪个厨房都能用。

</Callout>

## 第一步：编译成字节码

**编译器**（Java 自带的 `javac`）读 `.java` 文件，检查有没有写错（少个分号、类型对不上），没错就为每个类生成一个 `.class` 文件。`.class` 里装的就是字节码。

写错了的代码在这一步就会被拦下，根本到不了运行那一步。这叫**编译期错误**。

## 第二步：打包成 jar

一个服务有成百上千个 `.class`，还要带上它用到的别人写的代码（框架、工具库）。把这些装进一个压缩包，就是 **jar**（Java ARchive）。Patra 每个服务最后都打成一个 jar，交给部署流程。

打包这件事由构建工具 Gradle 来做，后面「构建：Gradle 把代码变成能跑的包」那篇专门讲。

## 第三步：JVM 从 main 开始执行

**JVM**（Java 虚拟机）是一个程序，它读字节码，翻成当前机器的机器码去执行。JVM 打开 jar 后不会随便从哪一行开始，它找一个固定写法的方法：

```java
public static void main(String[] args)
```

这就是**入口**，名字必须叫 `main`。下面是 Patra 的 identity 服务的入口：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/PatraIdentityApplication.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="9-18" />

```java
@SpringBootApplication
public class PatraIdentityApplication {

  /// 经启动器启动应用，服务名 `patra-identity`。
  ///
  /// @param args 命令行参数
  public static void main(String[] args) {
    PatraApplication.run("patra-identity", PatraIdentityApplication.class, args);
  }
}
```

`main` 里只有一行：把活交给 Patra 的启动器 `PatraApplication`，由它把整个服务拉起来。开头的 `@SpringBootApplication` 是一个「标签」，先不管，「注解：贴在代码上的标签」那篇再讲。

Patra 的六个后端服务各有一个这样的启动类，长得几乎一样，只是服务名不同。

## 在 Patra 里：容器里只装了运行环境

Patra 的后端服务在 Docker 容器里跑。容器的「底座」写在 Dockerfile 里：

<CodeRef at="patra-infra/docker/service.Dockerfile@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="21" />

```dockerfile
FROM eclipse-temurin:25-jre
```

`jre` 是 Java Runtime Environment，Java 运行环境：里面有 JVM，但没有编译器。容器根本没法编译代码，它只拿到 jar、只负责跑。启动命令在同一个文件的最后一行：

<CodeRef at="patra-infra/docker/service.Dockerfile@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="57" />

```dockerfile
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75.0", "-DJM.LOG.PATH=/app/logs/nacos", "-DJM.SNAPSHOT.PATH=/app", "-jar", "app.jar"]
```

去掉中间几个设置项，就是 `java -jar app.jar`：启动 JVM，让它打开 `app.jar`，找到 `main`，开始执行。

<Callout kind="warn">

字节码不挑操作系统，但挑 Java 版本。Patra 用 Java 25 编译，`25-jre` 里的 JVM 才认得它；拿版本更老的 JVM 去跑，启动时就会报错，说这个 class 文件的版本太新。

</Callout>
