<Callout kind="lead">

依赖注入：一个对象要用的其他对象（它的「依赖」），不由它自己创建，而是由外面造好、通过构造器交给它。在 Spring 里，「外面」就是容器。

</Callout>

## 自己 new 的麻烦在哪

先看不用依赖注入会怎样。假设登出处理类自己 new 会话存储：

```java
public class LogoutUserHandler {
  // 想用会话存储，就得自己造一个
  private final SessionStorePort sessions = new SessionStoreAdapter(new RedisSessionStore(...));
}
```

问题马上冒出来：

- 造 `SessionStoreAdapter` 要先造 `RedisSessionStore`，造它又要 Redis 的地址、密码、连接池……登出这个类本来只关心「删掉会话」，现在却要知道 Redis 怎么连。
- 想写个单元测试，不连真 Redis，只想看「会话删掉后登录记录有没有被标成登出」，做不到：`new` 写死在类里，换不掉。
- 另一个类也要会话存储，又 new 一份，两份连接池各管各的。

<Callout kind="analogy">

厨师做菜要用刀、锅、灶。一种做法是每个厨师上班先自己去铁匠铺打一把刀；另一种是后厨统一备好，厨师站到灶台前，东西已经摆在手边。依赖注入是后一种：厨师只说「我要一把刀」，不管刀从哪来。

</Callout>

## Bean 与容器

Spring 启动时会建一个**容器**（官方叫 ApplicationContext），可以把它想成一个大仓库。仓库里放的每一个由 Spring 管理的对象叫 **Bean**。

谁会进仓库？主要两种来源：

1. 类上贴了 `@Component`（或 `@Repository`、`@Service` 这类同义注解），Spring 启动时扫描到它，就造一个放进去。`LogoutUserHandler` 贴的是 `@Component`，`SessionStoreAdapter` 也是 `@Component`。
2. 配置类里写了 `@Bean` 方法，Spring 调这个方法，把返回值放进去。Patra 的 `Clock`（时钟）就是这样来的。

## 构造器注入：把要什么写在构造器上

看真实代码：

<CodeRef at="patra-api/patra-identity/patra-identity-app/src/main/java/dev/patra/identity/app/session/usecase/logout/LogoutUserHandler.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="23-32" />

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class LogoutUserHandler implements CommandHandler<LogoutUserCommand, Void> {

  private final CurrentUserPort currentUserPort;
  private final SessionStorePort sessions;
  private final UserLoginRecordRepository records;
  private final Clock clock;
  private final TransactionOperations transactions;
```

这里看不到构造器，是因为 Lombok 的 `@RequiredArgsConstructor` 在编译时替它生成了一个：所有 `final` 字段按顺序当参数。展开后相当于：

```java
public LogoutUserHandler(
    CurrentUserPort currentUserPort,
    SessionStorePort sessions,
    UserLoginRecordRepository records,
    Clock clock,
    TransactionOperations transactions) {
  this.currentUserPort = currentUserPort;
  // 其余四个同理
}
```

字段都是 `final`：对象一造好，依赖就定了，之后不会被谁偷偷换掉，也不会出现「忘了设、用到时是 `null`」。类只有一个构造器时，Spring 会自动用它来造对象，构造器上不用再贴注解。

找不到或找到不止一个，都会让启动失败：没有实现，容器说「缺一个 `SessionStorePort`」；有两个实现又没说用哪个，容器说「不知道选谁」。这比运行到一半才发现 `null` 好得多。

## 为什么这样更好测

依赖从构造器进来，测试时就可以自己 new 这个类，递进去想要的替身。这是 `LogoutUserHandler` 的单元测试：

<CodeRef at="patra-api/patra-identity/patra-identity-app/src/test/java/dev/patra/identity/app/session/usecase/logout/LogoutUserHandlerTest.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="38-47" />

```java
  private final CurrentUserPort currentUserPort = mock(CurrentUserPort.class);
  private final SessionStorePort sessions = mock(SessionStorePort.class);
  private final UserLoginRecordRepository records = mock(UserLoginRecordRepository.class);
  private final LogoutUserHandler handler =
      new LogoutUserHandler(
          currentUserPort,
          sessions,
          records,
          Clock.fixed(NOW, ZoneOffset.UTC),
          TransactionOperations.withoutTransaction());
```

这里没有 Spring、没有 Redis、没有数据库：

- `mock(...)` 造的是假的会话存储和登录记录，测试里可以规定「`revoke` 返回 `true`」，再检查登录记录有没有被保存。
- `Clock.fixed(NOW, ...)` 是一只停住的表，测试里「现在」永远是同一刻，断言登出时间时不会差几毫秒。
- `TransactionOperations.withoutTransaction()` 是一个不开事务、直接执行的替身。

这几样能换，全因为 `LogoutUserHandler` 不自己 new。Patra 的测试约定里「注入 `Clock`，不直接调 `Instant.now()`」，也是同一个道理。
