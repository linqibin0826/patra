<Callout kind="lead">

`@RestController` 标出一个处理 HTTP 请求的类。类和方法上的 `@GetMapping`、`@DeleteMapping` 等注解决定哪个请求交给哪个方法；`@PathVariable`、`@RequestBody` 决定请求里的值怎么变成参数；方法返回的对象由 Spring 写成 JSON。

</Callout>

## 一个真实的 Controller

identity 服务里管「我的登录设备」的 Controller，一共三个接口：看列表、踢一台、踢掉除本机外的全部。

<CodeRef at="patra-api/patra-identity/patra-identity-adapter/src/main/java/dev/patra/identity/adapter/session/rest/MeSessionController.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="18-52" />

```java
@Tag(name = "Me", description = "当前用户的账号设置")
@RestController
@RequestMapping("/me/sessions")
@RequiredArgsConstructor
public class MeSessionController {

  private final CommandBus commandBus;
  private final SessionQueryService sessionQueryService;

  /// 登录设备列表，只含活会话，本机第一。401 当前会话已不在。
  ///
  /// @return 列表
  @GetMapping
  public SessionListResponse list() {
    return SessionListResponse.from(sessionQueryService.list());
  }

  /// 踢掉除本机外的全部设备。403 超过再认证窗口（`traits` 含 `REAUTH_REQUIRED`）。
  ///
  /// @return 被踢掉的会话数
  @DeleteMapping("/others")
  public SessionsRevokedResponse revokeOthers() {
    return SessionsRevokedResponse.from(commandBus.handle(RevokeOtherSessionsCommand.of()));
  }

  /// 踢掉一个设备。已经不在也是 200（数量 0）；409 踢的是本机（`CURRENT_SESSION`，本机走退出登录）；
  /// 403 超过再认证窗口。
  ///
  /// @param id 会话 ID
  /// @return 被踢掉的会话数
  @DeleteMapping("/{id}")
  public SessionsRevokedResponse revoke(@PathVariable long id) {
    return SessionsRevokedResponse.from(commandBus.handle(RevokeSessionCommand.of(id)));
  }
}
```

它要的 `CommandBus` 和 `SessionQueryService` 照样是构造器注入进来的，和依赖注入那篇里的 `LogoutUserHandler` 一样。

## 路由映射：哪个请求交给哪个方法

类上的 `@RequestMapping("/me/sessions")` 是公共前缀，方法上的注解再补上请求方法和剩下的路径，拼起来就是完整的路由：

| 请求 | 交给 |
|---|---|
| `GET /me/sessions` | `list()` |
| `DELETE /me/sessions/others` | `revokeOthers()` |
| `DELETE /me/sessions/7001` | `revoke(7001)` |

`/{id}` 里的花括号是占位：这一段写什么都能匹配，匹配到的值留着给参数用。

## 参数绑定：请求里的值怎么变成参数

`revoke(@PathVariable long id)` 的意思是：把路径里 `{id}` 那一段取出来，交给参数 `id`。URL 里的 `7001` 本来是一串字符，Spring 按参数类型把它转成 `long`。转不了（比如 `/me/sessions/abc`），这个方法根本不会被调用，请求在进方法前就被拒绝，回一个 400。

除了路径，请求里还有别的地方能取值。登录接口要从请求体里读邮箱和密码：

```java
  @PostMapping("/login")
  public AuthenticatedUserResponse login(
      @RequestBody LoginRequest request,
      HttpServletRequest http,
      @RequestHeader(value = HttpHeaders.USER_AGENT, required = false) String userAgent) {
```

| 注解 | 从哪取 | 例子 |
|---|---|---|
| `@PathVariable` | 路径里的占位段 | `/me/sessions/{id}` 的 `id` |
| `@RequestParam` | `?` 后面的查询参数 | `?page=2` 的 `page` |
| `@RequestBody` | 请求体（通常是 JSON） | 登录时的邮箱、密码、客户端类型 |
| `@RequestHeader` | 请求头 | `User-Agent` |

`@RequestBody LoginRequest request` 里，`LoginRequest` 是一个 record，字段是 `email`、`password`、`clientType`、`deviceId`。请求体 JSON 里同名的键会被读进对应字段。

## 返回值怎么变成 JSON

`@RestController` 等于 `@Controller` 加 `@ResponseBody`：方法返回的对象不是页面名，而是直接写进响应体。写成什么格式？Spring 看调用方要什么、自己有哪些转换器，Patra 的接口一律是 JSON，由 Jackson 来写。

`revoke` 返回的是：

```java
public record SessionsRevokedResponse(int revokedSessions) {
```

写出来就是：

```json
{ "revokedSessions": 1 }
```

record 的每个字段变成 JSON 的一个键。对象怎么变 JSON、JSON 怎么变回对象，以及 Patra 里为什么有些数字被写成了字符串，是 Jackson 那篇的内容。

## Controller 里不写业务

注意 `MeSessionController` 里一行业务判断都没有：踢的是不是本机、有没有超过再认证窗口，都不在这里。Patra 的约定是：

- 写操作（会改数据的）包成命令交给 `CommandBus`；
- 读操作直接调 `QueryService`；
- Controller 不直接碰数据库，也不调别的 Controller。

这样同一个「踢设备」的逻辑，以后从定时任务、消息里触发，也不用复制一份。

<Callout kind="warn">

请求和响应用的是专门的 `*Request`、`*Response` 对象，不直接把领域对象（比如用户聚合）返回出去。领域对象一改字段，接口的 JSON 就跟着变，调用方会莫名其妙地坏掉。

</Callout>
