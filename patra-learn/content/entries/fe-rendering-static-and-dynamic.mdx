## HTML 在两个时间点之一生成

服务端组件把页面画成 HTML，这件事可以发生在两个时间点：

- **构建时**（静态生成，也叫预渲染）：`next build` 时就把 HTML 画好存下来，之后每个访客拿到的都是同一份，服务器不用再画。
- **请求时**（动态渲染）：每来一个请求，服务器现画一次，可以按这个请求的情况画出不同的内容。

这个学习站本身就是纯静态站：构建时把每一篇条目都预渲染成 HTML，运行时只把现成的文件发出去，不再去读条目的源文件。读者是谁、什么时候来，看到的都一样，所以没有理由每次现做。

门户就不一样了。用户主页要知道「来看的人是不是主页的主人」，只能等请求到了才知道。

## 什么让一页变成动态

Next.js 不需要你声明一页是静态还是动态，它看页面渲染时用了什么。下面这些只有请求到了才有答案，用到任何一个，这一页就改成请求时渲染：

- `cookies()`、`headers()`：读这个请求带的 Cookie、请求头；
- `searchParams`：读网址问号后面的查询参数；
- 带 `cache: "no-store"` 的 `fetch`：明说这份数据不许缓存，每次都要现取。

用户主页一上来就调用 `lookupSession()` 查当前用户。顺着它往下找，最终读的是 Cookie：

<CodeRef at="patra-portal/src/lib/auth/session-cookie.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="35-39" />

```ts
/// 读会话令牌；没有 Cookie 或值为空时返回 null。
export async function readSessionToken(): Promise<string | null> {
  const value = (await cookies()).get(sessionCookie().name)?.value;
  return value ? value : null;
}
```

另外，门户调网关的请求都走 `gateway.ts`，这里发出的请求一律不缓存：

<CodeRef at="patra-portal/src/lib/gateway.ts@4a13287485468f2c489027f1aac0bb6174643e8d" lines="52-55" />

```ts
  return fetch(`${baseUrl}${path}`, {
    method: init.method ?? "GET",
    headers,
    cache: "no-store",
```

公开收藏夹页和文献详情页还读了 `searchParams`（排序、页码）。这几页每一条都踩中了，都是动态的。

Next.js 判断动态的办法，是在静态生成的过程中让这些 API 抛出一个特殊的信号。门户代码里好几处 `try/catch` 都要先把这个信号原样抛回去，这是另一篇坑的主题。

## 静态页里的客户端组件，读查询串要包一层

客户端组件也能读查询参数，用的是 `useSearchParams`。静态页在构建时生成，那时没有查询参数，所以用到它的那一块只能等到浏览器里再画。门户的导航栏放在很多页面里，其中有不读请求的静态页；它里面读查询串的组件，各包了一层 `Suspense`：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="248-251" />

```tsx
      {/* 读查询串拼 next，包一层 Suspense，不让整个导航栏退出静态渲染 */}
      <Suspense fallback={null}>
        <PendingDeletionRedirect />
      </Suspense>
```

`Suspense` 圈出「这一块到浏览器里再画」的范围，外面的部分照样在构建时画好。不包的话，构建会直接报错。

## 静态还是动态，决定了预取取回多少

页面里的 `Link` 一进入可视区域，Next.js 就在后台把它指向的页面先取一部分回来，这叫预取。取多少，要看目标页是静态还是动态、有没有 `loading.tsx`。预取只在生产构建里自动发生，开发模式看不到。切换下面三种情况比一比：
