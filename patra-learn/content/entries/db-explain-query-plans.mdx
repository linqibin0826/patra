## 同一条 SQL，数据库有很多种执行办法

你写的 SQL 只说"要什么"。"怎么拿"是数据库的**查询规划器**决定的：先扫哪张表、用不用索引、先过滤还是先连表。规划器会估算各种办法的成本，挑一个它认为最便宜的。

这个选择就是**执行计划**。有时它挑得不对，或者因为你写法的缘故根本没有好选项。要知道它挑了什么，在 SQL 前面加 `EXPLAIN`：

```sql
EXPLAIN
SELECT * FROM cat_organization_name WHERE name_value ILIKE '%北京大学%';
```

数据库不执行这条查询，只把计划打印出来。

## EXPLAIN ANALYZE：真的跑一遍

`EXPLAIN` 给的是**估算**。想看**真实**耗时，用 `EXPLAIN ANALYZE`：它会真的执行查询，并给出每一步实际花了多少时间、实际返回多少行。

<Callout kind="warn">

`EXPLAIN ANALYZE` 会真的执行语句。对 `UPDATE`、`DELETE` 也是真改。想看这类语句的计划，要放在事务里，看完回滚：`BEGIN; EXPLAIN ANALYZE UPDATE ...; ROLLBACK;`。

</Callout>

Patra 在为机构联想接口选索引时，就是在 mini（作者家里常驻的 Mac mini 部署机，上面跑着开发环境的库）的真实数据上做的：开事务、建索引、跑每条查询的 `EXPLAIN (ANALYZE)`、最后 `ROLLBACK`，不在库里留任何痕迹。每条跑 3 次取第 3 次，这样看到的是数据已经在缓存里的耗时。

## 读一份计划

计划是一棵树。看缩进：最里面（缩得最深）的先执行，结果往外传。下面是示意输出（省略了成本等数字），查"名称里含北京大学"：

```
Bitmap Heap Scan on cat_organization_name
  Recheck Cond: (name_value ~~* '%北京大学%'::text)
  ->  Bitmap Index Scan on idx_org_name_value_trgm
        Index Cond: (name_value ~~* '%北京大学%'::text)
```

从内往外读：先用 `idx_org_name_value_trgm` 这个索引找到可能的行位置（`Bitmap Index Scan`），再回表把这些行取出来复查一遍（`Bitmap Heap Scan`）。

最常见的几种扫描方式：

| 节点 | 意思 | 好不好 |
|---|---|---|
| `Seq Scan` | 顺序扫描：整张表从头读到尾 | 表很小，或要取的行占大头时是对的；表大而只要几行时很糟 |
| `Index Scan` | 走索引，找到一行就回表取一行 | 取少数几行时很快 |
| `Index Only Scan` | 要的列索引里都有，不用回表 | 最快 |
| `Bitmap Index Scan` + `Bitmap Heap Scan` | 先走索引收集一批位置，再批量回表 | 命中行数中等时常见 |
| `Parallel Seq Scan` | 多个进程分头顺序扫描 | 大表全扫的并行版本 |

计划里还有几个值得看的字段：

- **`Index Cond`**：走索引时用的条件。
- **`Filter`**：取出行之后再逐行过滤的条件。条件出现在 `Filter` 而不是 `Index Cond`，说明没法靠索引定位。
- **`rows`**：规划器估计会返回的行数。`EXPLAIN ANALYZE` 里会再给一个"实际行数"，**估计和实际差几十上百倍**通常意味着统计信息过期，规划器是凭错误的数字选的计划。
- **`actual time`**：实际耗时，是 `EXPLAIN ANALYZE` 才有的。

规划器放弃索引的常见原因：

1. **没有合适的索引**，或者联合索引缺了最左列。
2. **列被函数包住**（`lower(col)`、`col + 1`、类型转换），索引里存的是原值。
3. **要取的行太多**，占表的很大比例，顺序扫描反而更快。
4. **表很小**，全扫比走索引便宜。
5. **统计信息过期**，规划器以为只有几行，实际有几万行，选错了计划。（`ANALYZE` 可以刷新统计信息。）

Patra 的机构联想正好撞上了第 2 条：为了让两个汉字的短查询（如「协和」）绕开一个麻烦，查询条件特意写成 `lower(n.name_value) LIKE lower(:contains)`。写成函数包列之后，规划器用不了 trigram 索引，两种计划都是顺序扫描，耗时稳定在 34 毫秒左右。为什么要绕开，下一篇会讲。
