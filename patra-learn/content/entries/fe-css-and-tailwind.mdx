## 每个元素都是一个盒子

CSS 眼里，页面上每个元素——按钮、段落、图片——都是一个长方形的盒子。盒子从里到外有四层：

| 层 | 是什么 | Tailwind 写法举例 |
|---|---|---|
| 内容 | 文字、图片本身占的地方 | `w-50`：宽 200px |
| 内边距 padding | 内容和边框之间的空隙 | `p-5`：四周各 20px |
| 边框 border | 盒子的那一圈线 | `border`：1px |
| 外边距 margin | 这个盒子和旁边盒子的间距 | `mt-4`：上方 16px |

<Callout kind="analogy">

像墙上挂的一幅装裱好的画：画本身是内容，画和画框之间的白衬纸是内边距，画框是边框，这幅画和旁边那幅之间留的墙面是外边距。

</Callout>

这里有一个大多数人第一次都会算错的地方：给盒子写了 `width: 200px`，它到底占多宽？答案取决于一条规则 `box-sizing`。切换看两种算法：

门户用的 Tailwind 在最开头放了一份「基础重置」样式，第一条就是把所有元素改成 `box-sizing: border-box`。所以在门户里写的宽度，就是盒子最终占的宽度。

## Flex 排成一行，Grid 放进格子

单个盒子之外，还要决定盒子之间怎么摆。最常用的是两种：

- **Flex**（弹性布局）：把子盒子沿一条线排开，常用来排一行按钮、图标加文字。
- **Grid**（网格布局）：先画好几列（或几行）格子，再把子盒子放进去，常用来分页面的几大块。

门户顶栏两种都用了。整条顶栏是一个三列的格子：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="105" />

```tsx
        <div className="mx-auto grid h-14 max-w-page grid-cols-[1fr_auto_1fr] items-center gap-6 px-gutter max-[880px]:grid-cols-[1fr_auto]">
```

`grid-cols-[1fr_auto_1fr]` 定了三列：左边是 Logo，中间是「首页 / 文献 / 期刊」导航，右边是按钮区。`auto` 是「内容多宽就多宽」，`1fr` 是「分剩下的地方」。

右边的按钮区里，几个按钮排成一行，用的是 Flex：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="142" />

```tsx
          <div className="flex items-center gap-1.5 justify-self-end">
```

`flex` 让子盒子横着排，`items-center` 让它们上下居中对齐，`gap-1.5` 在它们之间留 6px。

## Tailwind：把样式写成类名

传统写法是在单独的 CSS 文件里写规则，再给元素起个类名去对应。Tailwind 反过来：预先准备好成百上千个只做一件事的类名，你直接写在元素上。每个类名对应一两行 CSS：

| 类名 | 对应的 CSS |
|---|---|
| `flex` | `display: flex` |
| `items-center` | `align-items: center` |
| `h-9` | `height` 为 9 × 0.25rem，即 36px |
| `gap-6` | `gap` 为 6 × 0.25rem，即 24px |
| `rounded-full` | `border-radius` 设成无限大，两头变成半圆 |
| `grid-cols-[1fr_auto_1fr]` | `grid-template-columns: 1fr auto 1fr`（方括号里写任意值，下划线代替空格） |

类名前面还能加条件：`hover:text-ink-900` 是「鼠标移上去时字变成 ink-900 色」，`max-[880px]:hidden` 是「窗口窄于 880px 时藏起来」。

好处是样式就写在元素旁边，不用在两个文件之间来回找；代价是类名一长串，第一次读要逐个认。

## 设计 token：颜色只定义一次

`text-ink-900`、`bg-action-primary` 里的颜色不是随手写的色值，而是**设计 token**：给颜色、字号、间距起名字，全站只在一个地方定义它们的值。门户的 token 在 `src/styles/tokens.css`。

对应的几行真实代码：

<CodeRef at="patra-portal/src/styles/tokens.css@902182a65145dd7d152774d6ecaacc48ef9886bb" lines="99" />

```css
  --action-primary: var(--clay-700);
```

<CodeRef at="patra-portal/src/app/globals.css@4a13287485468f2c489027f1aac0bb6174643e8d" lines="66" />

```css
  --color-action-primary: var(--action-primary);
```

为什么要分「色值」和「用途」两层：主按钮哪天要换成另一个色系，只改 `--action-primary` 指向谁；而 `--clay-700` 可能还被别的地方当成别的用途用着，不该跟着动。

<Callout kind="warn">

在组件里直接写死色值（例如 `bg-[#97441e]`）也能出效果，但它绕过了 token：下次统一调色时这一处不会跟着变，页面上就会多出一块颜色对不上的按钮。门户的约定是只用 token 生成的类名。

</Callout>
