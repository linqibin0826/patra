## 现象

v0.9 配置中心那一版收尾时，专门演练了「推错配置」：把 identity 的登录失败上限 `patra.identity.login-throttle.max-failures` 推成 0。

这个配置类可以在线刷新，字段上有 `@Min(1)`。刷新时 Spring Cloud 重新绑定、校验失败，健康检查转为 DOWN，登录接口返回 422。到这一步都符合预期。

接着用推送脚本把出错前的原文推回去。Nacos 客户端日志里有 `data-received`，说明新内容收到了；可后面再也没有 `notify-listener`。服务一直是 DOWN，登录一直 422。

<Callout kind="insight">

为什么坏值会留在对象里：Spring Cloud 的重新绑定是先把新值写进配置对象、再校验。校验失败只会让刷新报错、健康检查转 DOWN，不会把旧值放回去。这是 Patra 有意接受的代价（见「取消自研的 RefreshableProperties」那篇）。

</Callout>

## 修法

恢复有两种办法：

1. 先推一版**内容不同**的配置（比如多一行注释），让 md5 变化、触发刷新并绑定成功，再推回原文。
2. 重启服务。

日常不会碰到第二步：配置文件放在 git 里，合进 main 后由 CD 推送，CD 改了某个服务的配置就会重新部署这个服务。用 git revert 撤回坏配置，CD 推送并重部署，服务自然恢复。只用推送脚本手动推回原文、不重部署时，才会掉进这个坑。
