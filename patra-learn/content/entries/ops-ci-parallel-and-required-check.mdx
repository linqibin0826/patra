## 先并行：总耗时取最慢的那个

上一篇算出了“要考哪些科”。这一篇看这些科怎么开考。

关键词是**并行**：各个检查任务互不依赖，各领一台云端机器**同时开工**。总耗时不是各科相加，而是等最慢的那一个。

backend 这一步值得细看。它用 **matrix（矩阵）** 把一个 job 展开成一组：

<CodeRef at=".github/workflows/ci.yml@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="119-147" />

- `matrix.unit` 的取值来自 detect-changes 输出的单元列表。列表里有几个单元，就生成几个并行任务。
- `fail-fast: false`：一个单元失败了，其余的继续跑完。这样一次就能看到所有出错的单元，不用修一个、再等一轮。
- 每个单元要跑什么 Gradle 任务，从 module-graph 里查，而不是写死在 workflow 里。

## 再汇总：为什么需要一个“总闸”

分支保护要指定“哪些检查必须通过”。问题来了：

- backend 的任务名随矩阵变化，比如 `backend (catalog)`，每个 PR 不一样，没法提前逐个指定。
- 有些任务在某些 PR 里根本不会跑。

所以 Patra 另写了一个任务 `required-check`，专门做汇总，并且它的名字永远不变。分支保护只认它。

<CodeRef at=".github/workflows/ci.yml@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="294-305" />

三个关键点：

1. `needs` 列出所有要汇总的任务。
2. `if: always()`：**前面的任务失败了，它也要运行**。这是最容易写错的一行，下面单独演示。
3. `allowed-skips`：这几个任务**没有跑（skipped）**，视为通过。没有在名单里的，比如 detect-changes 和 preflight，必须是成功。

## 允许被跳过，而不是允许被忽略

`allowed-skips: backend, portal, learn, coverage` 这一行的含义要想清楚：

- 这些任务**没有运行**，算通过。比如改文档时，它们本来就不该跑。
- 这些任务**运行了但失败**，仍然算失败。跳过和不及格是两回事。

所以，新增一个“有条件才跑”的任务时，要同时做两件事：把它加进 `needs`，并把它加进 `allowed-skips`。漏了第二件，下一个只改文档的 PR 就会被它挡住：它被跳过，但不在许可名单里，汇总任务判定为失败。

## 几处故意的不对称

- **门户的 e2e 测试**：在 PR 里失败不挡合并，在每晚的全量检查里才阻塞。浏览器测试偶尔会抖，不能因此卡住每个 PR。
- **学习站的 e2e 测试**：只在本地跑，不进 CI。
- **Gradle 缓存**：PR 里只读，只有主分支和夜间任务才写入。避免 PR 代码污染共享缓存。
- **每晚一次全量**：不管有没有 PR，每天固定跑一遍，兜住“局部检查漏掉的东西”，同时把缓存喂热。
