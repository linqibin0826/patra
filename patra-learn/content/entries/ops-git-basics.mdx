## 提交是一张快照

Git 是一个记录文件变化的工具。你改了一些文件，执行一次**提交（commit）**，Git 就把此刻整个项目的样子拍一张快照，并附上一句说明。

每张快照都有一个编号，是一串 40 位的十六进制字符，比如 `4a1328748…`，日常只看前 9 位就够。快照之间是接龙关系：每一张都记着“我的上一张是谁”。把这条接龙往回数，就是项目的完整历史。

在 Patra 仓库里执行 `git log --oneline`，看到的就是这样：

```text
4a1328748 feat(portal): 新增通知设置与退订、提醒改接通知服务、实时推送 (v0.16) (#344)
5b1d855a5 feat(notification): 新建通知中心后端：事件模块、RabbitMQ、通知服务与提醒邮件 (v0.16) (#343)
1a130a9ec build(deps): 升级 Spring Boot 到 4.1.2、Spring Cloud 到 2025.1.4 (PAP-152) (#342)
```

左边是快照编号，右边是那句说明。

<Callout kind="analogy">

提交像玩游戏时的存档点。每个存档都完整，随时可以回到任何一个，而且存档之间的先后顺序不会乱。

</Callout>

## 分支是一根指针

如果所有人都往同一条接龙后面接，改到一半的代码就会被别人看到。所以 Git 允许你开**分支（branch）**。

分支听起来像是把项目复制了一份，其实没有复制任何东西。它只是**一根指针**，指着某一张快照。你在这个分支上再做提交，指针就跟着往前走，别的分支的指针不动。

## 在 Patra 里，为什么从来不在 main 上直接写

`main` 是随时可以上线的版本，合并进去的那一刻，自动部署就会发车。所以 Patra 给 `main` 设了分支保护：**代码进 `main` 的正常路径是 PR**，要过检查和评审（后面的篇目细讲）。于是写代码的第一步永远是从 `main` 切一条自己的分支：

```bash
git switch -c feat/journal-search
```

分支名带类型前缀，比如 `feat/`、`fix/`，一眼就能看出这条分支在干什么。一轮最小的工作流程是：

```bash
git switch -c feat/journal-search   # 从当前位置切出新分支
git add 文件名                       # 选出要放进这次快照的改动
git commit -m "feat(catalog): 新增期刊检索接口"   # 拍快照
git push -u origin feat/journal-search           # 推到 GitHub，-u 记住对应关系
```

| 命令 | 作用 |
|---|---|
| `git status` | 看哪些文件改了、哪些已经选入快照 |
| `git log --oneline` | 一行一张快照，看历史 |
| `git switch 分支名` | 切换到另一个分支 |
| `git pull` | 把远端的新快照拿到本地 |
| `git push` | 把本地的新快照送到远端 |

<Callout kind="warn">

`git add` 只是挑选，`git commit` 才是拍快照，`git push` 才是同步。三个动作缺一个，GitHub 上都看不到你的改动。

</Callout>
