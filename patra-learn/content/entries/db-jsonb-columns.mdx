## 表的列是固定的，但数据的形状不一定

前面几篇的表，每一列都有名字和类型，一行一行整整齐齐。可有些数据天生不整齐：

- 不同来源给的元数据字段不同，而且会增减；
- 一块内容内部有嵌套（一个对象里还有列表）；
- 只需要整块存进去、整块取出来，很少单独查里面的某一项。

这时可以用 **JSON 列**：在表里放一个类型为 `jsonb` 的列，里面存一段 JSON。

## json 和 jsonb

PostgreSQL 有两种 JSON 类型：

| 类型 | 存法 | 特点 |
|---|---|---|
| `json` | 原样存文本 | 保留空格和键的顺序，每次读都要重新解析 |
| `jsonb` | 解析后存成二进制 | 读得快，能建索引，能用丰富的查询操作符；不保留空格、键顺序，重复的键只留最后一个 |

一般情况选 `jsonb`。Patra 里的 JSON 列都用 `jsonb`。

## 什么该放 JSON，什么该拆成列

这是用 jsonb 最该想清楚的事。判断标准很简单：**要不要对它做查询、排序、约束、连表**？

- 要 → 拆成独立的列。有类型、能建索引、能加 `NOT NULL` 和 `CHECK`，数据库能替你把关；
- 不要，只是整块存取、展示 → 放 jsonb。

## 在 SQL 里查 JSON

如果确实要查 JSON 里的内容，jsonb 提供了一组操作符。下面是示意（键名是假设的）：

| 写法 | 意思 |
|---|---|
| `data -> 'author'` | 取出键 `author` 对应的 JSON（还是 jsonb） |
| `data ->> 'title'` | 取出键 `title` 对应的值，当作文字 |
| `data @> '{"isOa": true}'` | `data` 是否包含这一小块 |
| `data ? 'doi'` | 有没有 `doi` 这个键 |

要让这类查询快，可以对 jsonb 列建 **GIN 索引**，或者对某个表达式单独建 B 树索引。不过那已经说明你在频繁查询里面的内容了，多半该考虑提成列。

## 在 Java 里读写

Patra 里有两种方式用 JSON 列：

1. 实体上用 Hibernate 的 `@JdbcTypeCode(SqlTypes.JSON)` 标记，字段是 Java 对象（上面的 `PublicationProfile`），保存时自动转 JSON，读取时转回对象。
2. 用 JdbcClient 写原生 SQL 时，把对象先转成 JSON 文本，再 `CAST(:snapshot AS jsonb)`：

<CodeRef at="patra-api/patra-interaction/patra-interaction-infra/src/main/java/dev/patra/interaction/infra/subject/persistence/SubjectRepositoryAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="86-89" />

```java

                   (subject_id, target_type, natural_key, source_id, state, snapshot, snapshot_at)
            VALUES (:subjectId, :type, :naturalKey, :sourceId, 'ACTIVE', CAST(:snapshot AS jsonb),
                    :snapshotAt)
```

JSON 的编解码统一用容器里的 `JsonMapper`，保证写进库里的 JSON 和应用其他地方的形态一致。JPA 映射里还有一个转换器 `JsonColumnCodec`，把空值的几种情形规定清楚：

<CodeRef at="patra-tool/patra-tool-jpa/src/main/java/dev/patra/tool/jpa/json/JsonColumnCodec.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="15-20" />

```java
/// 空值语义：
///
/// - [#read]：空白文本得到 `null`
/// - [#write]：`null` 节点得到 `null`
/// - [#fromMap]：`null` 或空 Map 得到 `null`，列保持 NULL
/// - [#toMap]：`null`、JSON `null`、缺失节点都得到空 Map
```

这里有一个新手容易混淆的点：JSON 列有**两种"空"**：

- 数据库层面的 `NULL`：这一格没有值；
- JSON 里的 `null`：这一格有值，值是 JSON 文本 `null`。

两者不一样。对应地，`NOT NULL` 约束只管第一种。写 JSON 列的代码要想清楚："没有"到底落成哪一种。

<Callout kind="cost">

jsonb 的代价：数据库不替你检查内部结构（键拼错了、类型错了它都不管）；要查里面的内容很费劲；同一份数据存了两处时要自己保持一致。所以只给"形状多变、整块存取"的数据用。

</Callout>
