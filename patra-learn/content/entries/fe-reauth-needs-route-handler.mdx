## 坑

v0.12 用户中心规定：改邮箱、注销、踢设备这类敏感操作，要求 10 分钟内认证过；超时了，服务端回 403 `REAUTH_REQUIRED`，门户弹窗让用户输密码，再认证成功后自动重试原操作。

再认证起初写成了 Server Action。真浏览器里试注销时出了问题：结果屏一闪就没了，页面被送去了 `/login?next=/settings/account`。

踢设备、改邮箱不受影响，因为那之后会话仍然有效，重渲染也没问题；只有注销会让会话消失。

## 怎么避开

再认证改成 Route Handler `POST /api/auth/reauth`：浏览器直接请求它，它调 identity，成功时在这里换会话 Cookie。Route Handler 写 Cookie 不会触发当前页的重新渲染。

<CodeRef at="patra-portal/src/app/api/auth/reauth/route.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="24-36" />

```ts
/// 再认证（spec §6.1）：浏览器 → 这里 → identity `POST /auth/reauth`，成功时在这里换会话 Cookie。用 Route Handler
/// 而不是 Server Action，换 Cookie 不会触发当前页的重新渲染（见 `reauthenticate` 的说明）。同源校验挡跨站请求。
export async function POST(request: Request): Promise<NextResponse> {
  if (!isSameOrigin(request)) {
    return new NextResponse(null, { status: 403 });
  }
  // ……读密码、调 identity、按结果回状态码
}
```

<Callout kind="cost">

Route Handler 没有 Server Action 自带的 `Origin` 校验，要自己补同源检查（上面的 `isSameOrigin`），还要自己定义响应的形状。这也和门户「写操作走 Server Action」的约定分了叉，所以理由写进了代码注释。

</Callout>
