<Callout kind="lead">

**类**是图纸，写清一个东西有哪些数据、能做哪些事；**对象**是照图纸用 `new` 造出来的实物；**接口**只列出「能做哪些事」，不写怎么做，由**实现类**来补上。

</Callout>

## 类：一张图纸

Java 代码几乎全写在类里。一个类通常有三样东西：

- **字段**：这个东西记着哪些数据；
- **构造器**：造它的时候要交给它什么；
- **方法**：它能做哪些事。

看 Patra 里一个真实的类。它负责「同一个邮箱密码输错太多次就锁一会儿」，失败次数记在 Redis（一个很快的内存数据库）里。它的第一行是 `public final class LoginThrottleAdapter implements LoginThrottlePort {`，`class` 后面就是类名。往下是字段和构造器：

<CodeRef at="patra-api/patra-identity/patra-identity-infra/src/main/java/dev/patra/identity/infra/account/throttle/LoginThrottleAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="43-53" />

```java
  private final StringRedisTemplate redis;
  private final Supplier<LoginThrottlePolicy> policy;

  /// 创建适配器。
  ///
  /// @param redis Redis 模板
  /// @param policy 失败限制参数的来源：每次开始或结算时取一次，配置刷新后下一次调用即用上新值
  public LoginThrottleAdapter(StringRedisTemplate redis, Supplier<LoginThrottlePolicy> policy) {
    this.redis = Objects.requireNonNull(redis, "redis 不能为 null");
    this.policy = Objects.requireNonNull(policy, "policy 不能为 null");
  }
```

（`///` 开头的是给人看的说明，叫文档注释，JVM 运行时不管它。）

- `redis`、`policy` 是**字段**：它要用的 Redis 连接，和「最多错几次、锁多久」这些规则。
- 和类同名、没有返回类型的 `LoginThrottleAdapter(...)` 是**构造器**：造对象时把这两样交进来，存进字段。
- 后面还有 `begin`、`recordFailure` 等**方法**，就是它能做的事。

## 对象：照图纸造出来的实物

图纸本身不能用，得照着造出来。造的写法是 `new 类名(构造器要的东西)`。Patra 的测试里就有一行，造了一个登录处理器：

<CodeRef at="patra-api/patra-identity/patra-identity-app/src/test/java/dev/patra/identity/app/account/usecase/login/LoginUserHandlerTest.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="152-166" />

`new LoginUserHandler(users, credentials, ..., loginThrottle, ...)` 执行完，内存里就多了一个 `LoginUserHandler` 对象，它的字段里存着这次交进去的那些东西。同一张图纸可以造很多个对象，每个对象各有各的字段值，互不干扰。

<Callout kind="analogy">

类像户型图，对象像照户型图盖出来的房子。一张户型图可以盖一百套房，每套房里放的家具（字段的值）各不相同；但每套房都有户型图上画的那几个房间（方法）。

</Callout>

## 接口：只说能做什么

`LoginThrottleAdapter` 那一行里还有半句 `implements LoginThrottlePort`。`LoginThrottlePort` 是一个**接口**：

<CodeRef at="patra-api/patra-identity/patra-identity-domain/src/main/java/dev/patra/identity/domain/account/port/throttle/LoginThrottlePort.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="14-45" />

```java
public interface LoginThrottlePort {

  /// 开始一次尝试，在校验密码之前调用。
  ///
  /// @param accountType 账号类型
  /// @param email 邮箱
  /// @return 被放行的尝试
  /// @throws LoginTemporarilyLockedException 处于锁定期，或「失败次数 + 在途次数」已到上限
  LoginAttempt begin(AccountType accountType, EmailAddress email);

  /// 按成功结算：删掉在途登记，清零失败计数，不动锁。
  ///
  /// @param attempt 尝试
  void recordSuccess(LoginAttempt attempt);

  /// 按失败结算：删掉在途登记，处于锁定期就不计数，否则失败计数加一，达到上限就上锁。
  ///
  /// @param attempt 尝试
  /// @return 处于锁定期时（包括这次刚上锁）返回剩余时间，否则为空
  Optional<Duration> recordFailure(LoginAttempt attempt);

  /// 按取消结算：只删掉在途登记，不计失败。用于中途出错（哈希排队超时、数据库异常等）。
  ///
  /// @param attempt 尝试
  void cancel(LoginAttempt attempt);

  /// 清零：删掉失败计数和锁，在途登记不动（自然过期）。重设密码成功后用。
  ///
  /// @param accountType 账号类型
  /// @param email 邮箱
  void clear(AccountType accountType, EmailAddress email);
}
```

跳过注释只看代码：每个方法都只有一行「签名」：叫什么、要什么、还什么，后面直接是分号，没有 `{ }` 包着的具体做法。接口就是一份约定：「谁说自己是 `LoginThrottlePort`，就必须会这五件事。」

## 实现类：把约定兑现

一个类写上 `implements LoginThrottlePort`，就是在说「我兑现这份约定」。编译器会检查：五个方法少写一个，编译就不过。`LoginThrottleAdapter` 里每个方法上的 `@Override` 是一个标签，意思是「这个方法是在兑现约定里的某一条」（开头带 `@` 的标签先不细究，「注解：贴在代码上的标签」那篇专门讲）：

<CodeRef at="patra-api/patra-identity/patra-identity-infra/src/main/java/dev/patra/identity/infra/account/throttle/LoginThrottleAdapter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="86-92" />

```java

  ///
  /// @param attempt 尝试
  @Override
  public void recordSuccess(LoginAttempt attempt) {
    settle(attempt, "SUCCESS");
  }
```

这回方法后面有 `{ }` 了，里面就是具体做法。
