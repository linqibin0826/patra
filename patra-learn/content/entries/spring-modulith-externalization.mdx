<Callout kind="lead">

外送是 Modulith 自带的一个监听器：事务提交后，它把选中的事件映射成对外的消息、按路由发到消息中间件（RabbitMQ、Kafka 等）。它和别的监听器一样有登记行，发失败了可以补投。

</Callout>

## 它就是一个监听器

上一篇讲的登记是「每个提交后监听器一行」。外送没有另起一套机制，它就是其中一个监听器：Modulith 的事件核心里有一个 `EventExternalizerModuleListener`，方法上贴着 `@ApplicationModuleListener`；AMQP 构件负责把它接到 RabbitMQ 上。所以：

- 发布一个要外送的事件，表里就有一行属于外送器的登记；
- 外送器方法正常返回，这一行算完成（Patra 的完成模式是删掉）；
- 外送器抛了异常，这一行停在失败，等补投再发一次。

有一点不一样：外送器把事务传播方式改成了 `SUPPORTS`，不给自己开新事务。这和「等 broker 确认时占不占数据库连接」有关，后面「等确认不占连接」那篇讲。

## 三步：选择、映射、路由

外送器每处理一个事件，按顺序问三个问题，答案都来自一个配置：

1. **选择**：这个事件要不要外送？
2. **映射**（可选）：发出去的消息长什么样？可以原样发，也可以换成另一个对象。
3. **路由**：发到哪个交换机、带什么路由键？

配置有两种写法。注解式是在事件类上贴 `@Externalized("交换机::路由键")`；编程式是在配置类里定义一个 `EventExternalizationConfiguration` bean。Patra 只用编程式，领域层的事件类上什么都不贴：领域层不该知道自己的事件会被发到 RabbitMQ。interaction 的配置：

<CodeRef at="patra-api/patra-interaction/patra-interaction-boot/src/main/java/dev/patra/interaction/config/InteractionEventsConfiguration.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="49-75" />

```java
@Bean
public EventExternalizationConfiguration eventExternalizationConfiguration() {
  return EventExternalizationConfiguration.externalizing()
      .selectByType(EXTERNALIZED::contains)
      .route(CommentPublishedEvent.class, event -> target(CommentPublished.ROUTING_KEY))
      .mapping(CommentPublishedEvent.class, IntegrationEventMapper::commentPublished)
      // ……另外四种事件，同样一条 route、一条 mapping
      .build();
}

private static RoutingTarget target(String routingKey) {
  return RoutingTarget.forTarget(InteractionExchange.NAME).andKey(routingKey);
}
```

- `selectByType`：只外送集合里列出的五种领域事件。「有帮助已取消」不在里面，因为没有队列订阅它（原因见下面第三件事）。
- `mapping`：把领域事件换成 `patra-interaction-api` 里的集成事件，只拷字段。为什么要换，「领域事件与集成事件」那篇讲过。
- `route`：都发到 `interaction.events` 交换机，路由键就是事件类型，比如 `comment.published`。

## 两种外送模式

Modulith 2.1 起有两种外送模式，由 `spring.modulith.events.externalization.mode` 选：

| 模式 | 怎么发 | Patra |
|---|---|---|
| `module-listener`（默认） | 就是上面说的那个提交后监听器 | 用这个 |
| `outbox` | 交给专门的发件箱库（Namastack Outbox 或 JobRunr）去发 | 不用：要多引一个库来驱动，RabbitMQ 的确认也只看 nack，不管超时和退回 |

## 默认不替你保证的三件事

外送跑通了，不等于可靠了。Patra 接入时碰到的三件事：

**1. 不等 broker 确认。** 默认模式下，RabbitMQ 外送调完发送方法就算成功，不等 broker 回确认。broker 恰好没收下，登记行也已经被当成完成删掉了，这条消息就丢了。Patra 在发送模板这一层补上了「同步等确认，没确认就抛异常」，「发送确认」那篇细讲。

**2. 映射会重跑。** 登记表里存的是领域事件，映射发生在每次外送时，补投就会再映射一遍。所以：

- 事件 ID 要在领域事件创建时就生成。要是在映射里生成，每次补投 ID 都不同，消费方就没法按 ID 去重。
- 映射只拷字段，不查库、不调别的服务。查库会让补投的结果随时间变化，还会让外送拿着数据库连接等确认。

**3. 发出去不等于有人收。** Patra 发送时带着 `mandatory`：没有队列绑定这个路由键，broker 会把消息退回，等确认的模板把它当失败处理，登记行留着，每分钟补投一次，永远发不出去。所以只外送真有队列订阅的事件；上线新事件时，先部署消费方把队列绑好，再部署发布方。

<Callout kind="warn">

还有一个小坑：`EventExternalizationConfiguration` 能配消息头，可 Modulith 2.1.2 的 RabbitMQ 默认路径会把配置的消息头丢掉（算好了却没传下去）。Patra 不用它加消息头，事件 ID 由发送模板写进 AMQP 的 `messageId`。

</Callout>
