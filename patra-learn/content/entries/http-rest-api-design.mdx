## 路径是名词，方法是动词

REST 风格的核心是一个分工：

- **路径**指向一个**资源**（一样东西）：`/me/collections` 是「我的收藏夹们」，`/me/collections/42` 是其中编号 42 的那一个。
- **方法**说明**对它做什么**：读、新建、替换、删除。

所以接口里不会出现 `/deleteCollection`、`/updateName` 这种把动词写进路径的写法。动词交给 HTTP 方法，路径只负责指明东西。

<Callout kind="insight">

幂等不等于「每次返回一模一样」。DELETE 第一次真的删了，第二次什么也没做；返回都是 204，结果状态相同，这就够了。

</Callout>

## PUT 和 PATCH

两者都是「修改」，区别在发什么：

- **PUT**：发整份新内容，整体替换。没写的字段会被当作「没有」。
- **PATCH**：只发要改的几个字段，其余保持不变。

Patra 的收藏夹改名接口用 PUT，请求里名称和简介两个字段都要带，整体替换。优点是语义简单、天然幂等；代价是调用方得带上不想改的字段。如果一个资源有几十个字段、经常只改一两个，PATCH 更合适。

## 几个小约定

- 一次只读取、不改变东西的接口用 GET；需要分页的，页码和每页条数放查询参数，并给默认值、限定上限（收藏夹的每页 1 到 100，默认 50）。
- 返回状态码要精确：新建用 201，没有内容的成功用 204，异步接受用 202。
- 不属于当前用户的资源，对外和「不存在」一样返回 404，不暴露它是否存在。
