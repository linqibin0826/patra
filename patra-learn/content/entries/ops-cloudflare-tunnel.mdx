<Callout kind="lead">

Patra 的门户自 2026 年 10 月 28 日起，经 Cloudflare Tunnel 对公网开放。部署机上常驻一个叫 `cloudflared` 的小程序，主动连到 Cloudflare；公网用户访问域名，请求到 Cloudflare，再沿着这条隧道转到部署机上的门户。**部署机一个入站端口也没开。**

</Callout>

## 入站与出站

<Callout kind="analogy">

想象一家公司没有前台，访客也找不到办公室的门牌号。办法是：公司的人先打电话给一个总机，并且一直保持通话。访客打总机的号码，总机就沿着这条通话线把访客转进来。公司始终是「打出去」的那一方。

</Callout>

对应到网络上：

- **入站**：外面主动连进来。家庭宽带通常不让，要开就得在路由器上配端口转发，同时暴露一个对着公网的端口。
- **出站**：里面主动连出去。几乎总是被允许的。

隧道把「公网请求进来」变成了「已有的出站连接上的往返」。

## 配置放在哪

这套东西有三块，只有一块在仓库里：

| 部分 | 在哪里 | 说明 |
|---|---|---|
| 转发规则 | Cloudflare 后台 | 远程管理：域名 `patra.linqibin.dev` 转到部署机本地的门户，`learn.linqibin.dev` 转到本地的学习站，其余一律 404。不在仓库里 |
| DNS 记录 | Cloudflare 后台 | 每个子域名一条代理的 CNAME，指向这条隧道 |
| 常驻进程 | 部署机 | `cloudflared` 由 macOS 的 LaunchAgent 常驻，崩了自动拉起；它的运行说明写在基础设施的 README 里 |

隧道的**令牌**相当于这条隧道的钥匙，谁拿到谁就能冒充这台机器接入。它保存在部署机上仓库之外的 `~/.patra/secrets/` 目录里，权限只允许本人读写，不进 git，也不进 Nacos。泄露后的做法是到 Cloudflare 后台轮换令牌，再覆盖这个文件。

要暂停对外开放也很干脆：停掉这个常驻进程，隧道断开，外面立即访问不到；恢复时重新加载它。

## 只开放该开放的

隧道把「能不能被外面访问」变成了转发规则里的一行配置。Patra 的做法是**只放门户**：数据库、Redis、Nacos、MinIO、RabbitMQ 这些基础设施端口，仍然只在局域网和 tailnet（作者自己的私有虚拟网络）里可达。

为什么这条界线要守得这么紧？基础设施的开发默认账号密码有意随仓库提交，方便部署机靠 `git pull` 同步；它们安全的前提是端口压根不暴露。一旦往隧道里加了别的服务，这个前提就失效了。

学习站也采用了同样的做法：v0.17 决定给它一个独立的域名 `learn.linqibin.dev`，放进同一条隧道，同时去掉原来在内网直接访问它端口的入口，让容器的端口只绑定在部署机本机。选一级子域而不是 `learn.patra.linqibin.dev`，是因为 Cloudflare 免费证书只覆盖一级子域。代价也要认下：学习站从内网工具变成公开站点，此后每次发布都对公网生效。

## 它的已知局限

<Callout kind="cost">

- **没有加 Cloudflare 的访问控制**：谁都能打开门户，访问控制只靠 Patra 自己的登录。
- **没有人机验证**：注册邮件以自己的域名发出，被人刷注册会影响这个域名的发信信誉。
- **速度**：免费版的节点离得较远。2026 年 10 月 28 日实测，首页首次打开 5～6 秒，连接复用后每个请求约 1 秒。
- **来源地址看不到真实的**：外网访问也经容器网络的端口转发进来，门户看到的来源是内部网关地址，登录设备列表里外网用户同样显示为「内网」。

</Callout>

这些都是写在 README 里的已知限制，当时的决定是：给少数人体验和测试用，这个门槛够了。
