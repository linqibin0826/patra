<Callout kind="lead" label="坑在哪">

在部署机上经 SSH 执行 `orbctl start`，OrbStack 以后台模式（`--internal-cli-background`）启动。容器都能跑，但它**不会**通过特权助手创建 `/var/run/docker.sock` 这个软链。平时手动敲 `docker` 用的是 OrbStack 自己的 context，不受影响；CD 却只认默认的 `/var/run/docker.sock`，于是连不上。

</Callout>

背景：作者的部署机是一台 Mac mini，docker 由 OrbStack 提供，CD 跑在机器上的自托管 runner 里。用别的 docker 发行版的人不会碰到这个具体问题，但「客户端连的是哪个入口」到处适用。

## docker 命令怎么决定连谁

docker 命令行先看 `DOCKER_HOST`，再看当前 context（记在 `DOCKER_CONFIG` 目录下的配置里），都没有才连默认的 `/var/run/docker.sock`。

Patra 的门户和学习站 CD 给 docker 设了一个自定义的 `DOCKER_CONFIG` 目录，用来绕开 macOS 钥匙串。这个目录里没有 OrbStack 的 context，于是 CD 里的 docker 一律去连默认 socket：

| 谁在执行 | 读哪份配置 | 连到 |
|---|---|---|
| 你在终端里敲 `docker ps` | `~/.docker`，当前 context 是 OrbStack | OrbStack 自己的 socket，能连 |
| CD 任务 | 自定义 `DOCKER_CONFIG`，没有 context | `/var/run/docker.sock`，软链不存在 |

## 什么时候会这样

2026-09-23 发现：OrbStack 大约在 09-05 停过一次，之后是经 SSH 用 `orbctl start` 拉起来的。从那以后门户和学习站的 CD 一直失败，到 09-23 才查清原因。

## 怎么避开

以图形界面方式重启 OrbStack，十几秒后软链就出现了：

```bash
ssh mini 'osascript -e "quit app \"OrbStack\""; orbctl stop; sleep 5; open -a OrbStack'
```

然后重跑失败的 CD。以后在部署机上要重启 OrbStack，都用 `open -a OrbStack`，不用 `orbctl start`。
