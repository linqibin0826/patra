<Callout kind="lead" label="坑在哪">

开了 `ControlMaster` 复用之后，`ssh -N -L` 不会挂住：它把转发交给已有的主连接，然后马上以 0 退出。转发还在，但归主连接管，主连接空闲 `ControlPersist` 秒后关闭，转发跟着断。你以为进程退出是转发失败了，或者以为转发会一直在，两种想法都不对。

</Callout>

## 连接复用是什么

每次 ssh 都要握手、认证，慢。`ControlMaster auto` 让第一次连接成为「主连接」，在本机留一个控制用的 socket；之后对同一台机器的 ssh 都通过这个 socket 借用主连接，不再重新握手。`ControlPersist 600` 表示最后一个使用者走了以后，主连接再留 600 秒。

在进程列表里，主连接长这样：

```text
ssh: /Users/<你>/.ssh/cm-<用户>@<部署机地址>:22 [mux]
```

v0.8 收尾时，作者要把本机的 4000 端口转发到部署机上的门户容器，让本机的 Playwright 直接测线上容器，就撞上了这个情况：命令一敲就退出，转发却又能用，过一阵又没了。

## 怎么避开

要一条自己能管的转发，这一次不用复用：

```bash
ssh -N -o ControlMaster=no -o ControlPath=none -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:4000:127.0.0.1:4000 mini
```

- `ControlMaster=no` 加 `ControlPath=none`：不借用主连接，也不自己当主连接，老老实实建一条新连接。
- `ExitOnForwardFailure=yes`：本机端口被占、转发开不起来时直接报错退出，不会挂着一个没有转发的连接。
- 放到后台跑，用完 kill 掉。

已经挂在主连接上的转发，用控制命令撤掉：

```bash
ssh -O cancel -L 127.0.0.1:4000:127.0.0.1:4000 mini
```
