<Callout kind="lead" label="坑在哪">

Patra 规定所有方法都写 `///` 风格的 Markdown 文档注释，提交钩子里的 spotless 用 google-java-format 格式化。一行 `///` 超过 100 列，格式化后变成这样（示意）：

```java
/// 按 ORCID 批量查作者，详见
// [dev.patra.catalog.domain.author.port.repository.AuthorRepository#findByOrcids]
```

第二行成了普通注释，文档里只剩前半句，链接丢了。

</Callout>

## 为什么没人发现

- **编译不报**：`//` 也是合法注释，代码照样编。
- **检查不报**：格式化后的代码本来就「符合格式」，`spotlessCheck` 通过。
- **看 diff 也容易漏**：只差一个斜杠。

v0.7 的 PR #192 里一次出了 4 处，都是带全限定名链接的长行，最后是 AI 评审指出来的。单纯把 `//` 改回 `///` 没用，下次格式化还会再折一次。

## 怎么避开

- 写含长链接的 `///` 行时，自己在 100 列以内换行；全限定名的链接单独占一行。
- `@param` 等标签的续行缩进 4 格，每行仍以 `///` 开头。
- 提交前可以扫一遍：上一行以 `/// ` 开头、本行以 `// ` 开头的，就是被折断的地方。

```java
/// 按 ORCID 批量查作者，详见
/// [dev.patra.catalog.domain.author.port.repository.AuthorRepository#findByOrcids]
///
/// @param orcids 要查的 ORCID，
///     为空时返回空列表
```
