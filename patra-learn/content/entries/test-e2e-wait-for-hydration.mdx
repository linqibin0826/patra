## 坑

Playwright 的 `page.goto` 返回时，页面的 HTML 到了，React 不一定已经接管。门户在开发模式下冷编译、或机器负载高时，这段空档会变长。测试在空档里操作：

- 点 `<Link>`，走的是浏览器原生的整页跳转，不是前端路由；
- 离开输入框，不触发前端校验。

结果是测试在 bug 还在时也能通过。v0.8 账号登录那一版写注册页时，回放计划里先写好的三条「应该失败」的测试，三条全过了，查下来就是这个原因。

<Callout kind="warn">

输入框有焦点也不能说明已经接管：React 19 的服务端渲染会直接输出 `autofocus` 属性，焦点是浏览器给的。Next 自己的 `window.__NEXT_HYDRATED` 标记只在它内部的测试模式下才有，项目里用不了。

</Callout>

## 为什么

React 接管（水合）一个 DOM 元素时，会在这个元素对象上挂一个以 `__reactProps$` 开头的属性，里面是它的事件处理函数。还没挂上这个属性，就说明这个元素上还没有 React 的事件处理。

## 怎么避开

操作之前，先等目标元素上出现 `__reactProps$` 开头的属性：

<CodeRef at="patra-portal/tests/e2e/support/account.ts@598dc3eeb2f5209dcc858393eff510a2a3c8a332" lines="26-41" />

```ts
export async function waitForTakeover(page: Page, selector: string) {
  await page.waitForFunction(
    (target) => {
      const element = document.querySelector(target);
      return (
        element !== null && Object.keys(element).some((key) => key.startsWith("__reactProps$"))
      );
    },
    selector,
    { timeout: 60_000 },
  );
}
```

用法是 `goto` 之后紧跟一句 `await waitForTakeover(page, "form")`，再去填表、点按钮。最多等 60 秒：元素一直不出现时尽快报错，不必干等到整条用例超时。
