## 坑

<Callout kind="lead" label="坑在哪">

给服务多加一条 `SecurityFilterChain`，starter 的默认链会整条消失，其他路径上的认证也一起没了。新链只匹配几个路径也一样。

</Callout>

这个坑是 v0.19 设计 `oauth2Login` 接入时对照源码发现的，没有等到线上才踩。

## 为什么

`patra-tool-security` 给下游服务的默认链做一件事：从 `Authorization: Bearer` 的身份断言建立当前用户。条件装配让它在应用自己声明了链时让位。

这个让位是有用的：网关声明的两条链要整套替代默认链。可 identity 不一样，它只想**多加**一条给第三方登录用，`/me/**` 还要靠默认链上的断言认证。条件分不清这两种意图，只看类型。

<Callout kind="insight" label="怎么认出它">

加了一条新链之后，新链之外的接口开始报「没登录」，带着有效凭据也一样。启动不报错，新链上的功能也正常，只有其他路径出问题。

</Callout>

## 怎么避开

把两种意图做成两种类型。starter 新增 `AdditionalSecurityFilterChain`：

默认链的条件忽略它：

<CodeRef at="patra-tool/patra-tool-security/src/main/java/dev/patra/tool/security/autoconfigure/SecurityServletAutoConfiguration.java@e3120fa01976688a7eb6f4c627d900e9c4b214d2" lines="127-131" />

```java
  @Bean
  @ConditionalOnMissingBean(
      value = SecurityFilterChain.class,
      ignored = AdditionalSecurityFilterChain.class)
  public SecurityFilterChain patraSecurityFilterChain(
```

identity 的声明：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/config/IdentityOAuth2SecurityConfiguration.java@e3120fa01976688a7eb6f4c627d900e9c4b214d2" lines="53-55" />

```java
  @Bean
  @Order(1)
  public AdditionalSecurityFilterChain identityOAuth2FilterChain(
```

<Callout kind="warn">

工厂方法的返回类型必须写 `AdditionalSecurityFilterChain`。条件按工厂方法的返回类型判断，写成 `SecurityFilterChain`、里面再返回子类，条件认不出来，默认链还是会消失。另外要用 `@Order` 排到默认链前面，并用 `securityMatcher` 限定路径，否则新链会把所有请求都接走。

</Callout>
