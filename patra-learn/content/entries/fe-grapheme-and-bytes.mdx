## 坑

同一段文字有好几种「长度」：

| 怎么数 | 「一家四口」表情 |
|---|---|
| 字素（用户眼里的字） | 1 |
| 码点 | 7（4 个人物 + 3 个连接符） |
| JavaScript 的 `length`（UTF-16 单元） | 11 |
| UTF-8 字节 | 25（4 个人物各 4 字节，3 个连接符各 3 字节） |

```js
const family = "\u{1F468}‍\u{1F469}‍\u{1F467}‍\u{1F466}";
family.length;                        // 11
new TextEncoder().encode(family).length; // 25
graphemeCount(family);                // 1
```

前端按字素计数，用户看到的「12/30」才和他感觉的一致。可 Patra 的后端对文字字段同时限两样：字素数和 UTF-8 字节数。只按字素数校验的前端，会让一个全是组合表情的昵称在计数器上显示合法，提交后却被后端拒掉。

## 为什么

字素数能表达「用户感觉的长短」，却管不住实际占多大：一个字素可以由任意多个码点组成。字节上限管的就是这一头。Patra 后端的这几处文字字段同时有这两个上限，字节上限按字素上限 × 4 定：昵称 30 字素、120 字节，投稿经验正文 2,000 字素、8,000 字节，评论 5,000 字素、20,000 字节。

## 怎么避开

前端计数用 `Intl.Segmenter` 按字素切，和后端计长度的口径一致：

<CodeRef at="patra-portal/src/lib/grapheme.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="1-16" />

同时按后端的规则规整（换行统一、NFC、去首尾空白）后，再量一次 UTF-8 字节数，两个上限一起判：

<CodeRef at="patra-portal/src/lib/discussion/limits.ts@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="1-33" />

```ts
export const COMMENT_LIMITS = { graphemes: 5000, bytes: 20000, mentions: 10 } as const;

export function measure(text: string): { graphemes: number; bytes: number } {
  const normalized = normalizeForCount(text);
  return { graphemes: graphemeCount(normalized), bytes: ENCODER.encode(normalized).length };
}
```

计数器显示字素数，超了字节上限时给单独的提示（`over-bytes`）。
