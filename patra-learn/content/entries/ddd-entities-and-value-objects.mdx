## 两种东西：认身份，还是认内容

- **实体**：有身份的东西。内容可以变，只要身份（通常是一个 ID）没变，它就还是它。一条评论被编辑、被删除，它还是那条评论。
- **值对象**：没有身份，只看内容。两个值对象的内容一样，就是同一个，随时可以互换。

<Callout kind="analogy">

人民币 100 元的纸币：你不在乎手里是哪一张，只要面值一样，换一张给你也行，这是值对象。你的身份证则是实体：改了地址，它还是你的身份证，号码不变；换一张别人的就不行。

</Callout>

## 值对象：Patra 里的 CollectionName

收藏夹的名称在 Patra 里不是一个裸的 `String`，而是一个 record：

<CodeRef at="patra-api/patra-interaction/patra-interaction-domain/src/main/java/dev/patra/interaction/domain/collection/model/vo/CollectionName.java@3cf6fa5757b3be54c3b030e4cace871f53e2599c" lines="1-30" />

注意两点：

1. record 的 `equals` 按值比较，所以两个 `CollectionName("读书笔记")` 相等。
2. 构造入口 `parse` 守着规则：去首尾空白、不能为空、不超过 100 个字素，不合法就抛异常。但它只是约定的入口：record 的规范构造器不能比 record 本身更不公开，`new CollectionName("   ")` 照样能编译，造出一个非法的名称。Patra 也没有 ArchUnit 规则拦这种写法，靠的是约定：调用方都走 `parse`，代码里除了 `parse` 自己，没有别处直接 `new CollectionName`。要真正做到不合法的值造不出来，得把校验写进紧凑构造器，后面的 `AuthorId` 就是这样。

<Callout kind="lead">

值对象把规则「焊」在类型上：检查只在造它的一处做一次，不用在每个用到的地方再检查。焊得牢不牢，看校验写在哪：写在 `parse` 里，靠的是大家都走 `parse`；写进紧凑构造器，连 `new` 也绕不过去。

</Callout>

## ID 也是值对象

那收藏夹本身是实体，它的 ID 呢？ID 是值对象，用来表示身份：

给 ID 单独一个类型，不是为了好看。看 catalog 里的 `AuthorId`：

<CodeRef at="patra-api/patra-catalog/patra-catalog-domain/src/main/java/dev/patra/catalog/domain/author/model/vo/AuthorId.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="15-25" />

它把校验写在紧凑构造器里，拒绝空值和非正数：不管走 `of` 还是直接 `new AuthorId(0L)`，都会抛异常，这才是真正造不出非法值，和只靠 `parse` 约定的 `CollectionName` 不同。更重要的是类型不同：函数要 `AuthorId`，你就没法误传一个 `OrganizationId` 或随手写的数字。裸 `long` 做不到这一点。

## 实体：Patra 里的评论

评论是实体。同一条评论，编辑了正文、被删成占位，评论 ID 不变，还是那条评论：

<CodeRef at="patra-api/patra-interaction/patra-interaction-domain/src/main/java/dev/patra/interaction/domain/discussion/model/aggregate/CommentAggregate.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="29-45" />

可以看到它有 `commentId`，状态会从正常变成已删除。「评论」靠 ID 区分，而不是靠内容区分：两条正文一模一样的评论，是两条评论。
