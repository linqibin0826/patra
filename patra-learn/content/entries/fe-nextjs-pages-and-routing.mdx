## 文件夹就是网址

门户用 Next.js 的 App Router。规则只有一条：`src/app/` 下的文件夹对应网址的一段，文件夹里放一个 `page.tsx`，这一段才能被打开。`page.tsx` 默认导出一个 React 组件，就是这个网址的页面。

门户里几个真实的例子：

| 文件 | 网址 |
|---|---|
| `app/page.tsx` | `/` |
| `app/u/[username]/page.tsx` | `/u/alice`、`/u/bob` |
| `app/u/[username]/collections/page.tsx` | `/u/alice/collections` |
| `app/papers/[id]/page.tsx` | `/papers/<文献编号>` |
| `app/journals/(list)/page.tsx` | `/journals` |

最后一行的圆括号文件夹叫路由分组，只用来整理文件，不出现在网址里。文件夹里没有 `page.tsx` 的（比如只放了组件），从网址上打不开。

## 方括号：从网址里取值

`[username]` 这样的文件夹叫动态段。打开 `/u/alice` 时，Next.js 把 `alice` 放进 `params` 交给页面。在 Next.js 16 里，`params` 是一个 Promise，要先 `await` 才能拿到值：

## 几个约定文件：外壳、加载、出错、找不到

除了 `page.tsx`，同一个文件夹里还能放几个名字固定的文件，Next.js 会自动把它们套在页面外面：

| 文件 | 管什么 |
|---|---|
| `layout.tsx` | 外壳。下面所有页面共用；在这些页面之间切换时，外壳不重新渲染、里面的状态保留 |
| `loading.tsx` | 页面数据还没回来时先显示的骨架 |
| `error.tsx` | 下面的页面渲染出错时显示的内容，带「重试」 |
| `not-found.tsx` | 页面调用 `notFound()` 时显示的内容 |

根目录的 `app/layout.tsx` 是必须有的根布局，`<html>` 和 `<body>` 只在这里写。提醒列表的三个页面共用一个布局，导航栏和页脚写一次：

<CodeRef at="patra-portal/src/app/notifications/layout.tsx@4a13287485468f2c489027f1aac0bb6174643e8d" lines="9-17" />

```tsx
export default function NotificationsLayout({ children }: { children: ReactNode }) {
  return (
    <>
      <TopNav />
      <main>{children}</main>
      <Footer />
    </>
  );
}
```

`children` 就是当前网址对应的那个页面。出错页 `app/error.tsx` 第一行是 `"use client"`：出错边界要在浏览器里运行，「重试」按钮才能点。

## 不是每个动态页都该有 loading.tsx

文献页有骨架，公开收藏夹页 `collections/[id]` 却故意没有。它的注释写着原因：

<CodeRef at="patra-portal/src/app/collections/[id]/page.tsx@6ead12db647bcd3e56f651af791d56e418cb79ff" lines="61-63" />

```tsx
/// 公开收藏夹页（简报 §3.14）：头部与第一页条目同时取，访客已登录就带会话（决策 H）。不存在、私有、所有者
/// 主页对访客不可见一律 404，在流式之前判（真的 404，所以不建 loading.tsx）；interaction 不可用是错误块，
/// 不是 404
```
