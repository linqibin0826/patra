## 文件能存数据，为什么还要数据库

先看文件在后端里会遇到什么。

- **找得慢**：文件是一长串字节，没有目录。要找邮箱是 `a@x.com` 的那一行，只能从第一行开始一行行读。
- **同时改会出事**：两个请求同时读到同一份内容，各自改了一处再写回去，后写的那个会把先写的那个盖掉。
- **写到一半断电**：一次修改要动两个地方，写完第一处就崩了，文件就留在一个谁也说不清的状态。

<Callout kind="analogy">

文件像一本没有目录、也没有管理员的账本：谁都能翻、谁都能涂改，找人要从第一页翻起。数据库像一间有管理员的档案室：你递一张条子说「要邮箱是 a@x.com 的那份」，管理员按他的索引柜去取；同时来了十个人，他会排好队，不会让两个人同时涂改同一份档案。

</Callout>

数据库做的就是这位管理员的活：**帮你存、帮你找、帮你排队**。它不是魔法，是一个一直开着的程序。

## 你的程序不直接碰文件，它去「问」数据库

在 Patra 里，PostgreSQL 是一个独立运行的程序（数据库服务）。后端服务不会自己去读写磁盘上的数据文件，而是通过网络连上数据库，发一句话过去，数据库把结果送回来。这句话用的语言叫 **SQL**。

## 表、行、列：一张带格子的表格

关系型数据库把数据放在**表**里。表就是你熟悉的表格：

- **列**：这张表有哪几种信息，每一列有名字、有类型（数字、文字、时间……）。
- **行**：一条记录。表里有多少条记录就有多少行。

Patra 的 catalog 服务要记录期刊，第一张表就叫 `cat_venue`（venue 是「出版载体」，期刊是其中最常见的一种）。它的前几列：

<CodeRef at="patra-api/patra-catalog/patra-catalog-infra/src/main/resources/db/migration/V1__create_venue.sql@0d51a79f0e608944fc44907891b4b37c22a68e6c" lines="20-26" />

```sql
CREATE TABLE cat_venue (
    id                  BIGINT                      NOT NULL,
    venue_type          VARCHAR(32)                 NOT NULL,
    title               VARCHAR(500)                NOT NULL,
    provenance_code     VARCHAR(32)                 NOT NULL,
    last_synced_at      TIMESTAMPTZ(6)              NULL,
    nlm_id              VARCHAR(20)                 NULL,
```

读这几行就够了：

- 每一列写着**名字**和**类型**：`BIGINT` 是大整数，`VARCHAR(500)` 是最长 500 个字符的文字，`TIMESTAMPTZ` 是带时区的时间点。
- 列末尾的 `NOT NULL` 表示「这一格必须有值」，`NULL` 表示「这一格可以空着」。比如每本期刊一定有标题，但不一定有 NLM 编号。

放进几行数据，它大概是这个样子（示意数据，不是真实期刊）：

| id | venue_type | title | provenance_code | nlm_id |
|---|---|---|---|---|
| 101 | JOURNAL | 示例医学杂志 | PUBMED | 空 |
| 102 | JOURNAL | 示例护理研究 | OPENALEX | 空 |
| 103 | CONFERENCE | 示例临床大会 | PUBMED | 空 |

## 「关系型」的意思：表和表之间能连起来

一个系统不会只有一张表。期刊有标题，但它每年发多少文章、有哪些标识符（ISSN、NLM 编号），是另外的信息。把它们都塞进 `cat_venue` 会让这张表又宽又乱，所以 Patra 另建了 `cat_venue_identifier`、`cat_venue_publication_stats` 等表，每张表只管一类信息，再靠一列「这行属于哪本期刊」把它们连起来。

这种「表和表之间有联系」的数据库，叫**关系型数据库**。Patra 用的 PostgreSQL 是其中最常见的一种。怎么把表连起来，下一篇「主键、外键与表之间的关系」讲。

<Callout kind="lead" label="先记住这三句">

- 数据库是一个独立运行的程序，帮你存、找、排队；
- 数据放在表里，一行一条记录，一列一种信息，列有类型；
- 表和表之间可以用「谁属于谁」连起来，这就是「关系型」。

</Callout>
