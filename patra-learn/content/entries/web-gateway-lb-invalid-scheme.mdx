## 现象

把会话查询改成「网关调 identity 的内部接口」的那次改动里，网关第一次有了自己的服务间客户端：用项目的 `RestClientFactory` 建一个 `RestClient`，地址 `lb://patra-identity`，再生成 HTTP Interface 代理。

<CodeRef at="patra-api/patra-gateway-boot/src/main/java/dev/patra/gateway/config/IdentityClientConfiguration.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="18-29" />

测试里一调就报 `Invalid scheme [lb]`。可 identity、catalog 调别的服务用的都是同一个工厂、同样的 `lb://` 写法，一直没出过问题。

<Callout kind="insight">

同一个原因还藏着另一个问题：分组的 Apache 工厂上带着这个分组单独配的超时（查会话的 identity 分组配了连接 1 秒、读 2 秒）。工厂被盖掉，超时也跟着没了，网关里的这个客户端用的是全局超时。报错之前，这个问题是看不见的。

</Callout>

## 根因

两件事叠在一起才会报错：

1. 负载均衡改写地址时保留了 `lb` 协议（实例没提供协议）。
2. 网关框架把每个 Builder 的请求工厂都换成了 Reactor，而 Reactor 不接受 `lb`。

只有第 1 件，Apache 不在乎；只有第 2 件，地址是 `http://`，Reactor 也没事。

## 修法

把分组请求工厂挪到 customizer 之后设：

<CodeRef at="patra-tool/patra-tool-http-client/src/main/java/dev/patra/tool/httpclient/factory/RestClientFactory.java@cfec9c9f30270dcf03f5cd7b6e54a0cd3b59296b" lines="109-120" />

这样网关和其他服务走同一条路：有分组超时，就是 Apache 工厂；分组超时也回来了。

<Callout kind="warn">

修完还剩一个口子：工厂只在分组超时和全局超时**不同**时才建分组工厂。两者一样时不建，网关里的客户端仍会落到 Reactor 上。这种情况要么给分组显式配一个不同的超时，要么把地址写成 `http://服务名`。

</Callout>
