## 切片：只装配一层

完整启动一个 Spring 应用，要装配几百个 Bean，连数据库、连中间件。只为了测一个 Controller，太重了。

Spring Boot 提供了**切片测试**：用一个注解，只装配应用的一层。测 Web 层用 `@WebMvcTest`，测数据访问层用 `@DataJpaTest`（上一篇见过）。没有被装配的东西，要么不需要，要么换成假的。

## 最小的例子

看 Patra 里一个很短的切片测试：登出接口。

<CodeRef at="patra-api/patra-identity/patra-identity-adapter/src/integrationTest/java/dev/patra/identity/adapter/session/rest/LogoutControllerIT.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="17-37" />

```java
@WebMvcTest
@Import(LogoutController.class)
@AutoConfigureRestTestClient
class LogoutControllerIT {

  @Autowired private RestTestClient restClient;
  @MockitoBean private CommandBus commandBus;

  @Test
  void should_logout_and_return_204() {
    restClient.post().uri("/auth/logout").exchange().expectStatus().isNoContent();

    verify(commandBus).handle(LogoutUserCommand.of());
  }
}
```

逐行认识：

- `@WebMvcTest`：只装配 Web 层。
- `@Import(LogoutController.class)`：明确说「我要测这一个 Controller」。
- `@AutoConfigureRestTestClient` 与 `RestTestClient`：Spring Boot 4 里发 HTTP 请求并断言响应的客户端，写法像 `restClient.post().uri(…).exchange().expectStatus()…`。
- `@MockitoBean`：把 `CommandBus` 换成假的，并登记进 Spring 容器。Spring Boot 4 里，旧的 `@MockBean` 已经被移除，现在统一用它。
- 最后的 `verify`：核对 Controller 把「登出」转成了正确的命令。

整个测试检查了两件事：HTTP 这一侧（204、没有响应体），以及命令那一侧（交给了总线什么）。

## 切片需要一个「根」

这里有个坑。`@WebMvcTest` 启动时，要找一个带 `@SpringBootConfiguration` 的类当配置的根。可 adapter 模块是被别的模块拼起来的，自己没有启动类。找不到，测试连起都起不来。

Patra 的做法是在测试目录里放一个专门的配置根：

<CodeRef at="patra-api/patra-identity/patra-identity-adapter/src/integrationTest/java/dev/patra/identity/IdentityITWebMvcConfig.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="1-12" />

它几乎是空的：`@SpringBootConfiguration` 加 `@EnableAutoConfiguration`。命名也有约定：`{Module}ITWebMvcConfig`。

可统一的错误格式、Long 变字符串这些 Web 层的定制，是怎么进到切片里的？答案在公共的 Web 工具模块里，它登记了一份文件：

<CodeRef at="patra-tool/patra-tool-web/src/main/resources/META-INF/spring/org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureWebMvc.imports@b6e01875bb5692356021c8a19562f557f319fc54" lines="1-2" />

文件里列了两个自动配置类：错误处理，和 JSON 定制。`@WebMvcTest` 会自动读这个文件，把它们加进切片。所以各服务的配置根不必再手工导入。

有的服务要多做一点。Catalog 的 adapter 里有 MapStruct 生成的转换器，需要被扫描到：

<CodeRef at="patra-api/patra-catalog/patra-catalog-adapter/src/integrationTest/java/dev/patra/catalog/adapter/config/CatalogAdapterITWebMvcConfig.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="20-36" />

它用 `@ComponentScan` 扫描 `rest` 和 `internal` 包里的组件，但**排除了 `@RestController`**：Controller 由每个测试自己用 `@WebMvcTest(controllers = …)` 或 `@Import` 挑，免得一个测试被迫连带加载无关的 Controller 和它们的依赖。

## 切片缺 Bean 时怎么办

切片测试最常见的报错是：

```text
No qualifying bean of type 'XxxService' available
```

意思是：Controller 需要一个 Bean，而切片没有装配它。有三种补法，先判断它属于哪一类：

| 缺的是什么 | 怎么补 |
|---|---|
| 下游的业务依赖（QueryService、CommandBus） | `@MockitoBean`：换成假的，这是最常见的 |
| 本模块里无副作用的辅助类（转换器、校验器） | `@Import` 它，或者让配置根的 `@ComponentScan` 扫到 |
| Web 层的通用定制（错误处理、JSON） | 不用补：公共模块的 `AutoConfigureWebMvc.imports` 已经带进来了 |

先猜一猜：下面这个情形，该选哪一种？

## 切片测试到底在守什么

看一个稍复杂的切片测试：会话列表与「踢设备」的接口。

<CodeRef at="patra-api/patra-identity/patra-identity-adapter/src/integrationTest/java/dev/patra/identity/adapter/session/rest/MeSessionControllerIT.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="138-170" />

```java
when(commandBus.handle(any(RevokeSessionCommand.class)))
    .thenThrow(new CurrentSessionRevocationException());

restClient.delete().uri("/me/sessions/1").exchange()
    .expectStatus().isEqualTo(409)
    .expectBody()
    .jsonPath("$.code").isEqualTo("IDN-0409")
    .jsonPath("$.traits[?(@ == 'CURRENT_SESSION')]").exists();
```

它让假的 `CommandBus` 抛出一个领域异常，然后断言 HTTP 响应：状态码 409，错误码 `IDN-0409`，错误特征里含 `CURRENT_SESSION`。这是在验证「领域异常怎么被统一的错误处理变成 HTTP 响应」，这个转换发生在 Web 层，所以正好是切片该守的。

同一个测试类里还有两处值得注意：会话 ID 在 JSON 里是字符串（公共模块把 Long 变字符串），以及 `/me/sessions/abc` 这样的非数字 ID 返回 400，而且命令总线**没有被调用**（`verifyNoInteractions`）。

<Callout kind="lead" label="切片测试的分工">

它检查的是 HTTP 的形状：路径、参数绑定、状态码、JSON 字段、错误格式，以及请求有没有被转成正确的命令。业务规则本身、数据库行为，都不在它的范围内。

</Callout>

<Callout kind="warn">

切片里的假对象会让测试「很容易绿」。不要只写「调用成功返回 200」这类测试：请同时覆盖参数不合法、领域异常、空值这些边界，那些才是 Web 层容易出错的地方。

</Callout>
