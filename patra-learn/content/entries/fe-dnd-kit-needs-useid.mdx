## 坑

v0.12 用户中心那一版做资料页的「关注领域」选择器时，用 dnd-kit 让用户拖动排序。`DndContext` 不传 `id` 时，内部用全局计数器给读屏说明（无障碍描述）生成 id。服务端渲染和浏览器数到的值不一样，开发模式就报水合不一致。

## 怎么避开

用 React 的 `useId()` 生成一个 id 传给 `DndContext`。`useId` 按组件在树里的位置生成，服务端和浏览器算出来是同一个值。

<CodeRef at="patra-portal/src/components/settings/profile/MeshInterestPicker.tsx@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="74-101" />

```tsx
// DndContext 默认用全局计数器生成读屏说明的 id，服务端与浏览器数到的不一样会水合不一致；给它稳定的 id
const dndId = useId();
// ……
// 传感器始终是同一组：窄屏只是让每个胶囊的 useSortable 关掉拖动，DndContext 的依赖不能随宽度变长短
const sensors = useSensors(useSensor(PointerSensor, { activationConstraint: { distance: 4 } }));
// ……
<DndContext id={dndId} sensors={sensors} collisionDetection={closestCenter} onDragEnd={onDragEnd}>
```

## 同一个组件里的第二个坑

窄屏上不需要拖动。最直接的写法是「窄屏时不注册传感器」，让 `sensors` 数组随屏宽变长变短。这会触发 React 的警告：依赖数组的长度变了（deps changed size）。

修法是传感器始终是同一组，窄屏时改为让每个可排序的项通过 `useSortable` 关掉拖动。
