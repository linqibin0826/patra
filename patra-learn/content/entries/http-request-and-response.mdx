## 一次交换：一问一答，格式固定

HTTP 是浏览器和服务器说话的规矩。一次交换分两半：客户端发**请求**，服务器回**响应**。两半的结构很像，都是三块：

1. **第一行**：请求里是「方法 + 路径 + 协议版本」，响应里是「协议版本 + 状态码」。
2. **头**（header）：一行一个 `名字: 值`，是关于这次交换的说明。
3. **正文**（body）：真正的内容，可以没有。

## 五个方法：先看承诺，再看用途

方法是请求里的第一个词，告诉服务器「你想做什么」。关键不在名字，在每个方法**对重复和修改做了什么承诺**。

| 方法 | 用来 | 会修改数据吗 | 重发同一个请求，结果一样吗（幂等） |
|---|---|---|---|
| GET | 读取 | 不会 | 一样 |
| POST | 新建，或触发一个动作 | 会 | 不保证，可能建出第二份 |
| PUT | 用整份新内容替换 | 会 | 一样：替换两次还是那份 |
| PATCH | 只改其中几个字段 | 会 | 通常一样，但取决于写法 |
| DELETE | 删除 | 会 | 一样：删两次，第二次已经没有了 |

「幂等」就是这个词：**同一个请求发一次和发多次，效果相同**。它很重要，因为网络会超时，客户端不知道请求有没有到，就想重发。能安全重发的方法，出错之后就好处理。

<Callout kind="warn">

方法只是约定，没有人强制。有人把「删除」写成 GET，浏览器预取链接时就可能把数据删掉。按语义选方法，是为了让中间的浏览器、代理、缓存都能做出正确的假设。

</Callout>

## 头和正文：各管什么

- 头里放**关于这次交换的说明**：内容是什么格式（`Content-Type`）、你是谁（`Cookie`、`Authorization`）、能不能缓存（`Cache-Control`）。后面几篇会逐个展开。
- 正文里放**数据本身**：提交的表单、接口返回的 JSON、一个 PDF 文件。
