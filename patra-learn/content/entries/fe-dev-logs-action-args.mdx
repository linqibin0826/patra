## 坑

v0.8 账号登录那一版写登录页时实测（Next 16）：开发模式下，每调用一次 Server Action，终端就打一行，参数原样带上：

```text
└─ ƒ login({"email":…,"password":…}) in …ms lib/auth/actions.ts
```

密码是明文。这行只在 `NODE_ENV === 'development'` 时打印，生产构建不会有，所以上线前的检查发现不了它。可开发日志常常被贴进 Issue、聊天记录，或者被别的工具读走。

## 怎么避开

在 `next.config.ts` 里把 `logging.serverFunctions` 设为 `false`（默认是 `true`）。关掉以后，请求本身的日志照常打印，只是不再带 Server Action 的参数。

<CodeRef at="patra-portal/next.config.ts@4a13287485468f2c489027f1aac0bb6174643e8d" lines="3-10" />

```ts
const nextConfig: NextConfig = {
  reactStrictMode: true,
  // 产出自包含 Node server 到 .next/standalone（容器化运行，镜像精简）
  output: "standalone",
  // 开发时 Next 默认在终端打印每次 Server Action 调用的参数，登录、注册的参数里有明文密码；也默认打印每个进来的
  // 请求（带查询串），一键退订地址的查询串里有退订令牌
  logging: { serverFunctions: false, incomingRequests: { ignore: [/\/unsubscribe\/one-click/] } },
};
```

后半句是同一类问题在 v0.16 通知中心那一版又遇到一次：开发模式默认打印每个进来的请求和它的查询串，而邮件里的一键退订地址把退订令牌放在查询串上。这次的修法是让请求日志跳过那一个路径。

<Callout kind="warn">

没关掉之前，别把开发服务器的日志贴到任何地方，也别让工具去读它。

</Callout>
