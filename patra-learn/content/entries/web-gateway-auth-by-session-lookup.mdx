## 网关要回答一个问题：这个令牌是谁

Patra 的登录用的是服务端会话：登录成功后，identity（身份服务）在 Redis 里存一条会话，给浏览器一个随机令牌。之后浏览器每个请求经门户转给网关，门户把令牌放在 `Authorization: Bearer` 里。

网关是所有请求的唯一入口。它要先弄清「这个令牌对应哪个用户、会话还在不在」，才能决定放不放行，并告诉下游是谁在请求。

下游服务（catalog、interaction 等）不自己查会话。网关查到人以后，用自己的私钥现签一份**身份断言**：一个 60 秒有效的签名 JWT，里面写着用户 ID、会话 ID、账号类型。下游只验签名，不碰会话。

<Callout kind="analogy">

令牌像酒店房卡，会话是前台登记簿上的那一行。网关是大堂保安：看到房卡，打电话问前台「这张卡现在还有效吗」，确认后给你贴一张当天有效的访客贴纸。楼上各层只认贴纸。

</Callout>

## 别人怎么做：三类做法

做这个决定前，查了大约 20 个系统的公开文档和源码（Keycloak、Ory、Pomerium、oauth2-proxy、Spring Security、Sa-Token、RuoYi-Cloud 等），做法可以分成三类。

<DecisionOptions
  options={[
    { name: "签发方独占，网关每次去问", summary: "会话只归身份服务读写；网关每个请求调它的查询接口（RFC 7662 的 introspection、Ory 的 whoami 都是这一类）。", pros: "会话的规则只写在一个服务里；登出、封号由身份服务一处删掉，下一个请求就生效。", cons: "每个带令牌的请求多一次服务间调用；身份服务挂了，所有要登录的请求都挂。", chosen: true },
    { name: "网关自己持有会话", summary: "网关存会话、签断言给下游，身份服务不碰会话存储（Pomerium、oauth2-proxy、云厂商的身份感知代理）。", pros: "少一次调用。", cons: "身份服务想主动踢人很难：要有办法通知网关。oauth2-proxy 的「后端发起登出」至今没合并。" },
    { name: "共享库加共享 Redis", summary: "身份服务和网关引同一个 jar，直接读写同一个 Redis（Spring Session、Sa-Token、RuoYi-Cloud 常见）。", pros: "实现最快，不多一跳。", cons: "会话格式写在两个服务都依赖的库里，改格式要两边一起部署；网关拿着 Redis 的读写密码。" }
  ]}
/>

Patra 一开始（v0.8 账号那一版）用的是第三类：网关直接读 Redis 并续期，和 identity 共用一个会话模块。到 v0.12 用户中心那一版，三个问题越来越明显：

1. TTL 公式、绝对过期、续期节流写在两个服务都依赖的库里，改会话格式要两个服务一起上线。
2. 网关持有 Redis 的读写凭据，还能调到 identity 的全部写方法，实际只用了「查并续期」一个。
3. 这个共用模块不属于六层里的任何一层，边界要靠文档解释。

## 选择：每个请求都问，不缓存

选的是第一类，并且查询结果不缓存。

决定性的理由是撤销。v0.8 否决这条路时，担心的是「每请求多一跳」和「撤销要等缓存过期」。不缓存，第二条就不存在了：会话一删，下一个请求就查不到。多一跳在一台 Mac mini 上是个位数毫秒。和 Patra 结构最像的组合是 Ory Kratos 加 Oathkeeper，Oathkeeper 开源版默认也不缓存；Traefik 的 ForwardAuth、Envoy 的 ext_authz、Spring Security 的 `opaqueToken()` 默认同样不缓存。

## 代价

<Callout kind="cost">

- **identity 不可用，要登录的请求全部 503**。网关把失败分成两类：identity 回 503、连不上、超时、注册中心里没有实例，算「暂时不可用」，回 503；其他失败回 500。不带令牌的请求不受影响。
- **每个带令牌的请求多一跳**，读超时设成 2 秒：identity 卡住时，几秒内就变成 503，而不是挂满一分钟。
- **网关不能回滚到这次改动之前的镜像**：旧网关要读 Redis 密码，而配置和部署文件都已经不再提供它。要回滚得先回退基础设施的改动。

</Callout>

什么时候该重新考虑：请求量大到这一跳成了瓶颈。到那时的常见做法是加一层短缓存，接受几秒的撤销延迟；或者缓存加「会话删除时广播失效」，但消息会丢，还要有过期时间兜底，这种组合目前没有成熟产品，Patra 现在的规模也用不上。

完整的设计见 `docs/patra/specs/2026-10-23-session-introspection-design.md`。
