## 坑

Patra 的会话存储注入了 `Clock`，测试可以把它拨快，用来测「60 秒内不续期、满 60 秒才续期」。但 Redis 里键的 TTL 走的是 Redis 服务端的真实时间：拨假时钟，`PTTL` 不会变。想靠「TTL 少了多少」来判断有没有续期，很容易写出一个怎样都通过的测试。

## 为什么

应用算 TTL 的时候用的是注入的时钟：比如「绝对过期时间减去现在」。算出来的数字交给 Redis 设置，此后 Redis 自己倒数，和应用的时钟再无关系。

这组测试里会话的不活跃过期是 30 天。如果测试用它建会话，然后检查「没续期时 TTL 还是约 30 天」，那续期了也是约 30 天：续期就是把 TTL 重设成 30 天。两种结果分不开，测试永远绿。

## 怎么避开

测试用较短的绝对过期，让「续了期」和「没续期」算出的 TTL 至少差出几十秒，再用一个比差值小的容差去断言：

<CodeRef at="patra-api/patra-identity/patra-identity-infra/src/integrationTest/java/dev/patra/identity/infra/session/store/RedisSessionStoreIT.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="157-172" />

```java
Duration oneHour = Duration.ofHours(1);
SessionToken token =
    store.create(newSession(42L, 7001L).expiresAt(START.plus(oneHour)).build()).token();
clock.advance(Duration.ofSeconds(59));

store.findAndTouch(token).orElseThrow();

// 续期会把 TTL 重算成 1 小时减 59 秒；没续期就还是约 1 小时（Redis 的 TTL 走真实时间）
assertThat(ttl(sessionKey))
    .isBetween(oneHour.toMillis() - TOLERANCE_MILLIS, oneHour.toMillis());
```
