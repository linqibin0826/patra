<Callout kind="lead" label="结论先说">

出站防火墙 LuLu 对 Claude 的几个进程（主程序、Helper、崩溃上报、更新器、Claude Code）都是「全部拦截」。内置浏览器加载每个跨域子资源前，会让 Claude 进程自己发一次 DNS 查询做预检；这些 UDP 53 的包被防火墙丢掉，等 20 秒超时，资源就被拦下。主文档走的是本机代理，防火墙默认放行本机回环，所以只有 HTML 能出来。

- **怎么修**：保留「全部拦截」，只给 DNS 服务器的 53 端口和内网网段加按地址放行的规则
- **值得记住**：终端里一切正常，不代表别的进程的网络也正常

</Callout>

背景：作者两天前装了 LuLu，并且有意把 Claude 设成全部拦截，当作断网保护（确保它只能经代理出网）。装了同款防火墙、同样设置的人才会碰到；值得带走的是「先按进程看」这个查法。

## 现象

- 内置浏览器打开外站：HTML 能出来，样式、字体加载不出；
- 打开局域网或 VPN 里的地址：直接失败，导航报 `ERR_INVALID_HANDLE`；
- 应用日志里有 `[PreviewContext] Blocked subresource to private-resolving host`；
- 终端里 curl、dig 同样的地址，全部正常。

症状很像代理或 fake-ip 出了问题，容易往那边走偏。

终端里的 curl、dig 是别的进程，防火墙里它们是放行的，所以怎么试都正常。

## 修法

全部拦截是有意设的，不改成放行。只在它前面加几条按地址放行的规则（作者在防火墙里自己操作）：

- Claude 主进程 → 本机用的几个 DNS 服务器的 53 端口；
- Claude Helper → 局域网网段、VPN 网段。

再遇到内置浏览器加载问题，先查防火墙里 Claude 的规则，再用 `nettop` 看 53 端口的流是不是 0 字节。
