## 页面默认是服务端组件

在 App Router 里，`page.tsx`、`layout.tsx` 以及它们引入的组件，默认都是**服务端组件**：只在服务器上运行，运行完把结果发给浏览器，组件的代码本身不发过去。

所以它们能做浏览器里做不了、也不该做的事：直接调网关、读请求里的 Cookie、用只有服务器知道的配置。用户主页一边取资料、一边查当前登录的是谁：

<CodeRef at="patra-portal/src/app/u/[username]/page.tsx@6ead12db647bcd3e56f651af791d56e418cb79ff" lines="48-52" />

```tsx
export default async function UserPage({ params }: UserPageProps) {
  const [lookup, session] = await Promise.all([
    fetchPublicProfile((await params).username),
    lookupSession(),
  ]);
```

`lookupSession` 要从 Cookie 里读出会话令牌，带着它去问网关。令牌只在服务器上出现，浏览器里的脚本碰不到。门户还给这类文件加了一道门：

<CodeRef at="patra-portal/src/lib/auth/current-user.ts@fe4c6bb68c591a9c9b5fe80f76bbfbbbc6aeae75" lines="1" />

```ts
import "server-only";
```

哪个客户端组件不小心引入了它，构建直接失败。

## 要交互的部分标 `use client`

状态、点击、effect、window 和 navigator，这些都要在浏览器里跑。需要它们的文件第一行写 `"use client"`，声明这是**客户端组件**。导航栏就是：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="1" />

```tsx
"use client";
```

服务端组件可以直接渲染客户端组件：用户主页里第一个就是 TopNav。点任意一块，看它在哪边：

## 边界画在 import 上

`"use client"` 只要写在一棵客户端子树的入口。被它引入的文件，以及那些文件再引入的，全都进浏览器的代码包，不用每个都写。导航栏引入的品牌标志 `BrandMark` 文件里没有这一行，照样跟着 TopNav 进了浏览器。

反过来不行：客户端组件不能引入服务端组件，引进来就成了客户端代码。但它可以**接收**服务端组件已经画好的结果。根布局里的 `QueryProvider` 是客户端组件，它包着的 `children` 却是各个服务端页面：

<CodeRef at="patra-portal/src/app/layout.tsx@4a13287485468f2c489027f1aac0bb6174643e8d" lines="52-56" />

```tsx
        <QueryProvider>
          {children}
          <NotificationStream />
          <Toaster position="bottom-right" />
        </QueryProvider>
```

页面在服务器上已经画完，`QueryProvider` 拿到的只是结果，不是页面的代码。

## 过边界的只能是数据

服务端组件渲染客户端组件时，传过去的 props 要先变成一段数据发给浏览器（序列化）。字符串、数字、普通对象、数组都可以；函数不行，比如服务端组件不能给客户端组件传一个 `onClick`（Server Action 是例外，另有一篇讲）。提醒页把要看哪一栏用一个字符串交给客户端的收件箱：

<CodeRef at="patra-portal/src/app/notifications/page.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="5-8" />

```tsx
export default async function RepliesPage() {
  await requireUser("/notifications");
  return <NotificationInbox tab="replies" />;
}
```

<Callout kind="warn">

传给客户端组件的 props 会原样出现在发给浏览器的数据里。会话令牌、只给服务器看的字段，不要顺手塞进 props。

</Callout>

## 客户端组件在服务器上也跑一次

名字容易让人误会。实际情况是：

| | 在服务器上跑 | 在浏览器里跑 |
|---|---|---|
| 服务端组件 | 是 | 否 |
| 客户端组件 | 是 | 是 |

第一次打开页面时，客户端组件先在服务器上跑一遍，画出 HTML，让页面马上能看；它的代码同时发到浏览器，在浏览器里再跑一遍，挂上点击这些交互。「客户端」的意思是「也在浏览器里跑」，不是「只在浏览器里跑」。两次运行的结果必须一样，这是下一篇「水合」的话题。
