## 背景：两个服务共用一份会话规则

v0.8 做账号登录时的设计是：identity 负责建会话、删会话；网关每收到一个带令牌的请求，自己去 Redis 查会话、顺手续期，查到了就给下游签一份 60 秒有效的身份断言。为此两边共用一个模块 `patra-identity-session`，里面有令牌格式、Redis 键、8 段 Lua 脚本和读写会话的类。

到 v0.12 用户中心收尾时（2026-10-23），这套结构暴露了三个问题：

1. 会话规则（过期时间怎么算、绝对过期、60 秒续期节流）写在两边都依赖的库里，改会话格式要两个服务一起部署。
2. 网关拿着 Redis 的读写密码，也拿着 identity 全部写会话的方法，实际只用到其中一个「查并续期」。
3. 这个模块不属于六边形的任何一层，边界只能靠文档解释。

## 业界怎么分：三类做法

为这个问题查过约 20 个系统的公开文档和源码，做法分成三类：

Patra 原来的做法是「第三类的机制、第二类的边界」：网关直读 Redis 并签断言，identity 建会话、删会话。

v0.8 当初否决过第一类，理由是「每个请求多一跳，撤销还有一个缓存时间的窗口」。这次重新算账：不缓存查询结果，就不存在撤销窗口；多一跳发生在同一台 Mac mini 上的两个容器之间，是个位数毫秒。

还排除过几条路：直接用 Spring Session（绝对过期、续期节流、换令牌等七八项仍要自己补）；Redis Functions 让脚本只归 identity（Spring Data Redis 没有调用它的接口，还会引入「先加载函数再部署」的顺序约束）；把格式放进 api 模块加契约测试（契约测试只能发现两边不一致，不能让规则只写一份）。

## 选择：网关只调 identity

<Callout kind="lead" label="选了什么">

identity 独占会话存储：共用模块删掉，内容并进 identity 自己的基础设施层。identity 提供内部接口 `POST /_internal/sessions/introspect`，按令牌查会话、节流续期，返回当前用户。网关去掉 Redis 依赖和密码，每个带令牌的请求调这个接口，查到了照旧签 60 秒断言。查询结果不缓存。

</Callout>

契约放进新建的 `patra-identity-api` 模块，这是 identity 的第一份服务间契约：

<CodeRef at="patra-api/patra-identity/patra-identity-api/src/main/java/dev/patra/identity/api/session/endpoint/SessionEndpoint.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="20-33" />

```java
@HttpExchange(url = "/_internal/sessions", accept = "application/json", contentType = "application/json")
public interface SessionEndpoint {
  @PostExchange("/introspect")
  SessionIntrospectionResp introspect(@RequestBody SessionIntrospectionReq request);
}
```

令牌放请求体而不放 `Authorization` 头，有两个原因：identity 自己的安全过滤器会把 `Authorization: Bearer` 当成身份断言去验签，会话令牌放进去会被拒成 401；放请求体也让令牌不进 URL 和访问日志。返回形状参照 RFC 7662 的 `active` 字段：令牌格式不对、会话不存在、过了绝对过期，都回 `200 {"active": false}`。

## 查不到时网关怎么回

网关只包住这一次调用，把失败翻译成两种结果：

| 情形 | 输出 |
|---|---|
| identity 回 503（它自己连不上 Redis） | 503 |
| 连不上 identity、超时 | 503 |
| 注册中心里没有 identity 实例 | 503 |
| identity 回了别的错误 | 500 |

## 代价

<Callout kind="cost">

- 每个带令牌的请求多一次网关到 identity 的调用；网关给这次调用配了 1 秒连接超时、2 秒读超时，identity 卡住时几秒内变成 503。
- identity 成了所有登录态请求的必经之路，它不可用，登录用户的请求全部 503。
- 网关不能再回滚到这次改动之前的镜像：旧网关启动要读 Redis 密码，而配置中心和部署文件都已经不再提供它。要回滚，得先撤销基础设施的改动。

</Callout>
