<Callout kind="lead">

Spring 发现一个 Bean 的方法上有 `@Transactional`，就不把原对象交给别人，而是交出一个**代理**：外表和原对象一样，调用它的方法时先开事务、再转给原对象、最后提交或回滚。只有经过代理的调用才有事务。类里面用 `this` 调自己的方法，不经过代理。

</Callout>

## 注解自己不开事务

`@Transactional` 和所有注解一样，只是贴在代码上的标签。它本身不会让任何事情发生，要有人读它、照它办。读它的是 Spring 的事务拦截器，而拦截器装在代理上。

<Callout kind="analogy">

公司规定「所有报销单都要经财务盖章」。外面的人递单子，都交给前台，前台转财务盖章，这一步不会漏。可如果你是部门内部的人，直接从同事桌上拿单子去办，就绕过了前台，也就没人盖章。代理就是那个前台，`this` 调用就是直接去同事桌上拿。

</Callout>

## 不靠代理的写法：TransactionOperations

除了拆 Bean，还有一种写法根本不依赖代理：把要放进事务的那段代码交给 `TransactionOperations`，由它当场开事务、执行、提交。Patra 的写命令 Handler 一律这样写，登出就是：

<CodeRef at="patra-api/patra-identity/patra-identity-app/src/main/java/dev/patra/identity/app/session/usecase/logout/LogoutUserHandler.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="50-68" />

```java
    Instant now = clock.instant();
    try {
      transactions.executeWithoutResult(
          status ->
              records
                  .findById(user.sessionId())
                  .ifPresentOrElse(
                      login -> {
                        login.end(LoginEndReason.LOGOUT, now);
                        records.save(login);
                      },
                      () ->
                          log.info(
                              "登出时找不到登录记录: userId={}, sessionId={}",
                              user.userId(),
                              user.sessionId())));
    } catch (RuntimeException e) {
      log.warn("登出后结束登录记录失败，记录留空: userId={}, sessionId={}", user.userId(), user.sessionId(), e);
    }
```

事务的范围就是 `executeWithoutResult` 里的那段，一眼看得见，也不存在「经没经过代理」的问题。前面删 Redis 会话那一步在事务外，因为事务里只放数据库操作。
