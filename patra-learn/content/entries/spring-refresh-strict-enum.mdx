## 坑

Spring Boot 读配置时，枚举值的写法很宽松：`dont-follow`、`dont_follow`、`DONT_FOLLOW` 都能对上 `DONT_FOLLOW`。

可配置刷新时，有的第三方组件会在一个新建的 `StandardEnvironment` 上重新执行它的环境后处理器，用的是 Spring 默认的转换服务，**只认常量原名**。jar 里写的是横线小写，启动没事，每次刷新都失败。

## 为什么

v0.9 配置中心那一版验收时发现：网关收到 Nacos 的配置变更，客户端通知监听器失败、重试 5 次后放弃，网关继续用旧配置，容器状态照样是 healthy。

原因在 Spring Cloud Gateway（Server MVC 版）的一个环境后处理器 `GatewayHttpClientEnvironmentPostProcessor`。它用 `environment.getProperty(键, 枚举.class)` 读两项 HTTP 客户端设置：`spring.http.clients.redirects` 和 `spring.http.clients.imperative.factory`。

<Callout kind="warn">

这个坑难查，是因为看不到原因：Nacos 客户端通知失败时只打 4 层堆栈，不打异常消息，翻日志找不到「哪个值转换失败」。

复现办法：本机起网关，加上 `--spring.cloud.nacos.discovery.register-enabled=false --management.endpoints.web.exposure.include=health,refresh`，然后 `POST /actuator/refresh` 手动触发刷新，响应和日志里有完整的异常。

</Callout>
