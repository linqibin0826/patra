<Callout kind="lead">

HTTP Interface 是用一个 Java 接口描述对方服务的某个 HTTP 接口：路径、方法、请求体、返回类型都写在注解和签名上。Spring 按这个接口生成一个代理对象，调它的方法，代理就替你拼好请求发出去，再把响应 JSON 变回 Java 对象。

</Callout>

## 契约：一个接口，两头都用

网关每收到一个带令牌的请求，都要问 identity「这个令牌对应谁」。这件事的契约是 `SessionEndpoint`，放在 identity 的 `patra-identity-api` 模块里。

<CodeRef at="patra-api/patra-identity/patra-identity-api/src/main/java/dev/patra/identity/api/session/endpoint/SessionEndpoint.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="21-33" />

```java
@HttpExchange(
    url = "/_internal/sessions",
    accept = "application/json",
    contentType = "application/json")
public interface SessionEndpoint {

  /// 按令牌查会话并节流续期。
  ///
  /// @param request 令牌原文
  /// @return 查询结果；令牌格式不对、会话不在或已过绝对期时 `active` 为 `false`
  @PostExchange("/introspect")
  SessionIntrospectionResp introspect(@RequestBody SessionIntrospectionReq request);
}
```

接口上的 `@HttpExchange` 给出公共前缀，方法上的 `@PostExchange` 说「这是一个 POST，路径再拼上 `/introspect`」。读下来就是：`POST /_internal/sessions/introspect`，请求体是 `SessionIntrospectionReq`，响应体是 `SessionIntrospectionResp`。

契约放在被调方的 `-api` 模块，是因为接口长什么样由提供接口的一方说了算。调用方只依赖这个小模块，拿不到 identity 的任何内部代码。

## 代理：调方法就是发请求

网关里生成代理的地方只有两个 Bean：

<CodeRef at="patra-api/patra-gateway-boot/src/main/java/dev/patra/gateway/config/IdentityClientConfiguration.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="23-39" />

```java
  @Bean
  public RestClient identityRestClient(
      @Qualifier("httpInterfaceLoadBalancedRestClientBuilder")
          RestClient.Builder loadBalancedBuilder,
      RestClientFactory factory) {
    return factory.createRestClient(loadBalancedBuilder, "identity", "lb://patra-identity");
  }

  /// 查会话接口代理。
  ///
  /// @param identityRestClient identity 的 RestClient
  /// @param factory RestClient 工厂
  /// @return 代理
  @Bean
  public SessionEndpoint sessionEndpoint(RestClient identityRestClient, RestClientFactory factory) {
    return factory.createProxy(identityRestClient, SessionEndpoint.class);
  }
```

第一个 Bean 是一个 `RestClient`：真正发 HTTP 请求的客户端，基础地址是 `lb://patra-identity`（`lb://` 怎么变成真实地址，另有一篇讲服务发现）。第二个 Bean 把它交给 Spring 的 `HttpServiceProxyFactory`，按 `SessionEndpoint` 生成代理。

## 失败：统一翻译成 RemoteCallException

Patra 的服务出错时回 RFC 7807 的 ProblemDetail（`application/problem+json`），扩展字段里带错误码 `code` 和语义特征 `traits`（比如 `NOT_FOUND`、`DEP_UNAVAILABLE`）。调用方要把这段 JSON 读回来，变成一个带着这些信息的 Java 异常。

这件事每个服务都要做，所以统一放在工具模块 `patra-tool-http-client` 里，由 `ProblemDetailErrorHandler` 完成。它挂在 `RestClient.Builder` 上的方式是一个 `RestClientCustomizer`：

<CodeRef at="patra-tool/patra-tool-http-client/src/main/java/dev/patra/tool/httpclient/autoconfigure/HttpClientInterfaceAutoConfiguration.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="94-108" />

```java
    return builder -> {
      ProblemDetailErrorHandler errorHandler = errorHandlerProvider.getIfAvailable();
      if (errorHandler != null
          && properties.httpInterface().errorHandling().problemDetailEnabled()) {
        builder.defaultStatusHandler(HttpStatusCode::isError, errorHandler);
        log.debug("已将 ProblemDetailErrorHandler 添加到 RestClient.Builder");
      }
    };
```

`defaultStatusHandler(HttpStatusCode::isError, …)` 的意思是：只要状态码是 4xx 或 5xx，就交给这个处理器。处理器读响应体，能解析成 ProblemDetail 就把 `code`、`traits`、`traceId` 都装进 `RemoteCallException`；解析不了的（比如对方回了一段 HTML）也包成 `RemoteCallException`，只是没有错误码。

<Callout kind="insight" label="顺带想通的">

网关用的是负载均衡版的 Builder（`httpInterfaceLoadBalancedRestClientBuilder`），它在自动配置里**故意不应用** customizer，注释写着「避免与 RestClientFactory 重复应用自定义器」。错误处理器是在 `RestClientFactory.createRestClient` 里挂上的：先 `clone()` 一份 Builder，再把所有 customizer 依次作用上去。所以只要通过工厂建客户端，就不会漏掉错误翻译。

</Callout>

## 调用方：按语义特征判断，不按状态码硬编码

翻译好的异常交给调用方处理。网关查会话的那一处是这样分的：

<CodeRef at="patra-api/patra-gateway-boot/src/main/java/dev/patra/gateway/security/SessionTokenAuthenticationConverter.java@5073ab1358404ecd989e722373cd9f7edafe238b" lines="76-89" />

```java
  private SessionIntrospectionResp introspect(String token) {
    try {
      return sessions.introspect(SessionIntrospectionReq.of(token));
    } catch (RemoteCallException e) {
      if (e.getErrorTraits().contains(StandardErrorTrait.DEP_UNAVAILABLE)) {
        throw new AuthenticationServiceException("会话存储暂时不可用", e);
      }
      throw new SessionLookupFailedException(e);
    } catch (ResourceAccessException | IllegalStateException e) {
      throw new AuthenticationServiceException("identity 暂时不可用", e);
    } catch (RuntimeException e) {
      throw new SessionLookupFailedException(e);
    }
  }
```

两点值得注意：

- 判断「是不是暂时不可用」看的是 `getErrorTraits()` 里有没有 `DEP_UNAVAILABLE`，而不是写死 `status == 503`。语义特征由 identity 自己声明，换个状态码也不会判错。
- `RemoteCallException` 只覆盖「对方回了响应，但是错误响应」。根本连不上、读超时时没有响应可读，`RestClient` 抛的是 `ResourceAccessException`，要单独接住。
