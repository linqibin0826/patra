## 浏览器把 HTML 读成一棵树

浏览器收到 HTML 后，不是把它当一整段文字留着，而是读成一棵**树**：每个标签是一个**节点**，标签里套的标签是它的子节点。这棵树叫 **DOM**（文档对象模型）。脚本操作页面，操作的就是这棵树。

<Callout kind="analogy">

像一本书的目录：书（`html`）下面分章（`head`、`body`），章下面分节（`header`、`main`），节下面是一段段内容。想改第三章第二节的一句话，先按目录找到它，再动笔。

</Callout>

## 脚本先找到节点，再改它

脚本里有一个现成的对象 `document`，代表整棵树。最直接的找法是按 `id` 找：HTML 里给某个标签写上 `id="…"`，脚本用 `document.getElementById("…")` 就能拿到那个节点。

门户的快速检索框打开时，要让光标直接落进输入框，免得你再点一下。它就是这么找的：

<CodeRef at="patra-portal/src/components/portal/QuickSearch.tsx@11f9efb07fd75ad12c2e22d7758c71a8680f37f4" lines="24-25" />

```tsx
        <Dialog.Popup
          initialFocus={() => document.getElementById(INPUT_ID)}
```

`INPUT_ID` 是同一个文件第 9 行定义的 `"quick-search-input"`，检索框里那个输入框的 `id` 正是它。找到节点以后，脚本就能改它：让它获得焦点、改里面的文字、加一个样式、整个删掉。浏览器看到树变了，就重新画页面。

## 事件：浏览器喊一声，登记过的才听得到

用户的每个动作——按键、点击、滚动、在输入框里打字——浏览器都会生成一个**事件**，交给关心它的代码。哪段代码关心，要事先**登记**：`addEventListener("事件名", 处理函数)`。

门户的 ⌘K（Windows 上是 Ctrl+K）就是这样做的。顶栏组件在整个窗口上登记了「有键按下时叫我」：

<CodeRef at="patra-portal/src/components/portal/TopNav.tsx@d0ca49caf72d9d9aacd7459c1054cf9131b3759e" lines="73-83" />

```tsx
  useEffect(() => {
    const onKeyDown = (e: KeyboardEvent) => {
      if ((e.metaKey || e.ctrlKey) && e.key.toLowerCase() === "k") {
        e.preventDefault();
        setSearchLoaded(true);
        setSearchOpen((open) => !open);
      }
    };
    window.addEventListener("keydown", onKeyDown);
    return () => window.removeEventListener("keydown", onKeyDown);
  }, []);
```

读法：

- `"keydown"` 是「有键被按下」这个事件。浏览器每次叫 `onKeyDown`，都会递给它一个事件对象 `e`，里面写着按的是哪个键（`e.key`）、有没有同时按着 ⌘（`e.metaKey`）或 Ctrl（`e.ctrlKey`）。
- 不是 ⌘K 就什么都不做：登记了 `keydown`，你按的每一个键都会叫到它，它得自己挑。
- `e.preventDefault()`：有些按键浏览器自己有默认动作（有的浏览器拿 ⌘K 去聚焦地址栏或搜索栏）。这一句是说「这次别做你的默认动作」。
- `setSearchOpen((open) => !open)`：把「检索框开着吗」这个状态翻过来。改状态以后，页面由 React（门户用的界面框架）去改 DOM 树，对话框随之出现或消失。

## 登记了，就要记得撤销

上面代码最后一行 `return () => window.removeEventListener("keydown", onKeyDown)` 是撤销登记：顶栏从页面上移除时，把这次登记取消。

<Callout kind="warn">

不撤销的话，顶栏没了，`onKeyDown` 还挂在 window 上，每次按键照样被叫到；顶栏再出现一次，又登记一份，按一次 ⌘K 就会被处理两次。登记和撤销要成对写。

</Callout>

## 按钮上的 onClick 也是同一套

「快速检索」按钮上写的是 `onClick={openSearch}`，看起来和 `addEventListener` 不一样。这是 React 的写法：你在标签上写 `onClick`，React 替你向浏览器登记点击事件、组件移除时替你撤销。背后仍然是「事件发生 → 叫登记过的函数」这一套。

门户的代码大多这样写，很少直接 `getElementById` 去改节点：代码只改状态（开着还是关着），让 React 去改 DOM 树。直接操作 DOM 的地方，是 React 管不到的：整个窗口上的快捷键、把光标放进某个输入框。
