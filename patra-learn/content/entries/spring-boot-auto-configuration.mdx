<Callout kind="lead">

自动配置：一个 jar 在固定位置放一份清单，列出自己的配置类；Spring Boot 启动时读所有 jar 的清单，逐个判断条件，满足就把配置类里的 Bean 装进容器。服务只要在构建脚本里引入这个依赖，不用写一行装配代码。

</Callout>

## 扫描只管服务自己的包

上一篇说过，贴了 `@Component` 的类会被启动时的扫描发现。扫描从哪开始？从启动类所在的包往下。identity 的启动类：

<CodeRef at="patra-api/patra-identity/patra-identity-boot/src/main/java/dev/patra/identity/PatraIdentityApplication.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="9-18" />

```java
@SpringBootApplication
public class PatraIdentityApplication {

  /// 经启动器启动应用，服务名 `patra-identity`。
  ///
  /// @param args 命令行参数
  public static void main(String[] args) {
    PatraApplication.run("patra-identity", PatraIdentityApplication.class, args);
  }
}
```

它在 `dev.patra.identity` 包里，`@SpringBootApplication` 后面什么也没加，所以只扫 `dev.patra.identity` 和它下面的包。`dev.patra.tool.launch` 不在里面。

这是 v0.10 定下的（release spec 决策 G）：启动类改回裸 `@SpringBootApplication`，工具模块的 Bean 一律由自动配置注册。之前启动类写的是 `scanBasePackages` 扫整个项目根包，同一个 Bean 在服务里靠扫描、在切片测试里靠自动配置，来源和顺序都不一样，有 6 个 Bean 实际上被注册了两遍。

<Callout kind="analogy">

扫描像物业挨家挨户登记本楼住户，只登记这栋楼。自动配置像快递柜：外面的包裹（工具模块）贴好了取件单（清单），物业按单子取出来放进楼里，不用挨个敲门。

</Callout>

## 那份清单长什么样

清单的位置是固定的：jar 里的 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`，一行写一个配置类的全名。事件模块 `patra-tool-events` 的清单：

<CodeRef at="patra-tool/patra-tool-events/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="1-3" />

```text
dev.patra.tool.events.autoconfigure.EventsRabbitAutoConfiguration
dev.patra.tool.events.autoconfigure.EventsResubmitAutoConfiguration
dev.patra.tool.events.autoconfigure.EventsConsumerAutoConfiguration
```

三行，三个配置类。每个配置类贴 `@AutoConfiguration`，里面是一个个 `@Bean` 方法。服务的构建脚本引入 `patra-tool-events`，jar 就到了运行时的类路径上，清单也跟着到了。

Patra 的构建会检查这份清单和代码对不对得上（规则 R4）：写了 `@AutoConfiguration` 却没登记进清单、清单登记了却找不到这个类，`./gradlew check` 都会失败；工具模块里也不许出现 `@Component` 这类靠扫描的注解，因为服务根本扫不到它们。

## 条件注解：满足才装

清单上的配置类不是无条件装进来的。每个类、每个 `@Bean` 方法上都可以贴「条件」，Spring Boot 逐个判断，不满足就跳过。Patra 里最常见的四种：

| 条件 | 意思 | Patra 里的例子 |
|---|---|---|
| `@ConditionalOnClass(X.class)` | 类路径上有 X 这个类才装 | 有 XXL-Job 才注册补投任务入口 |
| `@ConditionalOnBean(X.class)` | 容器里已经有 X 这种 Bean 才装 | 有 Modulith 的事件登记才注册补投器 |
| `@ConditionalOnMissingBean` | 容器里还没有这种 Bean 才装 | 服务没自己定义 `Clock` 才给默认的 |
| `@ConditionalOnProperty(...)` | 某个配置键是某个值才装 | `patra.launch.enabled` 不是 `false` 才装 |

提供 `Clock` 的那个配置类同时用了两种：

<CodeRef at="patra-tool/patra-tool-launch/src/main/java/dev/patra/tool/launch/autoconfigure/LaunchAutoConfiguration.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="24-31" />

```java
@AutoConfiguration
@ConditionalOnProperty(
    prefix = "patra.launch",
    name = "enabled",
    havingValue = "true",
    matchIfMissing = true)
@EnableConfigurationProperties(LaunchProperties.class)
public final class LaunchAutoConfiguration {
```

同一个类里，造 `Clock` 的方法：

<CodeRef at="patra-tool/patra-tool-launch/src/main/java/dev/patra/tool/launch/autoconfigure/LaunchAutoConfiguration.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="56-60" />

```java
  @Bean
  @ConditionalOnMissingBean
  Clock clock() {
    return Clock.systemUTC();
  }
```

`matchIfMissing = true` 的意思是：配置里压根没写这个键，也当作满足。所以默认就装，要关得明确写 `patra.launch.enabled: false`。

## 想换掉默认的：两个层次

**换一个 Bean**：像上面的 `Clock`，自己定义一个同类型的 Bean，默认的那个因为 `@ConditionalOnMissingBean` 让路。工具模块之间也这样配合。`EventsRabbitAutoConfiguration` 指定排在 Spring Boot 自己的 RabbitMQ 自动配置之前，先放进一个「等确认的发送模板」；轮到 Boot 时，它见容器里已经有了，就不再建自己那个：

<CodeRef at="patra-tool/patra-tool-events/src/main/java/dev/patra/tool/events/autoconfigure/EventsRabbitAutoConfiguration.java@5b1d855a5da18806b91a52f24253e64d40d743a8" lines="17-24" />

```java
/// RabbitMQ 收发的装配：收发共用的 JSON 转换器、`mandatory`、等确认的发送模板。
///
/// 排在 Boot 的 `RabbitAutoConfiguration` 之前：Boot 见到已有 `RabbitMessagingTemplate` 就不再建，
/// Modulith 的 AMQP 外送器拿到的 `RabbitMessageOperations` 就是 {@link ConfirmingRabbitMessagingTemplate}。
@AutoConfiguration(before = RabbitAutoConfiguration.class)
@ConditionalOnClass(RabbitMessagingTemplate.class)
@EnableConfigurationProperties(EventsProperties.class)
public final class EventsRabbitAutoConfiguration {
```

**换一个配置值**：工具模块还要给别人的配置键出默认值，比如 `spring.rabbitmq.*`。v0.10 决策 D 的做法是放进优先级最低的一层（`EventsDefaultsPostProcessor` 用 `DefaultPropertiesPropertySource.addOrMerge` 并入），服务的 yml、Nacos、环境变量写同一个键都能盖过它。配置的优先级是下一篇的内容。

<Callout kind="warn">

`@WebMvcTest` 这类切片测试只装和切片相关的那几个自动配置，工具模块的不会自动带上。Patra 里需要的切片测试要自己写 `@ImportAutoConfiguration(...)` 把它导进来。

</Callout>
