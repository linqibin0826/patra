## 背景

再认证是用户中心从 v0.12 起的规则：改邮箱、踢设备、注销这类敏感操作，要求当前会话 10 分钟内输过密码。超时了，服务端回 403 `REAUTH_REQUIRED`，门户弹密码框。

会话里记这件事的字段是 `auth_at`，它的前提是每个人都有密码。第三方登录打破了这个前提：只用 GitHub 的小陈没有密码。v0.12 写过一句预案：「没有密码的 OAuth 账号以后跳回提供方再认证」。到 v0.19 真要做时，查文档发现行不通：Google、GitHub 的文档都没有强制重新输密码的办法（GitHub 的 `prompt` 只能强制显示账号选择器），第三方登录状态还在时可能一闪而过。

## 选择

<Callout kind="lead" label="选了什么">

再认证只认密码，第三方登录不写 `auth_at`。决定性的理由是：跳回第三方证明不了「刚才是本人」，而敏感操作的保护强度不该因为绑定了第三方就下降。这样也不用再引入第二种再认证机制。

</Callout>

落到代码上，`auth_at` 从必填变成可空，守卫把没有值当作已超时：

<CodeRef at="patra-api/patra-identity/patra-identity-domain/src/main/java/dev/patra/identity/domain/session/service/ReauthenticationGuard.java@e3120fa01976688a7eb6f4c627d900e9c4b214d2" lines="42-53" />

```java
  public void requireRecent(CurrentUser current) {
    Objects.requireNonNull(current, "current 不能为 null");
    SessionPasswordProof proof =
        sessions
            .findPasswordProof(current.accountType(), current.userId(), current.sessionId())
            .orElseThrow(AuthenticationRequiredException::new);
    Instant now = clock.instant();
    boolean recent = proof.verifiedAt().filter(at -> policy.isRecent(at, now)).isPresent();
    if (!recent) {
      throw new ReauthenticationRequiredException();
    }
  }
```

没有密码的人点「输对密码再认证」其实走不通，所以门户要知道这个人有没有密码：`/auth/me` 多了 `hasPassword`。拿到 `REAUTH_REQUIRED` 后，有密码就弹密码框；没有就提示先设置密码，并说明所有设备会下线。

<Callout kind="insight" label="顺带想通的">

`auth_at` 可空之后，旧接口的空值就有了两个含义：会话不在，和会话在但没有证明。前者该回 401，后者该回 403。Patra 把它们拆开：外层 `Optional` 为空表示会话不在，里面的 `SessionPasswordProof` 再说有没有验证过。同一个空值不要挤两种含义。

</Callout>

## 代价

<Callout kind="cost">

只用第三方的用户要做敏感操作，就得先设一个密码；设置密码后所有设备下线，要重新登录一次。这替代了 v0.12 关键决策里的「跳回提供方再认证」。如果以后有了真能证明「刚才是本人」的另一种方式，这个决策可以重新考虑。

</Callout>
