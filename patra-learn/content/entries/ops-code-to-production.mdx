## 五个词，对应五站

- **提交与分支**：你的改动先在自己的分支上，不直接碰主分支。
- **CI（持续集成）**：合并前的自动检查，由 GitHub 的云端机器执行。
- **打包**：把代码连同运行环境做成一个镜像，后面的篇目会讲镜像是什么。
- **CD（持续部署）**：合并后自动把新版本换到线上。
- **巡检**：定时检查机器本身是否健康。

<Callout kind="analogy">

把它想成工厂流水线。CI 是出厂前的质检，CD 是装车发货，巡检是仓库每天早上的盘点。你只负责把货做出来。

</Callout>

## 三种坏法，三道防线

坏事有三个时态，每个时态对应一道防线。

| 什么时候坏 | 防线 | 在哪一站 |
|---|---|---|
| 将要坏：有问题的代码想进主分支 | 本地钩子、PR 检查、评审 | 合并前 |
| 正在坏：新版本上线后起不来 | 健康检查、自动退回 | 合并后 |
| 悄悄坏了：机器掉线、磁盘满了，没有人发现 | 每日巡检 | 平时 |

第三种最阴险，因为没有任何一次改动触发它，也就不会有人去看。
