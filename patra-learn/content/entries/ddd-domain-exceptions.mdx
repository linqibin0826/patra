## 先看直接抛 RuntimeException 的问题

最省事的写法是遇到重名就 `throw new RuntimeException("已有同名收藏夹")`。它的问题是异常只带一句话，没有含义：

- 调用方没法判断这是「业务冲突」还是「系统出错」。
- Web 层想翻译成状态码，只能去解析那句话，字一改就失灵。
- 前端想针对「重名」给出提示，没有稳定的标记可认。

## 异常里带的东西：语义特征

Patra 的领域异常都继承 `DomainException`。它有个硬性要求：**构造时必须至少给一个语义特征**，否则直接报错。

<CodeRef at="patra-tool/patra-tool-core/src/main/java/dev/patra/tool/core/error/DomainException.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="64-85" />

特征分两类：

- **标准特征** `StandardErrorTrait`：全站通用的八种含义，如 `NOT_FOUND`、`CONFLICT`、`RULE_VIOLATION`、`QUOTA_EXCEEDED`、`DEP_UNAVAILABLE`。
- **业务特征**：服务自己定义的原因码，如 `CollectionErrorTrait.COLLECTION_NAME_TAKEN`。

映射表就是引擎里的一个 Map：

<CodeRef at="patra-tool/patra-tool-web/src/main/java/dev/patra/tool/web/error/engine/DefaultErrorResolutionEngine.java@b6e01875bb5692356021c8a19562f557f319fc54" lines="62-71" />

所以你在领域层写 `StandardErrorTrait.QUOTA_EXCEEDED`，响应就是 429；写 `NOT_FOUND`，响应就是 404。换协议（比如以后加一个消息入口）时，领域异常一个字都不用改。

## 各层怎么处理异常

| 层 | 做法 |
|---|---|
| domain | 继承 `DomainException`，带语义特征，不依赖任何框架 |
| app | 领域异常直接往上传；只有意外的 `RuntimeException` 才用 `ApplicationException` 包装并给错误码 |
| Web 层 | 错误解析引擎统一翻译，Controller 里不写 try-catch |

<Callout kind="warn">

不要在应用层 catch 了领域异常再抛一个新的 RuntimeException。那样特征就丢了，引擎只能按兜底处理，用户看到的是模糊的错误。

</Callout>
