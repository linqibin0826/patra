## 坑

开着 `page.route` 拦截请求时，Playwright 会关掉浏览器的 HTTP 缓存。在门户的开发模式下，登录、注册、退出这类写 Cookie 的操作会让当前页重新渲染，并换一份新的样式表，`@font-face` 跟着重建；缓存关着，字体就真的重新下载。截图落在下载完成之前，抓到的就是回退字体。

这是 v0.8 账号登录那一版做视觉验收时踩到的：移动端「已退出」的截图里，等宽字体变成了比例字体。桌面和移动端都会发生，撞不撞上看时机。

## 为什么

几件事凑到了一起：

1. `next dev` 下，写 Cookie 的 Server Action 重渲染当前页时，会把 `/_next/static/css/app/layout.css?v=<时间戳>` 换成带新时间戳的一份。
2. 样式表换了，`@font-face` 规则重建，浏览器要重新拿字体文件。
3. 有 `page.route` 生效时缓存被关，字体真的走网络重下。
4. `document.fonts.ready` 可能在换样式表之前就已经返回了，等它也等不住。

不开拦截时同样会换样式表，但字体走缓存，看不出来；生产构建的样式表是带哈希的文件名，不会这样换。

## 怎么避开

截图前先撤掉拦截：用 `page.route` 挂住某个请求的脚本，先放行它，再 `page.unroute("**/*")`，然后截图。

<Callout kind="insight" label="怎么分辨真假">

怀疑是字体真没加载时，用生产构建（`pnpm build` 后启动）复现一次。生产构建里也错，才是页面的 bug。

</Callout>
