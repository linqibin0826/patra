## 1. 方向：花园

学习站像一座会长的花园：条目是「种下」的，主题随版本「长」出新条目，读者的掌握度从种子长成叶子。视觉上是带一点绿的纸色底、白卡片、水青色做唯一的强调色，标题用衬线体，安静、可以久读。

**从样稿 B 改了什么**

| 样稿 B | hi-fi | 为什么 |
|---|---|---|
| 中文用 Google 的 Noto Sans SC / Noto Serif SC | 中文全用系统字体，西文与数字 Source Serif 4 | 决策 G：不加中文网页字体 |
| 站名「Patra 花园」 | 「Patra 学习站」 | 写给第一次来的人，名字先说清这是什么；花园留在视觉与用词里（第 9 节） |
| 顶栏：今天 / 所有条目 / 主题 / 版本 | 今天 / 路线 / 主题 / 标签 + 搜索 | spec 的页面是路线、主题、标签、搜索；版本索引不单独成页 |
| 条目页没有难度、前置 | 每篇标难度（四格刻度）、写明前置、开头诊断题、结尾迁移题 | spec 2.1 节 |
| 掌握度按钮在文末一排 | 文末掌握度组件 + 条目页头的掌握度徽章 + 首页回顾卡里也能改 | 掌握度驱动「今天读这一条」 |
| 排查页的 curl 表里写了真实主机名和 tailnet IP | 换成 `<mini 的主机名>`、`<mini 的真实地址>` | 决策 E |
| 「最近种下的」6 张卡 | 「学习路线」8 张卡在前，「最近写的」3 张在后 | 新读者先找路线，老读者有回顾卡 |

### 2.2 字体（决策 G）

| token | 字族栈 | 用在 |
|---|---|---|
| `--font-display` | Source Serif 4 → Songti SC → STSong → Noto Serif CJK SC → Source Han Serif SC → serif | 标题、一句话、题干、大数字 |
| `--font-body` | Source Serif 4 → PingFang SC → Hiragino Sans GB → Microsoft YaHei → Noto Sans CJK SC → sans-serif | 正文 |
| `--font-ui` | system-ui → PingFang SC → … | 按钮、徽章、元信息、图示里的方块 |
| `--font-mono` | JetBrains Mono → ui-monospace | 代码、队列名、表名 |

- 中文全部走系统字体：标题宋体、正文黑体。Source Serif 4 只覆盖西文与数字，所以正文里的英文和数字是衬线、汉字是黑体，这是决策 G 的字面效果，已拍板保持（第 9 节）。
- 按钮、徽章、元信息、图示方块用 `--font-ui`（系统 UI 字体），控件用衬线会显得笨重。这是对决策 G 字面的偏离，已获接受。
- Source Serif 4 与 JetBrains Mono 落地自托管（`@fontsource-variable/*`），画板里走 Google Fonts 只是为了画出来。
- 标题宋体用 700（Songti SC Bold）。不同系统宋体字形不一样，是决策 G 已接受的代价。

### 2.3 字号、间距、圆角、动效

- 字号：条目标题 38 / 页面标题 32 / 节标题 22 / 卡片标题 18 / 一句话 19 / 正文 16（行高 1.85）/ 控件 14.5 / 元信息 13 / 徽章 12。
- 版心：页面最宽 1200，正文列最宽 680，侧栏 280，栏间 56。
- 间距 4 的倍数；圆角：卡片 14、内块 10、徽章 6、胶囊全圆。阴影只有两档：卡片 `0 1px 2px` 与悬停浮起 `0 10px 28px`。
- 动效三档：`--dur-1` 160 ms（悬停、按下）、`--dur-2` 280 ms（揭晓、展开、高亮切换）、`--dur-3` 560 ms（逐步动画里物件移动）。缓动对应 GSAP：`--ease-out` = `power3.out`、`--ease-io` = `power2.inOut`、`--ease-spring` = `back.out(1.6)`。**不跟随**系统「减少动态效果」（spec 2.1 交互、决策 D）。

## 4. 条目页

### 4.1 四类共用的骨架

从上到下：位置（路线第几篇 / 主题 / 标签）→ 类型 · 难度 · 掌握度 · 标签 → 标题（概念可加英文名）→ 出处与时长 → **先读这几篇** → **开头诊断题** → 正文 → **结尾复述题或迁移题** → **掌握度** → 上一篇 / 下一篇。右侧栏：所在路线的前后几篇、同一主题、被谁提到、出处与代码钉住的提交。

- **先读这几篇**只列直接前置，每篇带读者的掌握度点；前置自己的前置折叠成一行「它又要求先读」。新读者看到的提示是「开头那道题答得上，就可以直接往下读」。
- **诊断题**答错或点「我答不上来」时，给出一篇前置（标题、类型、难度、分钟、在哪条路线第几篇）和两个出口：「先去读这篇」「我直接往下读」。往下读后诊断题收成一行，能「重新答」。
- **侧栏路线**只显示当前篇前后各两篇，其余折叠成「前面 5 篇 · 读过 5 篇」「后面还有 7 篇」；路线长到 17～28 篇时不会挤满侧栏。

### 4.2 各类的差异

| 类型 | 正文结构 | 特有元素 |
|---|---|---|
| 概念 | 一句话 → 那时候碰到了什么 → 打个比方 → 图示 / 动画 / 对比 → 在 Patra 里长什么样（代码）→ 小心 / 代价 → 考考自己 | 英文名斜体副标题 |
| 排查 | 结论先说（怎么修、值得记住）→ 一开始看到的 → 一路怎么查过来的 → 证据（命令对比）→ 根因（时序图）→ 顺带想通的 → 下次碰到类似的 | 排查路径：排除的假设划掉、方向对的点琥珀色、找到的点水青；每一步先读假设，点「测一下，看结果」再展开 |
| 决策 | 背景 → 选项（2～4 个，点开看好处与代价，选中的标「选了这个」）→ 选了什么 → 付出的代价 → 来龙去脉 | 「已被取代」：页首琥珀色横幅指向取代它的条目，标题旁徽章，来龙去脉里两条都在 |
| 坑 | 坑在哪（一句话 + 警示图标）→ 你会看到什么 → 为什么（配交互）→ 怎么避开 → 怎么认出它 | 一坑一页，正文最短 |

### 4.3 个人环境

决策 E 的「个人环境」条目：页首一条虚线框说明「和作者本机有关，不进路线、不进首页推荐，只在个人环境标签下能找到；排查思路是通用的」。首页、路线、搜索结果里都不出现；标签页里「个人环境」与其他标签隔开、单独说明。

个人环境条目**可以挂主题**，条目侧栏照常列出同主题的条目（排查画板里的「本机网络与代理」就是这样）。一个主题下如果全是个人环境条目，这个主题不进主题列表、不上首页「正在长的主题」，只能从标签页或条目侧栏进入；主题里只有部分是个人环境条目时，主题照常展示，那几篇带「个人环境」标记。

## 5. 掌握度与「今天读这一条」

- 掌握度三档：**刚接触**（名字听过，细节还说不清）、**理解中**（能讲个大概，自己动手还要查）、**吃透了**（能给别人讲清楚，也知道什么时候不该用），加「没读过」。图标是种子 → 芽 → 两片叶。只存在浏览器里，选中后弹一句「记下了：理解中」并说明之后首页会怎么用它；可取消标记。
- 首页回顾卡：显示**推这条的理由**（「你标过理解中 · 17 天没看了」/「最久没看 · 23 天」/ 没标过时「上次看是 17 天前」），先给问题「先自己想一想」，点「想好了，翻开看看」才显示答案；揭晓后可直接改掌握度、读全文或换一条。卡上写「还有 N 条候选」。
- 候选与排序由 PAP-162 实现，画板只定呈现。回顾问题和答案需要内容模型里有对应字段（见第 8 节）。
- 新读者（或清空本地记录后）：第一屏换成「从这里开始」——一段说明、Web 与 HTTP 的前三篇、「从第一篇读起」；右侧解释四档难度，并说明进度只存在浏览器里。
- 路线卡：读者进度是一根按掌握度分段的细条 +「读过 n 篇」，路线有 17～28 篇，一篇一个点放不下。

## 6. 教学组件库

每个组件都是一块可交互画板，Tweaks 的「状态」可以直接跳到任一状态；条目页里嵌的是同一块。外壳统一：白卡片、上方标题 + 组件类型、下方操作栏（`--surface-soft` 底）。

| 组件 | 画板 | 状态 | 交互与动效 |
|---|---|---|---|
| 开头诊断题 | `C-Diagnose` | 未答 / 答对 / 答错 / 答不上来 / 答错后直接往下读（折叠） | 点选项即判；答错推一篇前置；判定条从下浮入（dur-2） |
| 考考自己 | `C-Quiz` | 未作答 / 选了还没对答案 / 答对 / 答错（可再试一次）/ 全部做完（第一次就答对几题） | 先选后「对一下答案」；多题有进度条 |
| 迁移题 / 复述题 | `C-Transfer` | 还没写 / 写了一半 / 对照参考 / 自评完；题型：迁移 / 复述 | 自由书写、不保存不提交；「写好了，对照参考」或「想不出来，直接看」；参考要点逐条打勾自评，给出想到几条 |
| 掌握度 | `C-Mastery` | 没标过 / 上次标过 | 三选一卡片，选中上浮；记下后的提示 2.6 秒后消失 |
| 结构图 | `C-Structure` | 默认 / 选中交换机 / 选中绑定 / 消息送到队列 / 消息没人接 | 点方块或绑定，其余变淡、下方说明换成它的职责；「发一条」让消息块沿路径移动 |
| 时序图 | `C-Sequence` | 第 1 条 / 第 4 条（卡住的地方，红色虚线）/ 全部看完 | 一条一条往下走，没走到的变淡；左侧时钟显示累计耗时；点任意一条消息跳过去 |
| 状态机 | `C-StateMachine` | 事务中 / 外送中 / 点了这个状态下不会发生的事件 / 已删除 | 点事件推进状态，当前状态弹一下（spring）；点了不可能的事件：说明条抖动、变红，列出现在能发生的事件 |
| 逐步动画 + 你猜会怎样 | `C-Stepper` | 开始前 / 第 3 步前等你猜 / 猜错之后揭晓 / 第 5 步前等你猜 / 播完 | 「下一步」驱动，不自动连播；关键步骤前插「你猜会怎样」单选，答完才能继续（可「不猜，直接看」）；消息块在节点间移动（dur-3, power2.inOut），到达的节点高亮 |
| 参数滑块与开关 | `C-Params` | 有队列 / 没队列只看 ack（坑）/ 没队列先看退回 / 不带 mandatory | 三个开关 + 补投间隔滑块，右侧实时给出「生产者依次收到」「消息去哪了」「登记行」和一句结论 |
| 对比切换 | `C-Compare` | 三种写法 × 顺利 / 崩溃 | 分段切换写法，开关模拟「崩在中间」；被跳过的步骤划掉，结果徽章换色 |

**图示的约定**：一张图只讲一个关系；方块是 `l-node`（选中加水青底与外圈、其余降到 38% 透明度），连线一段一个 SVG，标签带底色压住穿过的线；图里的名字用真实代码里的（`interaction.events`、`notification.inbox`、`event_publication`）。

## 8. 交接

**给 PAP-157（组件库）**

- 组件名与 PAP-155 对齐：开头诊断题 = `Diagnose`，结尾 = `Recap`（复述）/ `Transfer`（迁移）；另外需要 `Quiz`（文中的考考自己）、`Mastery` 不进 MDX（页面自带）。
- 画板里每个组件的状态（第 6 节表格）就是组件测试的场景清单。
- 画板里的动画是 CSS transition 演示，落地用 GSAP：时长、缓动按 2.3 节的 token；逐步动画每一步一个 timeline 片段，「上一步」反向播放。
- 诊断题的数据形状可参考画板的 `data` 属性：题干、三个选项、正确项、答对说明、答错说明、推荐的前置条目 slug。

**给 PAP-155（内容模型）**

- 首页回顾卡需要每篇有一个「回顾问题 + 答案」：可以复用诊断题，或单独加字段，由内容模型定。
